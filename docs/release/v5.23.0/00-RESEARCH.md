# v5.23.0 调研笔记（最后一公里：从"能跑通"到"能交付"）

> 流程位置：① 需求调研。上游事实来自 2026-11-17 用户视角实操评审（黑盒，不读实现自证）。
> 证据分级：**[已核实]** = 本轮实测（界面截图 / 接口响应 / 代码行 / 库表读数）；
> **[推断]** = 由已核实事实按常识外推，尚未单独取证；**[假设]** = 需产品侧裁决或新增采集才能确认。
> 本笔记只陈述事实与差异，不提方案、不写判据（那是 ② 评估 与 ③ PRD 的事）。
> 完整评审报告与 32 张截图见 `../../plan/UX体验评审与迭代规划-20261117/01-体验评审报告.md` 与 `shots/`。

## 3 [已核实] 三处阻断型卡点（P0）

| # | 卡点 | 实测现象 | 根因（有代码/接口证据） |
|---|---|---|---|
| F-23-06 | 执行→报告→对外导出终点链路断裂 | 执行时不采 metadata → 报告首屏"未判定 / 不可对外交付" → 测试报告页导出静默失败（`/api/test-reports/38/export` 400，界面干等 100 秒零提示） | 后端 400 body 已写明"报告元数据缺项…或改用 mode=internal"，前端 `ReportExportBar` 空 `catch` 吞掉 message |
| F-23-07 | 61 条跳过无解释、三处口径不一致 | 同一 run 界面出现 61 / 9 / 70 三个数 | 应跑/实跑/跳过/测试项口径未显式区分；SKIP 原因仅存 PDF 明细，界面无聚合 |
| F-23-08 | 报告"看不见" | 刷新后页面上找不到刚跑完的 run；"在跑 1"点不进去 | 发起页不持有 runId（进度为易失文本）；执行协调无状态筛选入口 |

## 4 [已核实] 提升型短板（P1/P2，摘要）

| # | 短板 | 实测现象 |
|---|---|---|
| F-23-09 | 建集只能单选、一次一条 | 候选下拉无计数、无滚动条、底部被裁切；469 条项目靠逐条加不现实 |
| F-23-10 | 无二次确认即执行 | 点提交立即跑，误触无法撤回 |
| F-23-11 | 两套报告分工未写明 | 菜单有"执行报告"与"测试报告"，用户不知进哪个；"客户看到的那份"无法预先查看 |
| F-23-12 | 菜单标题与文案不一致 | 全局总览标题仍叫"项目总览"；标题与菜单名不符 |
| F-23-13 | 术语密集、数字缺口径 | "需补判 / 不互斥 / D12 双口径 / exit 1"；通过率分母是否含跳过未说明 |
| F-23-14 | 视觉与排版 | 多处按钮错位、表头错位、右侧留白；导出回执 64 位 sha256 直接铺开 |

> 完整 40 条短板（P0/P1/P2/P3 + 横向）见总纲评审报告 §三；本版只处理与"最后一公里"直接相关者，取舍见 `01-ASSESSMENT.md`。

## 5 [推断] 由事实外推（未单独取证）

| # | 推断 | 依据 |
|---|---|---|
| I-23-01 | 导出失败提示若原样显示后端 message，可直接消除"干等 100 秒"的体验 | F-23-06 中后端 message 已是面向用户的完整中文 |
| I-23-02 | 发起时前置采集 7 项 metadata，可让报告首屏脱离"未判定" | 缺项清单与"不可对外交付"标注同源 |
| I-23-03 | 执行 runId 落 URL query 后，刷新可恢复进度与归属 | F-23-08 的成因是易失文本，URL 是可持久化载体 |

## 6 [假设] 需裁决或新增采集才能确认

| # | 假设 | 为什么不能当结论 |
|---|---|---|
| A-23-01 | SKIP 逐条原因可聚合成"五类" | 实测 SKIP 行 `failure_msg` / `criteria_json` 全空，`case_script_binding` 对 SKIP/PASS 一律 UNBOUND，`pytest_case_step` 该 run 0 行——**数据载体不存在**，见 DEV-PLAN §5 实测推翻表 |
| A-23-02 | 两套报告入口应合并 | 数据模型本就分离（run 级 vs 报告级），是否合并属产品口径，已另行裁决为 B+ 分离方案 |
| A-23-03 | 对外报告可直接复用内部版文案 | 实测 `WATERMARK="INTERNAL USE ONLY"` 硬编码进所有导出，对外版带"仅供内部"声明——属对外口径，需单独裁决 |
