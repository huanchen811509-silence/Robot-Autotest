## 1. 背景与用户故事

评审实测（2026-11-17，项目 `EHT pytest 用例库工程`，469 条用例）暴露的是一条**断在终点前**的链路：

### 故事 A：拿到了报告，但交不出去

> 我在 pytest 工程页发起 61 条用例执行，4 分钟后报告生成。打开报告，首屏写着「未判定」，下面一行「报告当前不可对外交付」。我点「导出 PDF」，按钮是灰的；转到「测试报告」页建了草稿再点导出，**页面毫无反应**，我以为卡了，连点三次。

**根因**：报告元数据（CASE_ID 等 9 项）在发起执行时从未被要求填写；元数据缺失导致导出被护栏拦住；护栏后端有清楚的中文提示，**前端把它丢了**。

### 故事 B：不知道那 61 条去哪了

> 我发起 61 条，界面显示「已完成 0/61」。跑完，运行记录写「5 / 4」，执行报告写「总数 70、跳过 61」。同一个 run，我看到三个不同的数。

**根因**：口径未统一（应跑/实跑/跳过/测试项），且 SKIP 原因只在 PDF 明细里，界面无聚合、无解释。

### 故事 C：找不到刚跑完的那次

> 提交执行后我离开页面再回来，页面上什么都没了。「执行协调」显示「在跑 1」，但那个 1 点不进去。

**根因**：发起页不持有 runId；进度仅为易失的一行文本。

### 故事 D：两个"报告"，我该进哪个？

> 菜单里有「执行报告」和「测试报告」。我要给客户出一份，先点进了执行报告，发现导出是灰的；转到测试报告，又得重新选一次执行记录。
> 我不知道两者的分工，也不知道"客户看到的那份"长什么样——我只能在导出后打开 PDF 才知道。

**根因**：两套报告的数据模型已经分开（run 级 vs 报告级），但**入口语义没写、派生关系不可见、对外视图不能预览**。这三件事不解决，分离就成了"分家不打招呼"。

## 2. 目标与非目标

| 项 | 内容 |
|---|---|
| 目标 | 一个人从建集到导出对外 PDF，全程无阻断、无静默失败、数字可自证 |
| 度量 | 端到端成功率 0% → 100%；同一 run 四处口径一致；校验性阻断 100% 可见 |
| 非目标 | 不合并两套报告入口（FR-18 待裁决）；不改报告字段白名单；不做字段级权限；不重做报告视觉（v5.28） |

## 6. 已裁决项：两套报告（FR-v5.23-18）

**大师 2026-11-17 口径**：

- **执行报告** = 测试人员自用。关注当前项目/当前用例集的执行情况，失败→查原因→修复→重跑。
- **测试报告** = 给合作伙伴/客户的交付物。关注这些用例对应的测试环境、工具，以及产品的功能/性能/稳定性；**内部先预览，OK 后导出**。

**裁决：分离，不合并。** 三个方案的处理：

| 方案 | 结论 | 理由 |
|---|---|---|
| A 合并为一条链路 | 否决 | 两种读者、两种对象、两种生命周期、两种合规要求，合并会同时毁掉两边 |
| B 分工 + 互跳 | 采纳并升级为 **B+** | 仅互跳不够，还要补"派生动作可见"与"对外视图可预览" |
| C 不动 | 否决 | 评审已证明用户会迷路（故事 A） |

**B+ 的五条要求**已写入 §4.6 FR-v5.23-18，落地为 W73-11（入口语义 + 派生 + 互跳）与 W73-18（预览客户视图）。

**本次不做、留给 v5.28.0 的两件**：

| 项 | 归属 | 原因 |
|---|---|---|
| 审核态（APPROVED）与审核人记录 | FR-v5.28-07 | 当前状态机 `DRAFT → FROZEN → REVOKED/ARCHIVED` 无审核语义，需先落地"谁批准对外"才谈得上审批流 |
| 交付批次（用例集 + 环境 + 版本 + 时间窗） | FR-v5.28-08 | 客户报告的对象不该是"最近一次 run"（可能是 9 条子集或调试运行），需引入批次取数规则 |

**菜单：大师已于 2026-11-17 批准「独立报告组 + 两个子项」，并于同日追加一级组更名。**
落地形态受 `config/navigation.ts` 的硬约束（层级 ≤2、不引三级、不设组级 capability、FR-UI-26 曾把执行与报告合为一组）限制，实际采用（2026-11-17 14:29 UI 实测确认）：
- 一级组更名：原「执行与报告」→ **「执行管理」**；原「报告」→ **「报告管理」**；
- 「执行管理」保留运行态五项（执行计划/运行记录/测试计划/执行节点/执行内核）；
- 「报告管理」下恰好两个主项：执行报告、测试报告；「报告模板」作为配置附属项保留在本组（未移入系统设置——因报告模板带项目上下文，塞进全局 SETTINGS_NAV 会让全局菜单出现项目级路径，属技术约束偏差，记入 ⑦ 回写）；
- 三个深链路径全部不变；E2E 探针与菜单快照断言同步更新。
**不得**在任何一级组下再套一层子组——那会形成三级菜单，违反 D-01。
