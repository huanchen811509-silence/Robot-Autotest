## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 用例集从「单栏纵向堆叠」改成**中栏集合 + 右工作区成员 + 成员详情 Dock**，成员与集合**信息幂等**并能看到执行文件；项目资产与公共资产**合并成一个工作台组件**，用 `scope` 区分列与动作，项目侧只显示授权资产 |
| 性质 | **复用版**：本版不自创交互，全部复用 5.11 的 `DetailDock` 与 `CaseScriptLink`；工作量集中在「把两套 1451 + 1106 行的资产页合成一套」 |

### 1.1 与上游评估的一处顺序调整（必须留痕）

评估报告 03 §3.3 建议「**先做 R9 的数据与写入，再做 R16 的合并**」，理由是「反过来会把采集入口在旧组件里实现两遍」。
总纲 §3.2 排的是 5.12 = R16、5.13 = R9。**本 PRD 按总纲执行，并说明为何不会实现两遍**：

| 顺序 | 会发生什么 |
|---|---|
| 先合并（本版） | 5.12 交付**唯一**的 `AssetWorkspace`；5.13 在这一个组件里接采集链路 → 采集入口只写一次 |
| 先采集（评估建议） | 5.12' 在 `GlobalAssetsView` 写一遍采集 → 5.13' 合并时把 `AssetsView` 的采集入口再写一遍 → 才是真的写两遍 |

结论：**先合并后接采集更省**。条件是本版**不在旧组件里新增任何采集逻辑**——只做形态与列的统一，采集按钮保持现状行为（`canCollect` 逻辑不动，缺陷按 FR-09 登记到 5.13）。此偏离记入 §12 修订记录。

### 1.2 现状的两个确凿反例

| # | 反例 | 证据 | 用户看到什么 |
|---|---|---|---|
| 1 | 用例集成员行不可点开、无路径 | `CaseSetsView.vue:778-806` 的成员行只有序号/编号/标题/三个按钮，**无 `@click`、无路径、无详情** | 想知道这条用例跑哪个文件，得跳去用例清单再搜 |
| 2 | 两套资产页能力互补但不重叠 | `AssetsView.vue` 1451 行（4 页签、批量删、平台引用/解除、链路）；`GlobalAssetsView.vue` 1106 行（2 页签、导入导出、采集、凭证绑定） | 同一个「设备」，在项目里能批量删、在全局能采集，两边都得学一遍 |

**R16 的「仅显授权」后端已经成立**（`AssetScopeSql.java:22-27`）：

```sql
WHERE (d.project_id = ? OR (d.owner_scope = 'PLATFORM' AND pa.id IS NOT NULL))
```

所以本版的工作**不是**做权限过滤，而是「同一套形态 + 同一套列 + 同一套动作」。

## 2. 约束与术语

| 术语 | 含义 |
|---|---|
| 成员信息幂等 | 成员表格的列集合 ⊆ 成员详情 DTO 字段集合；点开不得新增/缺失字段（与 5.11 同一不变量） |
| scope | 工作台的两种运行态：`project`（项目内，只看授权资产）/ `global`（公共资产库，看全部平台资产） |
| 差异矩阵 | `AssetWorkspace` 里「哪些列/动作在哪种 scope 显示」的唯一真值表（见 §3） |
| 平台资产引用 | 项目对 `owner_scope='PLATFORM'` 的设备通过 `project_asset`（`V7_3:48-63`）建立引用；解除引用不等于删除设备 |
| 原子快照 | 用例集选择是「当时的成员快照」，非动态引用（与 5.10 FR-07 一致） |

**硬约束**：

1. **不合并后端端点**：`/api/projects/{id}/devices|links|credentials` 与 `/api/global/assets*` 各有权限与审计语义，合并风险大；只合前端。
2. **不允许做成「都塞进去」的巨型组件**：必须先用 §3 的差异矩阵把列与动作枚举完，配置驱动，禁止「if (scope===global) 再渲染一大段模板」堆叠。
3. **项目侧删除语义必须区分**：平台引用 → 「解除引用」；项目私有 → 「删除」。两者不得同名按钮。
4. **本版不新增采集逻辑**：`canCollect` 等判定保持现状，缺陷登记到 5.13，避免两版各写一遍。
5. **迁移尽量为零**：预期无业务表变更；若需索引从 `V11_71` 起。

## 3. 资产工作台差异矩阵（本版核心交付物之一）

| 列 / 动作 | project scope | global scope | 说明 |
|---|---|---|---|
| 设备页签 | ✅ | ✅ | 共用 |
| 链路页签 | ✅ | ❌ | 链路是项目内拓扑概念 |
| 凭证页签 | ✅ | ✅ | 共用 |
| 授权租约页签 | ✅ | ❌ | 租约属项目 |
| 列：归属 `owner_scope` | ❌（本页都是自己的或引用的） | ✅ | 全局需要区分平台/项目私有 |
| 列：来源（公共资产 / 本项目） | ✅ | ❌ | 项目侧要能看出「借来的」 |
| 列：引用项目数 | ❌ | ✅ | 全局删除前需要 |
| 列：授权状态 | ✅ | ❌ | — |
| 动作：新建 | ✅ | ✅ | — |
| 动作：编辑 | ✅ | ✅ | 全局后端当前**无 PUT**，本版补（承接 5.9 FR-07 判据 3） |
| 动作：删除 | ✅（私有删、引用解除） | ✅ 仅管理员；被引用 → 409 | 文案必须区分 |
| 动作：批量删除 | ✅ | ✅（仅管理员） | 全局当前无批量删（5.9 通则 T3） |
| 动作：导入 / 导出 | ❌ | ✅ | 导入导出属平台库维护 |
| 动作：采集 | ✅（保持现状，5.13 打通） | ✅（保持现状） | **本版不动行为** |
| 动作：绑定凭证 | ✅（只读展示，5.13 可写） | ✅ | 本版只统一展示位 |
| 动作：引用平台资产 / 解除引用 | ✅ | ❌ | 项目侧独有 |

> 这张表是唯一真值。实施时任何「新增一列/一个动作」都必须先回国这张表，否则会出现「两个 scope 各写一套」的回归。
