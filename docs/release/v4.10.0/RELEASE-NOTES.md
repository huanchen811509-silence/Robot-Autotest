| 项 | 内容 |
|---|---|
| 版本 | `4.10.0`（在 `4.9.2` 基础上的功能版） |
| 日期 | 2026-11-11 |

| 兼容性 | 前端接口契约向后兼容；**两处破坏性变更**见下 |

> **v1.1 补记（2026-11-11 大师 5 项拍板后）**：`V11_44` 为内置模板补齐真实内容，并修复由此暴露的
> 「模板有内容时建项目 500」缺陷（`copyCase` 引用已重命名的 `category` 列）。

## 用户能拿到什么

1. **公共用例 / 项目用例 / 分配副本都能点开详情**，六组信息 + 参考表 14 列基线可见，来源与版本可追溯。
2. **用例支持一级 / 二级分类**，可按分类（含跨表交集）批量组成用例集、导出 CSV、编排测试场景。
3. **资产详情**给出硬件 / 软件与带外 / 状态三分区，带「采集时间 + 命令原文 + 原始输出 + 结构化值」四层证据；采集需显式选凭据并二次确认。
4. **模板卡片**与项目卡片同构，显示用例 / 用例集 / 场景 / 资产四类计数；全局模式可直接进模板编辑内容清单；**可一键从模板建项目**（单事务、默认复制），也可把项目存为模板。**内置模板自带真实内容**：接口回归 20 条、Web UI 巡检 20 条、Pytest 服务 18 条，各带 1 个场景与设备/凭据引用；「空白项目」保持空白。
5. **全局模式的系统设置改成与项目模式一致的二级菜单**，修掉此前「点一下就弹回项目模式」的缺陷。
6. **右上角新增主题 / 语言循环切换按钮**，与账户菜单内控件状态同步。
7. **项目模式系统设置的二级菜单按权限控制**，且权限判定来自服务端（`GET /api/me/menu-capabilities`），只做前端隐藏不算通过。

## 破坏性变更

| 变更 | 影响面 | 回滚 |
|---|---|---|
| `project_code_sequence` 主键 `scope` → 代理 `id`（保留唯一键） | 内部表，无外部依赖；`INSERT ... ON DUPLICATE KEY` 语义不变 | `V11_43` down 脚本 |
| `project_member_role` 联合主键 → 代理 `id`（原主键降级唯一键） | 内部表；`INSERT IGNORE` 语义不变 | 同上 |
| 5 张表新增审计列（`updated_at` 为 `NOT NULL DEFAULT CURRENT_TIMESTAMP(3)`） | 历史行按迁移时间回填 | 同上 |
| 前端移除 `ROLE_CAPABILITIES` 常量 | 依赖该常量的外部脚本改读 `GET /api/me/menu-capabilities` | — |

## 修复

| 缺陷 | 现象 | 修复 |
|---|---|---|
| L-49-08 | 模板里有 `CASE` 项时，`POST /api/projects/from-template` 返回 **500**（`Unknown column 'category' in 'field list'`）。四个内置模板内容长期为空，该分支自 v4.9.2 起从未被执行，属假绿 | `copyCase` 改 `INSERT ... SELECT` 整列搬迁，顺带带上 A端/B端/交换机/测试结果/测试资源五列与两级分类 id；新增 `ProjectTemplateCopyIT`（真实 `robot_it`）逐列断言 |

## 升级步骤

1. `bash scripts/db-migrate.sh`（`V11_40`→`V11_44`）。
2. `bash scripts/build.sh` 或分别构建前后端。
3. 重启 `robot-autotest-backend` / `robot-autotest-entry`。
4. 跑 `python3 tools/check_version_consistency.py` 确认五处版本同源。
