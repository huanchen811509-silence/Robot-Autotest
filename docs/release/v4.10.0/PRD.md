## 0. 结论先行

1. **本批的性质是「接通」不是「新建」**。R1/R2 的字段与两级分类已入库（同一份 `基本功能导入测试v0.5.0.0.xlsx` 的 730 条用例、2779 步骤、32 个一级分类，`CHANGELOG.md:21`），R3 的 SSH 主机清单采集链路已跑通（`HostInventoryService` + `SystemSshClient` + 10 类只读命令），R5 的「项目转模板」后端已实现（`ProjectTemplateService#saveAsTemplate`）。38 条 FR 里，需要新增后端**业务能力**的只有 R5 的建项目编排与 R7 的服务端菜单权限两处，其余是详情视图、编辑入口、导航与权限挂载点。
2. **两个必须先修的存量缺陷已升为 P0 FR**：R6 全局系统设置 8 张卡片的目标路由全不带 `meta.global`，按 `frontend/src/router/index.ts:354-358` 守卫，点击后被强制切回项目模式（功能性不可达）；R1 导入器 `HEADER_ALIASES` 不认「A端命令 / B端命令 / 交换机配置 / 测试结果」四列，参考表这四列**导入即丢**（数据损失）。
3. **需求里的「分配用例」不是新实体**。三类用例实际都落在同一张 `test_case`，靠 `project_id` 区分；公共库是单例平台项目 `PLATFORM-LIB`（`V11_31`），分配语义是有意为之的**快照复制 + 手动重同步**（`PlatformCaseSetController:17-18`），副本靠 `sync_job_item` 追溯。经大师拍板，本批**维持该语义**，不新建表、不改同步链。
4. **权限必须服务端同源**。项目模式系统设置 6 个二级项目前只有 3 项带 `capability`，且能力表 `ROLE_CAPABILITIES` 硬编码在前端；只做前端隐藏等于「假权限」，直接输 URL 仍能进 `/admin`。本批 FR-v4.10-31 ~ 34 要求前后端同一数据源 + 直接 URL 拦截 + 负向验证必须红。
5. **不做整包移植**。R10 受 `测试自动化demo程序/04 8001平台/AGENTS.md` 记载的 2026-10-25 收口令约束，该轮迁移已做过并被叫停；本批维持收口令，只把「反伪造复核 / 四层证据链」等方法论沉淀列入技术债，不立 FR、不进 WBS。
6. **退出标准不是「单测绿」**。按仓库纪律，只认真实链路：`scripts/gates.sh` 全量门禁、`check_release_docs.py v4.9.2` 基线不退化、每条 FR 至少 1 条 TC、关键需求有反例、浏览器证据受 CDP `:9222` 取消影响的显式标 `NOT-RUN` 且不计 PASS。
