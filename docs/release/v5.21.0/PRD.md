# v5.21.0 产品需求文档（PRD）：角色可用性与工程同构

> 流程位置：③ PRD（草案）。上游：`00-RESEARCH.md`（26 条事实）、`01-ASSESSMENT.md`（B 方案）。
> 版本号 `v5.21.0` 为**拟用号**，本文件不修改 `VERSION`。
> **本版 6 条 FR**：3 条 P0（角色可用）+ 3 条 P1（同构/偶发/口径）。
> **每条需求必须可判定**：写不出判据的不算需求。

## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 让"非管理员的三种角色"真的存在、能登录、看到该看的、点不到不该点的；并确认四个工程是同一套体验 |
| 性质 | **角色可用性版**：3 条 P0（角色数据缺失 → 能力集空 → 前端不设防）+ 3 条 P1 |
| 上游 | v5.19 §9 遗留 L-19-03（RF 同构）/ L-19-04（三角色体验）转正 |
| 不追求 | 不重写权限模型、不做字段级权限、不做自定义角色、不做 SSO |
| 判据基线 | 真实浏览器 + 真实接口 + 只读 SQL；视口 1440×900（关键项补 1366/1920） |

### 1.1 为什么这三条 P0 是一个整体

`role` 表没有 pm/engineer/viewer（F-21-01）→ 无法建非管理员账号（F-21-02）→ 三角色能力集返回空（F-21-07）→ 空能力被前端当成"全放行"（F-21-09/12）→ 用户看到不该看到的按钮、点进不该进的页面（F-21-13/14）。
**这五步是一条链，只修其中一环都会留下"看起来好了但一验就露"的中间态**，所以三条 P0 必须同版同批交付。

### 1.2 角色口径（本版判据的唯一口径）

| 层 | 载体 | 取值范围 | 作用 |
|---|---|---|---|
| 全局角色 | `user_role` → `role` 表 | admin / pm / engineer / viewer | 决定**平台级能力**（菜单能力集、管理域可达性） |
| 项目角色 | `project_member_role.role_code` | 同上 4 值（**统一小写存**） | 决定**项目级数据与操作权限** |
| 能力集 | `GET /api/me/menu-capabilities` | `settings:read` 等字符串集合 | 决定**菜单叶子可见性**（不决定数据权限） |

**关键约束**：能力集为空的账号，其菜单必须是**最小集**（`about` / `changelog`），**不得**因"空"而全开。

4. 不越界修 v5.19/v5.20 范围内的缺陷；发现即回写对应版本文档，不在本版顺手改。

## 4. 需求详述

### FR-v5.21-01 四内置角色落库且可在界面上分配【P0】

**现状**：`GET /api/roles` 只返回 admin 一条；"新建用户"的全局角色下拉只有"管理员"；6 个账号里 4 个角色为 `—`。代码里 4 个角色、库里 1 个。

**要做什么**：
1. 新增幂等迁移 `V11_80__v5_21_builtin_roles.sql`，补齐 `pm/engineer/viewer` 三行（`built_in=1`，中文名：项目经理 / 测试工程师 / 访客），已存在则不覆盖 `name`/`permissions`。
2. `RoleService` 启动自检：`RoleCode` 枚举的 4 个 code 必须在 `role` 表中存在，缺失时按内置角色定义补齐（与迁移同源，二者取其一为真源，另一处只校验）。
3. 用户管理"新建用户"与"编辑用户"的角色下拉，渲染 `GET /api/roles` 全量并可多选。

**不做**：不做自定义角色创建 UI；不做角色继承。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | `GET /api/roles` 返回 4 条，`code` 集合 = `{admin,pm,engineer,viewer}`，全部 `builtIn=true` | 响应原文 |
| 2 | "新建用户"对话框角色下拉可选项 4 个，文字为中文角色名 | 截图 + DOM 选项数组 |
| 3 | 通过界面创建一个 `engineer` 账号并登录成功，该账号 `roles=["engineer"]` | 截图 + `GET /api/users/{id}` |
| 4 | 迁移重跑两次，`role` 表仍为 4 行（幂等） | 两次 `db-migrate.sh` 输出 + SQL 计数 |
| 5 | 已存在角色行的 `name`/`permissions` 不被迁移覆盖（手工把 pm 名称改脏后重跑，值保持） | SQL 前后对照 |

### FR-v5.21-02 能力集与菜单自洽：空能力不放大【P0】

**现状**：三角色 `menu-capabilities` 返回 `[]`，但侧栏仍渲染 19 项且三角色完全一致；admin 7 项、无 `execution:read`。

**要做什么**：
1. 后端 `AccessControlService`：账号无任何全局角色时，返回**最小集** `{about, changelog}`（fail-closed），不得返回空、也不得放大。
2. 前端菜单过滤改为**白名单制**：每个叶子必须声明 `capability` 或 `public: true`；未声明 = 不可见（而不是默认可见）。
3. 新增机检 `tools/check_nav_capability.py`：`navigation.ts` 中每个叶子节点必须二者之一，缺失即判红；`capability` 字面量必须 ⊆ 后端白名单。

**不做**：不调整分组、不新增叶子、不改 `execution:read` 的授予（该条属 v5.19 FR-02）。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | `qa-e2e-viewer`（无全局角色）`menu-capabilities` 返回 `["about","changelog"]`，不含 `settings:read` | 响应原文 |
| 2 | 上述账号侧栏叶子数 ≤ 3，且不含「环境采集」「用户管理」「执行报告」 | 截图 + DOM 计数 |
| 3 | `engineer` 账号能力集含 `settings:read`/`about`/`changelog`，侧栏叶子数 > 上述账号（差异可解释） | 两账号对照输出 |
| 4 | admin 侧栏叶子数不低于当前基线（22 项），不因白名单制而减少 | 截图 + DOM 计数 |
| 5 | `check_nav_capability.py` 对现状 PASS；删掉任一叶子的 `capability` 后 `--self-test` 判红 | 机检输出 |
| 6 | 未声明 capability 的新叶子在页面上不可见（注入一个临时叶子验证后还原） | 注入前后截图 |

### FR-v5.21-03 写操作按角色显隐；越权直达可理解拦截【P0】

**现状**：viewer 能看到并可展开"新建用例"表单（保存才失败）；可直达 `/execution-plans`、`/runs`；`/g/iam/users` 打开后接口 403、页面空白。

**要做什么**：
1. 前端提供统一能力指令 `v-can="'CASE:WRITE'"`（或等价 composable），**按角色+项目角色**判定；第一批覆盖 8 类写操作：新建/编辑/删除用例、Excel 导入、新建/编辑/删除用例集、发起执行、成员管理。
2. 路由守卫：所有需要权限的路由必须有 `meta.capability`；无权限直达时跳 403 页，403 页文案含「当前角色（{角色名}）无此权限」+「返回工作台」+ 申请路径。
3. 页面级错误态：接口返回 403 时，内容区显示错误态（复用 v5.20 的 `ListState` 失败态），不得空白。

**不做**：不做字段级权限；不改后端 403 结构。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | viewer 在用例库看不到「新建」「Excel 导入」，行内看不到「编辑/删除/提交评审」 | 截图 + DOM 按钮清单（应为 0 个写按钮） |
| 2 | viewer 在用例集页看不到「管理用例/编辑/立即执行/删除」 | 截图 + DOM |
| 3 | engineer 在用例库能看到「新建/编辑」，看不到「删除」（按矩阵：engineer 有 DELETE？若矩阵含 DELETE 则改为可见，判据以矩阵为准并写明） | 截图 + 矩阵对照 |
| 4 | viewer 直达 `/execution-plans`、`/runs`、`/g/iam/users` 均落 403 页，文案含角色名 | 3 张截图 |
| 5 | 403 页有「返回工作台」按钮，点击回 `/workbench` | 截图为证 |
| 6 | 任一列表接口 403 时页面出现失败态（含原因与重试），不出现空白内容区 | 截图 + DOM 断言 |
| 7 | 新增机检：路由表每条（除 public）都有 `meta.capability`；`--self-test` 判红 | 机检输出 |
| 8 | engineer 删除用例后，**项目用例库不再显示**该条（列表计数 -1），但该用例仍存在于平台公共用例池（按用例编号可查） | 截图 ×2 + 接口对照 |
| 9 | 删除为软删：`SELECT deleted_at IS NOT NULL` 能查到该行；不存在 `DELETE FROM test_case` 的物理删除路径 | SQL + `git grep` |

### FR-v5.21-04 四工程 × 六页面表现一致并纳入门禁【P1】

**现状**：四工程 `/cases` 全部表高 44px、首行不可命中；侧栏 22 项完全一致（无 RF 特有页面）。

**要做什么**：
1. 把 v5.19 的列表可见性修复确认为**通用布局修复**（不写工程类型分支）；本版只做回归与补漏。
2. 新增门禁探针 `scripts/ux-probes/project-matrix.mjs`：遍历 4 工程 × 6 页面，断言"表格高度 ≥ 300 或空态可见" + "首行可命中（有数据时）"，任一失败即红。
3. 无数据工程（demo#1 用例集 0 条）按"空态"判定，不判红。

**不做**：不为 RF 工程单独做页面；不改路由。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 4 工程 `/cases` 首行可命中（有数据时）或空态文案可见（无数据时） | 探针矩阵输出 4×1 |
| 2 | 4 工程 × 6 页面 = 24 格全部 PASS，报告含每格的行数与表高 | 矩阵报告 |
| 3 | demo#1 用例集页为空态时不判红，但报告标注「无数据，仅验空态」 | 报告文本 |

| 5 | 不出现按工程类型分支的代码（`grep` 无 `projectType ===` / `kind ===` 的新增判断） | `git diff` + grep 输出 |

### FR-v5.21-05 用例集行内操作与右栏状态解耦【P1】

**现状**：ED202 用例集页 28 个行内按钮全部不可命中；同一页另一次加载又可达 → 随右栏状态偶发。

**要做什么**：让左侧列表宽度不随右栏内容变化而挤压操作列——操作列固定在列表右缘（sticky），横向滚动时始终可达；4 种右栏状态下表格可用宽度恒定。

**不做**：不改三栏整体结构（v5.12 版式保留）。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 4 种右栏状态 × 3 视口（1440/1366/1920）= 12 组，每组 4 个行内按钮中心点 `elementFromPoint` 命中自身 | 探针矩阵 12 组 |
| 2 | ED202 用例集（7 条）在上述 12 组中「管理用例」全部可点并打开成员面板 | 截图 ×3（每视口 1 张） |
| 3 | 表格可横向滚动时，操作列在滚动到最右仍完整可见（列宽 ≥ 4 个按钮） | 截图 + 列宽断言 |
| 4 | 无横向滚动时（1366 以下压缩列宽）操作列不被裁 | 截图 |
| 5 | 门禁新增"行内操作可命中"断言，`--self-test` 注入覆盖层判红 | 机检输出 |

### FR-v5.21-06 角色代码统一小写 + 存量迁移 + 读路径兼容【P1】

**现状**：`project_member_role.role_code` 存量 `viewer` 与 `ENGINEER` 并存，同一接口两种写法。

**要做什么**：
1. 迁移 `V11_81__v5_21_role_code_lower.sql`：将 `project_member_role.role_code` 与 `role.code` 统一为小写（`UPDATE ... SET role_code=LOWER(role_code)`，幂等）。
2. 写入路径入口统一 `toLowerCase()`；读路径先兼容大小写（`LOWER(role_code)=?`），迁移完成后再收紧。
3. 校验：`SELECT COUNT(*) FROM project_member_role WHERE role_code <> LOWER(role_code)` 必须为 0。

**不做**：不新增角色值；不改表结构。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 迁移后混写计数 = 0 | SQL 输出 |
| 2 | `GET /api/projects/29/members` 中 `roleCode` 全为小写 | 响应原文 |
| 3 | 迁移前用大写写入的请求，迁移后仍能正确识别权限（engineer 仍可 PUT 用例） | 接口前后对照 |
| 4 | 迁移重跑两次结果一致（幂等） | 两次输出 |
| 5 | 前端角色展示用中文名，不直接显示 `ENGINEER`/`viewer` 字面量 | 截图 |
