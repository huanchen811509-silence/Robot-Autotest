# v5.9.0 评估报告（第②道）

> **归档说明**：本版的可行性评估同样不重写。6 份维度评估（IA/UX/AST/RPT/OPS/GOV）在
> `docs/plan/重构评估-20261115/`，覆盖 5.9→5.16 全部版本。本文件是**5.9 版本边界上的取舍结论**：
> 哪几项进本版、哪几项不进、不进的代价是什么、开工前必须满足什么前置条件。

## 1. 一句话结论

**5.9 只做「导航唯一高亮 + 判权三源并集 + 用户与权限一级菜单 + 演示数据地基 + 列表 CRUD 通则」五件事。**
这五件是后续七个版本的公共底座：不先把「同一个事实只能有一个来源」定死，5.10 的向导、5.11 的
用例工作区、5.12 的资产关联都会各自再造一套判权与可见性。

## 1.1 证据分级

本报告的每条判断都标了证据来源；证据本身分三档，**不同档位的结论强度不同**：

| 档位 | 含义 | 本报告中的用法 |
|---|---|---|
| `[已核实]` | 打开源码 / 查库 / 跑命令确认 | §2 成本判断、§5 风险触发条件的**全部**依据 |
| `[推断]` | 由已核实事实推出，未独立验证 | 「不做」项的代价估计（如「5.10 要返工」）；标注了但未验证 |
| `[假设]` | 起草时的预估 | §3 中「归属版本」的安排（版本顺序本身是排期决定，不是事实） |

证据附录：`docs/plan/重构评估-20261115/`（6 份维度评估，含逐条 `文件:行` 定位）；
本版的实测推翻项见 `TEST-PLAN.md §8.3` A1~A8，实测读数见 `05-TEST-REPORT.md`。

## 2. 纳入本版的范围与理由

| 需求 | 维度 | 进本版的理由 | 成本判断 |
|---|---|---|---|
| R1 二级菜单双高亮 | IA | 是**确定性缺陷**（不是口味问题）：`queryMatches` 无 query 时恒真，导致同组多个叶子同时亮。有单测可回放判红 | 低（`navigation.ts` 单点 + 61 条 spec） |
| R2「我参与的项目」只有一个 | IA | 可见性三源（成员/负责人/组授权）必须一处实现；本版是三源并集的**唯一落点**，晚了每版都要返工 | 中（新增 `ProjectVisibilitySql` 单点 + 5 个测试桩同步） |
| R4 用户与权限独立一级菜单 | IA | 菜单结构一旦定型，后续所有 IAM 页都挂在它下面；且旧入口「系统设置→用户管理」必须同时下线，否则两处写入口 | 中（4 页 + 路由 + i18n + 能力闸） |
| R3 开发/演示数据隔离 | GOV | `is_demo` 是**跨版本契约**：越晚加，5.10~5.16 新建的表越要补 | 低（列 + 脚本 + 机检） |
| R13 列表按需增删改查 | UX | 五处缺失（报告删除/批量删/资产编辑/用例引用守卫/用例集确认）都是**已有后端能力没有前端入口**，属"能力空转" | 中（跨 5 个页面 + 2 个新端点） |
| R10 用户/角色/组/项目关联幂等 | IA | 与 R2 同源的判权口径，同版做才不出现「页面上按 A 口径、接口按 B 口径」 | 中（关系聚合端点 + 组 CRUD） |

## 3. 明确不做（本版范围外）

| 不做项 | 归属版本 | 不做的代价（如实登记） |
|---|---|---|
| 项目向导 / 模板向导（R4 的向导部分、R11） | 5.10 | 5.9 的成员步与授权步只能手工配；向导上线后要能复用本版的 `addMember` 幂等与三源口径，所以顺序不能倒 |
| 用例清单三栏工作区、详情就地展开（R5/R6） | 5.11 | 本版不动用例页结构；`DataTable` 只加了可选勾选列，未改布局范式 |
| 全站显示测试文件相对路径（R7） | 5.11 | `case_script_binding.script_path` 已存在但未 join；本版只在删除守卫里用它 |
| 资产采集凭证自动/手工关联持久化（R9） | 5.12 | 本版只给「公共资产改名」，不碰采集链路 |
| 执行报告与测试报告分家、模板预览（R14/R15） | 5.13 | 本版只补报告列表的删除能力，不动命名与模板 |
| 环境与拓扑重写、维护与恢复重写（R17/R18） | 5.14 | 需照抄白泽，属"必须重写"，混进底座版会拖垮本版 |
| 安装/升级/维护/拆卸运维管理（R19） | 5.15 | 同上 |
| 删除影响面端点（用户/角色删除前「影响 N 个项目」） | 5.10 | TC-35/41 判 BLOCKED；本版删除已做清理，但不量化影响 |
| `addMember` 返回 `added/skipped` 计数 | 5.10 | TC-26/27 判 BLOCKED；改返回结构要同步 4 处调用 + 契约，与向导成员步一起改更省 |
| 真实 HTTP / 真实浏览器端到端取证 | 5.9 收口后由大师安排 | 本版 PARTIAL 15 条 / BLOCKED 13 条，逐条在 `05-TEST-REPORT.md §3` 写明 |

## 4. 前置条件（开工/发版前必须成立）

| # | 前置条件 | 为什么是硬前置 | 当前状态 |
|---|---|---|---|
| P1 | WSL `~/robot-autotest` 为权威副本，构建测试不在 `/mnt/*` 上跑 | 9P 构建慢 35 倍且会出假超时 | 满足 |
| P2 | `V11_65/66/67` 三支迁移先于代码合入，且各配 `.down.sql` | `is_demo` 与组外键是编译/运行前提 | 满足（含 V11_67 改「只建索引」的实测修正） |
| P3 | 三源并集 SQL 必须单点（`ProjectVisibilitySql`），其他类不得再写 `project_member` 字面量 | 两处实现必然分叉 | 满足（`check_visibility_sql.py` 门禁 53/56 守） |
| P4 | 新增仓储方法必须给 `default` 实现，否则既有测试桩全红 | 5.9 已踩过（5 个假实现同时失效） | 满足（`caseReferences` / `isVisibleTo` / `effectiveRoleCodes` 均按此） |
| P5 | 菜单增减必须同步 `check_navigation.py` 与 `check_nav_kind.py` 的基线 | 基线是"少一个入口要留下痕迹"的机制，不许静默放宽 | 满足（`GLOBAL_EXPECTED 5→6`、`EXPECTED_LEAVES 41→44`） |
| P6 | 发版前 `check_release_docs.py` 全绿，含**历史版本**没有 FAIL | 有 FAIL 的版本不得作为下一版基线（流程 §9） | 本版收口时补齐 v5.8.0 的 `05-TEST-REPORT.md` 后才成立 |
| P7 | G 门授权归大师，AI 不得勾 M 项 | 硬规矩 | 遵守（本版未宣称 GA） |

## 5. 风险与对策

| 风险 | 触发条件 | 对策 |
|---|---|---|
| 三源并集改了可见性 → 既有 E2E 账号读数变化 | `qa-e2e-pm` 从 1 个项目变成 3 个 | 造夹具（`visibility-fixture.sh`）复现差异并留读数；不靠 dev 库现成数据"碰巧通过" |
| 新增仓储方法导致测试桩批量失效 | 接口加非 default 方法 | P4：一律 `default` 空实现 |
| 4 个新 IAM 页与旧设置页双写入口 | 旧「系统设置→用户管理」未下线 | W59-15：旧入口改 `redirect`，`settingsNav` 6→5；A4 实测 6 组 19 叶（不是起草时的 20 叶）|
| 色值/变量令牌不一致导致暗色主题失效 | 页面自造 `--link`/`--danger` | 门禁 06-lint + 15-css_vars 双守；本版已修 8 处 |
| 契约漂移 | 新增 `batch-delete` 与 `PUT /g/assets/{type}/{id}` | 契约重生成 446/365 并 `--check` PASS |

## 6. 结论

**方案可行，范围可控，前置条件已满足（P6 于本版收口时补齐）。** 本版不做的事逐条列在 §3 并给了
归属版本，不存在"漏排"；不做带来的代价（TC-26/27/35/41 判 BLOCKED）已进测试报告，不藏在计划里。
