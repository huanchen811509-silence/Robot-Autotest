## 用户能拿到什么

1. **全局模式也有两级菜单了**：项目 / 公共用例 / 公共资产 / 模板 / 系统设置五组共 14 个二级入口，风格、展开逻辑、选中态与项目模式完全一致；进哪一页，对应组头自动展开并高亮。
2. **「执行与报告」下多了「执行计划」**：选用例集（或搜索补选）→ 看实时条数 → 配并发与参数 → 安全预检 → 立即发起 → 直接跳到这次运行的详情。它不是定时计划，是「现在就跑这一批」。
3. **项目模式的「系统设置」收成两件事**：我是谁（`/settings/users`，只读，列出我创建或加入的项目）与关于。平台级配置（平台设置 / AI 助手 / 用户管理 / 审计日志 / 版本迭代）统一在全局模式。
4. **右上角顺序顺了**：检索 → 通知 → AI → 主题 → 语言，账户菜单固定在最右；760px 窄屏不再横向溢出。
5. **「我参与的」真的只列我参与的**：卡牌接口新增「我是创建者 / 我是成员」两个布尔，全局管理员不再因为身份兜底而看到「全部」。
6. **侧栏二级项可以直接复制链接**：导入记录、凭据、内置/自定义模板、我参与的项目都有独立 URL，粘到地址栏就能直达。
7. **导入预览可以强制重算**：同一份文件已经提交过时，默认仍走幂等回放（不改数据）；需要按当前库重新算差异时加 `force`，**重算不写库、不改批次状态**，历史记录保持原样。

## 破坏性变更

| 变更 | 影响面 | 回滚 |
|---|---|---|
| 侧栏菜单结构变化：全局 5 组 14 叶；项目「系统设置」由 6 项收敛为 2 项 | 依赖旧菜单结构（一级平铺、两模式 diff = 0）的外部脚本与断言需同步更新 | `git revert` 单提交 |
| `GET /api/projects/cards` 每张卡牌新增 `own` / `joined`；`GET /api/execution/runs` 每条记录新增 `runRequestId` | 只增字段不改语义；严格反序列化（拒绝未知字段）的调用方需放行 | 同上 |
| 顶栏不再提供 `header-quick` 容器 | 依赖该选择器的自定义样式或 E2E 选择器改指 `[data-seg="tools"]` | 同上 |

## 修复

| 缺陷 | 现象 | 修复 |
|---|---|---|
| L-49-07 | 「从模板建项目」后场景详情永远是空的 | `test_scenario.case_set_ids` 原写死空串；改为两轮写入——先建完所有用例集拿到完整 id 串，再写场景（模板里 `SCENARIO` 可能排在 `CASE_SET` 之前） |
| L-50-01 | 全局设置组头永不展开 | `activeGroupKey` 原先只认项目树，改为按当前模式的树求值 |
| L-50-02 | 同一个 path 挂多个 query 时两个叶子都不亮 | 每组第一个叶子作为默认值，裸路径与非法值一律 `router.replace` 规范化 |
| L-50-03 | 全局管理员看「我参与的」等于看「全部」 | `myRole` 对 admin 有兜底语义，不能用来判归属；改判 `own \|\| joined` |
| L-50-04 | 表格换 `DataTable` 壳后单元格样式静默失效 | 列由 `h()` 渲染在 `NDataTable` 内部，拿不到组件 scope id；样式统一改 `:deep()` |

## 升级步骤

1. **本版 0 迁移**：不需要跑 `db-migrate.sh`，也无 down 脚本可回。
2. `bash scripts/build.sh`，或分别构建前后端（编辑器 → 前端 → 后端顺序不能反）。
3. 重启 `robot-autotest-backend` / `robot-autotest-entry`。
4. 跑 `python3 tools/check_version_consistency.py` 确认五处版本同源（VERSION / build-info / 两份 CHANGELOG / openapi）。
5. `bash scripts/lint.sh` 应看到新增的菜单机检项（`tools/check_navigation.py`）为绿。

## 回滚

- 前端改动集中在 2 个配置 + 1 个组件 + 8 个视图，后端改动集中在 4 个文件且均为**加字段**，无 DDL、无数据迁移 → `git revert 695626f` 即可，无残留；
- `tools/check_navigation.py` 为新增机检，若规则过严可先在 `scripts/lint.sh` 里降级为 WARN，不要删脚本。
