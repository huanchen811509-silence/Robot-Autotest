# v5.22.0 评估报告：报告可信 + 体验收尾

> 流程位置：② 评估报告。上游：`00-RESEARCH.md` r2（25 条事实 / 5 条开放问题）。
> 本文决定「做不做、做什么、不做什么」；需求与判据写进 `PRD.md`。
> 所有事实编号沿用调研笔记的 `F-22-xx`，本文不复述证据，只引用。

---

## 1. 目标与范围

**目标**：让「报告」这个交付物**对外敢发**——同一份报告在界面、导出文件、列表三处说同一件事，且不出现假值；同时把 v5.20 遗留的 FR-06 四条体验判据收口。

**范围**：

| 组 | 内容 | 事实来源 |
|---|---|---|
| 可信-1 | 对外视图补齐 metadata 三键（`QA_PROJECT` / `DUT` / `LINK`）、换真项目名 | F-22-03 / F-22-04 |
| 可信-2 | 4 个硬编码假值处置（`coverageRate` / `caseCovered` / `failureDistribution` / `trend`） | F-22-05 / F-22-06 / F-22-08 |
| 可信-3 | 报告级导出可用：带用例明细、中文可读、撤回与不可对外有闸 | F-22-09 ~ F-22-15 |
| 可信-4 | 计数口径：`run` 表与 `test_result` 明细对齐（含 skip 无处存） | F-22-18 ~ F-22-21 |
| 体验 | FR-06 四件（新建即选中 / 空态三动作 / 0 次运行显 `—` / 参数化说明） | F-22-25 |

**不追求**：不合并两套报告入口（F-22-22 ~ F-22-24 只登记）、不重做报告设计、不做字段级权限、不刷历史报告快照。

---

## 2. 结论

**必须做，且优先级高于任何新功能。** 四条理由，按严重度排：

1. **对外文件里现在是假数据**。`coverageRate` 字面写死 `100.0`，`caseCovered` 恒等于 `caseTotal`（F-22-05）；同一份对外视图里 `conclusion=FAIL`、`passRate=0.0` 与 `coverageRate=100.0` 并列（F-22-08）。这不是「字段少」，是**报告自相矛盾**——一旦流出，性质是失实陈述，不是体验问题。
2. **能交的报告存在，但用户点的是不能交的那条**。run 级 xlsx 7 KB 带 70 条用例明细、pdf 540 KB 十页中文正常；报告级四格式 1.5–4 KB、无明细、中文变 `?`（F-22-09 / F-22-10）。**差距不在能力，在入口选错实现**。
3. **两条安全闸在用户实际路径上都不存在**。`REVOKED` 且 `exportable=false` 的报告，报告级导出仍 200（F-22-13 / F-22-14）。撤回语义在交付形态上等于没实现。
4. **FR-06 是 0/4，且都是小改动**（F-22-25）。v5.20 挂账、v5.21 未收，再拖就是把「体验基线」变成永久欠账。

**同时要承认的边界**：本版**不解决**两套报告并存（F-22-22）。合并是破坏性变更，需要产品定菜单口径（D-01 已锁「只有唯一增量」），不在本版范围。

## 3. 方案比较

| 方案 | 做法 | 成本 | 风险 | 结论 |
|---|---|---|---|---|
| **A. 只改渲染层** | 补 3 个 metadata 映射 + 换真项目名 + 删/改 4 个假值 | 小 | 视图不再说谎，但**导出仍是 1.5 KB 空壳**；用户拿到 PDF 依然无法交差 → 只解决「看」不解决「交」 | 不选（可作为第一刀，但不构成一个版本） |
| **B. 渲染 + 导出对齐 + 计数 + FR-06（推荐）** | A + 报告级导出改走 run 级同一套装配（明细 / 闸 / 中文）+ 计数回填 + FR-06 四件 | 中 | 动 `ReportExportService` 与白名单，触发 C5 自检与导出字段集比对；计数改动涉及迁移 | **选** |
| **C. 收敛成一条报告链路** | 废弃 run 级入口，全部走 `test_report`；或反之 | 大 | 破坏性变更：菜单、深链、既有导出记录、4 个 E2E 探针全要改；且要先把报告级能力补齐才有得选 | 不选（登记 v5.23） |

**选 B 的理由**：A 只修「说」不修「给」；C 在能力未补齐前合并，等于把「有明细的那套」删掉换「空壳那套」。B 是把 run 级已验证的能力（明细装配、`MetadataGate`、HTML→PDF 渲染）**搬到报告级入口**，而不是重写。

## 4. 可行性与风险

| 项 | 判定 | 依据 | 主要风险 | 量级 |
|---|---|---|---|---|
| 补 metadata 三键 | 可行 | `METADATA_ORDER` 五键已在白名单（F-22-02），`MetadataOverlay` 已合并 run 表元数据；快照里五键齐全（F-22-03 反例） | 模板若已勾选这三键，补映射会**新增导出列** → 需同步 C5 文档与字段集比对基线 | 小 |
| 换真项目名 | 可行 | 需从 `project` 表取 `name`，渲染器当前只有 `projectId` | 逐报告查一次会 N+1 → 必须批量或缓存，不能顺手 `select` 在循环里 | 小 |
| 假值处置 | 可行（**已拍板：删字段**，见 §11 D-22-03） | 四个字段均无真实数据源（F-22-05/06） | 删字段会改白名单 → 模板、C5 文档、导出字段集比对三处必须同步；旧快照渲染时由 `templateFields` 白名单二次过滤自然丢弃 | 中 |
| 报告级导出带明细 | 可行 | run 级 `xlsx(…, detailRows(tree))` 已产出 71 行明细（F-22-09），`ReportTreeService` 已有树装配 | 明细含 `command_text` / `failure_msg` → 必须过凭据闸（`assertNoSecretsInDetails` 已存在，需在报告级路径也调用） | 中 |
| 报告级 PDF 中文 | 可行（换实现） | run 级 PDF 十页中文正常（嵌入 NotoSansSC / SimSun），说明系统内已有可用渲染 | 报告级 PDF 是**手写最小 PDF**（`/F1 Helvetica` + `ascii()`）；给手写 PDF 嵌 CJK 字体成本极高 → 应改调 run 级同一个 `PdfExportService`，**不要试图补字体** | 中 |
| 撤回 / 不可对外加闸 | 可行（**已拍板：禁止导出**，见 §11 D-22-02） | `MetadataGate` 与 `exportable` 已在快照里（F-22-12），只是报告级路径没调用 | 加了闸会让现存 3 份报告（20/21/22）**立即不可导出** —— 这是**预期结果**，不是副作用；需在测试报告里写明「存量 3 份一并禁止」 | 小 |
| 计数回填 | 可行 | `test_result.verdict` 是真源（F-22-19）；回填 SQL 可从明细聚合 | `run` 表**没有 `skipped_tests` 列** → 必须加迁移；550 条历史 run 需回填，回填后历史报表数字会变 | 中 |
| FR-06 四件 | 可行 | 四处都定位到具体行（F-22-25），单点改动 | 第 2 条「空态三动作」要新增导入/样例入口，涉及路由与权限（viewer 是否可见「新建」） → 需按角色验 | 小 |
| 中文 PDF 拿回归证据 | 可行 | 现有对比样本（1521B vs 539607B）可直接做前后对照 | — | 小 |

## 5. 前置条件

1. **C5 白名单文档必须先改**（大师已授权，见 §11 D-22-01 / D-22-03）：`docs/plan/C5-对外报告字段白名单-20261106.md` 要同步「进 3 出 4」——进 `QA_PROJECT` / `DUT` / `LINK` 与用例明细，出 `coverageRate` / `caseCovered` / `trend` / `failureDistribution`；改完才动代码，否则违反「白名单唯一真源」。
2. **存量 3 份 `REVOKED` 报告加闸后立即不可导出**（已拍板接受，见 D-22-02）；需在发布说明里写明，避免被当成回归。
3. 计数回填的迁移只能**追加**（不改历史脚本），且回填脚本要可重跑（幂等）。
4. 本版允许改 `ReportViewRenderer` / `ReportExportService` / `TestReportController` 与新增迁移；**不允许**改 `ReportFieldWhitelist` 的字段顺序（改顺序等于改所有导出文件的列序，须单独授权）。
5. 导出字段数若变化，`delivery_bundle`（门禁 30）与 C5 自检的基线需同步更新，并在测试报告 §6 写明「字段数由 N → M」。

## 6. 不做清单（明确划界）

| 不做 | 理由 | 归属 |
|---|---|---|
| 合并两套报告入口 | 破坏性变更，且需先补齐报告级能力才有得选 | Q4 拍板后另立版本 |
| 重刷历史报告快照（含 fake 值） | 存量快照是冻结事实，改写等于篡改审计对象；只保证「新生成/新渲染」正确 | 永久不做 |
| `trend` 真值（历史趋势） | 无数据源（跨 run 聚合表不存在），本版只保证「不输出假空数组」 | v5.23 候选 |
| 报告视觉改版 / 新模板 | 与本版目标无关 | 未立项 |
| 软删 run 的报告可见性统一（F-22-22） | 属入口合并问题，单独做会与 Q4 冲突 | 随 Q4 |
| FR-06 之外的体验项 | 避免范围回流 | 按台账 |

## 7. 拆分与发布口径

| 项 | 口径 |
|---|---|
| 版本形态 | **单版发布**：可信与体验共享同一批报告页与导出探针，拆开会出现「导出修了但列表还显示假覆盖率」的中间态 |
| 不可降级 | ① 假值不再输出（F-22-05/06/08）；② 报告级导出带用例明细且中文可读（F-22-09/10）；③ `REVOKED` / `exportable=false` 被拦（F-22-13）。三条任一未达成 → 本版未完成 |
| 可降级 | ④ 计数回填（读路径先对、历史数据可延后一版，但必须在报告里写明「历史 run 数字未回填」）；⑤ FR-06 第 4 条（参数化说明，纯文案，可延后） |
| 与 5.19 / 5.20 / 5.21 的关系 | 不回改前三版判据；前三版门禁断言必须继续 PASS（67 步基线不得减少） |
| 落号 | **不擅自 bump**：完成 ④ 执行与 ⑦ 回写后，由大师决定是否落 5.22.0 |

## 11 决策记录（大师拍板，2026-11-17 04:5x）

| 编号 | 决策 | 取舍理由 | 影响面 |
|---|---|---|---|
| D-22-01 | **对外报告放 `CASE_ID` / `RUN_ID` / 用例明细** | 报告必须能追溯到「哪台设备、哪条链路、哪条用例」，这是对外文档的基本要求 | 授权改 C5 白名单文档；报告级 xlsx 增第二 sheet；明细必须过凭据闸 |
| D-22-02 | **`REVOKED` 报告禁止导出**（返回 400/409 并说明原因） | 撤回 = 不可对外，语义必须一致；允许导出等于撤回没实现 | 报告级导出加状态闸；存量 3 份报告一并禁止（已知且接受） |
| D-22-03 | **四个假值字段直接删除**（`coverageRate` / `caseCovered` / `trend` / `failureDistribution`），不做假真值 | 没有数据源的字段不该留在对外文件里；「算真值」需要先定义覆盖率语义，本版无此定义能力 | `EXTERNAL_ORDER` **21 → 22**（删 4 个假值 + 补 `qaProject`/`dut`/`link` + 加 `caseId`/`runId`）；`METADATA_ORDER` 5 → 7；C5 文档、模板字段集、3 个后端单测与 1 个前端单测同步；旧快照由白名单二次过滤自然丢弃 |
| D-22-04 | **本版不动两套入口**，只把报告级能力补齐 | 入口合并是破坏性变更（菜单 D-01 / 深链 / 导出记录 / E2E 探针），且必须先补齐能力才有得选 | L-22-01 登记 v5.23；本版不隐藏任何现有入口 |
| D-22-05 | 计数采用「**先修回填 + 幂等迁移**」（对 Q5 的处置，非大师逐条确认项，按 §4 可行性推定） | 改读路径实时聚合会动性能面与全部调用方；回填可重跑、可核对 | `run` 表加 `skipped_tests` 列；550 条历史 run 回填；历史报表数字会变化，需在发布说明写明 |
