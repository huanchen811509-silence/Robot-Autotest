> 版本线：v3.9.0（已发）→ **v3.10.0** → v3.11.0（v3.12.0 为候选，需单独授权）。

## 2. 关键设计决策

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-310-01 | 行内只留 1 个「更多」，四动作全进菜单 | PRD 同节判据写的是「首屏 ≤ 8 **+ 行内 1**」；「详情 + 更多」是行内 2，与自己的判据冲突，按判据执行 |
| ADR-310-02 | 「更多」菜单用 naive-ui `NDropdown`，不自造弹层 | 焦点管理、键盘导航、边界翻转已经验证过；自造弹层要重写这三样，收益为零 |
| ADR-310-03 | 冲突区 / 跳过区用折叠而不是页签 | 折叠保留「有冲突时一眼看见计数」；页签会把计数藏进非激活页 |
| ADR-310-04 | 报告草稿主路径是下拉，手打降级为「高级」而非删除 | 归档 run 仍可能按 id 建报告，一刀切删掉会断掉这条路 |
| ADR-310-05 | 过滤在前端做，不改后端 `RunPageQuery` | 加后端过滤要连带改契约与索引；当前只加载最近 100 条，够用。限制写进 DEV-PLAN 偏差 |
| ADR-310-06 | 时间过滤用固定档位（全部 / 7 天 / 30 天）而不是日期区间 | 「选一次报告」不需要精确到天；固定档位可判定、可单测 |
| ADR-310-07 | 用例集来源新增列而非新建表 | 一条报告一个来源，独立表换不来收益；与 ADR-39-02 同一取舍 |
| ADR-310-08 | 快照自包含：冻结时把源 run 的用例事实整段写进 `snapshot_json` | 判据③要求「脱离源 run 仍可渲染」，引用式快照做不到 |

## 3. 验收口径

1. 判据必须能被**命令**判定，不接受「看起来更清爽」。
2. 控件计数用**按区域排除**的探针（`plan-controls-probe.mjs`），不用「整页 button 数」——后者把侧栏、分页器都算进去，判不出「首屏主操作」。
3. 交互类判据必须有**真实浏览器**证据（CDP 探针）或**单测钉死边界**，二者至少其一，并写明另一条的缺口。
4. 「功能没丢」以逐项对照表为凭，不以「旧用例还在绿」为唯一依据——旧用例只覆盖被断言到的那部分。
5. 数据模型变更必须同时交付 down 脚本（`DownScriptGuardTest` 会判红）。
