## 2. 方案比较（FR-v3.10-01 信息架构）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A 全部收进菜单 | 工具条只留新建/刷新/更多，行内只留更多 | 控件数最少，一次到位 | 常用动作多点一次 | **采用**（行内 1 + 主操作 5） |
| B 页签分区 | 计划 / 冲突 / 跳过 三页签 | 分区最彻底 | 冲突计数被藏进非激活页；原来「有冲突一眼看见」的能力退化 | 否 |

| D 拆独立页 | 新建/编辑搬进独立路由 | 表单空间更大 | 断掉 `.form-card` 三条既有用例；判据未要求 | 否（排 v3.10.1） |

## 3. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 动作收进菜单后「找不到了」 | 用户投诉「功能没了」 | 出功能对照表（16 项逐个给新位置）+ 逐项用例断言 |
| 2 | `NDropdown` 在 happy-dom 下不渲染选项 | 单测写不出「点菜单项」 | 单测里点 `.more-menu` 后从 `document.body` 取 `.n-dropdown-option`，对 label 派发 mousedown→mouseup→click（v3.9.0 已踩过） |
| 3 | 下拉过滤放在前端 → 更早的 run 搜不到 | 用户以为「记录丢了」 | 界面给空态文案；DEV-PLAN 记偏差；保留高级手打入路 |
| 4 | `test_report` 加列后旧行 `source_type` 为空 | 列表显示空白来源 | 加列时 `DEFAULT 'run'` 回填，旧行解释为「按 run」 |
| 5 | 快照「自包含」写成引用式 | 冻结后源 run 删了报告就空 | 判据③用**契约测试**钉：删源 run 或改源 run 后快照渲染结果不变 |
| 6 | 新增迁移忘写 down 脚本 | `DownScriptGuardTest` 判红 | 迁移与 down 同批交付 + `migration-down-up-drill.sh` 真实演练 |

## 4. 结论与不做的事

**做**：FR-v3.10-01（方案 A）、FR-v3.10-02、FR-v3.10-03。

**不做**（明确排除，避免验收时被追问）：

| 项 | 为什么不做 |
|---|---|
| 新建/编辑抽屉化 | 判据未涉及；会重写 3 条既有用例，收益是「表单大一点」，不值 |
| 后端 run 关键词/时间过滤 | 要连带改契约与索引；当前只加载最近 100 条够用 |
| 报告草稿分页加载 run | `RunPicker` 只取 100 条；真需要翻更早记录时再上后端搜索（记 L-310 遗留） |
| 「更多」菜单键盘可达性专项 | 判据只要求「原功能可达」，`NDropdown` 自带键盘导航；专项排 v3.10.1 |
