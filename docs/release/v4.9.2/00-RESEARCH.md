# v4.9.2 研究纪要

## 背景

4.4–4.9 六个迭代分别交付了权限、双模式、公共用例、公共资产、模板与存量同步。
分散的版本证据已按版本归档在 `docs/release/v4.4.0 … v4.9.0`，本版只做三件事：

1. 把六块能力收敛为一次可发布的 GA 口径；
2. 补齐跨版本的门禁与证据索引；
3. 校正版本四处一致与「关于 / 版本迭代」页面展示。

## 关键决策

| 决策 | 证据等级 | 理由 |
| --- | --- | --- |
| 公共库挂在 `project.kind='platform'` 单例项目下 | [已核实] 代码 `PlatformProjectService` + `V11_31` | 复用既有 `project_id` 隔离，不引入第二套数据模型与权限旁路 |
| 导入拆「预览 / 提交」两段 | [已核实] `GlobalCaseService.preview/commit` | 预览零写入可重复回放，提交单事务；避免一次误操作污染全库 |
| 资产删除用引用计数而非硬删除标记 | [已核实] `GlobalAssetService.delete` + `project_asset` | 与真实引用一致，0 引用即可删，不制造悬空 |
| 同步冲突默认保留本地 | [已核实] `ProjectSyncService.execute` 缺省分支 | 覆盖不可逆风险最高；「接受公共库」必须显式选择 |
| 定时预览默认关闭 | [已核实] `SyncScheduler` `sync.auto.enabled:false` | 自动写作业放大噪音；开启后也只预览、不自动覆盖 |

## 未决与假设

- [假设] 部署环境可提供 `DB_PASSWORD`；本仓库默认不保存口令，故迁移演练标注 NOT-RUN。
- [已核实] 样本工作簿 `基本功能导入测试v0.5.0.0.xlsx` 不在仓库内（全库检索无此文件），
  导入相关证据以 `fixtures/ed202/ED202测试用例_V0.4.xlsx` 为准。
- [推断] 历史 `case_kind` 可作为一级分类回填来源，升级后仍需人工归并一次。
