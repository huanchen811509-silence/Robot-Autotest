## 1. 版本定位

| 维度 | v2.0（现状） | v2.1（本版目标） |
|---|---|---|
| 计划编排 | 单计划绑单用例集；依赖 DAG 只能逐条手工建边 | **计划组**：多计划一次成组、组内顺序可调、依赖图可视、关键路径与预计时长 |
| 失败处理 | 有四类粗分类（`CANCELED`/`ENV`/`INFRA`/`ASSERT`），无簇级聚合，界面逐条看 | **失败聚类**：**类 + 簇两级**聚合 + 一键生成建议重跑清单（复用既有分类器） |
| 报告模板 | 代码内两套固定视图（DEFAULT / EXTERNAL） | **模板实体**：字段白名单内可勾选可排序；新增 **XLSX** 导出 |
| 公用资产 | PUBLIC 引用只读、副本可演进，「有新版本」只在字段层面 | **升级闭环**：检测 → 提示 → 差异 → 同步或保持分叉 |
| 执行算力 | 单机进程内线程池 | **第二执行节点**：注册、心跳、指定节点执行、结果回收、离线降级 |
| 回归底座 | 依赖真实工程与 DUT 样本 | **5–10 条不映射业务的示例用例**，五态齐全，本机零依赖 |

**不追求**：分布式分片执行、多节点故障转移、模板表达式/脚本、AI L4–L5、多租户 SaaS。

### 1.1 与中长期规划 v3.0 的落位（口径锁定）

本版对应规划 §5.10 运营期 **Q3「提效」**（计划编排优化、报告模板可配置、失败聚类）与 **Q4「扩展」**（第二执行节点），
但规划**没有给这一批编号**（F11）。因此：

| 口径 | 取值 | 含义 |
|---|---|---|
| 批次 / 门 | **待占号（建议 B10 / G9）** | 本文**不自行占号**；PRD 评审通过后由大师在规划 v3.1 中确定，再回填本文 |
| 工作包状态 | **候选** | 13 包本轮**不进** `WBS-STATUS.md`，进度分母仍 **130** |
| 状态机 | 五态 | 未开始 / 进行中 / 待验 / 待现场 / 已完成 |
| 排期 | 不排日期 | 由波次进入条件 + §6 验收清单驱动 |
| 自主度 | A / B / C | D4 节点通信属 **C 类**（人工主导）；D1/D2/D3/D5 属 B 类 |

三条不可让的边界：

1. **既有 RF 命令逐字等价**——v2.1 任何改动不得改变 `KRN-02` 生成的命令；命令 diff 必须仍为空。
2. **编排仅一层**——沿用 v2.0 裁决 D5：`ScenarioService` 与新增计划组都不得出现多层嵌套；**报告 DAG 编排仍是非目标**（F10）。
3. **模板不得绕过白名单**——可配置的只有「字段是否显示 + 顺序 + 标题文案」，字段集合由 C5 白名单给定，模板不能新增字段。

## 3. 典型场景

**S1 一次编排多套用例**
测试经理要为「版本回归」建 6 个计划（冒烟 / PFC / RoCE / 稳定性 / 长稳 / 报告）→ 不再逐条建 6 个计划再连 5 条依赖，
而是新建**计划组**、批量加入 6 个计划、在组内拖动定顺序 → 平台自动建边并画出依赖图，给出关键路径与预计总时长。

**S2 失败先聚类再看**
一轮 3 个 run 共 214 条失败 → 打开失败聚类：`fixture 未清理（端口占用）` 138 条、`断言不符（阈值）` 51 条、
`环境缺失（pytest 不在 PATH）` 25 条 → 点第一簇「生成重跑清单」→ 得到 138 条用例的可执行清单，一键发起。

**S3 客户模板出报告**
对接人给了一份 Excel 格式的验收表 → 管理员在模板里勾选客户要求的 12 个字段并排序、改名 → 冻结报告时按模板渲染 →
导出 XLSX，字段与客户表头一致；敏感字段（IP / 命令）在白名单外，**选不到**。

**S4 公用资产升级**
平台库的「PFC 无损基线」用例集被改了 3 条 → 引用它的 2 个项目看到「有新版本」→ 点开差异：3 条新增、1 条修改 →
项目 A 同步，项目 B 保持分叉（副本不动），分叉态在列表里可辨。

**S5 加第二台执行机**
管理员在节点页填入第二台机器的地址与令牌 → 节点注册并心跳正常 → 发起 run 时可选「在 node-2 执行」→
执行结果回到主控库；node-2 心跳丢失 3 次后标记离线，此时发起该节点的 run 被**拒绝并提示**（不静默回落本机）。
