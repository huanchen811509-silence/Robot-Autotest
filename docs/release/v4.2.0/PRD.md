## 3. 关键设计决策

1. **工作区包以「可校验」为第一目标**：`manifest.json` 逐文件 `sha256` 与字节数，先验后写；导入默认 dry-run，默认策略 `skip`。
2. **签名用平台本地密钥**：`keyId=server-local-v1`，`G-10` 密钥流水线未定前不引入外部 KMS。
3. **远程采集拒绝「先连上再说」**：`known_hosts` 没有的指纹一律失败，平台不提供自动信任。
4. **Schema 常量单源**：`db/schema-contract.json` 同时供 `SchemaIT` 与 `db-audit` 读取；append-only 表允许业务时间锚点，但与 `created_at` 互斥。
5. **门禁只加不降**：门禁 29 → 32 步；修表格阻断用改组件而非扩白名单；`SchemaIT` 改 `-Pit` 而非放宽 `_it` 守卫。
6. **版本四副本一致**：`VERSION` / `build-info.properties` / `docs/contracts/openapi.json` / 前端 `public/CHANGELOG.md` 必须同版本，由 `tools/check_version_consistency.py` 机检。

## 4. 验收口径

| 档位 | 定义 | 用法 |
|---|---|---|
| `PASS` | 有可复核证据（日志 / JSON / 真库读数 / 真 HTTP），且判据全部成立 | 可计入交付 |
| `PARTIAL` | 主判据成立，但清单中若干子项无证据或降级取证 | 必须写明缺哪一项 |
| `NOT-RUN` | 前置条件不具备，未执行 | 必须写明原因与补齐方法，**不得计入通过** |

放行原则：`NOT-RUN` 不阻断本次落号，但必须逐条可见；`FAIL` 一律阻断。
