# v4.3.0 方案评估（RA-ASM-430）

**文档编号** RA-ASM-430 ｜ **版本** v1.0 ｜ **日期** 2026-11-10

## 1. 前置条件

| 条件 | 本轮现状 | 不满足时怎么办 |
|---|---|---|
| MySQL 8.0 可达（`robot_dev` 与 `robot_it`） | 具备 | 无库只跑非 IT 单测，IT 与迁移演练记 `NOT-RUN` |
| WSL `~/robot-autotest` 权威副本可用 | 具备 | 构建 / 测试一律在此执行，Windows 侧只编辑 |
| 后端 `:8081` 与入口 `:8001` 可启动 | 具备 | 运行期版本与页面读数改用静态结论并注记 |
| 前端 `node_modules` 已装 | 具备 | 用本地 `./node_modules/.bin/vitest`，不用 `npx` |
| Chrome CDP（`:9222`） | 时有时无 | 探针不可用即记 `NOT-RUN`，不拿单测替代页面取证 |
| 无第二空实例 | **不具备** | 跨实例对照记 `NOT-RUN`，同实例用 `P-A` / `P-B` 两项目取证 |
| 无受控压力环境 | **不具备** | 性能只记本机 20 次采样，口径写明，不外推 |

## 2. 方案比较

### 2.1 「新建项目」入口落点

| 选项 | 做法 | 取舍 |
|---|---|---|
| A | 挂在项目看板页内的按钮 | 无项目上下文时进不去，与「建项目」语义矛盾 |
| B | 只留在账户菜单 | 入口过深，侧栏导航组语义不完整 |
| **C（选用）** | 「工作台」组新增独立叶子 `/projects/new`，能力码 `project:create` | 一级组内可见、路径稳定、能力码与后端 `PROJECT CREATE` 对齐 |

### 2.2 建项目权限口径

| 选项 | 做法 | 结论 |
|---|---|---|
| A | 只给 ADMIN | 现场 PM 主导建项目，不满足 |
| **B（选用）** | ADMIN + PM 均可 `CREATE`（`RCU` 动作集） | 与现场职责一致；矩阵 / 单测 / 契约样本 / PRD 四处同版落地 |
| C | 给 ENGINEER 也开 | **不做**：与「PM 负责立项」的职责划分冲突 |

### 2.3 网卡归属的建模位置

| 选项 | 做法 | 结论 |
|---|---|---|
| A | 新建「网卡」实体表 + 外键 | 用户明确纠正过：不建网卡实体表 |
| **B（选用）** | 端口自带可空 `nic_name` / `nic_index` 两列 | 符合「设备→网卡→接口」是连接路径的语义；旧行留 `NULL` 即「未归属」 |
| C | 焊接 / 线缆字段 | **不做**：用户明确说明「焊接」是笔误 |

### 2.4 连接与拓扑的读取模型

| 选项 | 做法 | 结论 |
|---|---|---|
| A | 前端逐个调 CRUD 再拼 | 口径分散、无缓存、易漏禁用过滤 |
| **B（选用）** | 后端派生 `GET /asset-info` 一次返回连接 + 拓扑 + `stats` + `meta` | 单一事实源；`scope` 可选；节点 ID 三级稳定 |
| C | 落物化视图 / 新表 | **不做**：资产量级不需要，且会引入新的失效面 |

### 2.5 复用窗口与失效

| 选项 | 做法 | 结论 |
|---|---|---|
| A | 300 秒短缓存 | 用户纠正：应是**默认 12 小时**可配置 |
| **B（选用）** | 片段键 + 项目键两级缓存，TTL 默认 `43200s`，`ASSET_INFO_CACHE_*` 可配；资产变更事务提交后按项目前缀失效 + 手工 `POST /refresh` | 冷读快、脏读窗口由失效兜底 |
| C | 不缓存，每次全算 | 大项目（120 设备 / 150 链路）每次都付全量代价 |
| D | 每次请求都重算再写缓存 | 单飞之外仍有重复回源，且无法解释 `cacheHit` |

### 2.6 缓存键是否含别名

| 选项 | 做法 | 结论 |
|---|---|---|
| **A（选用）** | 片段键 `link:{id}:{contentHash}`、项目键 `project:{projectId}:{指纹}`，**别名不进键**，组装期按项目替换 | 同一平台资产被多项目引用时片段可复用，别名不串项目 |
| B | 别名进键 | 每个项目一份片段，复用率归零，且易把 `P-A` 的别名漏给 `P-B` |

## 3. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 别名串项目 | `P-B` 显示 `P-A` 的叫法，属 S1 | 别名不进缓存键 + `TC-v4.3-18` / `TC-v4.3-33` 双重拦截 |
| 变更后仍读旧值 | 用户改设备 IP 后页面不变 | `@TransactionalEventListener(AFTER_COMMIT)` 按项目前缀失效 + `TC-v4.3-22` |
| 并发刷新打穿 | 10 个并发 `refresh` 触发 10 次全量重算 | 单飞（同键合并），`TC-v4.3-25` 以 `recomputed` 计数取证 |
| 大项目静默截断 | `count` 少于库内可见资产 | 查询不加 `LIMIT`，`TC-v4.3-15` / `TC-v4.3-35` 用库内计数对照 |
| 排序漂移 | 两次请求顺序不同，前端行序抖动 | 连接按 `linkId`、拓扑按 设备→网卡→接口 稳定排序 |
| 迁移不可回滚 | 现场无法降级 | `V11_29` 只加可空列 + 普通索引，附 `down` 并做正-反-正演练 |
| 只读角色看到无效按钮 | 点了才 403 | 前端按钮按 `asset:update` 显隐，`TC-v4.3-24` 四角色对照 |
| 基线门禁本已红 | 无法证明 `FAILS=0` | `EW43-00` 留基线日志，收尾逐项对照并在报告写明差异 |

## 4. 结论与不做的事

**做**：`FR-v4.3-01` ～ `FR-v4.3-08`，共 8 条需求（清单见 [PRD.md](./PRD.md) §4）。

**不做**：

- 不建「网卡」实体表，不建「焊接 / 线缆」字段（用户明确纠正：焊接是笔误，实指设备→网卡→接口的连接路径）。
- 不做跨实例资产同步 / 合并，不新做平台资产池的完整列表页（P1 只给「按资产 ID 引用 / 解除引用」入口）。
- 不做物化视图或新落库表，不做物化拓扑快照的写路径。
- 不改既有设备 / 链路 / 凭据 API 的请求形状；`nicName` / `nicIndex` 只作为可选字段追加。
- 不把 `NOT-RUN` 记成 `PASS`；无 CDP / 无压力环境 / 无第二实例的项保持 `NOT-RUN` 并写明补齐方法。
- 不为通过放宽 lint 白名单，不降低门禁步数，不跳过 `vue-tsc`。
