## 1. 执行方式分类

| 代号 | 含义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `UT` | 后端/前端单测 | 逻辑分支正确 | 真实采集能通、界面能看见 |
| `MECH` | 机检脚本（带 `--self-test`） | 规则被守住且能判红 | 业务语义对不对 |
| `HTTP` | 真实服务请求 | 契约、错误码、闸门顺序 | 界面渲染 |
| `UI` | 真实浏览器 | 用户能看见、能点 | 后端边界 |
| `DOM` | 页面内断言（节点/边数、锚点） | 结构事实 | 观感 |
| `DB` | 直连数据库读数 | 落库事实 | 链路是否被调用 |
| `COLLECT` | 真实采集（对 DUT） | 端到端真跑、快照真写 | 与 DUT 无关的回归 |
| `PERF` | 耗时与帧率 | 不退化 | 功能正确性 |
| `REPLAY` | 在 v5.14 收口 commit 上回放 | 原缺陷存在 | 修复完整性 |

**放行口径**：P0 条目（FR-01/02/03/04/05/09）必须至少拿到 `HTTP` 或 `DB` 或 `COLLECT` 或 `UI` 一级证据；只有 `UT` 的条目不得计为达成。
**闸门是本版最高风险项**：TC-40 ~ TC-46 必须包含「声明不满足被拒」「无声明不拦截但留痕」「安全闸优先」三条真实请求证据，且必须有回放证明修前不拦。

## 5. 不可用推断补齐的条目（执行纪律）

| 情形 | 处理 |
|---|---|
| 无支持 LLDP 的交换机 | TC-28/TC-30 标「未执行（无 LLDP 设备）」，**不许**用伪造邻居充数 |
| 无第二台可采设备 | TC-17 项集对比无法做，标未执行 |
| 闸门用例元数据机制未落地 | 按 PRD 降级预案改项目级基线校验，但 TC-46（禁止推断）仍须通过，且遗留表登记 |
| `ps aux` 抓不到（采集太快） | 用并发采集 + 长命令拉长时间窗；仍抓不到则记录环境限制，不得写「已确认」 |
| 100 节点 300 边样本不足 | 用脚本造拓扑（标注压测项目），记录机器信息 |
