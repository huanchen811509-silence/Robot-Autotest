## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 把环境快照从「一行 JSON」变成**内容寻址的不可变对象**，把采集探针从「写死的 10 条命令」变成**可配置的探针包**，把拓扑从「结构派生线」变成**带置信度的三源分级**，并在执行前加一道**环境闸门** |
| 性质 | **重写版**（本批唯一两块之一）：6 个只读页 + 1 张死表 + 快照只存一行 JSON，是结构性缺口不是细节 |
| 上游需求 | R17 |
| 目标产出 | 2 张新表（快照对象 + 按项）；探针包可配置；`link` 加 `confidence/source`；6 页收敛为 4 页；执行前环境校验 |
| 不追求 | 不做运维控制台（5.16）、不做备份恢复（5.16）、不抄白泽的 57 条探针命令、不抄白泽的租约与 1s 轮询 |

### 1.1 为什么必须重写（结构性缺口，不是细节）

| # | 缺口 | 证据 | 后果 |
|---|---|---|---|
| 1 | **快照只存一行 JSON**，没有版本对象 | `env_profile.snapshot_json`（`V1:233-246`、`V11_27` 允许多份）；`EnvController.java:46-56` | 「环境漂移」无法按项追溯，只能整段文本 diff，也无法被执行引用 |
| 2 | **手工拓扑表是死表** | `topology_node`（`V1:248-263`）无任何 Repository/Mapper；`AssetInfoService.java:31-35` 明确「不合并手工拓扑」 | 拓扑完全由 device/port/link 派生 → 无 LLDP、无置信度、无「实测 vs 规划」分级 |
| 3 | **探针白名单写死在代码里** | `HostInventoryCollector.COMMANDS`（`HostInventoryController.java:78-82`），固定 10 条只读命令 | 加一项探针要改代码发版；交换机与 GPU 机型无法差异化 |
| 4 | **环境与执行的闸门断裂** | 执行前不看快照（ADR-0013 只看 `confirmReal` + 绑定） | 环境漂移只能事后追查，不能事前拦住「端口速率不对还去跑 400G 用例」 |
| 5 | 项目侧采集只能采本机 | `api/environment.ts:65-70` 只传 `host`，无凭证入参 | 与 5.13 的绑定凭证能力脱节 |

### 1.2 从白泽抄什么、不抄什么（逐条给源码位置）

| 机制 | 白泽实现 | 抄 / 不抄 | 我方落点 |
|---|---|---|---|
| 内容寻址快照 | `data/snapshots/<sha256>` + 索引表 `device_snapshot`，读时「摘要 + 设备身份」双匹配（`DeviceSnapshotIndex.java` 170 行、`SnapshotCompare.java` 141 行） | **抄**：快照为不可变对象、按 hash 寻址、按项对比 | `device_snapshot` + `device_snapshot_item` |
| 探针包 | Linux 基础 39 项 + 按发现的 netdev/HCA 动态追加 `mlnx_qos`/`qdisc`/`mlxconfig`；交换机按 `show version` 分流 Centec/Ruijie | **抄结构，不抄命令集**：包 = 命令组 + 解析器，可配置、按设备类型选 | `probe_pack`（表或 YAML + 种子） |
| 拓扑三源分级 | LLDP 邻居 / 同网段同速率 / 人工规划 / 人工确认，各有 `confidence`，重合时实测优先（`TopologyGraph.java` 498 行） | **抄** confidence 模型与「实测盖规划」 | `link.confidence` + `source` |
| SSH 安全细节 | 系统 ssh + askpass（口令不进 argv）+ 每设备独立 `known_hosts` + `StrictHostKeyChecking=yes` + 老算法用 `+` 追加 | **抄**（安全正确性不是风格） | 我方 `application/host` 的 SSH Runner（291 行）逐条核对 |
| 执行前环境闸门 | `require400G` 直接读快照 `speed_mbps` | **抄机制，不抄硬编码**（见 FR-09） | 用例声明环境需求 + 闸门解析 |
| 租约无 TTL、1s 轮询、路径强绑仓库 | 白泽 §6.6/§6.7/§6.9 | **不抄** | 保留我方 `ExecutionOrphanSweeper` 与 WebSocket 推送 |

## 2. 约束与术语

| 术语 | 含义 |
|---|---|
| 快照对象 | 一次采集得到的一份不可变环境事实，按内容 sha256 寻址；同一设备两次采集产生两个对象（内容相同可去重） |
| 快照项 | 快照里的一条事实（`item_key` + 值 + 采集命令 + 采集时间），可按项查询与对比 |
| 探针包 | 一组「命令 + 解析器 + 适用设备类型」；采集时按设备类型选包，可增删不改代码 |
| 置信度（confidence） | 拓扑边的可信程度：`LLDP` > `SAME_SUBNET_SPEED` > `PLANNED` > `MANUAL_CONFIRMED`（实测优先于规划） |
| 环境需求声明 | 用例上声明它依赖的环境事实（如 `speed_mbps >= 400000`），供闸门校验；**无声明则不拦截，但要在报告里注明未校验** |
| 四页 | 环境概览 / 设备感知 / 环境准备 / 拓扑与连接（6 页收敛后） |

**硬约束**：

1. **快照不可变**：已生成的快照不更新、不删除（可标记失效），任何「修正」都产生新对象。
2. **旧数据只读兼容**：`env_profile.snapshot_json` 不做破坏性迁移；旧页面读旧数据仍可用，新页面读新表。
3. **闸门不许猜**：用例未声明环境需求时，闸门**不拦截**但必须在执行记录与报告里写明「未声明环境需求，未做环境校验」；禁止从用例名/分类推断需求。
4. **执行闸门不影响现有安全闸**：ADR-0013 的 `confirmReal` + 绑定校验仍在环境闸门之前，两道闸并列而非替代。
5. **迁移只能追加**：从 `V11_75` 起（5.14 预留到 `V11_74`）。

## 5. 需求详述

### FR-v5.15-01 快照对象化【P0】

**描述**：新建两张表：

```text
device_snapshot
├─ id / device_id / project_id
├─ content_hash CHAR(64)         ← 按内容寻址（同设备同内容可复用）
├─ captured_at / captured_by / source(COLLECT|IMPORT)
├─ probe_pack_key / kernel_version
└─ UNIQUE (device_id, content_hash)

device_snapshot_item
├─ snapshot_id / item_key        ← 如 net.eth0.speed_mbps
├─ value_text / value_num        ← 数值型便于比较
├─ command_text                  ← 采这一项用的命令（可追证）
└─ UNIQUE (snapshot_id, item_key)
```

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 同一设备间隔采集两次 → 两个快照对象（id 不同）；若内容完全相同 → 复用同一 `content_hash`（不重复存储） | DB 查询 |
| 2 | `GET /api/environment/snapshots/{id}` 返回按项结构（`items[]`），不是一段 JSON 字符串 | 真实响应 |
| 3 | 按项可查：`GET .../snapshots/{id}/items?key=net.eth0.speed_mbps` 返回该值 | 真实请求 |
| 4 | 快照不可变：对已生成快照调更新接口 → 404/405（无此端点），或返回 409「快照不可修改」 | 真实请求 |
| 5 | 旧数据兼容：`env_profile` 的旧快照仍可通过旧端点读取（页面不报错） | 截图 + 真实响应 |
| 6 | 一张快照 500 项时写库 ≤ 3s，按项查询 ≤ 200ms | 性能记录 |

### FR-v5.15-02 采集写快照【P0】

**描述**：采集完成后，把结果写成「一个快照对象 + N 条快照项」；`env_profile.snapshot_json` 不再写新数据（只保留历史）。
采集来源标记 `source=COLLECT`；手工导入标记 `IMPORT`。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 触发一次真实采集 → `device_snapshot` 新增 1 行、`device_snapshot_item` 新增 N 行（N = 采集项数） | DB 查询 |
| 2 | `env_profile.snapshot_json` 在采集后**不再新增/更新**（旧行不变） | DB 前后比对 |
| 3 | 采集项数与探针包定义一致（抽 1 个包比对项名集合） | DB + 配置比对 |
| 4 | 采集失败时不产生快照（不落半份数据） | DB 前后比对 |
| 5 | 「采集记录分析」页能读到新快照数据（读路径已切换，非双写） | 截图 |

### FR-v5.15-03 按项对比【P0】

**描述**：新增对比：给定两个快照 id，返回 `{added[], removed[], changed[{key, old, new}]}`；
前端展示为三栏（新增/消失/变化），变化项显示旧值 → 新值。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 两份差异已知的快照对比 → 新增/消失/变化三项计数与构造时一致 | 脚本构造 + 真实响应 |
| 2 | 变化项显示旧值与新值，且值与快照项表逐项一致 | DB 比对 |
| 3 | 同一快照与自己对比 → 三项均为空（不是全量「变化」） | 真实响应 |
| 4 | 对比页能选择任意两份快照（不限于最近两份） | 截图 |
| 5 | 1000 项对比响应 ≤ 1s | 性能记录 |

### FR-v5.15-04 探针包配置化【P0】

**描述**：新增 `probe_pack`（表或 YAML + 种子），结构：

```text
probe_pack
├─ pack_key / display_name / device_type(SERVER|SWITCH|GPU|ANY)
├─ items: [{item_key, command, parser, required}]
└─ 版本 / 是否启用
```

采集时按设备 `device_type` 选包；`required=false` 的命令失败不阻塞整体采集，但要在快照里记录「该项未采到」。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 交换机与服务器采到的项集不同（项数与项名断言） | DB 查询 |
| 2 | **新增一项探针不改代码**：在配置里加一条项 + 重启（或热加载）→ 采集结果里出现该项 | 真实采集 + DB |
| 3 | 非必需项命令失败 → 整体采集成功，该项标记「未采到」并带原因 | 真实采集 + DB |
| 4 | 必需项命令失败 → 采集失败并点名该项（不静默降级） | 真实采集 |
| 5 | 包配置非法（重复 `item_key`）→ 加载时被拒并点名 | 启动日志/机检 |
| 6 | 现有 10 条命令全部迁入包，行为不变（回归同一设备两次采集项集一致） | DB 比对 |

### FR-v5.15-05 拓扑三源分级【P0】

**描述**：`link` 表加 `confidence VARCHAR(16)` 与 `source VARCHAR(16)`；
置信度优先级 `LLDP > SAME_SUBNET_SPEED > PLANNED > MANUAL_CONFIRMED`（数值上 undefined < PLANNED < SAME_SUBNET_SPEED < LLDP，人工确认可覆盖但需标注）；
同一对端口有多条来源时，**图上只显示置信度最高的一条**，其余折叠可查。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 同一对端口同时有 LLDP 与规划数据 → 图上只显示一条，`confidence=LLDP` | 截图 + DB |
| 2 | 过滤「仅实测」后规划线消失（只剩 LLDP） | 截图 |
| 3 | 人工确认可覆盖实测，但图上标注「人工确认（与实测不一致）」并可查看实测值 | 截图 + DB |
| 4 | 置信度过滤后边数与接口返回一致（计数断言） | DOM 断言 |
| 5 | 迁移后既有 link 行有默认 `source=MANUAL`/`confidence=PLANNED`（不出现 NULL） | DB 查询 |

### FR-v5.15-06 LLDP 邻居导入与去重【P1】

**描述**：从采集结果解析 LLDP 邻居（`lldpctl`/`show lldp neighbors`），写入 `link`（`source=LLDP`，含对端设备名/端口/机箱 id）；
对端未登记为设备时创建「待认领」占位或标记 `peer_unresolved`，不静默丢弃。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 一台具备 LLDP 的交换机采集后产生邻居边（数量与真实邻居数一致） | 真实采集 + DB |
| 2 | 重复采集不产生重复边（幂等：同源同目标同端口唯一） | DB 前后比对 |
| 3 | 对端未登记 → 边存在但标记 `peer_unresolved`，界面可见 | DB + 截图 |
| 4 | 解析失败（命令无输出）→ 记录「未获取 LLDP」，不创建假边 | DB 查询 |

### FR-v5.15-09 执行前环境校验【P0】

**描述**：这是本版最有价值也最容易做成假的一条，因此定义清楚：

| 环节 | 规则 |
|---|---|
| 声明 | 用例上声明环境需求，形如 `env_require: [{key: net.eth0.speed_mbps, op: ">=", value: 400000}]`（存用例扩展元数据，不新建用例表列） |
| 解析 | 执行前取该用例的**最新快照**，按 key 查值，按 op 比较 |
| 拦截 | 任一不满足 → 拒绝执行该用例，返回 409 + 点名 `key / 期望 / 实际 / 快照 id` |
| 无声明 | **不拦截**，但执行记录与报告注明「未声明环境需求，未做环境校验」 |
| 无快照 | 声明了但没有快照 → 拒绝并提示「请先采集环境」 |
| 顺序 | 在 ADR-0013 安全闸之后执行（安全闸不过直接 400，不进入环境校验） |

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 用例声明 `speed_mbps >= 400000`，快照实际 100000 → 执行被拒，错误信息含 key、期望、实际、快照 id | 真实请求 + 截图 |
| 2 | 快照实际 400000 → 执行通过（200） | 真实请求 |
| 3 | 无声明用例 → 执行通过，记录中注明「未做环境校验」 | 真实请求 + DB |
| 4 | 声明了但无快照 → 拒绝并提示先采集 | 真实请求 |
| 5 | 安全闸优先：`confirmReal` 缺失 → 400（不进入环境校验，错误信息不含环境字段） | 真实请求日志 |
| 6 | 反向判据：在 v5.14 收口 commit 上执行判据 1 → 执行成功（无闸门） | 回放日志 |
| 7 | **禁止推断**：代码检查无「按用例名/分类猜需求」的实现 | 代码检查 |

**降级预案**：若用例侧元数据机制无法在同版落地，允许先支持「项目级环境基线校验」（项目声明最低要求，执行前对所有用例生效），但判据 7 仍须满足，且必须在遗留表登记「用例级声明待补」。

### FR-v5.15-12 SSH 安全细节核对【P1】

**描述**：逐条核对（照抄白泽的正确做法）：

| 项 | 要求 |
|---|---|
