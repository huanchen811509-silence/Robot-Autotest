## 1. 执行方式分类

| 代号 | 含义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `UT` | 后端/前端单测 | 逻辑分支正确 | 真实请求能通、界面能看见 |
| `MECH` | 机检脚本（带 `--self-test`） | 规则被守住且能判红 | 业务语义对不对 |
| `HTTP` | 真实服务请求（curl/脚本） | 契约、错误码、真实数据 | 界面渲染 |
| `UI` | 真实浏览器（CDP/人工） | 用户能看见、能点 | 后端边界 |
| `DB` | 直连数据库读数 | 落库事实 | 链路是否被调用 |
| `CONC` | 并发脚本 | 竞态下的唯一性 | 长时间稳定性 |
| `MANUAL` | 人工走查 | 观感与一致性 | 可重复性（须留截图） |

**放行口径**：P0 条目（FR-01/02/03/05/10）必须至少拿到 `HTTP` 或 `DB` 或 `UI` 一级证据；只有 `UT` 的条目不得计为达成。
**「真实创建」要求**：本版每条 TC 的期望对象都必须是向导真正建出来的（不是 SQL 直插），否则「向导能建」这件事没被证明。

## 5. 不可用推断补齐的条目（执行纪律）

| 情形 | 处理 |
|---|---|
| 并发创建无法在单机复现真并发 | 用 `xargs -P5` 起 5 个真实请求；仍无竞态则记录「未复现竞态」，**不许**用单测替代 |
| 模板重名策略未定 | 本版已定「允许 + 确认」，若实施时改成硬拒，须改 PRD 与 TC-24 期望并留痕 |
| 演示项目造不出来 | 用向导造；仍失败则 TC-47 标「未执行」，不得以脚本直插冒充 |
| 导入向导的字段映射依赖具体文件格式 | 固定一份样本 CSV 进证据目录，保证可复跑 |
