## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 把「建项目 / 建模板」从**一屏表单**改成**分步向导**，让六类关联（模板、用例、用例集、资产、凭证、用户组）在向导里一次配好，并让项目编号**不复用、不撞号、可注册** |
| 性质 | **入口与流程版**：项目向导已存在（971 行、六步），本版是「补齐 + 改名 + 接上 5.9 的口径」；模板向导是**新建**（后端模型够用、前端装不下） |
| 上游需求 | R4、R11、R3（清理脚本落地） |
| 目标产出 | 「项目」组与「模板」组各有一个向导二级项；项目向导六步变八步（补凭证、补用户组）；模板向导五步新建；项目编号序列化 |
| 不追求 | 不改用例清单与用例集布局（5.11/5.12）、不做资产工作台合并（5.12）、不改报告（5.14）、不做环境拓扑（5.15） |

### 1.1 现状：一个已有但找不到，一个根本没有

| 对象 | 现状 | 本版要做的 |
|---|---|---|
| 项目向导 | `ProjectWizardView.vue` 971 行，六步 `['template','basics','runtime','members','content','review']`（`:34`），能力已覆盖模板/基础/内核/成员/内容/复核 | ① 菜单上叫「项目向导」（现在两个入口分别挂在「工作台」组和「项目」组，**没有叫向导的二级项**）；② 补**凭证**与**用户组**两步 |
| 模板向导 | **不存在**。`GlobalTemplatesView.vue:118` 只有一个内联表单，硬性要求「至少关联 1 条用例或 1 个用例集」（`:88`、`:305`） | 新建 `/g/templates/new` 五步向导 |

**为什么模板必须用向导而不是把表单加大**：后端模板模型支持四类明细 + 资产：

```java
// ProjectTemplateService.java:33-50
public record TemplateDetail(TemplateRow template, List<TemplateItem> items,
                             List<TemplateItem> cases, List<TemplateItem> caseSets,
                             List<TemplateItem> scenarios, List<TemplateItem> assets) {}
```

即模型够用、**前端表单装不下**——六类对象在一屏里无法表达「先选什么、后选什么、冲突怎么办」。这正是需要向导的判据。

### 1.2 R4 的一处裁决：资产/用例导入**不新增二级菜单**

| 对象 | 现状 | 裁决 | 理由 |
|---|---|---|---|
| 公共资产 | 已有「导入预览 → 提交」两步弹窗（`GlobalAssetsView.vue:235-271`，后端 `/import/preview`、`/import/commit`） | **升级为分步向导，入口留在设备页操作列** | 导入是**动作**不是**页面**；新增菜单会造成「同一件事两个入口」 |
| 公共用例 | 已有 Excel 导入 + 批次记录（「导入记录」二级项 `?view=imports`） | 同上，结果页仍用既有「导入记录」 | 同上 |

判据：R4 的本意是「让复杂动作有引导」，不是「多一个菜单壳」。这条裁决必须写进 PRD，否则实施时容易顺手加两个菜单。

## 2. 约束与术语

| 术语 | 含义 |
|---|---|
| 向导步（step） | 向导的一个阶段，有「已完成 / 当前 / 未开始」三态，可回退，不可跳过必填步 |
| 关联矩阵 | 「项目向导」与「模板向导」各自能关联什么、必填还是可选（见 §3） |
| 编号序列 | `project_code_sequence`，按「前缀 + 年月 + 内核」记录已发最大号，**只增不减** |
| 前缀注册 | `project_code_prefix`，集中登记编码前缀及其含义，两个模板不得用同一前缀 |
| 原子选择 | 选一个用例集 = 选它当时的成员快照，不是「引用一个会变的集合」；快照事实写进创建结果 |
| 演示项目 | `is_demo=1` 的项目（5.9 已建机制）；向导「属性」步可选「标记为演示项目」 |

**硬约束**：

1. **向导不得成为第二套写入 API**：每一步的提交都调用既有端点（`POST /projects`、`POST /projects/{id}/members`、`POST /groups/{id}/grant`、`POST /projects/{id}/assets`），不新增「向导专用」端点。
2. **中途退出不留半成品**：向导创建采用「最后一步一次提交」或「草稿项目 + 明确可见的未完成标记」二选一，**不允许**出现「点了三次下一步，库里多了三个空项目」。
3. **编号不可复用**：删除最大编号项目后新建，新号必须是原最大号 +1。
4. **迁移只能追加**：从 `V11_68` 起（5.9 预留到 `V11_67`），每支配 `.down.sql`。
5. **门禁同版改**：新增 2 个二级项要改 `navigation.spec.ts` 的叶数断言；`GLOBAL_EXPECTED` 组数不变（都在既有组内加子项）。
