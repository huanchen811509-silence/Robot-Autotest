## 1. 执行方式分类

| 代号 | 含义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `UT` | 后端/前端单测 | 逻辑分支正确 | 真实请求能通、界面能看见 |
| `MECH` | 机检脚本（带 `--self-test`） | 规则被守住且能判红 | 业务语义对不对 |
| `HTTP` | 真实服务请求 | 契约、错误码、真实数据 | 界面渲染 |
| `UI` | 真实浏览器（CDP/人工） | 用户能看见、能点 | 后端边界 |
| `DOM` | 页面内断言（iframe 长度、`sandbox` 属性、锚点） | 结构事实 | 观感 |
| `DB` | 直连数据库读数 | 落库事实 | 链路是否被调用 |
| `FILE` | 导出件实体检查 | 文件能打开、内容一致 | 页面渲染 |
| `PERF` | 耗时与内存 | 预览/导出不退化 | 功能正确性 |
| `REPLAY` | 在 v5.13 收口 commit 上回放 | 原缺陷存在 | 修复完整性 |

**放行口径**：P0 条目（FR-01/02/03/04/08）必须至少拿到 `UI` 或 `DOM` 或 `DB` 一级证据；只有 `UT` 的条目不得计为达成。
**数字一致性是硬要求**：TC-07 必须是「列表套件数 = 详情树一级子节点数」，至少 3 个样本（RF 单套件 / RF 多套件 / pytest 参数化），不接受「看起来对」。

## 5. 不可用推断补齐的条目（执行纪律）

| 情形 | 处理 |
|---|---|
| pytest 参数化样本不足 | 用真实 pytest 工程跑一次参数化用例；造不出则 TC-06 的该口径标「未执行」 |
| 无「两次真实执行」 | 差异功能 TC-47 标「未执行（缺两次样本）」，**不许**用伪造 run 冒充 |
| 10MB 快照造不出 | 用大日志合成报告；仍无则 NFR-04 标「未测」，不得写「应该没问题」 |
| 导出件无法打开 | 一律视为失败，不接受「下载成功即通过」 |
| 冻结报告不存在 | 必须先冻结一份；否则 TC-22/TC-49 未执行 |
