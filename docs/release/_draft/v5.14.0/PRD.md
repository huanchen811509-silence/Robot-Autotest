## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 把「执行报告 / 测试报告」的**界面口径统一**（一条链路现在有三个名字）；给执行报告补上**套件数**并可点进套件；把测试报告从「能建草稿、不能看」补成**能预览、能导出、能打印**，并为 EHT pytest 工程提供**按内核的模板与三段式编写逻辑** |
| 性质 | **口径 + 接线版**：后端渲染/导出/快照能力大多已有，前端一个都没接；套件数需要 1 列迁移 |
| 上游需求 | R14、R15 |
| 目标产出 | 全站「对外报告」零命中；套件数列与深链；测试报告详情页；三格式导出；模板 `kernel` 维度 + EHT 预置模板 |
| 不追求 | 不改执行链路（5.8 已收口）、不改报告存储结构（只加 1 列）、不改环境快照（5.15）、不做运维界面（5.16） |

## 2. 约束与术语

| 术语 | 含义 |
|---|---|
| 执行报告 | `run` 表的界面投影，对内，含用例/套件/日志/产物 |
| 测试报告 | `test_report`，对外，自包含快照（`snapshot_html` + 冻结字段） |
| 套件数 | 该 run 的 `case_key` 唯一前缀集合大小；**必须与详情树同一套切分规则**，否则列表数字与树对不上 |
| 深链 | `/reports/{runId}?suite=<path>`，让详情页展开并高亮对应套件节点（不新增页面） |
| 冻结 | 测试报告生成快照后不可变；预览以快照为准，不因模板变更而变 |
| kernel 维度 | `report_template.kernel`，取值 `robot` / `pytest` / `any`，决定默认模板选择 |

**硬约束**：

1. **不改表名与代码命名**：`run` / `test_report` / `TestReport*` 保持；只用 i18n 层对齐文案。改表名要迁移 + 契约重生成，收益为零。
2. **套件数必须与详情树同源**：抽同一个切分函数，禁止列表用一套、树用另一套（这是最容易出的「数字不一致」投诉）。
3. **测试报告预览以冻结快照为准**：`snapshot_html` 直出，不重新渲染当前模板——否则「昨天打印的和今天看的不一样」。
4. **对外口径变更须大师拍板**：「对外报告 → 测试报告」属对外口径，按规矩由大师确认后定稿（本 PRD 采信总纲 D 类裁决）。
5. **迁移只能追加**：从 `V11_73` 起**跳号追加**。R-1 实测 `V11_69 ~ V11_72` 从未落文件，
   「5.13 预留到 V11_72」只是编号约定，不是已建迁移；W1 已用真实迁移演练确认 Flyway 与
   `db-audit.sh` 接受跳号（表数仍 109）。

### FR-v5.14-09 EHT pytest 三段式编写逻辑【P1】

**描述**：按三段式重写 pytest 报告的组织（内容逻辑，不是排版）：

```text
一、结论层（1 页）
   本次执行结论（通过 / 不通过 / 缺证据 / 未执行 四态计数）
   + 判据未定项清单（点名到 nodeId）
   + 与上次同工程执行的差异（新增失败 / 修复 / 仍失败）
二、证据层（按用例分组）
   每条：nodeId · 判据行原文 · 实测值 · 证据文件（junit / json-report / 日志）相对路径
   证据路径可点击（复用 5.11 的 CaseScriptLink 同一套路径组件）
三、附录
   metadata 十项 + 执行环境（内核版本、插件版本、仓库 commit、快照引用）
```
