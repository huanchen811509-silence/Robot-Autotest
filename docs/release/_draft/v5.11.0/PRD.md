## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 用例清单**只留一个视图**：中栏两级分类树 + 右工作区用例表 + **表格正下方**详情区；每个用例都能打开看全部细节，且细节与表格**严格信息幂等**；全站显示用例的地方都带**测试文件相对路径** |
| 性质 | **交互范式版**：本版产出的 `DetailDock` 组件与「列表 + 中栏 + 工作区」布局，是 5.12（用例集、项目资产）复用的地基 |
| 上游需求 | R5、R6、R7、R13 |
| 目标产出 | 删掉一个视图 + 一条孤儿路由；新增 1 个通用详情组件 + 1 个两级分类树组件 + 1 个脚本路径组件；三处 API 补脚本路径 join |
| 不追求 | 不改用例集的布局（5.12）、不改资产页（5.12/5.13）、不改报告（5.14）、不做 RF 脚本路径的自动匹配（见 §5 FR-05 边界） |

### 1.1 为什么这三条必须同版

1. **R5 的「详情在列表下方」就是 R6**：R5 要求「每个用例要单独能打开看全部细节」，位置要求「在当前列表下方」。若先做 R5 的布局再补 R6 的组件，详情区要写两遍。
2. **R7 的路径列要进 R5 的表格**：表格列定义在同一次改动里定稿，分开做等于改两遍列配置与列设置持久化。
3. **R13 的提示挂在用例详情与集合头上**：详情区与集合头都在本版重写范围内，改一处即可；延后就要回头再动一次详情组件。

### 1.2 现状的三个确凿反例

| # | 反例 | 证据 | 用户看到什么 |
|---|---|---|---|
| 1 | 详情说「源表无此列」，库里却有 | `CaseDetailPanel.vue:77-79` 把 `precondition/steps/expected` 硬编码为「源表无此列」，而 `V2_3:8-11` 有这两列、`V1:294-303` 有 `test_case_step` 表 | 列表里有「前置条件」，点开详情说没有 |
| 2 | 「分类归组」与「列表」是两个互斥视图 | `GlobalCasesView.vue:42-47`（`?group=1` 切换）、`:459-462`（单栏树） | 同一批数据两种看法，切来切去 |
| 3 | 全站没有脚本路径 | `case_script_binding`（`V11_47:20-41`）已有 `script_path`，但用例列表/详情/用例集**都不 join**（仅有 `PytestWorkbenchView.vue:52-57` 一处） | 不知道这条用例对应哪个 .py 文件 |

### 1.3 关于 R13 的结论（写进 PRD，避免实施时被当成风险项反复讨论）

**项目模式下修改用例/用例集，不影响全局。** 代码级依据：

| 事实 | 证据 |
|---|---|
| `test_case` 只有 `project_id`，**无** `owner_scope`/`tenant`/`scope` 列 | `V1__baseline.sql:269-293` |
| 「全局用例库」是一个特殊项目 `PLATFORM-LIB`，不是共享行 | `PlatformProjectService.java:14-50` |
| 编辑/删除一律带 `project_id` 且经 `TenantGuard.requireProjectScope` | `TestCaseRepositoryJdbc.java:186-197`、`:200-215` |

因此 R13 **不需要「防串改」机制**，只需要在**两个真实场景**加提示（见 FR-06）。

## 2. 约束与术语

| 术语 | 含义 |
|---|---|
| 工作区（workspace） | 列表页右侧承载表格与详情的区域；本版定义的布局是「中栏固定宽 + 右工作区自适应」 |
| DetailDock | 详情停靠区：位于**当前列表容器内部、表格之后**，不是弹窗、不是抽屉、不是新页面、不是 fixed 浮层 |
| 信息幂等 | 不变量：**表格列配置里的每个 `key`，都能在详情 DTO 里找到同名（或显式映射）的字段，且值来自真实数据** |
| 两级分类 | L1 = 分类域，L2 = 分类；点 L1 按整个域过滤，点 L2 按叶子过滤 |
| 脚本路径 | `case_script_binding.script_path`（相对仓库根的路径）+ 末段文件名 + 绑定状态三件套 |
| 绑定状态 | `BOUND_VERIFIED`（已校验）/ `BOUND_UNVERIFIED`（已绑定未校验）/ `UNBOUND`（未绑定）/ `NOT_APPLICABLE`（该内核不支持脚本绑定） |

**硬约束**：

1. **不得用弹窗/抽屉承载列表行详情**：本版涉及的列表页（全局用例、项目用例、用例集成员）全部改为 `DetailDock`。
2. **不得隐藏「没有的字段」来假装幂等**：修法是「详情取真值」，不是「表格少显示」。
3. **不造假的路径**：RF 用例当前没有与 `test_case` 关联的脚本列（`robot_file.path` 存在但无关联列），显示 `NOT_APPLICABLE` 并写明原因，**不做半假的最长公共子串匹配**。
4. **URL 可分享**：筛选与选中详情落 URL（`?detail=<id>`），刷新可恢复。
5. **迁移尽量为零**：本版预期**不新增业务表**；只可能补索引。若必须加列，从 `V11_70` 起（5.10 预留到 `V11_69`）。

## 5. 需求详述

### FR-v5.11-01 `DetailDock` 详情停靠组件【P0】

**描述**：新增通用组件 `DetailDock`，约定：

| 项 | 约定 |
|---|---|
| 位置 | 列表容器内部、表格之后（**不是**页面最底部，**不是** fixed 浮层） |
| 触发 | 单选行 → 就地渲染；再点同一行 → 收起；切换行 → 原地替换 |
| 滚动 | 打开时 `scrollIntoView({ block: 'nearest' })`，**不允许**把页面滚到底部 |
| 宽度 | 与表格同宽（`clientWidth` 差值 ≤ 2px） |
| 结构 | 两列（字段 / 值），不做三栏 |
| 状态 | URL 可带 `?detail=<id>`，刷新恢复 |
| 首个接入点 | 项目用例清单（`CasesView.vue:622-629` 现有 `expand` 行内展开迁到 Dock，统一范式） |

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 1440×900 视口下点开任意行，详情区**首屏可见**（无需滚动页面），且表格仍可见 | 截图 + 视口尺寸记录 |
| 2 | 详情区与表格同宽（`clientWidth` 差值 ≤ 2px） | DOM 测量输出 |
| 3 | 再次点击同一行收起；点击另一行原地替换（不追加第二个详情区） | 截图 3 张 + DOM 断言（详情区实例数 = 1） |
| 4 | URL 带 `?detail=<id>` 打开 → 详情自动展开且滚动位置正确 | 截图 + URL 文本 |
| 5 | 全站列表行详情**零弹窗**：本版触及的 3 个页面里 `dialog`/`drawer` 承载行详情的实例数 = 0 | 代码检查 |
| 6 | 组件被至少 2 个页面复用（项目用例、全局用例） | 代码检查（import 同一文件） |

**降级预案**：若某页表格行高导致「首屏可见」在 1366×768 下无法满足，允许详情区默认折叠为「摘要一行 + 展开」两态，但判据 1 在 1440×900 下仍须满足。

### FR-v5.11-04 信息幂等不变量与单测【P0】

**描述**：把「信息幂等」写成可执行的不变量：

| 层 | 规则 |
|---|---|
| 表格 → 详情 | 表格列配置的每个 `key` ∈ 详情 DTO 字段集合（同名或显式映射表里有对应） |
| 详情 → 数据 | 详情里每个字段的值必须来自真实数据；**禁止**硬编码「源表无此列」这类文案（除非该字段在 DTO 里确实不存在，且 DTO 与表结构一致） |
| 单测 | 遍历列配置，断言映射完整；对 `precondition/steps/expected` 单独断言「详情值 = 库值」 |

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 单测：遍历 `GlobalCasesView` 与 `CasesView` 的列配置，每个 `key` 都能在详情 DTO 里找到，缺失则单测红 | `npm test` 输出（含注入一个假列名时判红的自检） |
| 2 | `precondition` / `steps` / `expected` 在详情区显示真实值（取 `test_case` 列与 `test_case_step` 表），**不再出现「源表无此列」** | 截图 + DB 同值比对 |

| 4 | 反向判据：在 v5.8 收口 commit 上执行判据 2 → 必须看到「源表无此列」 | 回放截图 |
| 5 | DTO 与表结构一致性机检：DTO 字段在表/视图里都能找到来源（允许计算字段但需在映射表里声明） | 机检输出 |

**降级预案**：若某字段确实是「计算得到」而非表列（如「最近执行结论」），必须在映射表里显式声明来源与算法，**不得**归为「源表无此列」。

### FR-v5.11-06 项目改动影响面提示【P1】

**描述**：R13 结论是「物理隔离」，因此提示只需覆盖两个**真实**会跨边界变化的场景，不做泛化的「警告」：

| 场景 | 机制 | 提示形态 |
|---|---|---|
| 平台用例集的副本同步 | 集合 `source_asset_id` 非空即为平台集副本；`syncFull` 按 `case_code` 找成员，`ADD_ONLY` 保留本地改写后判 `DIVERGED`（`AssetVersionService.java:271-350`） | 集合头徽章：「来源：平台集 #123 · 已同步 / 已分叉（本地有改动）」；同步前弹**影响面预览**（新增 N / 覆盖 M / 保留 K） |
| 存量同步（ProjectSync）按 `external_id` 覆盖 | 相同 `external_id` 视为同一条，非 `local_override` 字段被覆盖（`ProjectSyncService.java:20-23`） | 用例详情显示「来源：存量同步 · 本地已改写（不再覆盖）」徽章 |
