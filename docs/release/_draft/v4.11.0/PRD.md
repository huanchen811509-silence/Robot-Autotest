## 1. 背景与目标

v4.10.0 已完成「用例详情 / 两级分类 / 资产详情 / 模板建项目 / 菜单权限 / 主题语言切换」六项，但**菜单信息架构仍有两处不对称**：

1. **全局模式是扁平的**：5 个一级项全是叶子（调研 A1），而项目模式是 7 组 / 32 叶（B1）。同一产品两种侧栏形态，用户跨模式切换要重新建立心智。
2. **设置入口重复且未对齐**：全局 `/g/*` 有完整 6 项设置，项目模式又派生了一份同名同序的 6 项（A5/B3），且全局侧栏并不显示这 6 项（只在页面内，A4）。

同时顶栏的「账户（管理员）按钮」不在最右（C2），以及「执行与报告」缺少一个「以用例发起执行」的独立入口（D4）。

**本版目标**：
- 让全局与项目两套侧栏在**风格、布局、交互逻辑**上完全对齐（同一组件、同一展开规则、同一能力过滤口径）。
- 把「平台级配置」的入口收敛到一处，消除双份设置。
- 顶栏按「上下文 → 工具 → 身份」重排，账户按钮最右。
- 新增「执行计划」二级菜单，承载「选用例 → 配参数 → 一键发起」。
- 结清 v4.10.0 遗留 5 项（L-49-03/04/05/06/07）。

| 角色 | 主场景 |

## 4. 菜单信息架构目标态

### 4.1 两模式对照

| 模式 | 一级（组）数 | 二级（叶）数 | 形态 |
|---|---|---|---|
| 全局（本版后） | 5 | 5 + 设置 6 + 详情 3（走 `alsoMatch` 点亮父项，不计入侧栏条目） | 分组可折叠，默认只展开激活组 |
| 项目（不变） | 7 | 32 | 同上 |

### 4.2 全局菜单目标树

| 一级组 | 图标 | 二级项 | 路径 | 能力 |
|---|---|---|---|---|
| 项目 | dashboard | 全部项目 | `/g/projects` | `public`（角色准入另判） |
| 公共用例 | cases | 公共用例 | `/g/cases` | `case:write` 或只读兜底 |
| 公共资产 | database | 公共资产 | `/g/assets` | `asset:read` |
| 模板 | boxes | 模板列表 | `/g/templates` | `public` |
| 系统设置 | admin | 平台设置 / AI 助手 / 用户管理 / 审计日志 / 关于 / 版本迭代 | `/g/settings`、`/g/settings/ai`、`/g/admin`、`/g/admin/audit`、`/g/about`、`/g/changelog` | 沿用 `SETTINGS_NAV` 的 6 条能力 |

> 单页组（项目 / 公共用例 / 公共资产 / 模板）允许「组 + 唯一子项」形态，目的是与项目模式视觉一致；若实施时发现「一组一叶」点击两次太啰嗦，可由 D-01 决策降级为叶子（见 §7 P-07）。

## 5. 功能需求

### A. 全局菜单两级化

**FR-v4.11-01 全局侧栏改为两级结构**
- 描述：`GLOBAL_NAVIGATION` 由 5 个叶子改为 5 个 `NavGroup`，`AppNav.vue` 不改渲染逻辑，直接复用。
- 验收判据：全局模式下侧栏渲染出 5 个可折叠组头（`aria-expanded` 属性存在）；每组展开后有 ≥1 个 `.app-nav-sub` 叶子；`AppNav.vue` 的 diff 为 0 行（组件不因本需求改动）。

**FR-v4.11-02 激活组判定按当前模式取树**
- 描述：`activeGroupKey()` 增加入参（当前模式的导航树），不再硬编码项目 `NAVIGATION`。
- 验收判据：在 `/g/settings/ai` 刷新页面后，「系统设置」组自动展开且组头带 `has-active`；单测覆盖「传入全局树时返回 `global-settings`」。项目模式回归：`/plans/graph` 仍展开「执行与报告」。

**FR-v4.11-03 全局导航接入能力过滤**
- 描述：`App.vue` 的 global 分支改为 `filterNavByCapabilityPredicate(GLOBAL_NAVIGATION, has)`，与项目分支同口径；子项全被过滤掉的组整组隐藏。
- 验收判据：用无 `user:write` 的账号进入全局，「系统设置」组内不出现「用户管理」；把该账号权限降到只剩 `public` 时，「系统设置」组仍保留（因 `关于`/`版本迭代` 是 `public`），且组内恰 2 项。

**FR-v4.11-04 全局系统设置 6 项进侧栏**
- 描述：`SETTINGS_NAV` 直接作为「系统设置」组的 children 数据源，路径用 `/g/*` 原名。
- 验收判据：侧栏 6 项顺序与 `SETTINGS_NAV` 数组顺序逐项一致（单测断言 `navKeys == SETTINGS_NAV.map(k)`）；`GlobalSettingsView.vue` 页内列表保留且不重复高亮（页内导航与侧栏同时存在时，选中态一致）。

**FR-v4.11-05 选中态与展开态对齐项目模式**
- 描述：详情路由（`/g/cases/:id`、`/g/assets/:id`、`/g/templates/:id`）通过 `alsoMatch` 点亮所属父项；展开态沿用 `localStorage['robot.nav.expanded']`，且**手动折叠优先于自动展开**。
- 验收判据：进入 `/g/templates/1` 后「模板」组亮且「模板列表」叶子亮；手动折叠「模板」组后切到 `/g/templates/2`，组**保持折叠**（与项目模式行为一致）。

**FR-v4.11-06 菜单机检扩展**
- 描述：新增机检断言，锁死两级化后的不变量。
- 验收判据：机检脚本对两套树都断言：① 层级 ≤ 2；② 全局一级 ≤ 6、项目一级 ≤ 7；③ 一级项不含 `BUSINESS_DOMAIN_LABELS` 任一业务域名；④ 每个组 children 非空、每个叶子 path 唯一。任一条不满足则非 0 退出。

### B. 设置入口收敛（依赖 P-01）

**FR-v4.11-07 全局模式准入口径调整**
- 描述：按 **P-01=A（已拍板）** 调整 `canEnterGlobalMode`：所有登录用户均可进入全局模式，写入类入口由能力过滤 + 后端 403 兜底。
- 验收判据：ENGINEER 登录后顶栏可见「全局」切换按钮并能进入 `/g/projects`；其侧栏不出现「用户管理 / 审计日志 / AI 助手」；直接请求 `/api/admin/users` 仍返回 4xx（前端过滤不等于放权）。

**FR-v4.11-08 系统设置入口去重**
- 描述：按 **P-01=A（已拍板）** 落地——项目模式**移除**「系统设置」一级，设置入口只保留全局一处。
- 验收判据：项目模式侧栏一级项由 **7 变 6**，且不含任何 `/settings` 入口；直接访问 `/settings/ai` 时按 DEV-PLAN 选定的策略重定向到 `/g/settings/ai`（或 403），不得停在空白页；`SETTINGS_NAV` 仍是 6 项单一真源，全局侧栏与页内导航 diff = 0。

### C. 顶栏重排

**FR-v4.11-09 顶栏控件顺序**
- 描述：工具段内顺序固定为 **检索 → 通知 → AI 助手 → 主题 → 语言**；账户段紧随其后。
- 验收判据：`AppHeader.vue` 中 `[data-seg="tools"]` 的可聚焦控件按上述顺序排列（单测按顺序断言 `aria-label` 数组）；`.app-sep` 数量仍为 **2**。

**FR-v4.11-10 账户按钮最右**
- 描述：账户菜单（管理员按钮）位于顶栏最右侧，其后无任何可聚焦控件。
- 验收判据：`[data-seg="account"]` 是 `header-actions` 内最后一个 `data-seg`；其 `getBoundingClientRect().right` 大于同段所有其他控件；`header-quick` 容器不再存在。

**FR-v4.11-11 窄屏与无障碍回归**
- 描述：1080 / 760 两个断点的间距规则从 `header-quick` 迁到工具段；Tab 顺序保持「上下文 → 工具 → 账户」。
- 验收判据：760px 宽下顶栏不出现横向滚动（`scrollWidth <= clientWidth`）；Tab 遍历一次覆盖全部控件且顺序符合上述；主题/语言按钮 `aria-label` 与账户菜单内同名控件语义一致。

### D. 执行计划

**FR-v4.11-12 新增「执行计划」二级菜单与路由**
- 描述：「执行与报告」组 `section: run` 段第一项为「执行计划」，路由 `/execution-plans`，能力 `execution:read`。
- 验收判据：侧栏「执行与报告」展开后顺序为 **执行计划 → 运行记录 → 测试计划 → 执行节点**，分隔线后接报告三项（共 7 叶，1 条分隔线）；直接访问 `/execution-plans` 未授权账号返回 403。

**FR-v4.11-13 选择区：用例集与用例**
- 描述：支持「按用例集多选（展开成 caseIds）」与「按用例搜索勾选」两种方式，实时显示已选条数。
- 验收判据：选 1 个含 20 条用例的用例集后，已选计数显示 20；再手工取消 2 条后显示 18；提交时 `caseIds.length` 与显示一致（单测断言请求体）。

**FR-v4.11-14 参数区**
- 描述：暴露 `environmentId`、`concurrency`、`timeoutSeconds`、`testTimeoutSeconds`、`includeTag` 五项，缺省值沿用后端默认（不填即不发该字段）。
- 验收判据：不改任何参数提交，请求体只含 `caseIds` 与 `runRequestId`；改并发为 4 后请求体含 `concurrency: 4`，其余字段仍不出现（避免覆盖后端默认）。

**FR-v4.11-15 安全预检与发起**
- 描述：选择变化即调 `safetyPrecheck`，L2 / LX 用例在提交前标红并给出原因；提交后跳运行详情。
- 验收判据：勾选 1 条 `safetyLevel=LX` 用例后，发起按钮禁用且提示文案含用例编号；取消该条后按钮恢复可用；发起成功跳转 `/runs/:id` 且 `runId` 与响应一致。

**FR-v4.11-16 发起记录**
- 描述：页面下方展示最近 20 条「由本页发起」的执行记录；来源用 `runRequestId` 前缀 `EP-` 标记，不新增表/列。
- 验收判据：发起 1 次后记录列表首行为该次执行（`runId`、发起人、条数、时间）；从用例页发起的执行**不出现**在本列表（来源过滤生效）。

### E. 遗留结转

**FR-v4.11-17 L-49-07：模板场景回填用例集**
- 描述：`SCENARIO` 项生成时，把同模板 `CASE_SET` 产出的 set id 写入 `case_set_ids`。
- 验收判据：用模板 3 建项目后，场景详情返回的 `caseSetIds` 非空且与该项目用例集 id 一致；`ProjectTemplateCopyIT` 增一条断言。

**FR-v4.11-18 L-49-03：导入预览增量 diff（依赖 P-05）**
- 描述：按 **P-05=B（已拍板）** ——**保留** `replayed` 幂等语义不变，新增显式重算参数 `force=1`，带该参数时重算并返回增量 diff（新增/修改/无变化三类计数）。
- 验收判据：同一 xlsx 连续预览两次——**不带** `force` 时第二次仍返回 `replayed=true`（幂等语义未被破坏）；**带** `force=1` 时返回 `replayed=false` 且 `diff.added + diff.updated + diff.unchanged == 总行数`；负向验证：篡改指纹后带 `force=1` 必须判为 `updated`，不得判 `unchanged`。

**FR-v4.11-19 L-49-06：`check_tables` 存量债（P-06=A 已拍板）**
- 描述：按 **P-06=A（已拍板）** 清掉 `ProjectSyncView.vue`(2)、`GlobalAssetsView.vue`(1)、`GlobalCasesView.vue`(3) 共 6 处原生 `<table>`，统一改用 `DataTable` 壳（**不加机检豁免**）。
- 验收判据：`scripts/lint.sh` 第 06 项 `check_tables` 由红转绿（读数 0 处违规），且 lint 总读数变为「24 项 / 24 绿」；三个页面的既有交互测试全过。

**FR-v4.11-20 L-49-04：补 2 个组件单测**
- 描述：为 `CategoryTree.vue`、`TemplateWorkbenchView.vue` 补 spec。
- 验收判据：两个 spec 文件存在且用例数 ≥ 5/≥ 4；`vitest` 全量通过；覆盖点包含「一级选中连带二级」「保存后计数刷新」。

**FR-v4.11-21 L-49-05：3 条浏览器级用例（条件项）**
- 描述：CDP `:9222` 恢复后补跑 R6 全局设置可达（04）、R8 顶栏布局（16）、45。
- 验收判据：CDP 可用时三条 PASS 并留截图证据；不可用时在测试报告中如实记 NOT-RUN 并注明原因，**不计 FAIL、不阻塞发版**。
