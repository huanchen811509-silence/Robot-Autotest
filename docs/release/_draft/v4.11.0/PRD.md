## 1. 背景与目标

v4.10.0 已完成「用例详情 / 两级分类 / 资产详情 / 模板建项目 / 菜单权限 / 主题语言切换」六项，但**菜单信息架构仍有两处不对称**：

1. **全局模式是扁平的**：5 个一级项全是叶子（调研 A1），而项目模式是 7 组 / 32 叶（B1）。同一产品两种侧栏形态，用户跨模式切换要重新建立心智。
2. **设置入口重复且未对齐**：全局 `/g/*` 有完整 6 项设置，项目模式又派生了一份同名同序的 6 项（A5/B3），且全局侧栏并不显示这 6 项（只在页面内，A4）。
3. **全局 5 组里有 4 组只有 1 条路由**（A1）：即便改成两级，也是「一组一叶」，形式上是分组、用起来还是单页，与项目模式「每组 2~6 叶」的实际手感不对齐。

同时顶栏的「账户（管理员）按钮」不在最右（C2），以及「执行与报告」缺少一个「以用例发起执行」的独立入口（D4）。

**本版目标**：
- 让全局与项目两套侧栏在**风格、布局、交互逻辑**上完全对齐（同一组件、同一展开规则、同一能力过滤口径）。
- **全局每个一级组至少 2 个二级项**（合计 14 叶），让「分组」名副其实，而不是一组一叶的伪分组。
- 把「平台级配置」的入口收敛到一处：**全局 6 项全量迁入侧栏**，项目侧只留「用户管理（仅当前用户和关联项目）」+「关于」2 项。
- 顶栏按「上下文 → 工具 → 身份」重排，账户按钮最右。
- 新增「执行计划」二级菜单，承载「选用例 → 配参数 → 一键发起」。
- 结清 v4.10.0 遗留 5 项（L-49-03/04/05/06/07）。

## 4. 菜单信息架构目标态

### 4.1 两模式对照

| 模式 | 一级（组）数 | 二级（叶）数 | 形态 |
|---|---|---|---|
| 全局（本版后） | 5 | **14**（2 + 2 + 2 + 2 + 6） | 分组可折叠，默认只展开激活组 |
| 项目（本版后） | 7 | **29**（4 + 7 + 3 + 3 + 6 + 4 + 2） | 同上；执行与报告 6→7（新增执行计划），系统设置 6→2 |

> 两侧详情路由（`/g/cases/:id`、`/g/templates/:id`、`/cases/:id` 等）一律走 `alsoMatch` 点亮父项，**不计入叶数**。

### 4.2 全局菜单目标树（5 组 / 14 叶，每组 ≥2）

| 一级组 | 图标 | 二级项 | 路径（含 query） | 能力 |
|---|---|---|---|---|
| **项目** | dashboard | 全部项目<br>我参与的 | `/g/projects`<br>`/g/projects?scope=mine` | `public`<br>`public` |
| **公共用例** | cases | 公共用例<br>导入记录 | `/g/cases`<br>`/g/cases?view=imports` | `case:write` 或只读兜底<br>同左 |
| **公共资产** | database | 设备<br>凭据 | `/g/assets?tab=devices`<br>`/g/assets?tab=credentials` | `asset:read`<br>`asset:read` |
| **模板** | boxes | 内置模板<br>自定义模板 | `/g/templates?kind=builtin`<br>`/g/templates?kind=custom` | `public`<br>`public` |
| **系统设置** | admin | 平台设置 / AI 助手 / 用户管理 / 审计日志 / 关于 / 版本迭代 | `/g/settings`、`/g/settings/ai`、`/g/admin`、`/g/admin/audit`、`/g/about`、`/g/changelog` | 沿用 `SETTINGS_NAV` 的 6 条能力 |

**项目模式「系统设置」组（本版后只留 2 项）**

| 二级项 | 路径 | 能力 | 与全局的关系 |
|---|---|---|---|
| 用户管理（仅当前用户和关联项目） | `/settings/users` | `public` | **项目域独有新页**，不是 `/g/admin`（后者是系统级账号管理，B6） |
| 关于 | `/about` | `public` | 与 `/g/about` 同一视图、同一数据源 |

> **路径值约定**：全局页签统一用复数（`devices` / `credentials`），与项目模式 `/assets?tab=devices` 同词表，避免同一概念两套拼写。`view` / `kind` / `scope` 三个参数为本版新增，均为纯前端筛选，不改后端入参。
>
> **路由保留**：项目侧 `/settings`、`/settings/ai`、`/admin`、`/admin/audit`、`/changelog` 五条路由**不删**，只是不再出现在侧栏；历史书签、关于页跳转（`/changelog`）仍可达，不会 404。
>
> **已知冗余（保留，不修）**：`/g/settings` 目前是「设置索引页」，页内还有一份 6 项 `RouterLink` 列表；侧栏接管后会出现两份导航。**本版保留页内索引**——因为 `SettingsView`（真实平台设置内容）强依赖 `auth.projectId`（`SettingsView.vue:22,43`），全局域没有项目上下文，`/g/settings` 没有可渲染的正经内容；改成跳转或空页只会更差。判据只要求「侧栏与页内对同一路由的选中态一致」，不要求消除冗余。

## 5. 功能需求

### A. 全局菜单两级化

**FR-v4.11-01 全局侧栏改为两级结构**
- 描述：`GLOBAL_NAVIGATION` 由 5 个叶子改为 5 个 `NavGroup`，`AppNav.vue` 不改渲染逻辑，直接复用。
- 验收判据：全局模式下侧栏渲染出 5 个可折叠组头（`aria-expanded` 属性存在）；**每组展开后恰有 ≥2 个 `.app-nav-sub` 叶子**（5 组叶数分别为 2/2/2/2/6，合计 14）；`AppNav.vue` 的 diff 为 0 行（组件不因本需求改动）。

**FR-v4.11-02 激活组判定按当前模式取树**
- 描述：`activeGroupKey()` 增加入参（当前模式的导航树），不再硬编码项目 `NAVIGATION`。
- 验收判据：在 `/g/settings/ai` 刷新页面后，「系统设置」组自动展开且组头带 `has-active`；单测覆盖「传入全局树时返回 `global-settings`」。项目模式回归：`/plans/graph` 仍展开「执行与报告」。

**FR-v4.11-03 全局导航接入能力过滤**
- 描述：`App.vue` 的 global 分支改为 `filterNavByCapabilityPredicate(GLOBAL_NAVIGATION, has)`，与项目分支同口径；子项全被过滤掉的组整组隐藏。
- 验收判据：用无 `user:write` 的账号进入全局，「系统设置」组内不出现「用户管理」；把该账号权限降到只剩 `public` 时，「系统设置」组仍保留（因 `关于`/`版本迭代` 是 `public`），且组内恰 2 项。

**FR-v4.11-04 全局系统设置 6 项进侧栏**
- 描述：`SETTINGS_NAV` 直接作为「系统设置」组的 children 数据源，路径用 `/g/*` 原名。
- 验收判据：侧栏 6 项顺序与 `SETTINGS_NAV` 数组顺序逐项一致（单测断言 `navKeys == SETTINGS_NAV.map(k)`）；`GlobalSettingsView.vue` 页内列表保留且不重复高亮（页内导航与侧栏同时存在时，选中态一致）。

**FR-v4.11-05 选中态与展开态对齐项目模式**
- 描述：详情路由（`/g/cases/:id`、`/g/assets/:id`、`/g/templates/:id`）通过 `alsoMatch` 点亮所属父项；展开态沿用 `localStorage['robot.nav.expanded']`，且**手动折叠优先于自动展开**。
- 验收判据：① 手动折叠「模板」组后切到 `/g/templates/2`，组**保持折叠**（与项目模式行为一致）；② **详情页归属**：`/g/cases/:id` 点亮「公共用例」；`/g/assets/:id` 按详情类型点亮「设备」或「凭据」（加载后已知 `type` 时 `router.replace` 到对应 `?tab=`）；`/g/templates/:id` 按 `builtin` 点亮「内置模板」或「自定义模板」；三个详情页都必须让**组头亮**（不允许「进了详情、侧栏全灰」）。

**FR-v4.11-06 菜单机检扩展**
- 描述：新增机检断言，锁死两级化后的不变量。
- 验收判据：机检脚本对两套树都断言：① 层级 ≤ 2；② 全局一级 ≤ 6、项目一级 ≤ 7；③ 一级项不含 `BUSINESS_DOMAIN_LABELS` 任一业务域名；④ 每个组 children 非空、每个叶子 path 唯一。任一条不满足则非 0 退出。

### A-2. 全局各组第 2 个二级项（N1' 专项）

> 这 5 条是「每组 ≥2」的落地拆解。共同约束：只做「已有数据面换入口」，不新造功能；所有 query 参数由侧栏写、页面读，双向同步（返回/前进可复原）。
>
> **默认值必须规范化（否则「同 path 多 query」必然出现双双不亮）**：4 个组里除系统设置外，都是「同一个 path + 不同 query」。`isLeafActive` 对带 query 的叶子做严格比较（`navigation.ts:365-385`），因此直接访问 `/g/assets`（无 query）时**两个叶子都不亮、组头也不亮**。统一规则：进入该组任一页时，若无 query 或 query 非法，用 `router.replace` 规范化到默认值（`devices` / 第一项 / `builtin` / 第一项），使 URL 恒定带 query。

**FR-v4.11-25 「每组 ≥2」机检不变量**
- 描述：在 FR-v4.11-06 的机检里增加一条硬约束，防止后续版本又把某个组退化成单叶。
- 验收判据：机检对 `GLOBAL_NAVIGATION` 断言三件事，任一违反即非 0 退出：① 每个 `NavGroup.children.length >= 2`；② 同 path 的叶子其 `query` 两两不同（防两个查询参数写成一个）；③ 每个同 path 组都有且只有一个「默认 query」（无 query 时规范化到此值）。同时打印每组叶数与合计（应为 14）。项目树不受 ① 约束（其最小值为 2，未来出现单叶组也不误伤）。

**FR-v4.11-26 公共用例：导入记录提级为二级项**
- 描述：把 `GlobalCasesView` 页内折叠块 `<details class="batches">` 提级为独立视图分支，路由参数 `?view=imports`；数据仍走既有 `GET /api/global/cases/import/batches`（A10）。
- 验收判据：`/g/cases?view=imports` 只渲染导入批次表（不渲染用例列表）；`/g/cases` 只渲染用例列表；两者切换不重复请求用例列表（网络面板断言）；批次表的页码与总数行为与提级前一致。

**FR-v4.11-27 公共资产：两个页签接入 URL**
- 描述：`GlobalAssetsView` 的 `type` ref 与 `?tab=devices|credentials` 双向同步（照抄 `AssetsView.tabFromQuery`，A9）；侧栏 2 项分别指向两个 query。
- 验收判据：点侧栏「凭据」→ URL 变 `/g/assets?tab=credentials` 且只剩 2 个页签中的「凭据」为激活态；在页面内点页签 → URL 同步变化；直接访问 `/g/assets?tab=credentials` 刷新后仍停在凭据；**无 query 或非法值（如 `?tab=links`）时 `router.replace` 到 `?tab=devices`**（URL 被改写，不留在裸路径），且不报错。

**FR-v4.11-28 模板：按 `builtin` 拆内置 / 自定义**
- 描述：`GlobalTemplatesView` 增加 `?kind=builtin|custom` 维度筛选（`TemplateRow.builtin` 已有，A11）；侧栏 2 项分别指向两个 kind。
- 验收判据：`?kind=builtin` 下每行 `builtin === true` 且「编辑 / 删除」按钮不出现（与只读规则一致）；`?kind=custom` 下每行 `builtin === false`；两个 kind 的条数之和等于不带 kind 时的总数（空数据时均显示空态而非报错）。

**FR-v4.11-29 项目：全部项目 / 我参与的（含后端补字段）**
- 描述：`/g/projects?scope=mine` 只显示「我创建或我加入」的项目。因 `ProjectCard.myRole` 对全局 admin 无成员关系时也返回 `admin`（A14），须在卡片接口补 `own` / `joined` 两个布尔（`ProjectCardRepository` 已取 `member_role`，仅需比对 `owner_id`）。
- 验收判据：① 后端：`ProjectCard` 新增 `own`、`joined`，`GET /api/projects/cards` 返回二者；单测覆盖「admin 且非成员 → `own=false, joined=false`」「owner → `own=true`」「普通成员 → `joined=true`」三种情形。② 前端：`?scope=mine` 下每张卡满足 `own || joined`；admin 账号下该视图条数 **严格小于** 全部项目条数（至少少 1 条，证明「admin 但非成员」被正确排除）；ENGINEER 账号下该视图与工作台卡片中 `myRole != null` 的集合一致（A14 的语义边界）。

### B. 设置入口收敛（v1.2 落法 C）

**FR-v4.11-07 全局模式准入口径（维持现状）**
- 描述：按 **v1.2 修订**，`canEnterGlobalMode` **维持 admin / pm**（A13：该判定是纯前端函数，后端 `/api/global/*` 无角色注解）。
  理由：项目侧已保留「用户管理（项目域）+ 关于」，engineer 不再依赖全局入口（A15 关于页还能到版本迭代），放宽只会扩大变更面而不解决任何入口缺失。**此为 P-08 的建议值**；若大师要求放宽，仅需改该纯函数 + 2 处断言。
- 验收判据：ENGINEER 登录后顶栏**不出现**「全局」切换按钮；直接访问 `/g/projects` 被送去 `/403`；ADMIN / PM 进入 `/g/projects` 正常；`GET /api/me/menu-capabilities` 返回项与侧栏可见项逐条一致（过滤口径统一）。
  （若 P-08 改为「放宽」，则判据替换为：ENGINEER 可见切换按钮、可进 `/g/projects`，侧栏不出现「用户管理 / 审计日志 / AI 助手」，且直接请求 `/api/admin/users` 仍 4xx。）

**FR-v4.11-08 项目侧设置组裁为 2 项，全局承载全部 6 项**
- 描述：按 **v1.2 修订（§4.2 落法 C）**——全局「系统设置」组 6 项全量进侧栏（数据源 `SETTINGS_NAV` 不变）；项目侧**保留**「系统设置」一级组，但 children 只有「用户管理（仅当前用户和关联项目）」与「关于」2 项。
- 验收判据：① 项目侧栏一级项仍为 **7**，其中「系统设置」组内**恰 2 项**且顺序为「用户管理 → 关于」；② 全局侧栏「系统设置」组内**恰 6 项**，名称与顺序与 `SETTINGS_NAV` 逐项一致（单测断言 `navKeys === SETTINGS_NAV.map(k)`）；③ `SETTINGS_NAV` 仍只描述全局 6 项，项目侧 2 项由新增常量 `PROJECT_SETTINGS_NAV` 描述，两者**不再 diff = 0**，改为断言「项目 2 项均能在全局或项目域找到同源视图」；④ 项目侧 `/settings`、`/settings/ai`、`/admin`、`/admin/audit`、`/changelog` 五条路由直接访问仍可用（不 404、不空白）。

**FR-v4.11-30 项目域「用户管理」只读页**
- 描述：新建 `/settings/users`「用户管理（仅当前用户和关联项目）」，**只读**：上半区当前登录用户（用户名 / 显示名 / 角色 / 所属项目数），下半区该用户关联的项目列表（名称 / 编号 / 我的角色），每行可跳 `/:projectId/overview`。身份取自 `auth` store（A16），关联项目取 `/api/global/projects` 过滤 `own || joined`（A12）。**不复用 `/admin`**（B6：那是系统级账号 CRUD，能力 `user:write`，语义与越权面都不同）。
