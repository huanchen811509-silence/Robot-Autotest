## 1. 执行方式分类

| 代号 | 含义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `UT` | 后端/前端单测 | 逻辑分支正确 | 真实请求能通、界面能看见 |
| `MECH` | 机检脚本（带 `--self-test`） | 规则被守住且能判红 | 业务语义对不对 |
| `HTTP` | 真实服务请求 | 契约、错误码、越权拦截 | 界面渲染 |
| `UI` | 真实浏览器（CDP/人工） | 用户能看见、能点 | 后端边界 |
| `DOM` | 页面内测量（列存在性、字段数、路径一致性） | 结构事实 | 观感 |
| `DB` | 直连数据库读数 | 落库事实 | 链路是否被调用 |
| `PERF` | 耗时与帧率 | 性能不回退 | 功能正确性 |
| `MANUAL` | 代码检查 / 人工走查 | 无第二套实现、功能零回退 | 可重复性（须留记录） |

**放行口径**：P0 条目（FR-01/02/03/06/07）必须至少拿到 `UI` 或 `DOM` 或 `HTTP` 一级证据；只有 `UT` 的条目不得计为达成。
**「零回退」是本版核心风险**：FR-06 的走查必须逐条对照合并前的动作清单，不能只测「新页面能打开」。

## 5. 不可用推断补齐的条目（执行纪律）

| 情形 | 处理 |
|---|---|
| 走查清单缺失 | FR-06 不算达成：必须先列出合并前两页的全部动作，再逐条勾 |
| 越界直访返回 200 但内容为空 | 视为**失败**（语义上等于泄露存在性）；期望 404/403 |
| 成员 DTO 与列配置映射写成通配 | 视为未达成：必须能注入假列名判红 |
| 端口无被引用样本 | 造一条链路引用；造不出则 TC-42 标「未执行」 |
| 矩阵行数与 PRD §3 不一致 | 阻断：文档与代码必须同版对齐 |
