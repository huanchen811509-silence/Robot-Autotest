## 1. 执行方式分类

| 代号 | 含义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `UT` | 后端/前端单测 | 逻辑分支正确 | 真实采集能通、界面能看见 |
| `MECH` | 机检脚本（带 `--self-test`） | 规则被守住且能判红 | 业务语义对不对 |
| `HTTP` | 真实服务请求 | 契约、错误码、权限边界 | 界面渲染 |
| `UI` | 真实浏览器（CDP/人工） | 用户能看见、能点 | 后端边界 |
| `DB` | 直连数据库读数 | 落库事实 | 链路是否被调用 |
| `COLLECT` | 真实采集（对 DUT） | 端到端真跑、验证事实真写 | 与 DUT 无关的回归 |
| `PERF` | 耗时测量 | 画像聚合不拖慢列表 | 功能正确性 |
| `REPLAY` | 在 v5.12 收口 commit 上回放 | 断点确实存在且判据能抓到 | 修复是否完整 |

**放行口径**：P0 条目（FR-01/02/03/04/05/06/10）必须至少拿到 `HTTP` 或 `DB` 或 `COLLECT` 一级证据；只有 `UT` 的条目不得计为达成。
**两条防线必须真实跑**：
- TC-16（已绑 A 用 B 采集，绑定仍为 A）—— 用真实请求 + DB 前后比对，**不接受单测**；
- TC-13（两者都未绑 → 400 点名）—— 真实请求日志。
**采集类前置**：DUT 可达、`confirmReal=true`、ADR-0013 安全级已判定；安全闸不回退由 TC-17 验证。

## 5. 不可用推断补齐的条目（执行纪律）

| 情形 | 处理 |
|---|---|
| 无真实 DUT 窗口 | 采集类 TC 标「未执行（待 DUT 窗口）」，**不许**用 fake 结果替代；`DB` 类前置可先跑 |
| 错误密码样本无法构造 | 必须构造（改一条凭证的密码即可）；否则 TC-07/TC-18 未执行 |
| 「不覆盖非空」用单测代替 | **不接受**：TC-17 必须真实请求 + DB 前后比对 |
| 500 台设备样本不足 | 用脚本造到 500 台（标注压测项目前缀），并记录机器信息 |
| 越权凭证样本不存在 | 必须造第二个项目的凭证；造不出则 TC-22/TC-44 未执行 |
