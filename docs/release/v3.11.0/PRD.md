# v3.11.0 产品需求文档（RA-PRD-311）

> 上游：`docs/plan/v3.9+版本演进-产品PRD-20261109.md`（§6.3、§7.11~7.13）。
> 本文件是**发布口径**：只收 v3.11.0 的 3 条需求，判据与证据形态一一对应。
> 版本线：v3.9.0 → v3.10.0 → **v3.11.0**；v3.12.0 为候选，需单独授权。

## 2. 关键设计决策

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-311-01 | 10 类采集命令集中在 `HostInventoryCollector.COMMANDS`，是唯一事实来源 | 采集执行它、机检比它、证据逐项记它；写两份必然漂移，而「报告里的命令」与「真跑的命令」不一致等于证据失效 |
| ADR-311-02 | 清单整体存 `spec_json`，不拆 10 张子表 | 一次采集 = 一个时点的整体事实，拆表会让「CPU 是 10:00、磁盘是昨天」成为可表达状态 |
| ADR-311-03 | 摘要列（网口数 / RoCE 口数 / 最高速率）写入时算好，但详情以 JSON 为准 | 列表页不必解析几十 KB；摘要只是索引，不能变成第二套事实 |
| ADR-311-04 | 未采到 = `value=null` + 非空 `reason`，禁止 `-`/`未知`/`0` 占位 | 占位值最坏之处不是难看，是事后无法与真值区分 |
| ADR-311-05 | 采集只由显式 POST 触发，无定时任务 / 启动预热 / 进页面自动采 | 「用户以为只读了一页」不能变成「机器上跑了一串命令」 |
| ADR-311-06 | 只读页的判据放在**运行时网络请求**，不只看源码 | 写动作搬到 API 层之后，页面源码干净也可能发出写请求 |
| ADR-311-07 | 8 页统一 `*-empty` / `*-failed` 双态 + 重试 | 读不到数据时白屏不算「空态明确」 |
| ADR-311-08 | 补 `GET /snapshots/profiles`（环境名清单），不复用带 `name` 的根 GET | 靠「有没有传 name」切换语义会让忘传参变成一个静默的不同接口 |
| ADR-311-09 | V11_27 把 `env_profile` 的 `(project_id, name)` 唯一键换成普通联合索引 | 实测同名第二份快照 500；不换掉，「两快照对比」在数据层就不可能成立 |
| ADR-311-10 | 恢复记录只映射审计的 4 个字段，不取 `detail` | `detail` 可能含 token 与命令痕迹（v2.2 安全口径） |
| ADR-311-11 | 只读找回用既有 `GET /search?types=run`，不新增执行入口 | 检索既有 run 就够了；任何 create/quick-run/rerun 都会违反「不产生新 run」 |
| ADR-311-12 | 恢复类数据当前 0 条如实显示 0 条，不造行 | 「来自真实数据」不等于「必须有行」；造行反而污染审计真值 |

## 3. 验收口径

1. 判据必须能被**命令**判定；「看起来接上了」不算。
2. 「接真实接口」= 探针里该页的期望 GET 路径全部命中，不是「有任意 /api/ 请求」。
3. 「只读」= 浏览器录下该页加载期与交互期的请求方法，写方法数必须为 0。
4. 迁移必须同时交 down 脚本，并在集成库跑一次真实 down→up。
5. 取证缺口写在 `docs/evidence/v3.11.0/README.md`，不留在「应该没问题」。
