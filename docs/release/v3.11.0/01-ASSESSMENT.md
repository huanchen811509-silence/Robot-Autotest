## 3. 方案比较（只读口径怎么判）

| 方案 | 做法 | 结论 |
|---|---|---|
| 源码静态扫描「没有 method: POST」 | 旧 spec 的做法 | 不足：接了真实接口后写动作搬到 API 层，页面源码干净也可能在运行时发写 |
| 真浏览器录 `Network.requestWillBeSent`，逐页断言 0 个写方法 | 新增 `env-pages-probe.mjs` | **采用**：判据④「只读页仍不发写请求」只有运行时能证 |
| 两者都要 | 源码级钉「写函数不出现在只读页」+ 运行时钉「0 写」 | **采用**：互为补充，前者防接线错、后者防副作用 |

## 4. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | `env_profile` 唯一键让同名第二份快照 500 | 判据②不可能过 | 迁移 V11_27 换普通联合索引 + down 脚本 + 真实 down→up 演练（实测 PASS） |
| 2 | 页面「打开即采集」 | 用户以为只读，机器上跑了 10 条命令 | 采集/建快照都要**两次点击**；探针断言「点一次 0 写请求」 |
| 3 | `GET /search` 有缓存，同参复搜不发请求 | 探针误判「只读找回没查」 | 检索前改关键字；判据改为「只发 GET /search 且 0 写」 |
| 4 | 读不到数据时页面白屏 | 空态判据不过 | 8 页统一 `*-empty` / `*-failed` 双态 + 重试按钮；探针逐个核对必现控件 |
| 5 | 恢复记录展示审计 `detail` 泄漏命令/令牌 | 违反 v2.2 安全口径 | 视图模型只搬时间/对象/动作/操作人四字段，spec 禁 `.detail` 属性访问 |
| 6 | 文档工作区与 WSL 权威副本漂移 | 改了代码但 jar 里是旧类 | 每次改动显式 `cp` 到 WSL 再重建；本次两处修复首跑未生效即因漏同步，已修正 |
| 7 | 新增迁移忘写 down | `DownScriptGuardTest` 判红 | V11_26/V11_27 均同批交付 down，并各跑一次真实演练 |

## 5. 结论与不做的事

**做**：FR-v3.11-01（已完成）、FR-v3.11-02（5 页）、FR-v3.11-03（3 页）、V11_27、`GET /snapshots/profiles`、`env-pages-probe.mjs`、门禁第 29 步。

**不做**：

| 项 | 为什么不做 |
|---|---|
| 远程主机采集 | 本版只支持本机 `localhost/127.0.0.1/::1/主机名`，远程返回带原因的「未采集到」，不伪造本机数据（记 L-311-01） |
| 拓扑节点 `topology_node` 独立 CRUD | 判据要的是「快照创建/对比」；快照 JSON 已含真实设备与链路，另建一套会与 `env_profile` 重复 |
| 恢复记录专用表 / 重试编排 | 判据要「来自真实数据」；已有审计日志与 `run.retry_of_run_id`，重做编排不属于本版 |
| 自动定时采集、后台预热 | 与「显式触发」判据直接冲突 |
| 8 页的可视化拓扑画布 | 判据未涉及；画布是独立工作量，排 v3.12 候选 |
