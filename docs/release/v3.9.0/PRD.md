## 2. 关键设计决策

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-39-01 | 不引入自定义下拉组件，用原生 `select` + 主题令牌 | 可读性靠令牌即可解决；换组件引入焦点/键盘/SSR 三类风险 |
| ADR-39-02 | 命令三列直接放 `test_result`，不做独立表 | 一条用例一条命令（首条），独立表换不来收益；未来多命令再拆 |
| ADR-39-03 | `NONE` 与 `NULL` 语义分离 | 「本来没有」和「还没采集」是两种结论，混用会得出错误的覆盖率 |
| ADR-39-04 | RF 侧用关键字白名单 + 子树前序遍历，不做全文正则盲扫 | 盲扫会把断言消息里的字串误判成命令，报告变成假证据 |
| ADR-39-05 | 页大小固定四档 + localStorage 记忆，不做自由输入 | 自由输入会造出语义模糊的页，且后端分页无收益 |
| ADR-39-06 | pytest 日志摊平为 `case-log.jsonl`（JSONL 而非分隔符文本） | 日志正文含任意字符，自定义分隔符必然撞车 |
| ADR-39-07 | 预置模板强制保留 6 个必填项 | 预置是「省事」不是「绕过门禁」 |
| ADR-39-08 | 探针产物入库（`docs/evidence/v3.9.0/`），门禁只读产物 | 取证与判据分开：「数据怎么来」与「算不算达标」互不掩盖 |

## 3. 验收口径

1. 每条判据都必须能被**命令**判定，不接受「看起来更好」。
2. 涉及真实链路的判据（FR-v3.9-02/03）必须用**平台执行链跑出来的 run**，不接受手工造数。
3. 探针类判据必须带**负向自证**（注入反例必须判红），否则「一直绿」无法证明判据有效。
4. 导出件（PDF/Word）与报告页同源：报告页有的字段，导出件必须也有。
