# v3.9.0 需求调研（RA-RES-39）

> 需求来源：`docs/plan/v3.9+版本演进-产品PRD-20261109.md` 第 4 章「现状问题清单」Q1-1 ~ Q3-2。
> 本文只做**事实核对**：每条标 `[已核实]` / `[推断]` / `[假设]`，不把推断写成结论。

## 1. 调研方法

| 手段 | 覆盖对象 | 说明 |
|---|---|---|
| 源码检索 | 前端表单控件、报告树、模板页、计划页 | 只看实际渲染路径，不看设计稿 |

## 2. 事实清单

### Q1 暗色下拉不可读

- `[已核实]` 探针在暗色主题下扫描 27 个 `<select>`，修复前 `flagged>0`：控件底色为
  `transparent`，实际显示的是父容器色，展开后的 `option` 由浏览器默认白底渲染，深色文字落在
  白底上时对比度不足。
- `[已核实]` `option` 从未在 CSS 中声明过前景/背景，属「完全依赖浏览器默认」。
- `[推断]` 用户主观感受「看不清」主要集中在暗色主题下的报告模板页与设置页（控件密集）。

### Q2 报告可追溯性缺口

- `[已核实]` `test_result` 表此前没有任何命令字段；报告页只有日志抽屉。
- `[已核实]` RF `output.xml` 中的命令原文位于**白名单关键字子树**内的 `Log` 消息里，
  不在用例或套件节点的属性上。
- `[已核实]` pytest `json-report` 的 stdout 落在 `setup/call/teardown` 三个 stage 对象内，
  用例顶层没有输出字段。
- `[已核实]` pytest run 的日志抽屉恒为空：`test_result.log_offset = -1`、`log_span = NULL`，
  而日志服务只认 `output.xml` 的偏移切片。
- `[已核实]` pytest run 的 `run_artifact` 中存在一条 `kind=output_xml` 记录，其 path 实际指向
  `pytest-report.json`（v2.7 遗留）。
- `[假设]` 现场对「这条用例到底发了什么命令」的追溯需求，主要发生在失败用例评审时。

### Q3 布局与信息架构

- `[已核实]` 列表页页大小硬编码 10，表格 `max-height: calc(100vh - 340px)`；
  1440×900 下 `/cases` 分页条下方空白 337px、`/runs` 231px。
- `[已核实]` 计划页首屏可交互按钮 22 个（修复前后均为 22，属另一工作包 EW310-01 范围）。
- `[已核实]` 报告模板页 21 个字段平铺，无分类；页面总高 1.8 屏。
  **修正**：早先「1.8 屏」的测量对象是 `documentElement.scrollHeight`，而应用是内滚容器
  （`.app-main`），该值恒等于视口高度。按 `.app-main.scrollHeight` 实测为 **2.4 屏**。
- `[已核实]` 页面根容器不是 flex，`.page` 的下级即使写 `min-height: 100%` 也无法撑满，
  这是「放开条数也填不满」的根因。

## 3. 结论

7 条需求的现状问题**全部复现**，且其中 2 条（pytest 日志抽屉为空、measuring 对象错误）
在计划阶段未被识别，属本次调研新增事实，已回写计划文档。
