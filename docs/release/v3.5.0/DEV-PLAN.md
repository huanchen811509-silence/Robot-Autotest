## 2. 推进顺序与依赖

B0 → B1（度量与门禁汇总）→ B2（回归 / 无障碍 / CWV / 回写）→ B3/B4（精修与用户验收）→
B5/B6（稳态与容量 / DR）→ 文档回写。依赖不可倒置：**无基线不许优化，无精修结论不许定运维默认值**。

## 3. 降级预案

真人 / 真机 / 用户签字类判据缺资源时记 `BLOCKED`（写明阻塞原因与所需条件），
工具与机检部分记 `PARTIAL`；**`PARTIAL` 不得读作通过**，不得用机器指标替代人的效果证据。

## 4. 风险预判

见母文档 §8 与本报告 `01-ASSESSMENT.md` §5；重点是旧汇总被当现状、样本不足、语义漂移。

## 5. 开发约束

- 只在 WSL ext4 构建测试；改源码须重建 jar + `systemctl --user restart robot-autotest-backend`。
- 迁移只追加、带 down；负向验证「备份 → 注入 → 判据红 → 备份还原 → 复跑绿」四步缺一不算。
- 一个任务包一个 PR、一次最多并行两个包；状态四态，`已完成` 需可复现命令或证据路径。
