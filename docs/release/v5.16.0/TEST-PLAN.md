## 1. 执行方式分类

| 代号 | 含义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `UT` | 后端/前端单测 | 逻辑分支正确 | 真实执行能通、界面能看见 |
| `MECH` | 机检脚本（带 `--self-test`） | 护栏被守住且能判红 | 业务语义对不对 |
| `HTTP` | 真实服务请求 | 契约、错误码、护栏拒绝 | 界面渲染 |
| `UI` | 真实浏览器 | 用户能看见、能点 | 后端边界 |
| `DB` | 直连数据库读数 | 落库事实与行数不变 | 链路是否被调用 |
| `SH` | 真实脚本执行（`backup.sh` / `update-drill.sh` / `doctor.sh`） | 脚本能跑、输出结构正确 | 界面交互 |
| `FAULT` | 故障注入（停依赖 / 杀进程 / 造差异） | 降级行为与恢复 | 正常路径 |
| `PERF` | 耗时测量 | 不阻塞、页面不慢 | 功能正确性 |

**放行口径**：P0 条目（FR-01/02/03/04/07/09/10）必须至少拿到 `HTTP` 或 `SH` 或 `DB` 或 `UI` 一级证据；只有 `UT` 的条目不得计为达成。
**本版一票否决项**（违反即视为版本未完成）：
- TC-19（非 `_it` 库恢复被拒）；
- TC-44（无 `--apply` 写入行数 = 0）；
- TC-41（任务被杀后 `ABORTED` 而非永久 `RUNNING`）。
这三条都是「界面能碰生产数据」的边界，不接受降级。

## 5. 不可用推断补齐的条目（执行纪律）

| 情形 | 处理 |
|---|---|
| 非 `_it` 库的拒绝无法验证（库里没有其他库） | 必须先造一个 `robot_dev_test` 库用于拒绝验证；仍无法造则 TC-19 未执行且本版不放行 |
| 磁盘不足场景无法真实制造 | 用挂载小容量 tmpfs 或配额模拟；不得只改阈值冒充 |
| 长任务杀不掉（跑太快） | 用 `sleep` 注入的测试脚本；否则 TC-40/41 未执行 |
| 备份目录只有 1 份 | 先跑两次备份；仍只有 1 份则 TC-11 的「条目数」断言不可靠，须造样本 |
| 审计机检无法注入 | 视为机检不合格，需补注入点 |
