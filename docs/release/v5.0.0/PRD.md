## 0. 结论先行

1. **5.0.X 不新增功能面，只做「把已有能力用得顺、跑得稳、看得清、守得住」。** 4.12.0 已完成一轮新功能迭代（凭据与设备双向可用、三通道采集、失败四分类、我的账户），本版的收益必须来自存量路径的缺陷收敛与度量补证，而不是新模块。
2. **先证明，再优化。** 11-09 的 `3.5+` 评估已核实：任务成功率、SUS、50 查询集、axe、跨浏览器、CWV、diff 覆盖等**效果类度量在 `CHANGELOG` 与 `docs/evidence/v3.*` 均无证据**；本版 B0 必须先建立可复跑基线，任何「提升」都要有前后对照，禁止凭观感填 PASS。
3. **口径冲突是本版第一号真实缺陷，不是文档瑕疵。** 只读盘点发现同一指标在不同证据里值不同（i18n 键数 1544 与 2383、表数 98 与 71 与 76、CDP `:9222` 恢复与关闭）。判据若建立在这些数上，机检会「怎么改都不红」或「改对了也红」。B0 必须裁决单一真源。
4. **行业实践按可判定方式落地，不做名词堆砌。** 以 ISO/IEC 25010:2023（第二版，九特性）映射七维度质量属性；以 DORA 2025 的四关键指标做**自身基线趋势线**（2025 报告已取消 Elite/High/Medium/Low 分级）；以 WCAG 2.2 AA 与 Core Web Vitals p75 阈值做 UI/UX 硬判据。
5. **存量欠账只登记、排期、不擅自销账。** L-xx、6 个待现场包、门禁第 13 步、G 门状态单列第 5 章；现场与真机类仍受 ADR-0013 禁跑令约束，G 门判定与发版口径归大师。

### 6.2 设计原则

1. **不增加新的心智模型**：沿用项目 / 全局双模式、两级导航、DataTable、既有令牌与状态语义。
2. **先给可见反馈，再谈优化**：加载、空、错误、部分成功、降级五态必须有明确呈现。
3. **默认安全**：新增能力默认关闭；危险操作二次确认；不在证据里写凭据。
4. **可度量优先于可描述**：任何「更快 / 更顺 / 更好看」都要落到可复跑的指标。
5. **实验室与现场分离**：本机 CDP、离线契约、fake CLI 的结果不冒充真实用户与真实端点。
