## 1. 现象与根因

### 1.1 退出按钮「点了没反应」

| 事实 | 分级 | 来源 |
|---|---|---|
| 退出入口只有 `App.vue` 的 `logout()` 一处，内部调 `auth.logout()` | [已核实] | `frontend/src/App.vue` |
| `auth.logout()` 先 `await authApi.logout()`，成功后才 `clear()` 与 `router.replace('/login')` | [已核实] | `frontend/src/stores/auth.ts` |
| 因此后端慢、挂住或网络抖动时，本地 token 一直在、页面一直不跳，用户看到的就是「没反应」 | [已核实] | 代码路径 + 用「永不 resolve 的请求」复现 |
| v2.3 顶栏改 28px 栅格后 `flex-wrap: nowrap`，账户区在最右，视口不足时被推出可视区 | [已核实] | `frontend/src/styles/main.css` 改前版本 |
| 被推出的那段仍然「占位」，所以看起来按钮在、点下去命中不到 | [推断] | 布局机制推断；本机 CDP 不可用，未做真机点击取证 |

**结论**：这不是「按钮坏了」，是**两件独立的事叠在一起** —— 逻辑上先等网络、布局上被推出视口。
只修一件仍会被另一件掩盖，必须同时修。

### 1.2 菜单只剩图标没有文字

| 事实 | 分级 | 来源 |
|---|---|---|
| v2.3 把折叠按钮从顶栏移到侧栏头部，但没人负责旧键 `robot.layout.side.collapsed` | [已核实] | `useAiDrawer.ts` 历史版本无迁移逻辑 |
| 该键在老用户浏览器里仍是 `true`，于是启动即窄轨 | [已核实] | 手工置位复现 |
| `@media (max-width: 999px)` 只把轨道压到 56px，**没有隐藏文字**，文字被 `.app-side` 的 overflow 裁掉 | [已核实] | `main.css` 改前 `@media` 块 |
| 于是窄屏下侧栏是「56px 宽 + 文字仍在 DOM 里但看不见」，与设计意图（窄轨只留图标）不符 | [已核实] | 同上 |

**结论**：三重根因 —— 遗留状态无人认领、断点只改宽度不改内容、1000~1200px 这类常见笔电宽度正好落进坏区间。

### 1.3 一级菜单命名

| 文案集中在 `menu.cases` / `menu.assets` 两个 i18n 键，改键值即可，不动路由与能力键 | [已核实] | `frontend/src/locales/*.ts` |

### 1.4 版本号写死

| 事实 | 分级 | 来源 |
|---|---|---|
| 关于页版本来自构建期生成的 `app.version`，改一次版本要改 pom + 重新打包 | [已核实] | `gen_build_info.py` 原实现 |
| 无 `VERSION` 文件，版本号没有单一真源 | [已核实] | 仓库根 |
| 关于页打开一次就固定，构建后再换版本页面上看不到 | [已核实] | `AboutView.vue` 改前无刷新 |

### 1.5 各 AI 助手无法配置

| 事实 | 分级 | 来源 |
|---|---|---|
| 候选 7 条已进代码，但端点 / 模型 / 凭据只能改代码或改 systemd `Environment` | [已核实] | `AiProcessManager` 改前签名 |
| pi 在本机**必须**用 ARK coding 专用端点，且模型要写 provider 限定 | [已核实] | 2026-11-08 实测（`InvalidEndpointOrModel` / `ambiguous across providers`） |
| 凭据要求：密文入库、接口只回掩码、明文不落日志 | [已核实] | 大师测试项目硬约定 + 既有 `SecretCipher` |
