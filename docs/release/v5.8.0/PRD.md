# v5.8.0 产品需求文档（PRD）：遗留清算与「结论可见 · 选择可下发」收口

> 流程位置：③ PRD（`docs/process/版本开发流程.md` §2.3）。
> 上游：`00-RESEARCH.md`（17 条遗留逐条核实）、`01-ASSESSMENT.md`（三档评估 + 大师拍板 L 全档）。
> **每条需求必须可判定**：写不出判据的不算需求（本文件 §5 每条都带「验收判据 + 证据形态」）。
> 版本号 v5.8.0 为拟用号，本文件**不修改 `VERSION`**；落号以 G 门判定与大师授权为准。

---

## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 把 v5.7.0 遗留里**用户已经在用、但用不出效果**的断链修到可用，并把需要真机的四条能力做出可复跑的证据 |
| 性质 | **清算版**：不引入新业务概念，只补齐上一版承诺与实际之间的缝；唯一新增能力是「条件选择可下发」与「真实判据样本」 |
| 上游遗留 | `L-57-01`~`L-57-11`（11 条）+ `L-56-01`~`L-56-06`（6 条），共 17 条 |
| 目标产出 | 遗留从 17 条压到 ≤5 条；三类断链（结论 / 选择 / 判据）各闭环一条端到端证据 |
| 不追求 | 不新增菜单、不改导航结构、不改主题色板、不新增数据库表（性能数据集除外，见 §8） |

### 1.1 为什么这一版值得单独做

v5.7.0 交付后，用户能在界面上点到三样东西，但点下去都没有效果：

1. **报告页看不到结论** —— 结论只在导出件里；
2. **「全选所有命中」只是视觉状态** —— 下发时只带当前页的 ids，或者根本发不出去；
3. **判据入库没有真实样本** —— 只有单测证明，没跑过一次真的。

这三条的共同点是：**界面有、数据没有、链路断在中间**。本版就是把这三条接上，并且要求
每条都以「真实请求 / 真实执行 / 真实界面」为证，不接受「单测绿」替代。

## 2. 约束与术语

| 术语 | 含义 |
|---|---|
| 选择描述符（selection descriptor） | `{mode: ids｜filter, filters?, excludeIds?}`，表达「按条件全选」而不必逐条列举 id |
| 结论（conclusion） | 由判据汇总得出的整体判定，取值 `PASS / FAIL / UNDETERMINED`；与 `passCount/failCount` 无关 |
| 判据（criteria） | 用例里声明的通过条件；未声明时结论必须是 `UNDETERMINED`，不得默认 PASS |
| real / fake | pytest 执行模式。real 登录 DUT 真跑；fake 是 **Plan-only**（只渲染计划，不执行、无 junit） |
| 切批（batching） | 单次选择超过执行上限时，按批拆分下发；pytest 内核已有 `MAX_CASES_PER_BATCH = 100` |
| 证据包（evidence bundle） | 按 key + sha256 归档文件的目录，用于「事后证明某文件当时就是这样」 |

**硬约束**：

1. **不得为了通过而放宽判据**：本版所有 FR 的判据都是「现象消失」，不是「代码写了」。
2. **真机执行不可绕安全闸**：real 必须 `confirmReal=true` + ADR-0013 安全级可执行 + 绑定可映射，缺一即 400。
3. **不新增数据表**：性能数据集用独立库/独立 project 承载（§8），不改业务表结构。
4. **口径纠正要留痕**：`L-57-11` 与 `L-57-10` 的前版诊断有偏差，PRD 与测试报告都要写修订记录，不许悄悄改。

## 5. 需求详述

### FR-v5.8-01 报告详情返回并展示结论【P0】

**描述**：`GET /api/reports/{runId}` 的响应体必须包含整体结论；报告详情页必须有可见的结论区域。
结论取自入库时刻的快照值（`ReportRecord.effectiveConclusion()`），未声明判据时返回 `UNDETERMINED`。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | 响应体含 `criteriaConclusion` 字段，取值 ∈ `{PASS, FAIL, UNDETERMINED}` | 真实 `curl` 输出（`docs/evidence/v5.8.0/.../raw/`） |
| 2 | 报告详情页在「结论」区渲染该值；`UNDETERMINED` 时显示「未判定」并给出原因文案 | 浏览器截图 + DOM 断言 |
| 3 | 有一条 `failCount > 0` 但判据全部 PASS 的报告 → 页面结论显示 `PASS` 而非「失败」 | 真实数据 + 截图 |
| 4 | 反向判据：在上一版（`9fda073`）上跑同一测试 → 必须判红（无字段 / 无结论区） | 回放日志 |

**降级预案**：若历史快照没有 `criteriaConclusion`（旧数据），显示 `UNDETERMINED` + 「该报告入库时未记录判据」，
**不得**回退成按 `failCount` 推断。

### FR-v5.8-02 批量端点接受选择描述符【P0】

**描述**：批量端点（通用批量、用例批量）接受可选 `selection`：`{mode: ids｜filter, filters?, excludeIds?}`。
服务端先用既有 `SelectionResolver` 解析成 ids，再走原有逐条事务逻辑。`selection` 与 `ids` **互斥**，
同时出现返回 400 并点名冲突字段。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | `POST /api/projects/{id}/batch` 带 `selection.mode=filter` → 200，响应含 `resolvedCount` = 命中数 | 真实 HTTP 日志 |
| 2 | 只带 `ids` 的旧请求体行为不变（逐条结果、`undoToken` 语义不变） | 回归单测 + 真实请求 |
| 3 | `ids` 与 `selection` 同时给 → **400**，错误信息含两个字段名 | 真实 HTTP 日志（严格反序列化下应点名） |
| 4 | 条件命中数 > 10000 → 400，错误信息含实际上限 | 单测 + 真实请求 |
| 5 | 条件解析结果与请求时刻数据不一致时，响应回显 `resolvedCount`，前端据此提示「可能已变化，请刷新」 | 单测 + 界面文案断言 |

**降级预案**：若某实体暂不支持条件批量（解析器无该实体映射），返回 400「该实体暂不支持条件批量」，
**不得**静默退化成「删除当前页」。

### FR-v5.8-06 长列表 10000 行 fps 基线【P2】

**描述**：用可复现数据集（`tools/perf_dataset.py` 固定种子）造 10000 行，量测长列表滚动 fps，
写入 `docs/evidence/v5.8.0/perf/perf_longlist.json`，`status` 只能是 `PASS` 或 `FAIL`（不许 `未测量` 交差）。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | `sample_size ≥ 3` 轮，每轮 fps 与机器信息齐全 | json 文件 |
| 2 | `min_fps ≥ 50` 则 PASS，否则如实 FAIL 并登记遗留 | json + 机检输出 |
| 3 | 数据集 manifest（行数/sha256）随证据归档，可复现 | manifest 文件 |
| 4 | `perf_longlist.py --selfcheck` 仍能判红「0 轮冒充达标」 | 机检输出 |
| 5 | 造数据不影响既有项目统计（隔离方案见 §8） | 前后对比 DB 读数 |

**实测结论（2026-11-14，W58-09/10，大师拍板「双口径都测」）**：预算场景「10000 行同屏滚动」在产品里
**不可达**——每页硬顶 100 行（`PageQuery.MAX_SIZE = 100`，前端档位 10/20/50/100，全站无超过 100 的取数）。
硬报一个 `rows=10000` 的产品读数就是伪造，因此分两个口径，各自说清量的是什么：

| 口径 | 量的是什么 | rows | minFps（5 轮） | 是否决定 `status` |
|---|---|---|---|---|
| product | `PERF-LONGLIST` 10000 条数据集 + 每页 100 行的真页面 | 100 | 60.1 | 是 → **PASS** |
| harness | 一次性 HTML 渲染 10000 行（非产品页面） | 10000 | 20.4 | 否（补充基线） |

| 判据 | 状态 | 证据 |
|---|---|---|
| 1（`sample_size ≥ 3` 轮 + 机器信息） | 达成（5 轮 × 3 秒） | `docs/evidence/v5.8.0/perf/longlist-raw.json` |
| 2（`min_fps ≥ 50` 才 PASS） | 达成 PASS（60.1 ≥ 50） | `perf_longlist.json` + `check_perf_budget --require` |
| 3（数据集 manifest 随证据归档） | 达成 | `dataset-manifest.json`（`contentHash 59824208438adcd7…`，两次生成一致且与 v3.2.0 逐字节相同） |
| 4（`--selfcheck` 判红 0 轮冒充） | 达成（4 类反例全判红，并当场抓出「2 轮 60fps 也判 PASS」的漏洞已修） | `python3 tools/perf_longlist.py --selfcheck` |
| 5（不污染既有统计） | 达成（既有工程 13→13、既有用例 2491→2491） | `seed-report.json` 前后对比 |

口径偏差记 **D-58-08**；harness 10000 行只有 20.4~28.5fps 记 **D-58-09**，作为「将来取消分页/上虚拟滚动」
的前置输入登记遗留 **L-58-06**，本版不改产品。

### FR-v5.8-11 RF 判据载体确认与口径收口【P1】

**描述**：先用 10 份真实 robot `output.xml` 做 spike，确认是否存在可依赖的判据载体
（结构化字段 / tag / 文档字符串约定）。

**验收判据**

| # | 判据 | 证据形态 |
|---|---|---|
| 1 | spike 报告列出 10 份样本中「有载体 / 无载体」各多少，附片段 | `docs/evidence/v5.8.0/rf-criteria-spike/` |
| 2 | 有载体（≥3 份可稳定提取）→ 实现 RF 判据提取并补单测；无载体 → PRD 与界面同时标注「判据机检仅覆盖 pytest 内核」 | 代码或界面文案 |
| 3 | 无论哪条路径，界面必须让「该报告未参与判据机检」**可见** | 截图 |

**明确禁止**：不允许从用例名/文档字符串里**猜**判据并参与 PASS 判定（会把未声明用例误判为 PASS）。

**实测结论（2026-11-14，W58-11/12）**：10 份真实 `output.xml` 全部可解析，但**无框架级判据载体**。
`<doc>` 只在 2/10 出现且语义不一（一份是真判据「能读取 CX7 的 PCI Vendor/Device ID…」，
一份只是说明「最朴素的通过路径…」）；断言关键字出现在 3/10，参数多为 `1 / 1` 或未替换的
