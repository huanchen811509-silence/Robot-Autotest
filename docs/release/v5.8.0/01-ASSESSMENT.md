## 2. 评估口径

- **不看「遗留条数」，只看「用户能不能用上」**：一条遗留如果只是内部一致性（例如骨架统一），
  收益是长期维护成本，不应挤占同一版里用户可感知的断链修复。
- **反向判据优先**：每个方案必须能说清「修完之后，什么现象会消失」；说不清的，不做。
- **真机不做默认项**：B 类需要 G-1 授权窗口 + 安全闸双通过，且会产生真实 `test_result` 行，
  只有能明确提升「判据链可信度」时才值得动用（目前只有 `B1` 符合）。

## 3. 逐项方案

### 3.1 A1 报告结论贯通（对应 L-57-11）

| 项 | 内容 |
|---|---|
| 真实问题 | 后端 `ReportDetailView` 没有 `criteriaConclusion`，前端拿不到；领域对象里已经有 `effectiveConclusion()`（空值兜底 `UNDETERMINED`） |
| 做法 | ① `ReportController.ReportDetailView` 加 `criteriaConclusion` 字段，`from()` 用 `record.effectiveConclusion()`；② 前端 `ReportDetail` 加字段，详情页顶部加「结论」区（有判据显示判据结论，无判据显示「未判定」并给出原因）；③ 导出/快照链路不动（已经正确） |
| 改动面 | 后端 1 个 DTO + 1 个单测；前端 1 个类型 + 1 个视图 + 1 个 spec |
| 风险 | 低。唯一要定的是「历史快照与当前重算不一致时显示哪个」（研究 §5 U2）：建议显示**快照值**并在悬浮说明「结论来自入库时刻」 |
| 消失的现象 | 报告详情页再也不会出现「全部通过/失败」这种只由 `failCount` 推出来的结论，用户不必导出才看得到判据汇总 |
| 反向判据 | 在 `9fda073` 上回放：`GET /api/reports/{runId}` 响应体无该字段、页面无结论区 → 新单测必须判红 |

### 3.2 A2 条件全选可下发（对应 L-57-09、L-57-06）

| 项 | 内容 |
|---|---|
| 真实问题 | `useServerSelection.toDescriptor()` 是「只写不用」的代码；两个批量端点都只收 `List<Long> ids`，条件模式无处可发 |
| 做法 | ① `GenericBatchService.BatchRequest` 与 `TestCaseService.BatchRequest` 增可选 `selection`（`mode/filters/excludeIds`），服务层**先解析成 ids 再走原逻辑**（保证既有 `ids` 调用零影响）；② 解析复用 `SelectionResolver`（已有 ALL/SET/CASE/MIXED 与 10000 上限）；③ 前端把 `toDescriptor()` 接到用例集页与用例清单页的「全选所有命中」；④ 撤销语义定为「整批一次 undoToken，回滚按解析结果逐条」 |
| 改动面 | 后端 2 个 record + 2 个服务方法 + 1 个解析适配 + 单测（含「ids 与 selection 同时给 → 400」）；前端 2 页 + 1 个 composable 调用点 + spec |
| 风险 | 中。三条：① `selection` 与 `ids` 并存会造成歧义 → 必须 400 拒绝；② 条件解析在工作树里做过一次（`SelectionResolver`），批量路径再走一次可能命中不同集合（并发改数据）→ 在响应里回显 `resolvedCount`，与界面显示不一致时提示重试；③ 既有 `undoToken` 消费方只有前端一处，回归面可控 |
| 消失的现象 | 「勾了 500 条点批量删除，界面显示成功但只删了当前页」；条件全选不再只是视觉状态 |
| 反向判据 | 在 `9fda073` 上回放：批量请求体会被判「未知字段 `selection`」→ 400（这正是 56 步的严格反序列化带来的好处） |

### 3.3 A3 用例集服务端筛选（对应 L-57-06）

| 项 | 内容 |
|---|---|
| 真实问题 | `CaseSetsView` 用 `items.value.filter(...)` 在内存里筛，翻页后筛选结果与显示条数都不对 |
| 做法 | 筛选条件进 URL（与 `ListScaffold` 的 `useTableFilters` 同源），查询走服务端分页；条数取服务端 `total` |
| 改动面 | 前端 1 页 + spec；后端若已支持 `keyword/status` 参数则零改动（待 DEV 阶段确认），否则补 1 个查询参数 |
| 风险 | 低-中。主要风险是「筛选口径变化导致既有用例数量断言失败」，需同步更新 spec 的期望值 |
| 消失的现象 | 筛完只剩 3 条，但底部还写「共 200 条」；翻页后筛选条件丢失 |
| 反向判据 | 造 3 页数据，在第 2 页筛一个只命中第 1 页的关键字 → 修前返回空（内存过滤只看当前页），修后返回正确结果 |

### 3.4 A5 证据包补接报告导出与编辑器保存（对应 L-57-03）

| 项 | 内容 |
|---|---|
| 真实问题 | `EvidenceBundleService` 只有「用例导入」一处调用，导出件与编辑器保存件不在证据包里，出问题时无法按 hash 追证 |
| 做法 | ① `ReportExportService` 生成文件后 `write("report-export:" + runId, path)`；② 编辑器保存路径同样 `write("editor-save:" + docId, path)`；③ 复用已有 `write/read/verify`，不新增接口 |
| 改动面 | 后端 2 处调用 + 2 个单测（断言证据包内能按 key 读回且 hash 一致） |
| 风险 | 低。注意导出件可能很大，`write` 要沿用现有的流式/大小上限，不能整读进内存 |
| 消失的现象 | 「导出件被改过」无法证明；证据包只覆盖一条链路 |
| 反向判据 | 单测在 `9fda073` 上回放：`read("report-export:xxx")` 抛 not found → 判红 |

### 3.5 B1 判据真实入库样本（对应 L-57-10）

| 项 | 内容 |
|---|---|
| 真实问题 | 不是「入库逻辑漏了」——收尾确实调 `parseAndIngest` 且会写 `criteria_*`；缺的是**从没跑过一条 real**，所以这条链路只有单测证据 |
| 做法 | 用 gpu-node-01（`10.202.54.106`，22 可达）跑**1 条**带判据声明的用例：`confirmReal=true` + ADR-0013 安全闸 + 已绑定的 NIC 画像；跑完取 `test_result` 该行 `criteria_json/verdict`，再打开报告详情验证结论（与 A1 串成一条链） |
| 改动面 | 零代码（若发现字段缺失再补）；主要是执行与取证 |
| 风险 | 中。三条：① 会在报告列表留下一条真实记录（U5）→ 跑完按「测试数据」软删并留证据；② 真机状态不可控（需先确认 pytest 环境与用例库版本）；③ 若该用例判据声明缺失，样本就不成立 → 先挑一条确认有判据的用例 |
| 消失的现象 | 「判据入库」从「单测 + 代码走查」变成「有真实行、有报告页可看」 |
| 反向判据 | 修前取证：`SELECT count(*) FROM test_result WHERE criteria_json IS NOT NULL` = 0；跑完 = 1 |

### 3.6 A4 列表骨架补接（建议缓做）

| 项 | 内容 |
|---|---|
| 真实问题 | `ListScaffold` 只接了 `TestReportsView` 一页，台账 42 行里还有多页是手写表格 |
| 为什么缓做 | 这条**没有用户可见的断链**：功能都在，只是实现不统一。补接要动 4 个页面 + 5 个 spec，回归面覆盖前端 1015 例的大头，收益是维护成本 |
| 若做 | 按台账 C 类逐条决定：能接的接，不能接的**写明理由**（比强行统一更诚实） |
| 判据 | 台账 C 类条目数下降，或每条都有「不接的原因」 |

### 3.7 A6 10000 行 fps（建议缓做）

| 项 | 内容 |
|---|---|
| 真实问题 | `check_perf_budget.py` 要求 `long_list.fps ≥ 50`，但没有样本，门禁长期按「未测」处理 |
| 关键澄清 | 历史上的「零数据改动」是**数据库迁移约束**（零新增表/列），不是「不许造测试数据」；但 `perf_longlist.py` 把它理解成了后者，导致这条一直没做。要做得先回答「数据放哪」 |
| 做法（若做） | 用 `tools/perf_dataset.py`（固定种子、可复现）生成 CSV → 导入**独立压测库或独立 project**（不碰 `robot_dev` 的既有项目）→ 用 CDP 量滚动 fps → 写 `perf_longlist.json` |
| 风险 | 中-高。造数会污染统计口径（首页项目数、用例数），需明确隔离方案；fps 受本机性能影响，需记录机器与轮次 |
| 判据 | `status=PASS/FAIL` 且 `sample_size ≥ 3 轮`，禁止 0 轮写达标（`perf_longlist.py --selfcheck` 已经会判这个） |

### 3.8 A7 RF 判据提取（建议不做）

| 项 | 内容 |
|---|---|
| 真实问题 | 判据提取只有 pytest 侧，RF 报告入库不产出判据行 |
| 为什么不做 | robot 的 `output.xml` 里**没有结构化的判据字段**，只能从 tag/文档字符串里猜。按猜测实现判据门禁，比「没有判据」更危险（会把没声明判据的用例误判成 PASS） |
| 替代 | 在 PRD 写明「判据门禁当前只覆盖 pytest 内核」，并在界面标注「本报告未参与判据机检」——**让缺失可见**，而不是用推断填补 |
| 若大师要求做 | 先做 0.5 天 spike：抽查 10 份真实 `output.xml`，确认是否有可依赖的判据载体，再决定 |

### 3.9 B2 / B3 / B4（建议不进本版）

| 编号 | 内容 | 不进本版的理由 |
|---|---|---|
| B2 | 201~10000 条切批下发 | A2 已让「条件」能下发，但真跑万级会长时间占用 DUT，价值要等选择模型稳定后再验 |
| B3 | 一次性凭证驱动真实采集 | 依赖 B1 的 real 通路，且价值集中在「凭证可用性」后续版本 |
| B4 | 命令重解析 / 复现率 / 批次取消 / FLAKY（L-56-01~04） | 都需要多轮真机批次与自然出现的抖动用例，不是「做」出来的，是「等」出来的 |

`L-57-07`（权限枚举语义等价）、`L-57-08`（预览不启动进程是设计）、`L-56-06`（入库同步调用已获认可）

## 4. 三档范围建议

| 档位 | 包含 | 用户可感知的改善 | 风险 | 建议 |
|---|---|---|---|---|
| **S 最小** | A1 + A5 + C 类文档 | 报告页能看到结论；导出件能追证 | 低 | 只解决最刺眼的一条 |
| **M 推荐** | S + A2 + A3 + B1 | 再加：条件全选真的能批量操作、用例集筛选不再骗人、判据链有真实样本 | 中 | **推荐**：三类断链（结论 / 选择 / 判据）各闭环一条 |
| **L 全量** | M + A4 + A6 + A7 + B2/B3/B4 | 再加：列表实现统一、有性能基线、RF 参与判据 | 高 | 不建议：A4/A6 无用户可见收益，A7 是伪需求风险，B 类要占真机窗口 |

**推荐 M 档的理由**：M 档的 5 条覆盖了 v5.7.0 遗留里**仅有的三类「用户已经在用、但用不出效果」的断链**；
其余条目要么是实现一致性（A4）、要么是缺样本（A6）、要么是载体不明（A7）、要么是「等数据」（B2-B4）。
M 档做完后，`L-57-01/03/06/09/10/11` 六条可以真正关掉，遗留从 11 条压到 5 条。

## 5. 依赖与顺序

```
A1（DTO+前端，独立）
 ├─→ B1（跑完 real 后要用 A1 的报告页验收结论）
A2（后端 selection + 前端接入，独立）
A3（前端筛选，独立但建议在 A2 之后：共用 useTableFilters 口径）
A5（后端 2 处接入，独立）
```

- 先做 A1 + A5（低风险、当天可见），再做 A2（唯一有接口变更，需更新契约快照），
  再做 A3，最后做 B1（需要真机窗口，单独排）。
- A2 会改 `openapi.json`（`438 endpoints` 的请求体形状变化），必须重生成契约快照并跑第 20 步。

## 7. 前置条件（开工前必须成立）

> 这一版没有新增依赖、没有新库表，但有四件事如果**不先成立**，做出来的东西无法验证——
> 属于「不是代码问题、但会让验收落空」的前置项。

| # | 前置条件 | 为什么是前置 | 现状（2026-11-14） |
|---|---|---|---|
| P1 | WSL `~/robot-autotest` 与 `origin/main` 同源，工作树干净 | 本版改动横跨后端/前端/工具三条线，基线不干净时「红是新的还是老的」无法判定 | 成立：`f16825e` / `c1108e1` 均已提交，四处 sha 一致 |

| P3 | 真机窗口可用（gpu-node-01 可达 + ADR-0013 安全闸 + `confirmReal`） | B1/B2/B3/B4 与 W58-13 全靠它；无窗口时这些项只能登记未达成 | 部分成立：`10.202.54.106/107:22` 可达（`/dev/tcp` 探测），执行授权按场景给（G-1） |

P3 不成立则 B 类四项整条降级，不得用「以前跑过」代替；P4 不成立则 A6 不得开跑，

| # | 问题 | 决策 | 影响 |

| D1 | 范围档位 | **L 全量档** | 含 A1~A7 与 B1~B4；本文件 §4 的「缓做/不做」建议被覆盖，A4/A6/A7/B2/B3/B4 全部纳入 |
