## 1. 测试策略

| 层级 | 手段 | 判据 | 覆盖对象 |
|---|---|---|---|
| L1 单元 | JUnit 5 / Vitest | 全绿，新增用例数达标 | 服务、聚合、digest、判据解析、组件逻辑 |
| L2 契约 | 端点冒烟 + OpenAPI 一致性 | 端点存在、字段名与类型一致 | 26 个契约变更（PRD §15） |
| L3 集成 | `robot_it` 库 + 真实端点串联 | 一条链路走通并留证据 | 播种 → 建集 → 向导带入 → 执行 → 判据 |
| L4 界面 | 浏览器实操 + 截图 | 每个入口可点、空态自解释、权限正确 | 台账内 ≥ 24 个列表页，两档宽度 × 两主题 |
| L5 回归 | 全量单测 + 门禁 | `GATES_RESULT FAILS=0 UNJUDGED=0` | 既有能力不退化 |
| L6 安全 | 越权与注入 | 越权 403、SQL 无拼接 | 平台集写、服务端全选、`ALL` 模式跨项目、一次性凭证零泄漏 |

**第二轮新增三条不接受**：① 用「页面能打开」当 CRUD 通过（必须真实改一次、删一次并查库）；
② 用「本机采集成功」当凭证验证通过（本机不需要凭证，必须远程通道）；
③ 用「组件单测绿」当布局合格（必须有 1440/1280 两档的 DOM 断言与截图）。

**不接受的证据**：「单测绿」「构建绿」不算功能通过（既有硬规矩 4）。功能类 TC 必须有界面或接口的**真实链路证据**。

## 2. 环境与数据准备

| 项 | 要求 |
|---|---|
| 代码位置 | WSL `~/robot-autotest`（ext4）。**禁止**在 `/mnt/*` 跑测试（慢 35 倍） |
| 数据库 | `robot_it`（集成库，库名以 `_it` 结尾由守卫强制） |
| 凭据加载 | `set -a; . ~/.config/robot-autotest/env; set +a` |
| 就绪探针 | 打 `:8081`；`/api/_ping` 200 **不算**健康（构建后必须重启后端） |
| 分类数据 | 至少 3 个一级分类 + 每个下 1–2 个二级分类；其中一个一级分类下 0 条用例；一个分类 `status='disabled'` |
| 用例数据 | 至少 120 条 active 用例分布在 3 个一级分类；含 5 条未分类；含 1 条含空格路径的脚本（验证 argv 转义） |
| 平台集数据 | 至少 1 个只读期遗留平台集（`sample_flag=0`） |
| 权限账号 | 4 个：admin（`case:write`+`project:create`）、pm（同 admin 但非系统管理员）、engineer（`case:write` 无 `project:create`）、viewer（仅 `asset:read`） |
| 浏览器 | 1440×900 **与 1280×800 两档**；浅色与深色主题各跑一遍台账内列表页 |
| 执行选择数据 | 两个项目各 ≥ 30 条用例（验证 `ALL` 不跨项目）；≥ 120 个用例集（验证去掉 100 上限）；10 万用例压测数据集（W7 专用，单独库） |
| 列表 CRUD 数据 | 执行报告 / 用户报告 / 运行记录各 ≥ 10 条，含 1 条已冻结、1 条已归档、1 条带导出历史 |
| 凭证数据 | ≥ 4 条凭证：本设备验证成功、同型号验证成功、验证失败、从未验证；1 台可连通设备（或 mock SSH 通道，须写明未接真机） |

## 3. 证据形态约定

| 代号 | 含义 | 具体要求 |
|---|---|---|
| `UT:` | 单元测试 | 写「类名#方法名」，并要求该测试在改动前后都能跑 |
| `API:` | 接口证据 | 完整 curl + 关键响应字段（不贴整包） |
| `DB:` | 数据库证据 | 查询语句 + 结果行数/关键列值 |
| `UI:` | 界面证据 | 截图存 `docs/evidence/v5.7.0/`，文件名含 TC 号 |
| `LOG:` | 日志/审计 | `audit_log` 或后端日志行 |
| `GATE:` | 门禁 | 尾部 `GATES_RESULT FAILS=N UNJUDGED=M` |
| `PROBE:` | 安全探针 | `tools/probe_oneshot_secret.py` 六处扫描输出，须逐处 PASS |
| `MATRIX:` | 覆盖度台账 | `docs/evidence/v5.7.0/list-crud-matrix.md` 对应页行 + `check_list_crud.py` 输出 |
| `VIS:` | 视觉基线 | `docs/evidence/v5.7.0/ui/<页>-<宽度>-<主题>.png` + DOM 溢出断言结果 |

## 8. 缺陷分级与放行条件

| 级别 | 定义 | 放行影响 |
|---|---|---|
| P0 | 数据错误、越权、审计缺失、摘要承诺可绕过 | **阻断**，必须修复 |
| P1 | 主流程不可用（建集失败、向导建不出项目、判据不显示） | **阻断** |
| P2 | 边界场景错误（分页、空态、并发提示） | 可带病放行，须登记 L-57-xx |
| P3 | 文案、样式、i18n 缺键 | 可带病放行，须登记 |

**放行条件（全部满足）**：

1. P0/P1 缺陷为 0。
2. 30 条 FR 在 `05-TEST-REPORT.md` 有逐条结论（达成 / 降级 / 未达成）。
3. 降级项必须写明「降级理由 + 授权人」。
4. `GATES_RESULT FAILS=0 UNJUDGED=0`。
5. 七个迁移（拟定 `V11_58` ~ `V11_64`）在空库可重放。
6. 遗留 `L-57-xx` 全部登记且有归属。
7. 五份文档已回写（流程第 7 道）+ `list-crud-matrix.md` 实测结论 + UI 基线归档。
8. `PROBE:` 一次性凭证六处零泄漏 6/6 PASS；`check_list_crud.py` 白名单外 0 缺口。
9. 两档宽度 × 两主题视觉断言全绿；差异基线经人工确认。
10. `ALL` 模式跨项目对照用例（TC-v5.7-131）通过，无越权命中。

**明确不接受**：「单测绿」当功能通过；「未测项」写达成；用「全部标记 PASS」凑判据覆盖率；
「页面能打开」当 CRUD 通过；「本机采集成功」当凭证验证通过；无真机样本时写「真机验证达成」。
