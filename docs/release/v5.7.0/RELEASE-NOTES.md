# v5.7.0 发布说明（RA-RN-570）

**版本** `5.7.0` ｜ **日期** 2026-11-14 ｜ **构建** `<commit>`（与打包时的 HEAD 同源，真值见包内 `MANIFEST.json` 的 `commit` 字段） ｜ **发布类型** 内部发布（大师授权发版，**不是** GA）

> 本说明面向**部署方与使用方**，只讲「拿到什么、怎么升、有什么限制」。
> 需求与验收细节见同目录 [PRD.md](./PRD.md)、[DEV-PLAN.md](./DEV-PLAN.md)、[TEST-PLAN.md](./TEST-PLAN.md)、[05-TEST-REPORT.md](./05-TEST-REPORT.md)。
> **发版不等于判定**：G 门仍未判定，界面与文档不得称 GA；对外的验收口径归大师，本说明只报实装、机检、部署三项结论。

## 1. 一句话概览

公共用例从「一张平铺的表」变成**可归组、可成套、可勾选**的资产；新建项目从「填一堆表单」变成**向导四类来源任选**；
手工发起执行从「一把梭全跑」变成**全部 / 按用例集 / 按用例 / 组合**四模式且选择被冻结成不可变快照；
执行与报告从「看得到结果」变成**先说清要跑什么、再给得出证据**（命令摘要 + 内容寻址证据包 + 判据与结论分离）；
同时全站 37 个列表补齐增删改查骨架，设备凭证支持「带验证态自动关联 + 手工输入」。

## 2. 本次交付内容

### 2.1 全局用例资产化（FR-v5.7-01 ~ 06）

| 能力 | 用户可见变化 |
|---|---|
| 全局「用例集」二级菜单 | 全局侧栏新增 `/g/case-sets`，与「用例」并列；项目侧原入口不变，两叶不会同时点亮 |
| 公共用例按一二级分类归组 | 左侧分类树显示每级真实条数，点一级节点即按 `categoryL1` 过滤；分组接口返回 `l1Id/l1Name/l2s[].count` 真树 |
| 平台用例集开放写操作 | 建 / 改名 / 删除 / 成员增删 / 排序 / 按分类批量加入；写权限由 `isAdmin` 放宽到 `case:read` + `CASE:UPDATE`，VIEWER 仍 403 |
| 样例集自动播种 | 首次按一级分类生成样例集（`SAMPLE-<n>`）；手动重建时若某集被用户改过（`user_modified`）则跳过，不覆盖人工成果 |
| 名称长度前置校验 | 超过 DDL 宽度（名称 128 / 描述 512 / 编号 64）在入口返回 **400 并点名字段与上限**；此前会冒到全局异常处理变成 500 |

### 2.2 向导式建项目（FR-v5.7-07 ~ 12）

- 四类来源：**模板 / 用例集 / 用例 / 测试资产**，每类可全选、可部分、可整步跳过；
- 用例用**三态分类树**勾选（全选 / 半选 / 未选），右侧常显已选摘要与去重后的条数，提交保序去重；
- 全局入口走独立路径 `/g/projects/new`，与项目内入口互不复用高亮。

### 2.3 手工发起执行的四种选择模式（FR-v5.7-13 ~ 19）

| 模式 | 行为 |
|---|---|
| 全部 | 按项目用例总数（`cases/count`）一次带出，确认前可看到「将执行 N 条」 |
| 按用例集 | 勾选若干用例集，展开为其成员并集 |
| 按用例 | 逐条勾选（跨页选择状态已具备：可跨页计数、二次确认、排除集；**条件全选的下发未接入**，见 L-57-09） |
| 组合 | 集 + 单条混合；**取消某集时只移除该集带来的来源**，手工单独勾选的用例保留（本版修掉的真实缺陷，`TC-v5.7-136` 硬对照） |

选择在 `POST /runs/preview` 时冻结为不可变快照（`execution_selection_snapshot`），确认只吃 `snapshotId`；
派发前重算 `selectionSha256`，不一致返回 **409 且不启动进程**。

### 2.4 执行可信度（FR-v5.7-20 ~ 25）

- **命令清单只读预览**：`preview-commands` 返回 `kernel` / `requested` / `executable` / `skipReasons`，让「要跑什么」先于「跑」可见；
- **命令摘要承诺**：`sha256("v5.7-run-confirm:" + 规范化命令)`，确认时比对，改动命令即失效；
- **判据与结论分离**：`status` 是事实（用例执行状态），`conclusion` 是判据结论；**未声明判据不默认 PASS**；
- **内容寻址证据包**：同挂载点临时目录写全 → `ATOMIC_MOVE` → 指针原子替换 → 读时重算 `sha256`，半成品不可见。

### 2.5 列表能力（部分落地，FR-v5.7-26 ~ 30）

> **口径订正（2026-11-14，依 `06-ACCEPTANCE-AUDIT.md` §四 P2）**：本节原写「全站列表能力 / 服务端跨页全选」，与代码实际不符——`ListScaffold` 只有 `/test-reports` 一页接入（`grep -rl ListScaffold frontend/src` 仅 1 处生产命中），`useServerSelection.toDescriptor()` 无生产调用方、后端批量端点只收显式 `ids`。
> 已按实际改写为「部分落地」，未接入项逐条登记 L-57-05 / L-57-09；**不得把它读成「全站列表已统一」**。

- 列头筛选 **URL 化**（可收藏、可回退）、跨页选择状态（计数 / 二次确认 / 排除集；条件全选下发未接入，L-57-09）、六槽位 `ListScaffold`（当前 `/test-reports` 一页接入，其余见台账缺口白名单）、统一危险操作确认文案；
- 执行报告 / 运行记录 / 用户报告支持**编辑与软删**（`deleted_at` / `deleted_by`，删除幂等，恢复置回 `NULL`）；
- **42 页**覆盖度台账由 `tools/check_list_crud.py` 守门（`PASS=114 FAIL=0`，`--self-test` 双向通过），未接入的 7 条逐条登记理由（L-57-05）。台账已订正 3 条事实错误：`/g/assets` 无 `PUT`（不是「C/R/U/D 全」）、`/plans/groups` 与 `/scenarios` 实有写操作（由 C 类改为 A 类）。

### 2.6 设备凭证（FR-v5.7-28 配套）

- 候选按「验证态」四级排序：已验证可用 > 已验证失败 > 未验证 > 其他；
- 连通性验证**只探测不采集**（不落任何设备数据）；
- 手工输入凭证走**独立通道**：只经 POST body 进内存材料，**不落库**，由六处零泄漏探针守门（DB / 日志 / 审计 / 响应 / 证据包 / 异常堆栈，`6/6 PASS`）。

## 3. 升级须知

1. **数据库**：新增迁移 `V11_58` ~ `V11_64` 共 7 支，业务表 98 → **108**；全部为**加表 / 加可空列或带 DEFAULT 列**，历史行无需回填，已应用迁移未改动。各自配 `db/down/V11_*.down.sql`，`DownScriptGuardTest` 配对断言通过。
2. **升级步骤**（安装根下，与 `docs/ROLLBACK.md` 同源）：
   - 备份：`bin/backup.sh --apply`；
   - 演练：`bin/update.sh --package /path/to/robot-autotest-5.7.0`（默认 dry-run，只列迁移清单）；
   - 执行：`bin/update.sh --package /path/to/robot-autotest-5.7.0 --apply`，按提示输入 `UPDATE`；
   - 复核：`bin/status.sh` 看当前版本、上一可用版本与服务状态。
3. **源码部署**（非交付包）：`bash scripts/deploy.sh` 一条命令完成「生成 build-info → 同步 CHANGELOG 到 `frontend/public/` → 构建 → 停旧进程 → 起新进程 → 健康检查 → 四项自校验」。**只重建不重启会被自校验判红**（判据 2/4）。
4. **前端静态副本**：根 `CHANGELOG.md` 必须与 `frontend/public/CHANGELOG.md` 一致，否则版本迭代页与关于页「最近更新」会停在旧版；由 `tools/check_version_consistency.py` 第 3、6 项守门。
5. **权限**：平台用例集写权限语义为 `case:read` + `CASE:UPDATE`（枚举无 `WRITE` 值）；`VIEWER` 仍 403，非管理员可写是**本版授权变更**（D-57-04），升级后请复核角色配置。
6. **门禁**：`bash scripts/gates.sh` 56 步；`--self-test` 三步会真注入故障再还原，需在登录 shell（`bash -lc`）下跑。

## 6. 已知限制（升级前必读）

| 编号 | 限制 | 影响 | 规避 |
|---|---|---|---|
| L-57-01 | `ALL` 模式命中 201~10000 条时，`confirm-and-start` 未接既有批量派发（`MAX_CASES=200`） | 超大选择实际发不起 | 分次按用例集发起；**不得宣称「四模式全部可真实发起」** |
| L-57-02 | 判据采集只做 pytest 侧统一 JSON 提取，RF 侧未覆盖 | 判据覆盖率偏低 | pytest 项目优先；RF 判据另版 |
| L-57-03 | 证据包只接了「用例导入」，报告导出与编辑器保存仍走旧路径 | 两处证据未内容寻址 | 服务 `write/read/verify` 已公开，可直接补接 |
| L-57-04 | 一次性凭证只做到「受理 + 内存材料 + 六处零泄漏」，未触发真实远程采集 | 手工输入尚不能真实采设备 | 需真机验证后再对外承诺 |
| L-57-05 | `ReportsView` / `GlobalTemplatesView` / `GlobalAssetsView` 未接 `ListScaffold` 行内 CRUD | 三页交互与其余 34 页不完全一致 | 台账白名单登记理由 |
| L-57-06 | `CaseSetsView` 筛选仍是前端内存过滤 | 跨页全选条数以本地集合数为准 | 大集合场景下先缩小筛选范围 |
| L-57-09 | 条件全选只停在客户端状态：`toDescriptor()` 无生产调用方，后端批量端点只收显式 `ids` | 跨页「全选所有命中」不能直接下发 | 先缩小筛选范围再逐页勾选；接后端批量条件入参排 v5.8.0 |
| L-57-07 | 平台集写权限落在 `PermissionAction.UPDATE`（枚举无 `WRITE`） | 语义等价，VIEWER 仍 403 | 已在 `01-ASSESSMENT.md` 说明 |
| L-57-08 | RF dryrun 只做 `[ ERROR ]` 静态判定，不拉起真实进程 | 预览是纯只读 | 按设计，预览不得启动进程 |

**未执行的测试面（如实登记，不用推断补齐）**：真实浏览器视觉走查、真机 SSH 采集、真实派发执行（需 `confirmReal=true` + ADR-0013 安全闸）、性能压测类 TC 共 153 条未执行，逐条原因与补齐方法见 `05-TEST-REPORT.md` §四。
