## 1. 版本定位

**一句话**：把「用例分类」从**筛选条件**升级为**组织手段**，把「建项目」从**六步表单**升级为**带来源的向导**，把「通过」变成**有程序依据的结论**，并把「发起执行 / 列表操作 / 设备凭证」这三条日常主路径做成**选得清、改得动、连得上**。

**五个用户可见的变化**：

1. 全局侧栏「公共用例」组从 2 项变 3 项，多出**用例集**；用例不再只是一张长表，可以按一二级分类**归类浏览**，也能**按分类生成样例集**、**按分类勾选建集**。
2. 全局「项目」组多出**新建项目**，向导内容步可以同时从**模板 / 用例集 / 用例 / 资产**四类来源取料。
3. 发起执行前会先看到**这次到底要跑什么命令**，确认的是一个摘要而不是一个勾选框；跑完的「通过」要过判据机检，缺指标不会显示通过。
4. 手工发起执行可选**全部用例 / 仅用例集 / 仅用例 / 两者组合**，组合时每条用例看得见来源、取消一个集不会误删手工勾选的用例；全站列表统一交互骨架，两档宽度不挤压不溢出。
5. 全局与项目两侧的列表都能**增删改查**（系统产物类列表按契约给编辑/删除/导出），设备选凭证时**自动带出已验证可用的那条**，也可以**手工输入一次性凭证**。

**为什么是现在**：v5.6.0 已让「跑完即入库」成立，报告页能看到用例了。但同一次实测暴露了两件事——**用例库有分类字段却没有分类视角**（用户只能一条条筛），**报告说通过却没有程序依据**（白泽报告 §8.2 指出的经典造假路径）。前者是「资产摆不出来」，后者是「结论站不住」，正好是同一个版本该解决的两头。

**范围三分法**：

| 类别 | 含义 | 条数 |
|---|---|---|
| 本版必做 | 不做则本版目标不成立 | 30 |
| 本版可降级 | 依赖外部条件，可按预案降级并登记遗留 | 2（判据层 RF 侧指标来源、其余列表逐页补齐可分波） |
| 后续版本 | 方向已定，本版不排期 | 6（见 §17） |

## 2. 约束与术语

| 术语 | 定义 |
|---|---|
| 平台用例集 | `test_set.project_id IS NULL` 且 `owner_scope='PLATFORM'` 的集合，全局可见、跨项目复用 |
| 项目用例集 | `test_set.project_id = ?` 且 `owner_scope='PROJECT'`，只在所属项目内可见 |
| 样例集 | 由系统按**一级分类**自动生成的平台用例集，`sample_flag=1` + `sample_l1=<一级分类名>` 作为幂等键 |
| 手工集 | 用户创建的集合，`sample_flag=0` |
| 归组视图 | 用例按「一级分类 → 二级分类 → 用例」树形展开的浏览形态，与「列表视图」共存 |
| 命令清单 | 本次执行将要运行的 argv 数组集合（每条用例一条），是摘要承诺的输入 |
| 确认摘要 `confirmation_digest` | `sha256(前缀 : planId : selectionSha256 : commandDigest)`，用户确认后被持久化，派发前重算比对 |
| 判据 | 用例声明的可机检条件（指标名 / 期望 / 比较符 / 是否强制），与断言分离 |
| 判据结论 `criteria_verdict` | `PASS` / `FAIL` / `MISSING` / `NULL`（未声明判据） |
| 服务端全选 | 「全选」不是把 N 个 id 传给后端，而是把**筛选条件**传给后端，由后端决定命中集合 |
| 选择模式 | 发起执行的四种范围：`ALL`（本项目全部用例）/ `SETS`（仅用例集）/ `CASES`（仅用例）/ `MIXED`（集合 ∪ 单选用例） |
| 选择来源 | 一条用例被选中的原因（`SET:<id>` 或 `MANUAL`）；同一用例可有多个来源，组合语义是**来源集合的并集** |
| 选择快照 | 发起时冻结的不可变记录：模式 + 集合 id + 单用例 id + 筛选条件 + 项目作用域 + 命中数 + `selection_sha256` |
| 列表脚手架 `ListScaffold` | 全站列表统一的六槽位骨架：工具条 / 筛选区 / 批量操作条 / 表格 / 分页 / 空错载态 |
| A 类列表 | 用户可创建类（项目 / 模板 / 用例集 / 用例 / 资产 / 凭证 / 计划 / 用户报告等），契约要求 C/R/U/D 齐全 |
| B 类列表 | 系统产物类（执行报告 / 运行记录 / 导入批次 / 导出历史），C 不适用；要求 R + 元数据编辑 + 删除或归档 + 导出 |
| C 类列表 | 只读派生类（看板 / 趋势 / 失败聚类 / 拓扑 / 审计日志），须登记白名单、写明理由、页面明示只读 |
| 凭证验证记录 | 「某条凭证在某台设备上真的连通成功过」的可查询证据，含通道、结果、时延、时间、操作者 |
| 一次性凭证 | 本次请求内有效的手工输入材料（用户名 / 口令或私钥 / 类型 / 连接参数），**不落任何持久化介质** |

**硬约束**（违反即打回）：

1. 已应用迁移不可改，只追加新号；开工前用 `ls db/migration/*.sql | sort -V | tail -1` 复核空号。
2. 既有端点语义不变；平台集从只读变可写属**新增能力**，原 GET 行为与响应结构保持兼容。
3. 平台集写权限放宽到 `case:write` 属**安全口径变更**，须大师拍板（D-57-04）后实施。
4. 判据层**不得**用「全部标记 PASS」凑覆盖率；无用例判据时 `criteria_verdict` 必须是 `NULL`。
5. 服务端全选**不得**回退既有批量执行的 `ids` 入参；`selection` 是并列分支。
6. 前端 i18n 字面量含 `@` 必须写 `{'@'}` 且整串用双引号（否则 vue-i18n 编译抛错、整页空白）。
7. 选择快照一经确认即不可变；`ALL` 模式冻结的是**筛选条件与命中数**，不是展开后的 id 列表。派发前重算不一致一律 409。
8. 手工输入的一次性凭证不得进入 DB / 日志 / 审计 detail / 异常消息 / 响应 / 证据包；只走 POST body，脱敏复用 `SensitiveMask` 与 `HostAccess.toString()`。
9. 列表删除一律**软删 + 审计 + 影响面提示**；`test_result` 等原始事实表不在删除范围内（事实与结论分离）。
10. C 类只读列表必须登记白名单并在页面明示理由，**不允许用灰掉的「编辑/删除」按钮假装支持**。
11. 全站列表改造不得新增 npm / maven 依赖；`ListScaffold` 与 `DataTable` 是同一套组件的组合，不复制第二份表格实现。

## 3. 角色与关键场景

| 角色 | 本版关注点 |
|---|---|
| 平台管理员 | 维护平台用例集、播种样例集、看判据覆盖率 |
| 项目 PM | 用向导建项目，一次把用例集与资产带进去 |
| 测试工程师 | 按分类找用例、按分类建集、确认命令清单再执行 |
| 观察者（viewer） | 只读：能看用例集与归组视图，不能建集、不能确认执行 |

**关键场景 S1**：工程师接手一个新项目，需要「以以太网分类的 40 条用例为基础」建一个回归集 —— 现在要一条条翻页勾选；本版应在树上一勾一级分类即完成。

**关键场景 S2**：PM 建新项目，希望直接复用平台上的「RDMA 样例集」与 3 台设备 —— 现在要先把项目建出来，再进项目里逐项加；本版应在向导内一次完成。

**关键场景 S3**：执行前用户看到「将运行 12 条命令」，确认了一个摘要；派发时若命令变了（比如别人改了用例），系统必须拒绝而不是照跑。

**关键场景 S4**：报告说「通过」，评审问「凭什么」。本版要求能点开看到该用例的判据逐条比对结果。

**需求**：全局模式「公共用例」组新增第三个叶子「用例集」，落到 `/g/case-sets`；页面左侧为集合列表（搜索 + 来源筛选：全部 / 样例 / 手工），右侧为选中集合的成员表。

**验收判据**：

| 编号 | 判据 |
|---|---|
| AC-01-1 | 全局侧栏「公共用例」组渲染 3 项，第 3 项文案为「用例集」 |
| AC-01-2 | 点击后 URL 为 `/g/case-sets`，该叶高亮，且「用例清单」「导入记录」均不亮 |
| AC-01-3 | 进入 `/g/case-sets/:id` 时「用例集」叶仍亮（`alsoMatch` 生效） |

**依赖**：FR-v5.7-03（写端点）。

### FR-v5.7-02 全局用例按一/二级分类归组

**需求**：全局用例页在现有「筛选」之外增加「归组视图」。URL 带 `group=1` 时，用例按「一级分类 → 二级分类 → 用例」树形展开，每个节点显示用例数；未分类用例归入虚拟节点「未分类」。

**验收判据**：

| 编号 | 判据 |
|---|---|
| AC-02-1 | `group=1` 时渲染树；不带该参数时保持现有列表视图，行为不变 |
| AC-02-2 | 一级节点数 = `case_category` 中 `level=1 AND status='active'` 的条数（含 0 条用例的分类） |
| AC-02-3 | 二级节点只出现在其父一级节点下；某一级下无二级时直接列用例 |
| AC-02-4 | 每个节点右侧计数与后端聚合接口返回一致（抽查 3 个节点，逐一点开核对条数） |
| AC-02-5 | `category_l1` 为空或指向已禁用分类的用例，归入「未分类」；该虚拟节点不可编辑、不可删 |
| AC-02-6 | 归组视图可与关键词、生命周期筛选叠加；叠加后计数按筛选后口径重算 |
| AC-02-7 | 视图切换（列表 ↔ 归组）保留关键词与筛选，只增删 `group` 参数 |
| AC-02-8 | 树节点默认全部折叠到二级，展开状态不持久化（避免与筛选混淆） |

**边界与异常**：

- 单分类下用例 > 200 条时节点内分页，显示「显示前 200 条，共 N 条」。
- 分类字典为空时，归组视图退化为单个「未分类」节点并提示「尚未维护分类字典」。

### FR-v5.7-03 平台用例集开放写操作

**需求**：平台用例集从「只读 + 仅管理员」改为「可读可写 + 能力控制」。读需要 `case:read`，写需要 `case:write`。

**端点变更**（详见 §15）：

| 方法 | 路径 | 变更 |
|---|---|---|
| GET | `/api/platform/case-sets` | 改：加 `source`（all/sample/manual）筛选；`requireAdmin` 改为 `case:read` |
| POST | `/api/platform/case-sets` | 新：新建平台集 |
| PUT | `/api/platform/case-sets/{id}` | 新：改名/描述 |
| DELETE | `/api/platform/case-sets/{id}` | 新：删除（连带成员） |
| POST | `/api/platform/case-sets/{id}/items` | 新：批量加成员（`caseIds` 数组） |
| DELETE | `/api/platform/case-sets/{id}/items/{caseId}` | 新：移除成员 |
| PUT | `/api/platform/case-sets/{id}/order` | 新：重排 |
| POST | `/api/platform/case-sets/{id}/items/category-filter` | 新：按分类批量加（复用项目侧同款语义） |

**验收判据**：

| 编号 | 判据 |
|---|---|
| AC-03-1 | 具备 `case:write` 的用户可新建集合；落库后 `project_id IS NULL` 且 `owner_scope='PLATFORM'` |
| AC-03-2 | 仅 `case:read` 的用户调用写端点返回 403，且前端不渲染写按钮 |
| AC-03-3 | `set_code` 在平台作用域内唯一，重复提交返回 409 并提示「编号已存在」 |
| AC-03-4 | 删除集合后：集合行不可见，其 `test_set_item` 同步清除（或标记删除），列表总数减 1 |
| AC-03-5 | 批量加成员时，已存在成员不重复插入（唯一键兜底），返回体区分 `added` / `skipped` |
| AC-03-6 | 排序端点提交的 id 序列与库中 `seq_no` 一致（1..N 连续，无空洞） |
| AC-03-7 | 每个写操作落审计（`audit_log`），含操作人、集合 id、动作、变更摘要 |
| AC-03-8 | 项目侧引用平台集仍为**只读副本**语义不变；本版不做双向同步（登记遗留 L-57-01） |

**边界与异常**：

- 集合名称长度 > 128 拒绝（与列宽一致），返回 400 带字段名。
- 删除被项目引用的集合：允许删除，但返回体带 `referencedBy` 数量提示（不阻断）。

### FR-v5.7-04 样例集按一级分类自动播种

**需求**：首次进入全局用例集页时，对每个「还没有样例集」的一级分类，自动创建一个样例集，成员为该分类下全部 `lifecycle_status='active'` 的用例。

**幂等键**：`sample_flag=1 AND sample_l1=<一级分类名>`。**不用名称匹配**（名称可被用户改）。

**验收判据**：

| 编号 | 判据 |
|---|---|
| AC-04-1 | 库中 0 个样例集、3 个一级分类时，首次访问后样例集数 = 3 |
| AC-04-2 | 命名规则为 `<一级分类名> · 样例`；`set_code` 为 `SAMPLE-<一级分类拼音或序号>`，全局唯一 |
| AC-04-3 | 每个样例集成员 = 该一级分类下全部 active 用例，按 `case_code` 升序 |
| AC-04-4 | 二次访问不新增集合（总数仍为 3），不重复插入成员 |
| AC-04-5 | 某分类下 0 条用例时仍建集，成员为空，页面显示「该分类下暂无用例」 |
| AC-04-6 | 播种失败（DB 异常）不阻塞页面渲染，页面顶部提示「样例集自动生成失败，可手动重建」，列表照常显示 |
| AC-04-7 | 播种只发生一次（进程级或幂等键级），并发两次请求不产生重复集合 |
| AC-04-8 | 已禁用的分类（`status='disabled'`）不播种 |

**边界与异常**：

- 一级分类 > 30 个时，播种耗时可能超前端超时；改为异步（先返回列表，播种在后台完成并刷新）。
- 播种集合的 `created_by` 记为 NULL（系统行为），页面标注「系统生成」。

### FR-v5.7-05 样例集手动重建

**需求**：页面上提供「按一级分类重建样例集」按钮，补齐缺失分类的样例集，并可把新增用例补进已有样例集。

**验收判据**：

| 编号 | 判据 |
|---|---|
| AC-05-1 | 点击后弹出二次确认，说明「将补齐缺失分类的样例集，不会删除你手工添加的成员」 |
| AC-05-2 | 缺失分类的样例集被创建，已存在的样例集不重建（id 不变） |
| AC-05-3 | `user_modified=1` 的样例集被跳过，结果里列出「跳过 N 个（已手工修改）」及集合名 |
| AC-05-4 | 结果摘要含三项计数：新建集合 X 个 / 跳过 Y 个 / 新增成员 Z 条 |
| AC-05-5 | 重建不删除任何既有成员（含用户手工加的跨分类用例） |
| AC-05-6 | 重复点击（无缺失、无新增）返回「无需重建」，不写库 |
| AC-05-7 | 操作人、时间、结果计数落审计 |

### FR-v5.7-11 命令摘要确认与派发比对

**需求**：确认页展示 `confirmation_digest`，用户点击「确认并执行」后落库；派发前重算比对，不一致返回 409 且不启动任何进程。

**摘要公式**：`confirmation_digest = sha256("v5.7-run-confirm:" + planId + ":" + selectionSha256 + ":" + commandDigest)`

**验收判据**：

| 编号 | 判据 |
|---|---|
| AC-11-1 | 确认页显示 digest 前 12 位与命令条数，用户点击「确认并执行」才落库 |
| AC-11-2 | 相同输入（planId / selection / 命令清单）计算出的 digest 恒定（单测锁死样例值） |
| AC-11-3 | `execution_plan` 落 `confirmed_digest` / `confirmed_at` / `confirmed_by` 三列 |
| AC-11-4 | 派发前重算，不一致返回 409，**不创建 run、不启动进程**，审计记 `run.digest-mismatch` |
| AC-11-5 | 409 响应体含差异项：新增的用例、删除的用例、顺序变化的用例（各列编号） |
| AC-11-6 | 未确认的计划被 cron 触发时，跳过本次并记 `run.blocked-unconfirmed`，不静默执行 |
| AC-11-7 | digest 计算对输入做规范化：环境变量按 key 排序、路径转绝对、分隔符固定，顺序不同但内容相同的命令得同一 digest |
| AC-11-8 | 确认后用户再次编辑计划内容（改用例/改参数），digest 自动失效，需重新确认 |

**边界与异常**：

- 服务重启后 `confirmed_digest` 仍在，不要求重新确认（落库即有效）。
- 并发两次确认：后到者覆盖前者的 digest 并记审计（同 planId 只保留最新确认）。
- 降级：若命令清单在计划（cron）场景无法预生成，则 cron 计划首次触发时先进入「待确认」而非直接执行，并在计划列表标红提示。

### FR-v5.7-13 「通过」必须过判据机检

**需求**：报告的「通过」结论不再直接等于 `verdict=PASS`，而要同时满足判据机检；缺指标按「未通过（缺证据）」呈现。

**判定矩阵**：

| `verdict` | `criteria_verdict` | 最终结论 | 报告显示 |

| PASS | MISSING | 未通过（缺证据） | 未通过 — 缺指标 |
| PASS | NULL | 通过（无判据） | 通过（标注「未声明判据」） |

## 16. 兼容与迁移策略

| 对象 | 策略 |
|---|---|
| 既有平台用例集（只读期创建的数据） | 不动数据；`sample_flag=0`，视为手工集 |
| 既有项目用例集 | 不动；`sample_flag=0` |
| 既有 `test_result` 行 | `criteria_verdict` 为 NULL，报告显示「未声明判据」，不追溯判定 |
| 既有 `execution_plan` 行 | `confirmed_digest` 为 NULL；cron 触发时按降级规则进「待确认」 |
| 既有证据目录（扁平结构） | 读取兼容，不强制迁移；新写入走分片 |
| 既有批量执行调用方（传 `caseIds`） | 保持可用，快照是并列新增；两条路径各留一条集成测试 |
| 既有执行报告 / 运行记录 / 用户报告 | `deleted_at` 为 NULL，列表默认过滤不变；旧数据打开正常 |
| 既有设备凭证绑定（`management_credential_id` / `bmc_credential_id`） | 不动数据；无验证记录时显示「未验证」，不自动改选、不自动清空 |
| 既有发起台（`selectedCaseIds` 扁平选择） | `CASES` 模式下老行为等价，组合模式才启用来源映射；老单测必须全绿 |

**回滚**：七个迁移均为**加列/加表**，不改既有列语义，回滚只需停用新功能开关（后端配置 `app.v57.enabled=false` 关掉新入口与写端点），不需要删列。软删数据可通过清空 `deleted_at` 恢复；一次性凭证因不落库，回滚无需处理。
