# v2.6 工作助手体验 · ② 评估报告

**文档编号** RA-REL-2026-026-A ｜ **版本** v2.6-assistant-ux ｜ **批次** B14（待落号） ｜ **门禁** G13（未判）
**日期** 2026-11-08 ｜ **结论** 三条诉求都值得做，且都不需要新架构：宽度是「已有的状态没接线」，
Agent/模型是「已有的能力没入口」，输入输出是「写死的尺寸」。总改动集中在一个组件 + 两个接口。

---

## 1. 做不做

| 诉求 | 值不值 | 理由 | 判据 |
|---|---|---|---|
| 宽度可调 | **做** | 现状是假的：`width` 不进布局，按钮只改数字。这属于「功能声称存在但不可用」 | 拖动边界，`.app-shell` 第三列真的跟着变；340/760 两端夹住 |
| 改悬浮？ | **不改整体形态** | 全悬浮会遮挡主内容，与「边看边问」相悖；窄屏已有悬浮，分工正确 | 见 §2 方案对比 |
| 选 Agent / 模型 | **做，本版主件** | 7 条 CLI 与逐条配置都在，就差抽屉里的入口与按次覆盖 | 选 pi + ark 模型得到真实回答；选未安装的 claude 回落并明示 |
| 输入输出放大 | **做** | 240px 硬上限 + 单行输入 + 12px 字，在 1000px 高的抽屉里只用了 1/4 | 历史区撑满剩余高度；输入是多行、可长高 |

**不做的事（明确划出去）**：

1. **不做全屏 / 独立窗口**。抽屉定位是「旁路助手」，全屏是另一个产品形态。
2. **不做按会话保存不同的 agent**。偏好是全局单份（每台机器一份），会话级会让「换页面就换助手」变得不可解释。
3. **不把 `FEATURE_AI_REAL_CLI` 默认打开**。真实调用有费用与外部依赖，默认值是发版口径，归大师；
   本机只为验收临时打开（见 §3 C4）。
4. **不做模型清单的服务端拉取**（`/v1/models`）。各家端点差异大，先把「能选」做实，清单用目录建议值 + 已配置值。
5. **不在抽屉里做凭据配置**。那是设置页的事，抽屉只选「用哪个」，不碰「怎么连」。

## 2. 方案对比与定稿

| 决策点 | 候选 | 定稿 | 理由 |
|---|---|---|---|
| 桌面形态 | 推挤 / 悬浮 | **推挤** | 不遮挡主内容；1440 下最窄主区仍有 480px |
| 窄屏形态 | 推挤 / 悬浮 | **悬浮**（沿用现状） | 窄屏并排放不下两栏 |
| 宽度交互 | 仅档位按钮 / 拖拽 + 键盘 + 档位 | **三者都有** | 鼠标求精确、键盘求可达、按钮求快 |
| 宽度范围 | 280–520 / 340–760 | **340–760** | 340 以下读不动；760 以上该开独立页 |
| Agent 清单权限 | 复用设置页接口 / 新开只读接口 | **新开 `GET /api/ai/agents`** | 设置页含端点与掩码，且 `requireAdmin()`；抽屉面向所有能访问项目的人 |
| 选中项失效 | 报错 / 静默改用默认 / 回落 + 明示 | **回落 + 明示** | 本地偏好是上一轮存的，机器状态会变；报错会让抽屉彻底不可用，静默会让用户以为选对了 |
| 换 agent 时的模型 | 保留 / 清空 | **清空** | 上一家的模型名换一家多半不存在，留着必然报错 |

## 4. 风险

| 风险 | 处置 |
|---|---|
| 拖拽把主内容压到不可用 | 上限 760 由 JS 钳制；CSS 兜底缺省 420 |
| 拖拽事件泄漏（松手后仍跟随） | `pointerup` 移除两个监听；组件卸载前也会随 window 事件自然失效 |
| 宽度变量悬空（CSS 里查不到定义） | 在 `theme.css :root` 里声明 `--ai-drawer-w: 420px` 作为默认值，机检才通过 |
| 选了不存在的 agent 导致 500 | 后端回落 + `cliFallback` 标记；前端提示，不静默 |
| 清单接口泄露凭据 | 只回 key/name/models/defaultModel，单测锁死「不得出现 baseUrl / apiKeyEnc / keyMasked」 |
| Jackson 对 record 缺字段报错 | 单开 `AiChatRequestBindingTest` 用真实 ObjectMapper 过老/新两种请求体 |
