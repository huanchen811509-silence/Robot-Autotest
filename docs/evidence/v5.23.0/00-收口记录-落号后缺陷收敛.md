## 3. 红项按根因归类

### 3.1 真缺陷（改代码修，4 条）

1. **用例失败被记成执行器故障**：`run.failure_class` 原先把「用例断言失败」与「平台跑不起来」
   混成一个 `INFRA`，导致看板上「平台故障率」虚高、真实的用例失败被埋。改法是把
   `executionOk`（产物是否可信：无超时 + 无启动失败 + 产物可解析 + 分片完整）与
   `success`（是否全绿：`executionOk` 且退出码 0 且无单用例超时）拆开，用例失败记
   `ASSERT`/`tests_failed`。计数口径钉死 `total = passed + failed + skipped`。
   统计只取 `<test>` 的**直接子** `<status>`——`<kw>`/`<if>`/`<for>` 里也有 status，
   文档级 `getElementsByTagName` 会把 1 条数成十几条（夹具 `mixed-status.xml` 锁死这条）。
2. **首跑按钮字色=底色**：`.btn-first-run` 只写了 `color: var(--accent)` 没写 `background`，
   继承到的底色恰好也是 `rgb(251,146,60)`，对比度 **1.00:1**（肉眼不可见）。补
   `background: transparent` 后 6.77:1（浅色）/ 5.50:1（深色）。
3. **顶栏重复显示「当前：项目名」**：下拉框本身已显示当前项目，顶栏再多一行重复文字。
4. **用例集空名称 500**：`setCode` 留空有自动生成兜底，`name` 直接落库 → 空体请求走到
   SQL NOT NULL 报 500。改为前置校验返 400。

### 3.2 判据与事实脱节（改机检/探针，5 条，判定标准一律不放宽）

1. **菜单一级项 7 → 8**：v5.23 把一级「执行与报告」拆成「执行管理」+「报告管理」，
   机检期望值没跟。改后仍校验「每组 children 非空 / 层级 ≤2 / 同 path 的 query 两两互异」。
2. **`check_navigation.py --self-test` 从 v5.10.0 起恒红**：自检原本只删
   `global-templates` 组的一个叶子；v5.10.0 给该组加了第三叶（新建模板向导）后，删一个
   还剩 2 项，按「每组 ≥2」不构成违规——**坏的是自检，不是机检**。改为连删两叶让该组只剩
   1 项；第二个正则需跳过块内注释行，否则匹配不到。
3. **表高口径不一致**：`project-matrix.mjs` 硬卡 `tableH >= 300`，`row-hit.mjs` 用
   `min(300, rows*44+44)`。同一张表两个探针两套标准 → 统一为后者（数据少时只要求不被裁）。
4. **「需要滚动」被误判成「被遮挡」**：`elementFromPoint` 直接取按钮坐标时，行在内部滚动区
   之外会把命中落到分页条上。改为先 `scrollIntoView({block:'nearest'})` 再取坐标，判完恢复
   `document.scrollingElement.scrollTop`（否则污染「整页不许被滚」判据）。修后 20/20 命中；
   `--self-test` 注入覆盖层仍判红 2 条（判据未放宽）。
5. **原生 `<table>` 白名单三处 → 四处**：`TestReportDetailView.vue` 的客户视图预览是
   `v-for (value, key) in customerView` 铺开的 22 字段 key→value **定义表**，无分页/排序/选行，
   塞进数据网格是错配——与 `ReportDetailView.vue` 同类。

## 4. 本轮自己造成、自己修掉的 3 条操作事故

> 记下来是因为它们都能复现，且都在「改完就重启」这一步踩的。

1. **`build.sh` 覆盖了运行中的 jar → 全站登录 500**。Spring Boot 的嵌套 jar 是懒加载的，
   `target/*.jar` 被重写后，运行中的进程读不到新中央目录，抛
   `java.io.EOFException (ZipContent.loadZipCentralDirectoryFileHeaderRecord)`，连 mariadb 的
   `AuthenticationPluginLoader` 都加载不出来 → Hikari 建连超时 → 所有 DB 操作 500。
   而 `_ping` 仍 200（它不查库），**不能拿 `_ping` 当健康**。
   正确顺序：**先停服务 → build → package → 再起服务**。
2. **把后端当"手工进程"重启，反而破坏了托管**。开发机上后端一直由
   `systemctl --user robot-autotest-backend` 托管（unit 指向 `backend/target/*.jar`、
   `EnvironmentFile` 指向本机 env、日志 append 到 `/tmp/rt-backend.log`、`Restart=always`）。
   我误查了系统域（`systemctl is-active` 无 `--user`）得到 `inactive`，于是手工 `exec java`，
   结果 wsl 会话结束时进程收到 SIGHUP，进入"半关闭"（Tomcat 停止 accept，新连接被 RST，
   对外表现 `502 backend unavailable / read ECONNRESET`）。
   正确做法：`systemctl --user restart robot-autotest-backend`。
3. **无头浏览器路径只存在于启动命令行 → 报告 PDF 导出 503**。`PdfRenderer` 探测顺序是
   `REPORT_PDF_CHROME` → 配置；原先靠命令行 export，一重启就丢
   （`503 DEPENDENCY_UNAVAILABLE 未找到可用的无头浏览器`）。已把路径写进本机
   `~/.config/robot-autotest/env`（不入库），重启不再丢。
