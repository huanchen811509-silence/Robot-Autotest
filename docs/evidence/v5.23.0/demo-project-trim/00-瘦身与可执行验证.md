## 4 发现但未修的平台缺陷（需单独评估）

robot 执行结束后，`run` 表记 **total=10 / passed=0 / failed=10**、`failure_class=INFRA`、
`failure_message=分片执行失败: ok`，但 `stdout.log` 明确是 `7 passed, 2 failed, 1 skipped`。

根因：`RunExecutionService` 聚合计数用的是一刀切逻辑——

```java
int total = result.totalTests();
int passed = result.success() ? total : 0;   // 只要有失败就把全部算失败
int failed = total - passed;
```

后果：任一条用例失败（本例 DEMO-008/010 是**设计上就该失败**）→ 整单判 INFRA，界面显示「10 条全失败」，
掩盖真实结果。建议在下一版修：按 `output.xml` 的真实统计回填 passed/failed/skipped，
并把「用例失败」与「执行器失败」区分开（当前 `INFRA` 归类也不对）。
