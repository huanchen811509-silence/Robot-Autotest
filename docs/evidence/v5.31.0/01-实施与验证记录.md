1. **UI 真机点击未逐一执行**：`TC-v5.31-*~TC-v5.34-*` 中依赖界面的条目只做到「组件级 spec + 构建通过」，
   未做逐条真机点检。这是本次最大的证据缺口，须由大师人工核对补足。
2. **计划合并（FR-v5.33-01）、节点自动归档（FR-v5.33-03）、列表能力机检（FR-v5.33-05）、
   环境工作台（FR-v5.34-02）四条未做**，故对应 TC 全部标「未执行」。
3. **`link.evidence` 撤回**，`FR-v5.34-04` 的 TC 一并标「未执行」。
4. 门禁 13 步（截图）依赖 Chrome CDP 9222；本次已启动无头 Chrome，但若门禁中途失败在该步，
   应按 `docs/evidence/v5.23.0/00-收口记录-落号后缺陷收敛.md` 的同一套方法补。
5. **端口编辑表单没有暴露 `V11_93` 新增的 6 个字段**：数据通路（迁移 → 实体 → 仓储 → 渲染器）
   已通，但界面仍只有原来的字段，因此线上要靠导入或接口写入。这是已知缺口，不是「已完成」；
   补齐表单需要动设备向导（含校验与 i18n），未在本轮范围内。
6. **`sriov_offload` 是自由 JSON**：渲染器按 JSON 对象透传，但没有任何校验规则，
   写错只会体现在真机执行。与 `counter_patterns` 同一处理口径。
