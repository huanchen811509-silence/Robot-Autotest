## 2 PDF 换实现的根因（W72-05，本版最大不确定项）

原 `ReportExportService.pdf()` 手写 PDF obj：单字体 `/F1 Helvetica` + `ascii()`
把 `c < 32 || c >= 127` 全换成 `'?'`。**中文根本写不进去**，实测恒定 1,521 字节、单页空壳。
补齐 CJK 字体嵌入成本极高，改为「对外视图 → HTML 表格 → 无头浏览器打印」。

排查过程中遇到并解决的两个环境障碍（**都不是代码问题，但不解决就拿不到证据**）：

| 现象 | 根因 | 处置 |
|---|---|---|
| PDF 接口 503（`未找到可用的无头浏览器`/产物缺失） | 原 `REPORT_PDF_CHROME` 指向 `scripts/chrome-wsl-bridge.sh`，桥到 Windows Chrome **160.0.8157.0 dev**；该版本已移除 `--print-to-pdf`，退出码 0 但不产文件 | 改用 WSL 内 Chrome for Testing 159（playwright 自带，原生 Linux，无需路径翻译） |
| PDF 生成了，但 `pdftotext` 等价提取全是 `\x00` | WSL 里 **一个中文字体都没有**（`fc-list :lang=zh` = 0） | `apt install fonts-noto-cjk` → 30 项 |

> 这两条同时解释了一个旧事实：run 级 PDF 曾在旧版 Chrome 时期拿到 539,607 B（中文正常），
> 之后环境升级就断了，而**没有门禁覆盖 PDF 内容**，所以一直没人发现。
> 本波把 PDF 内容判定写进探针（字体 + 提取文本 + 关键字段），下次断了会立刻红。

## 3 明细列与对外口径

`ReportExportService.CaseDetailRow` 固定五列：编号 / 结论 / 耗时 / 失败原因 / 下发命令。

- **对外（external）**：`commandText` 置空 → 写占位符 `—`。C5 §3 明确禁止对外文件出现命令原文，
  这不是"还没做"，是"不许有"；`failureMsg` 过 `scrub` 脱敏。
- **内部（internal）**：五列原样，含命令原文——内部件的用途就是排查，脱敏会把线索一起抹掉。
- 快照里 `cases` 存原文（6 键），因为快照是内部事实；裁剪发生在导出期，不在冻结期。
- 冻结期另有一道**凭据硬拒**：`failureMsg` / `commandText` 命中 `password=` / `token=` 等形态时
  直接拒绝冻结，报错只报用例编号、不回显命中内容（`ReportSnapshotCasesTest` 守住）。
