## 判红归类（均按产品缺陷处理，不改判据）

1. `L1 事实七项有真实值` —— `appHome()` 直接把 `user.dir` 当安装根，
   而部署是从 `backend/` 起进程，于是 `VERSION` 读成 null、`installRoot` 指向 `backend/`。
   修：`user.dir` 以 `backend` 结尾且父目录有 `VERSION` 时上跳一级。
2. `任务历史可查且刷新后仍在` / `任务创建 id=0` / `比对动作落审计行 before=0 after=0` ——
   三处同源：`create(..., dryRun=true)` 直接返回 `taskId=0` 且不落库，
   于是「谁预演过备份」在审计里查不到（违反 P4 全量审计）。
   修：dry-run 也插一行审计（只到 PRECHECK，标记 `DRY_RUN`），业务仍零写入。
3. `中止后落库为 ABORTED` —— 上一条的连带：任务不存在所以 404。
   修完落库后，探针自身还有一处选样错误：拿「已完成」任务去中止，
   实际返回 409 是**正确**行为。已改为「已完成任务 409」+「RUNNING 夹具中止落 ABORTED」两条判据。
