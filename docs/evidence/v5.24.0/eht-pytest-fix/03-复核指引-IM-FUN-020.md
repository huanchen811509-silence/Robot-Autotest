## 5. **未达成项：命令执行过程看不到**

用例库原始产物里**确实记录了真实 SSH 命令和回显**：

目录：`/mnt/e/workspace/自动化测试/pytest-cases/artifacts/EHT-REAL-NOKEY-1795141269/cases/tests_nic_base_test_im_fun_020.py_test_im_fun_020_pci_device_info/raw/`

`gpu01_10.202.54.101.commands.jsonl`（原文）：

```json
{"command_id":"45e2414737","endpoint_key":"gpu01@10.202.54.101","command":"readlink -f /sys/class/net/ens17np0/device","purpose":"定位 ens17np0 所属 PCI 设备的 BDF",...}
{"command_id":"4961ce89a2","endpoint_key":"gpu01@10.202.54.101","command":"sudo -n lspci -Dnnvv -s 0000:45:00.0","purpose":"读取 0000:45:00.0 的 PCIe 能力、实际链路状态与设备标识",...}
```

`framework.log` 里还有 paramiko 连接日志与 `exit=0 duration=...`，`45e2414737.stdout.txt` / `4961ce89a2.stdout.txt` 是命令原始回显。

**但平台报告的命令三列是 `NONE`**——数据存在，平台没接上。

### 根因（已用诊断测试证实）

| 环节 | 事实 | 证据 |
|---|---|---|
| 命令索引本身 | **能正确提取**第一条命令 `readlink -f /sys/class/net/ens17np0/device` | 临时诊断测试直接用真实产物调 `PytestCommandIndex.lookup`，首个候选 `has=true` |
| 执行侧补录 | `PytestNicRunController:578` 用新归一器 + `PytestCommandEnricher` 补录，结果只用于内存计数 | 源码 578-583 行 |
| 报告侧入库 | `ReportIngestService:183` **重新调用老内核 `PytestKernel.normalize`**，从 json-report 取命令；新用例库没有 json-report → `NONE` | 源码 52、183 行 |
| 落库 | `test_result.command_text` 写的是老内核结果，补录结果从未写回 | `ReportIngestService:233-240` |

**一句话**：执行侧和报告侧用了两套归一器，命令补录只做在内存里，报告入库时丢了。
