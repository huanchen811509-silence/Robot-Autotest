## 2. W-EHT-06：报告不再用一串 0 冒充"没有用例"

**改了三种可判定状态**（`EhtSections.Assembly`）：

| 状态 | 含义 | 报告表现 |
|---|---|---|
| `OK` | 装配成功，计数可信 | 正常渲染 |
| `NO_DATA` | 装配成功但 0 条用例结果 | 顶部横幅「本次执行没有任何用例结果」 |
| `FAILED` | 装配失败 | 顶部横幅「报告装配失败」+ 原因 + 明确说明"下方 0 不代表没有用例" |

**证据层空字段也显性化**：判据为空时写「未采集到判据（缺证据）」，不再渲染成"判据行原文："后面一片空白。

**单元测试**：`EhtPytestReportTest` **15 项全绿**，其中新增 5 项：

| 测试 | 断言 |
|---|---|
| `assemblyFailureIsExplicitNotSilentZeros` | 失败横幅出现、原因带出、且位于结论层之前 |
| `noDataIsDistinguishedFromAssemblyFailure` | 空跑不被说成装配失败 |
| `emptyEvidenceFieldsSaySoInsteadOfRenderingBlank` | 空判据/空实测值有文字说明，不渲染空白标签 |
| `planIsRenderedWithConnectionFactAndBranches` | 计划段渲染出 `connection=false` 与分支 |
| `absentPlanExplainsItself` | 无计划时有解释文字 |

## 4. W-EHT-08：real 模式不再选到 127.0.0.1

**根因**：project 95 设备按 id 排序，两台演练设备（id 18/19，`model=fake-plan-only`，IP `127.0.0.1/2`）排在真实 DUT（id 20/21，`10.202.54.101/102`）之前；用例 `case_target("first")` 稳定选中第一台 → SSH 必然失败。

**修法**：`real` 模式在选设备阶段排除 fake 设备（判据：`model` 以 `fake` 开头 / 名称 `eht-fake-*` / IP 为 `127.*`），并写一条 warning；fake 模式保持原行为（Plan-only 演练本就该用演练设备）。

**实测（run 17083，real 模式，请求里不传 hostKeys）**：

| 指标 | 结果 |
|---|---|
| 执行结论 | `success=true`，`reason=ok` |
| 用例结果 | `passed_tests=1`，`total_tests=1` |
| 判据 | `criteria_verdict=PASS`，`criteria_json` 241 字节 |
| 日志区间 | `0:16` |
| 步骤 | **8 条** |
| `inventory.yaml` | **不含 `127.0.0.x`**，hosts 只有 `gpu01@10.202.54.101` |

**单元测试**：`PytestEnvRendererTest` **14 项全绿**，其中新增 3 项：

| 测试 | 断言 |
|---|---|
| `real模式排除fake演练设备` | hostKeys 只剩真机、inventory 无 127.0.0.1、有"已排除"告警 |
| `real模式点名fake设备时明确拒绝` | 报错含「fake 演练设备」，不是笼统"设备不存在" |
| `fake模式保留fake演练设备` | 不误伤 fake 模式 |

## 5. W-EHT-09：口径收口（部分）

| 项 | 状态 | 说明 |
|---|---|---|
| `framework.log` 假表述 | **已删** | `PytestNicKernelCommand` 原注释称"监视改为 tail framework.log"，但全库无任何读取代码（grep 确认），已改为真实描述：监视靠进程 stdout 逐行泵送 |
| json-report 归属注释 | **已修** | `PytestCriteriaExtractor.JSON_REPORT` 原注释称由 `PytestKernel` 决定；实际由 `PytestNicKernelCommand` **条件性**添加（契约探测通过才加），且多数真实产物里根本不存在 |
| `ethtool -S` 多 counter 复用 | **未做** | 属超集能力（用例库框架内的采集优化），不影响当前缺陷；转后续版本，理由见下 |
| 双命令链路收口 | **已核实无需改码** | 老链路 `PytestRunAdapter.run` 已要求 `pytest-report.json` 可归一且 `total>0`，无产物一律 `pytest_artifact_invalid` / `no_tests_executed`（`PytestRunAdapterTest` 已覆盖），不会把空 junit 当成功 |

**counter 复用为何转后续**：它属于"平台成为用例库框架超集"的能力补齐，与"空执行/假报告"无因果关系；本轮先把**证据链正确性**闭环，避免范围膨胀。
