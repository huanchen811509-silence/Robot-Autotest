## 2. 测试层级与证据形态

| 层级 | 手段 | 证据形态 | 谁能声称通过 |
|---|---|---|---|
| L1 单测 | `mvn -o -B test`、`npm test` | surefire XML 汇总（tests/failures/errors）+ 前端摘要 | 数字，不是口头 |
| L2 定向机检 | `check_nav_kind.py` / `check_api_contract.py` / `check_md_tables.py` 等 | 命令原文 + 退出码 | 必带 `--self-test` 的红/绿两侧 |
| L3 全量门禁 | `bash scripts/gates.sh`（52 步） | 尾部 `GATES_RESULT FAILS=N` + 日志片段 | 只认尾部读数 |
| L4 真实链路 | 工程 95 真机执行、报告导出 | `docs/evidence/v5.6.0/**` 下的 json + 产物文件 | 必须有文件，不接受「我试过了」 |
| L5 UI E2E | 浏览器脚本 | 录屏/截图 + 网络日志 | 失败必须留截图 |

**证据目录约定**：

```
docs/evidence/v5.6.0/
├── probe/     W56-00 四项待验结论（每个一个 json/md）

└── e2e/       UI 冒烟截图与网络日志
```

## 6. 判定纪律

| 纪律 | 说明 |
|---|---|
| 只认尾部读数 | `GATES_RESULT FAILS=N`；日志目录是历史累积，`grep FAIL` 会误判 |
| 新旧段分开登记 | 原 48 步段与新增段分别记，不得相加成「全绿」 |
| 不许改证据凑源码 | 门禁红就修源码或如实登记，禁止删证据/改断言迁就 |
| 真注入才算自检 | `--self-test` 必须「注入→判红→还原→判绿」三步都留输出 |
| 每跑全量门禁后还原四份副产物 | `ai-eval.json` / `capacity-report.json` / `security-scan.json` / `dora-trend.json` |
| 真机执行边界 | gpu01/02 优先，gpu03 备用，**gpu04 禁用**；`real` 必须 `confirmReal=true` |
