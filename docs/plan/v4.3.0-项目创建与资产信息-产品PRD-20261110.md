## 1. 背景与目标

### 1.1 背景

1. **项目入口分散**：侧栏没有「新建项目」，该入口藏在顶栏账户下拉里；入口显隐用 `settings:read`，
   导致项目经理（PM）能看到入口、点击后被后端 `PROJECT/CREATE` 拒绝（前后端口径不一致的既有缺陷）。
2. **创建权限过窄**：只有 ADMIN 拥有 `PROJECT/CREATE`，PM 无法建项目，与「有权限的用户都能创建项目」不符。
3. **资产连接信息不可得**：「设备 → 网卡 → 接口」的连接关系没有建模，拓扑只能靠前端手工拼装浅层快照
   （仅 `id/name/enabled`，每类上限 100 条会静默截断），且每次现拼，多项目共用同一资产时重复计算。

> 口径说明：需求原文中的「焊接」为笔误，实际含义为**设备、网卡和接口的连接**（见评估报告 v1.1 §10）。

### 1.2 目标

| 目标 | 可度量结果 |
|---|---|
| G1 项目创建入口独立、稳定 | 侧栏「工作台」组内出现独立「新建项目」叶子项；已选项目时仍呈现 |
| G2 创建权限口径统一 | ADMIN 与 PM 前端可见 ⇔ 后端可创建；不再出现「可见但 403」 |
| G3 连接信息结构化可得 | 提供「设备 → 网卡 → 接口」连接明细与拓扑，覆盖全量资产、不截断 |
| G4 分配后自动获取 | 资产分配（共享/引用）后无需人工操作即可读到连接与拓扑 |
| G5 跨项目复用可控 | 默认 12 小时窗口内复用；资产变更立即失效；支持手工强制刷新 |

## 3. 角色与权限

### 3.1 角色定义（变更点）

| 角色 | 项目资源 | 资产资源 | 变更 |
|---|---|---|---|
| ADMIN 管理员 | READ / CREATE / UPDATE / DELETE / MANAGE | 全动作 | 无 |
| PM 项目经理 | READ / UPDATE / **CREATE（新增）** | 全动作 | **新增 PROJECT CREATE** |
| ENGINEER 工程师 | READ | READ / CREATE / UPDATE | 无 |
| VIEWER 访客 | READ | READ | 无 |

### 3.2 权限变更的四处联动（硬要求）

| # | 位置 | 变更 |
|---|---|---|
| P1 | `backend/.../domain/iam/PermissionMatrix.java` | PM 的 `PROJECT` 动作集合增加 `CREATE` |
| P2 | `backend/src/test/java/.../PermissionMatrixTest.java` | 删除/改写「PM 不能建项目」断言 |
| P3 | `backend/src/test/resources/authz-matrix.yaml` | `AUTHZ-PM-PROJECT-WRITE` 期望改 `ALLOW`，reason 同步 |
| P4 | 本 PRD §3.1 | 角色定义回写 |

> 任一处缺失，`AuthzMatrixTest` 与 `PermissionMatrixTest` 将互相矛盾，门禁必红。

### 3.3 前端能力码

| 能力码 | 含义 | 持有角色 |
|---|---|---|
| `project:create` | 可创建项目（侧栏入口 + 路由守卫） | admin、pm |

- 前端能力码**只做入口显隐**，后端 `PROJECT/CREATE` 仍是唯一授权判定（403 兜底）。
- 「是否已选中某个项目」**不参与**该能力码的判定（见 FR-v4.3-01 规则 R3）。

## 4. 功能需求

### FR-v4.3-01 项目创建菜单独立呈现

**描述**：在侧栏「工作台」组内新增一个独立叶子项「新建项目」，与「项目看板」并列；已选中项目时仍呈现。

**规则**

| # | 规则 |
|---|---|
| R1 | 「工作台」组子项顺序：`项目总览`（`/workbench`）→ `项目工作区`（`/workspace`）→ `项目看板`（`/overview`）→ `新建项目`（`/projects/new`） |
| R2 | 「新建项目」为叶子项，`capability: 'project:create'`；无可该能力的角色不渲染 |
| R3 | 入口显隐**不依赖**当前是否已选中项目；已选项目时仍完整呈现 |
| R4 | 「项目看板」与「新建项目」的 `labelKey` 必须不同，均为独立可点击项 |
| R5 | 一级菜单仍为 **7 组**，组内 ≥2 个子项，7 个一级图标仍两两不同 |
| R6 | 顶栏账户下拉的「新建项目」保留为快捷入口，显隐口径改为 `project:create`（与侧栏一致） |

**边界**：不改变「工作台」组原有三个子项的顺序与路径；不新增一级菜单。

**验收**：见 §9 A1–A6。

---

### FR-v4.3-02 创建权限口径统一（ADMIN + PM）

**描述**：ADMIN 与 PM 均拥有创建项目的能力，前端入口、路由守卫、后端授权三层口径一致。

**规则**

| # | 规则 |
|---|---|
| R1 | 后端 `POST /api/projects` 要求 `PROJECT/CREATE`；ADMIN、PM 通过，ENGINEER、VIEWER 返回 403 |
| R2 | 前端 `/projects/new` 路由 `meta.capability = 'project:create'`；无能力者跳 `/403` |
| R3 | 创建成功后：写审计 `project:create` 一条；创建者自动成为该项目 `ADMIN` 成员；当前项目切换到新项目 |
| R4 | 创建向导的步骤与字段**保持现状**（模板 → 基本信息 → 运行设置 → 成员 → 确认） |
| R5 | PM 与 ADMIN 的创建结果无差异（均成为新项目管理员） |

**边界**：不改变项目创建的业务字段与事务语义；不改变「非成员不可见」的既有隔离规则。

**验收**：见 §9 A7–A10。

---

### FR-v4.3-03 连接信息建模与自动派生（设备-网卡-接口）

**描述**：从设备、端口（含网卡归属）、链路派生「连接明细」，一条 = 一条链路端点对。

**规则**

| # | 规则 |
|---|---|
| R1 | 端口新增两个可空字段：`nic_name`（网卡名）、`nic_index`（网卡序号）；不新建网卡实体表 |
| R2 | 连接一行包含：链路 id/名称、A 端设备/网卡/接口、B 端设备/网卡/接口、协议、速率、MTU、MAC、IP、端口状态 |
| R3 | 端口未填写网卡归属时，按「未归属」分组展示，不报错、不丢数据 |
| R4 | 同一设备下按 `nic_index` 升序、`nic_name` 字典序稳定排序；输出顺序稳定可复现 |
| R5 | 项目可见资产范围 = 本项目私有资产 + 已引用的平台共享资产（沿用既有可见性规则） |
| R6 | 输出**全量**，禁止分页截断；单项目设备/链路数量不设上限（受性能约束时降级但不得静默丢数据） |
| R7 | 项目别名（`project_asset.alias`）在**输出组装阶段**套用；别名不得进入缓存键或跨项目复用 |

**边界**：不修改设备/链路既有字段语义；不引入外部数据源。

**验收**：见 §9 B1–B4、B9。

---

### FR-v4.3-04 拓扑自动派生

**描述**：由资产自动派生「设备 → 网卡 → 接口」三级拓扑，节点与边来自 FR-v4.3-03 的连接明细。

**规则**

| # | 规则 |
|---|---|
| R1 | 节点层级：设备（根）→ 网卡 → 接口；链路两端接口之间连边 |
| R2 | 节点字段：`id`（类型化唯一键）、`name`、`type`、`parent`、`enabled` |
| R3 | 边字段：`from`、`to`（接口级唯一键）、`linkId`、`linkType`、`speedGbps` |
| R4 | 统计字段：设备数、网卡数、接口数、链路数 |
| R5 | 默认返回**包含**禁用资产并带 `enabled=false` 标记；前端提供「仅看启用」开关 |
| R6 | 不使用 `topology_node` 手工数据，不与其合并 |

**边界**：不生成图片资源、不做布局算法持久化；布局由前端渲染层负责。

**验收**：见 §9 B5–B6。

---

### FR-v4.3-05 自动获取 · 复用 · 失效

**描述**：资产分配后自动可用；多项目共用同一资产时在窗口内复用结果；资产变更立即失效。

**触发时机**

| # | 触发 | 类型 |
|---|---|---|
| T1 | `share` / `reference` / `unreference` 事务提交后 | 自动（事件） |
| T2 | 设备 / 端口 / 链路 写操作提交后 | 自动（事件失效） |
| T3 | 首次读取且缓存缺失或过期 | 自动（懒加载） |
| T4 | `POST .../asset-info/refresh` | 手工 |

**规则**

| # | 规则 |
|---|---|
| R1 | 复用窗口默认 **12 小时（43200 秒）**，配置项 `asset-info.cache.ttl-seconds` 可调 |
| R2 | 缓存两级：资产片段（`type:id:contentHash`）+ 项目聚合（`project:{projectId}:{assetSetFingerprint}`） |
| R3 | 多项目引用同一平台资产：片段级结果跨项目复用；项目聚合各自独立 |
| R4 | 资产变更（设备/端口/链路/引用关系）**立即失效**，不等窗口到期 |
| R5 | 返回值携带 `meta{generatedAt, cacheHit, source, expired, ttlSeconds}` |
| R6 | 缓存不可用时退化为直算，功能不降级（仅性能下降） |
| R7 | 本期按单实例进程内缓存交付；不引入后台定时轮询远端 |

**边界**：不调用任何远端命令或外部接口；不做跨实例缓存一致性。

**验收**：见 §9 B7–B10、B13。

---

### FR-v4.3-06 手工触发获取

**描述**：用户可显式触发重新获取本项目连接与拓扑，绕过复用窗口。

**规则**

| # | 规则 |
|---|---|
| R1 | `POST /api/projects/{projectId}/asset-info/refresh`，默认 `force=true` |
| R2 | 权限 `ASSET/UPDATE`；无权限返回 403 |
| R3 | 每次调用写审计 `asset-info.refresh`，含 `scope` 与 `force` |
| R4 | 幂等：相同 scope 连续调用结果一致（除资产已变更） |
| R5 | 并发单飞：同一项目同一 scope 在途时只执行一次重算，其余请求复用同一结果 |
| R6 | 返回结构与 GET 一致，便于前端原地替换 |
| R7 | 前端按钮按 `ASSET/UPDATE` 能力显隐，点击需二次确认 |

**边界**：不做异步任务队列；不返回任务 id（同步返回结果）。

**验收**：见 §9 B11–B12。

---

### FR-v4.3-07 「连接与拓扑」展示页

**描述**：「环境与拓扑」组新增独立页面，展示连接明细与拓扑，并提供元信息与手工刷新。

**规则**

| # | 规则 |
|---|---|
| R1 | 路由 `/environment/connections`，导航叶子 `labelKey: menu.envConnections`（中文「连接与拓扑」） |
| R2 | 页面包含：拓扑图区、连接明细表、元信息条、刷新按钮 |
| R3 | 元信息条展示：生成时间、数据来源（`internal`）、是否命中缓存、是否过期 |
| R4 | 连接明细表列头含：链路、A 端（设备/网卡/接口）、B 端、协议、速率、状态 |
| R5 | 空态：未分配资产或无连接数据时显示引导文案，不显示错误 |
| R6 | 支持按设备名、网卡名、接口名筛选（前端本地过滤） |
| R7 | 中英词条齐全，无硬编码文案 |

**边界**：不做拓扑编辑器；不提供连接的新增/编辑（连接由链路定义）。

**验收**：见 §9 B14–B16。

### FR-v4.3-08 资产分配最小入口（P1）

**描述**：为多项目共用平台资产提供最小可用入口：引用 / 解除引用平台共享资产。

**规则**

| # | 规则 |
|---|---|
| R1 | 在资产页提供「引用平台资产」与「解除引用」操作，仅对平台共享资产可见 |
| R2 | 权限沿用后端 `ASSET\|CREDENTIAL UPDATE`，失败提示不清空表单 |
| R3 | 引用成功后触发 T1，连接与拓扑自动可用 |
| R4 | 解除引用后该项目不再可见该资产，缓存失效 |

**边界**：不做资产「共享到平台」的普通用户入口（仅保留既有后端能力）；P1 可与主链路并行，缺省不阻塞 FR-v4.3-03 ~ FR-v4.3-08 验收。

### 6.2 手工刷新

```
POST /api/projects/{projectId}/asset-info/refresh
Body: { "scope": ["connections","topology"], "force": true }
权限：ASSET/UPDATE
审计：asset-info.refresh（含 scope、force）
```

- 响应结构与 6.1 一致。
- `force=false` 时遵循 12h 窗口；`force=true` 强制重算。
- 并发单飞，重复调用幂等。

### 6.3 端口接口扩展

`GET/POST/PUT /api/projects/{projectId}/devices/{deviceId}/ports` 的请求与响应增加 `nicName`、`nicIndex`（可空）。
既有调用方不传时行为不变。

## 7. 非功能需求

| # | 类别 | 要求 |
|---|---|---|
| N1 | 性能 | 缓存命中 P95 < 300ms；冷启动（500 设备 / 2000 端口 / 1000 链路）P95 < 2s |
| N2 | 完整性 | 连接/拓扑输出条数与库内可见资产一致，不得静默截断 |
| N3 | 并发 | 并发 refresh 单飞；缓存读写线程安全 |
| N4 | 安全 | 权限以 `ASSET/READ` / `ASSET/UPDATE` 判定；不返回其他项目私有资产 |
