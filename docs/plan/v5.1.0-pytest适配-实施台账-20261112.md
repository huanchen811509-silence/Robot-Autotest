## 五、过程中修掉的三处「自造事实」

这三处都是「代码里写着、机制其实不存在」，属于最容易骗过评审的那类：

1. **`PYTEST_ARTIFACT_ROOT` 环境变量**——我最初在命令 env 里设了它，声称能把证据目录搬走。
   实际框架 `Runtime(artifact_root="artifacts")` 是硬编码，**不读任何环境变量**。
   已删除该变量并加单测断言它不存在；证据定位改为 `artifactRoot(repo, runId) = <repo>/artifacts/<run_id>`，
   由 `run_env.run_id`（唯一真实可控项）决定目录名。
2. **`check_pytest_artifact.py` 的 `file_stem`**——先按点取末段再剥 `.py`，导致索引键全变成
   `py::函数名`，反查永不命中，而「匹配键 61 / 命中 61」的计数看起来完全正常。
   已改为与 Java 同序（先剥 `.py` 再取末段）。
3. **`PytestEnvRenderer.resolveDevices()` 检查顺序**——先判空再核「点名的主机是否存在」，
   点一台不存在的主机会报「未选中任何设备」，把排查方向引偏。已调换顺序。

### 7.3 本轮修掉的四处「看着绿其实没生效」

1. FailureFingerprint 用词边界正则抹耗时——`5000ms` 里 `0` 与 `m` 都是词字符，**根本没抹掉**，
   导致同一失败永远聚不到一起。改为无边界 `\d+`，并补「带单位的耗时数字也要被抹掉」回归用例。
2. 命令集合的 `-p Sup3rSecret` 是**两个 argv 元素**，单参数正则认不出 → 改为按位置取下一个参数掩码
   （VALUE_FLAGS，纯数字视为端口而不掩码），机检脚本同步改为 token 级判定。
3. executionEvent 的 name 被加了 `event:` 前缀——数据里带显示装饰会同时污染过滤与统计，已去掉。
4. 连接类错误（network is unreachable / Connection refused 等）被判成断言失败，后果是
   「该重试不重试 + 环境雷达低估」；FailureRuleSet.defaults() 已补该族关键字。

### 7.7 本轮新增的一个必踩坑：运行中的 jar 被覆盖 → 登录 30s 超时

`mvn test` / `scripts/build.sh` 会重写 `backend/target/robot-autotest-backend-*.jar`。
systemd 跑的正是这个 jar，**JVM 只在需要时懒加载类**，jar 被替换后旧进程再去加载新类就抛：

```
NoClassDefFoundError: ch/qos/logback/classic/spi/ThrowableProxy
```

表现不是「启动失败」，而是**登录接口 30s 超时**（`/api/_ping` 仍 200，看起来服务正常），
于是门禁 23 `version_consistency` 与 24 `ai_eval` 双双 timed out。

处置：**构建后必须重启后端**（`systemctl --user restart robot-autotest-backend`，本次 8s 就绪），
不要拿「`_ping` 200」当「服务健康」。这也是 §一 那条「源码对齐≠部署对齐」的第二副面孔。
