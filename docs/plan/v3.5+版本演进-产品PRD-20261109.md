## 0. 结论先行

1. **本轮的定位不是继续加功能，而是「把已经做出来的东西证明好用、把欠账收干净、把新能力变成稳态」。** v3.1.0–v3.4.0 在 2026-11-08 一天内交付了体验、性能、AI、规模化四条线（`CHANGELOG.md` `[已核实]`），功能面从 57 个 Controller / 222 个路由涨到 68 个 / 345 个路由注解，表从 71 涨到 87（`[已核实]`）。但上一轮 PRD 承诺的效果类指标（Top 8 任务成功率、SUS、搜索命中率、跨浏览器、真实用户性能、diff 覆盖）在 `CHANGELOG.md` 与 `docs/evidence/v3.*` 中**没有对应证据**[已核实]。**功能已交付、效果未验证**，这是 3.5+ 要解决的第一矛盾。
2. **第二条矛盾是基线不可复现**：v3.1–v3.4 的实现在 WSL 与 E 盘两个工作副本中**都还没有形成提交**（两仓 HEAD 同为 `4dea84a`，2026-11-08 15:46）[已核实]；WSL 工作树 2940 项变更中 2765 项是文件模式位 `100644→100755` 噪声、175 项未跟踪[已核实]。不先固化基线，任何打磨都建在浮沙上。
3. **第三条矛盾是门禁"步数涨了、汇总没跟上"**：`scripts/gates.sh` 已声明 27 步[已核实]，11-09 00:02–00:05 的分步日志显示 12/13/20–27 各步均为 PASS[已核实]，但 `00-full-run.log` 仍是 **11-08 12:06 的 19 步 `FAILS=2` 旧汇总**[已核实]。**不得拿旧汇总当现状，也不得据分步日志宣称 27 步全绿。**
4. **演进分四条版本线**：v3.5.0「可证明」（基线固化 + 效果度量 + 回写）、v3.6.0「精修」（用数据定向打磨六项产品目标）、v3.7.0「稳态」（新能力运营化、韧性、安全、变更管理）、v3.8.0「规模化 / GA 准备」（候选，需大师拍板）。补丁线只修缺陷。
5. **行业实践落到判据，不停留在口号**：WCAG 2.2 AA、Core Web Vitals（LCP / INP / CLS，p75）、DORA 四指标 + 可靠性、Google SRE 的 SLI/SLO/错误预算、NIST AI RMF 与 OWASP LLM Top 10（2025）、ISO/IEC 25010 质量模型、测试分层与 diff 覆盖、渐进式交付——每条都映射到具体 FR 的可判定判据（§12.2）。
6. **发版判定权不转移**：G4 / G5 / G7 / G8 未判、G6 七日观察钟未启动、6 个「待现场」包未验、ADR-0013 开发期禁跑令仍有效[已核实，见 §1.6]。**3.5+ 的版本验收不替代既有发版门禁，也不产生任何对外口径。**

一句话验收：**上一次是"做出来了"，这一次要能拿出证据说"确实更好用、更快、更稳、更可信，而且说得出哪里还不行"。**

| 测试负责人 | 掌握进度、对比趋势、分派与复盘 | 视图复用率、报告对比 / 趋势可用、SUS |
| 平台管理员 | 权限、节点、归档、准入、安全、备份可控 | 告警触达、RTO/RPO、审计完整 |
| 新人 / 临时用户 | 不培训能上手、误操作能退 | 引导完成率、撤销成功率、错误提示可恢复率 |
| 外部报告接收方 | 数字可信、口径一致、不涉及敏感信息 | metadata 十项齐全、对外字段白名单、事实可追溯 |

### 2.2 Top 8 任务（体验基线的固定脚本，v3.5.0 冻结）

T1 建项目并配置内核 / 资产 → T2 导入或编辑用例并保存 → T3 从台账挑用例发起运行 → T4 运行中查看进度 / 日志 / ETA → T5 定位失败用例与证据 → T6 生成并导出报告（内 / 外两种口径）→ T7 用搜索 / 保存视图找回历史运行 → T8 管理员处理归档 / 节点 / 告警。

> 这 8 条脚本在 v3.5.0 冻结，之后每版用**同一脚本**复测，禁止改脚本来「优化」数字。

### 2.3 典型痛点（本轮要解决，不做新功能域）

1. 功能都在，但**找不到 / 步骤多**：搜索有了却没测过命中率，保存视图有了却没测过复用率 [推断]。
2. 报告能出，但**结论要人自己拼**；跳过数、基线、失败聚类散落在多页 [已核实：v3.1 已加速览卡，效果未测]。
3. 出错时**只知道失败，不知道下一步**：错误文案与诊断 ID 未做全站走查 [推断]。
4. 机器预算达标但**真实交互体验未知**：无 LCP / INP / CLS、无跨浏览器矩阵 [已核实]。
5. AI 能答但**采纳率不明**：黄金集 20/20 是机器分，缺用户侧采纳与拒答体验数据 [已核实 + 推断]。
6. 新能力（归档 / 准入 / 配额 / 告警）**上线了但没人练过故障**：默认停用、409 背压、降级路径缺演练记录 [推断]。

### 3.3 护栏指标（不可为达标而交换）

- 不因体验优化降低权限、审计、脱敏、metadata 十项门禁与对外字段白名单能力。
- 不因性能优化改变执行结果语义、状态映射、报告口径与历史 run 事实。
- 不因 AI 引入自动改代码、自动提交、自动执行真机 / 实网动作；高影响动作必须人工确认。
- 不伪造真机、实网、负载、用户测试结果；现场项只记真实结果或 `BLOCKED`。
- 不降低既有门禁阈值、不删门禁步骤、不改测试来迁就实现。
- 不因「打磨」擅自重做主题、替换双内核、引入分布式组件。

### 3.4 非目标（明确写出来防蔓延）

- 不做微服务化 / 分布式重写，不引入多租户公有云形态。
- 不做原生移动端；仅保证 760px 以上桌面 / 平板可用。
- 不新增与「打磨存量」无关的大功能域（新资产模型、新执行引擎、新报告体系）。
- 不承诺真实 CI Runner 自动注册、真实 DUT 全量自动化、G 门判定与正式发版。
- 不在本阶段把 AI 从「辅助问答」升级为「自主执行代理」。

## 6. UI/UX 与用户体验规范（增量，不重做主题）

### 6.1 设计原则

1. **一致性优先于新奇**：在既有令牌、页面原语、Naive UI 组件上增量，不换设计语言。
2. **渐进披露**：高频操作一步可达，低频操作收进二级；用保存视图替代重复配置。
3. **防错与可退**：危险动作确认 + 一次撤销 + 草稿恢复（Nielsen 启发式 3/5/9）。
4. **状态可见**：加载、空、错、成功、只读、无权限六态都有明确反馈与下一步。
5. **Jakob 定律**：沿用用户已熟悉的行业惯例（表格、筛选、快捷键），不发明新交互。
6. **可访问即好用**：键盘、焦点、对比度、动效偏好是默认要求，不是补丁。

### 6.2 设计系统增量

| 项 | 要求 | 判据 |
|---|---|---|
| 令牌 | 语义色 / 间距 / 字号 / 圆角 / 层级 / 动效时长集中定义，DTCG 风格命名 | 令牌扫描 0 硬编码色；门禁 15 / 27 步不回退 |
| 页面原语 | `PageHeader` / `Toolbar` / `FilterBar` / `DataGrid` / `EmptyState` / `ErrorState` / `Skeleton` / `StatusBadge` / `FormField` / `ConfirmDialog` / `SidePanel` / `Toast` | 核心页覆盖率 100% |
| 状态矩阵 | 每页六态 × 明暗 × 密度组合有快照 | 四档走查截图齐，视觉差异有人工结论 |
| 动效 | 仅在 `transform` / `opacity` 上做；`prefers-reduced-motion` 下关闭 | 走查 + 机检 |
| 图标与文案 | 图标按需加载；错误文案「原因 + 下一步 + 诊断 ID」；不用颜色单独表意 | 文案走查 100% |

### 6.3 WCAG 2.2 增量清单（相对 2.1 的新增准则）

| 准则 | 落地要求 | 验收 |
|---|---|---|
| 焦点外观 / 焦点不被遮挡 | 焦点环尺寸与对比度达标，弹层不遮焦点 | 键盘走查 + 截图 |
| 目标尺寸（AA 最小 24×24 CSS px） | 图标按钮 / 表格行操作 / 分页控件达标 | 机检 + 抽检 |
| 拖曳替代 | 抽屉宽度拖拽除外的所有拖放有键盘 / 按钮替代 | 键盘用例 |
| 一致帮助 | 帮助入口在各页位置一致 | 走查 |
| 避免重复输入 | 表单草稿 / 自动填充不要求重输 | 任务测试 |
| 可访问认证 | 不依赖记忆 / 解谜类认知测试 | 走查 |

### 6.4 内容设计与反馈

- 错误文案三段式：**发生了什么 + 为什么 + 下一步怎么做**，附诊断 ID（对应 `X-Request-Id` / traceId）。
- 「跳过」「部分通过」「无数据」「未测量」四种状态不得混用；无数据显示「未测量」而非 0。
- 对外报告字段白名单不变；metadata 十项门禁不变；AI 结论必须区分事实 / 推测 / 建议三段。

## 8. 数据与产品度量

### 8.1 原则

**最小、可选、透明、可关**：服务端聚合优先；客户端事件仅在内部评估期开启；不采凭据、令牌、用例正文、实网配置、设备口令；所有事件字段进事件字典并过隐私评审。

### 8.2 最小事件集（建议，v3.5.0 冻结）

| 事件 | 字段（不含内容） | 用途 |
|---|---|---|
| `task_step` | 任务 ID、步骤序号、耗时桶、结果码 | 成功率 / 耗时 / 步数 |
| `search_query` | 查询集 ID、Top3 是否命中、零结果标记 | 搜索质量 |
| `form_submit` | 表单 ID、校验拦截 / 成功、耗时 | 一次提交成功率 |
| `error_shown` | 错误码、是否含下一步、诊断 ID 存在性 | 错误可恢复率 |
| `ai_answer` | 会话 ID、时延桶、是否采纳、是否拒答、是否降级 | 采纳率 / 时延 / 降级 |
| `route_nav` | 路由 ID、加载耗时桶、CWV 采样 | INP / LCP / CLS |

### 8.3 看板与口径

五类（体验 / 性能 / 运行 / AI / 运维）共用一份数据字典；**机器预算（API p95、包体）与用户体感（CWV、任务耗时）并列展示，不互相替代**；无数据显示「未测量」。
