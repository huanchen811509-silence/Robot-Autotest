1. **本计划只做存量打磨，不新增功能面。** 工程策略固定为「度量先行 + 局部治理 + 零新增表 + 零破坏性 API + 双内核执行链零改动」，收益来自度量补证、局部治理、机检加固与证据归档，不来自重构或换肤。

## 附录 B · 已踩过的坑（本版禁止重复）

1. `check_md_tables.py` 把表格单元格内代码中的裸竖线当列分隔符，须转义；代码块与引用块内不受影响，不要全局替换。
2. `check_release_docs.py` 只认全编号 `FR-v<version>-NN`；区间写法会被展开成短编号判孤儿。
3. `check_colors.py` 连 `var(--accent, #2563eb)` 的 fallback hex 也拦；`check_tokens.py` 的 px 白名单不轻易扩。
4. `gen_build_info.py` 必须在**合并后**重跑，且 `mvn package` 阶段会重生成，顺序反了运行期 commit 就滞后。
5. `check_delivery_bundle.py` 取 `sorted(releases/*.tar.gz)[-1]`，同版本两个包时旧包必须先归档。
6. `curl` 的 `--noproxy '*'` 不加引号会被 shell 展开成当前目录文件名。
7. `db_exec` 查不带库名限定的 SQL 必须加 `-D "$DB_NAME"`；已应用 Flyway 迁移不可改只能追加。
8. 负向验证必须「备份 → 注入 → 定向判据红 → 备份还原 → 复跑绿」，禁止用 `git checkout` 还原。
9. 就绪探针打 `:8081`；`:8001/_ping` 是 node 入口自回 200，不算数。
10. `docs/evidence/gates/logs/` 被 `.gitignore` 忽略，报告引用它会导致 clone 后不可复核。
11. 源码对齐 ≠ 部署对齐：systemd 跑 `backend/target/*.jar`，改码须重建 jar 并重启服务。
12. WSL 非登录 shell 没有 node 进 PATH；`npx` 会落到 Windows shim 报 UNC 路径不支持，需显式 `/opt/node22/bin/node`。
13. `output.xml` metadata 十项字段、`RUN_ID` 键名、值 ≤40 字符均不变；metadata 不得放凭据。
