## 1. 结论先行（七条）

1. **交接文档的功能读数成立**：W0–W5 六个波次的功能确已落地。`scripts/gates.sh` 有第 18 步，逐步日志 01–17 时间戳 22:15–22:17，后端 `Tests run: 985, Failures: 0, Errors: 0`、前端 `44 files / 299 tests`，`PERF_RESULT PASS`；双远程 `origin` / `github` 的 main 均为 `ffae7e6`，工作区干净。
2. **但「六个波次全部完成」是功能口径，不是 W0 的退出判据**。中期规划 §3 给 W0 的退出条件是「P0=0、PARTIAL ≤10、6 待现场清零或书面降级、G4/G5 可判」；实测 v2.0 台账仍 **PASS 16 / PARTIAL 44 / NOT-RUN 7**，6 个待现场包仍在，G4/G5/G7/G8 仍未判。八个 W0 子项中只有 **W0.1 / W0.2 / W0.8** 有证据包，W0.3 / W0.4 / W0.5 / W0.6 / W0.7 未检索到收口证据。按规划 §7.6 第 6 条，宜改记为「功能子项完成、收口子项未结」。
3. **后续中期工作的重心必须从「开发」切到「收口 → 判定 → 试点」**。中长期规划 §5.10 运营期 Q1–Q4 的功能面，已被 W0（P0/日志）、W4（性能基线/备份/告警）、W5（覆盖/编排/聚类）、W1（提效）、W2+W3（扩展/分布式）基本覆盖；规划里**最大一块未启动的工作是 §5.9 的 B8 试点迭代（R0）**，而它的进入条件是 G7 判过，不是「再写一批功能」。
4. **最优先的是文档回写与治理收口（层 S，8 项，0 外部条件）**：测试台账未回写、WBS 双轨分母（130 台账 vs Q7 拍板 143）、门禁汇总日志仍是 17 步旧版、交接文档提交链读数过期、最终交付报告「147 项未提交变更」已被后续提交推翻、v2.1 PRD 仍「待评审」、规划自身 96/130 口径并存、XLSX 已落地但非目标表未撤销。这些正是规划 §7.6 第 5/6 条列的「文档漂移 / 假进展」——**不补则 G 门连核验对象都不一致**。
5. **仍存在真功能缺口，不是「证据不足」**：TC-04 通过率分母（1P1S 实测 5000bp，PRD 要 10000bp）、TC-05 测试报告 PDF 中文标题变 `????`、TC-09 跨 run 对比/趋势（W0.1 已修入库路径，需复验后回写）、TC-27 超时文案不含内核名、G-A9-1~3 AI 真实调用缺口、双内核矩阵 **M1–M10 仍有 9 组 PARTIAL**、T4 抽样比对无记录。G8 第 2 条「M1–M10 全过」远未满足。
6. **墙上时钟是最容易漏的排期风险**：`G6-启动记录-20261104.md` 明确写「提前挂起观测，**正式 7 天仍从 G5 通过当天起算，本记录不构成计时开始**」，且当时 `execution_plan` enabled=0、触发样本 0。规划 §16.1 规定 G5 通过当天启动；**判 G5 当天必须同时创建 enabled 合成用例每日计划并记第 1 天**，否则上线门硬卡 7 天。同理 G4 的 20 轮 4 并发压测、G7 的 UAT 8 条与回滚演练需提前预约。
7. **下一批性质需大师拍板**：收口/判定版 vs 扩功能版；WBS 分母与波次编号；现场日与 `G-授权`；G4/G5/G7/G8 判定时点；运营期 B8 是否立项。学徒不擅自决定，详见 §7。
