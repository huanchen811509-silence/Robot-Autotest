## 三、22 个失败的真根因（含证据链）

### 3.1 现象

`run_20261030_120849`：26 用例 4 通过 / 22 失败，全部报
`Imported library 'metrics_collector.py' contains no keywords`。

### 3.2 定位过程

1. **证明 RF 没坏**：`RECORD` 校验 278 个文件哈希 0 不符、0 缺失、0 多余；
   与官方 wheel 逐字节 `diff -rq` 无差异。
2. **证明不是自研库写错**：连最小 ASCII 库都能复现——
   ```python
   class AsciiLib:
       def hello_world(self): ...
   ```
   `robot.libdoc ascii_lib.py list` → 空；`robot` 运行 → `contains no keywords`。
3. **证明发现引擎本身可用**：`TestLibrary.from_class(AsciiLib)` →
   `[StaticKeyword(name='Add Numbers'), StaticKeyword(name='Hello World')]` 正常。
4. **锁定差异点**：走"按名字/路径导入"时才失败。RF 源码
   `robot/utils/importer.py`：

   ```python
   def _get_class_matching_module_name(self, module, name):
       cls = getattr(module, name or module.__name__, None)
       return cls if inspect.isclass(cls) else None
   ```

   这是**精确匹配**：`metrics_collector.py` 的 `module.__name__` 是
   `metrics_collector`，类名是 `MetricsCollector` → `getattr` 取不到 →
   回退成"模块级库"→ 模块里没有函数 → 0 关键字 → warn `contains no keywords`。

### 3.3 根因结论

**RF 要求「类名与模块（文件名）名严格一致」**（如 `MyLibrary.py` + `class MyLibrary`），
或用 `ROBOT_AUTO_KEYWORDS` 显式声明。本项目 `metrics_collector.py` + `class MetricsCollector`
不符合该约定，因而库永远发现 0 个关键字。

> 时间线上也吻合：`06:26` 那次 **26/26 全通过**（彼时该库尚未引入），
> `11:35` 引入 `libraries/metrics_collector.py` 后立刻变成 4/22。

### 3.4 三种候选修法实测（在 `/tmp/libprobe` 隔离验证）

| 方案 | 做法 | 结果 |
| --- | --- | --- |
| A | 文件名改为 `MetricsCollector.py` 与类名一致 | ✅ 关键字可发现 |
| B | 加 `@library` 装饰器 | ❌ 仍然空（RF 7.5 该回退路径未命中） |
| C | 改点号导入 `metrics_collector.MetricsCollector` | ✅ 可发现（需配 `--pythonpath`） |
| **D** | **类里加一行 `ROBOT_AUTO_KEYWORDS = True`** | ✅ **可发现，改动最小，不动文件名/不动导入语句** |

### 9.3 本轮修复的截断问题（重要）

**问题**：RF 默认 `--maxassignlength 200`，赋值消息被截到 200 字符，导致 `ping` 的
`packet loss` / `rtt min` 统计行、`free -m` 的 `Mem:` 行、`df` 的表头**根本没落盘**。

实测对比（run_14 未修 vs 修复后）：

```
未修复: Executing command = 8 次  |  packet loss = 0 次   （命令原文在，输出丢了）
修复后: Executing command = 48 次 |  packet loss = 16 次  （输出完整）
```

**试过但无效的三种方案**（记录以免下次返工）：

| 方案 | 结果 |
|---|---|
| 项目根放 `robot.toml` | **无效**——RF 7.5 源码里 `grep -r toml` 结果为 0，根本不支持 toml 配置 |
| 平台 `advanced_config.args` 传 `--maxassignlength` | **被拦**——`403 feature_disabled:executionAdvancedArgs` |
| `--maxassignlength 0` | **反效果**——0 表示"完全不显示赋值"，只剩 `...` |

**最终采用**：在 `resources/common.robot` 三个采集点各加 `Log    ${out}`，不依赖任何
runner 配置，界面跑和手工跑同时生效。改动 3 处、共 9 行，`output.xml` 从 59KB → 240KB。

### 9.5 RoboScope「详细报告」看不到命令 —— 平台解析缺陷已修（2026-10-30 21:18）

**现象**：命令的输出确实进了 `output.xml`，但 RoboScope 报告页的 `Detailed Report` 标签页里，
ping、磁盘检查这些在 `FOR` 循环里执行的关键字**整段消失**，只留下循环外的少量步骤。

**根因**（`src/reports/parser.py`）：

```python
# 修改前
child_keywords = []
for child_kw in kw_elem.findall("kw"):        # ← 只找「直接子 kw」
    child_keywords.append(_parse_keyword_deep(child_kw))
```

RF 7 把循环存成 `<for><iter><kw>`，`<kw>` 不是直接子节点，所以 `findall("kw")` 一个都取不到。
`if` / `try` / `group` 同理。这不是配置问题，是解析器没实现控制结构展开。

**修法**：新增 `_collect_keywords()`，递归下降 `for` / `while`（取 `iter`）、`if` / `try`（取 `branch`）、
`group`，把里面的关键字提升到父级，并加位置前缀 `[FOR 1]`、`[ELSE]` 等标记迭代序号。
`_parse_keyword_deep` 与 `_parse_test_deep` 都改用它（2 处替换 + 1 个新函数）。

**效果**（report#8 / run#16 实测）：

| 指标 | 修改前 | 修改后 |
|---|---|---|
| 关键字节点数 | 342 | **514** |
| `packet loss` 消息 | 0 | **16** |
| `Executing command` | 40 | 48 |

界面 Detailed Report 展开后可见完整链路：

```

  - Log
    | ping -c 2 10.202.54.101 原始输出:
  - Log

```
