# v5.18.0 产品需求文档（PRD）：缺口闭合（二）建设与清场

> 流程位置：③ PRD（草案）。**待 v5.17.0 收口后进 ④**，进 ④ 时整体移入 `docs/release/v5.18.0/` 并补齐六份产物。
> 上游：`01-ASSESSMENT.md`（本批共用的缺口评估，位于 `../v5.17.0/`，含大师 D-1~D-4 拍板与清场盘点）；本版 00-RESEARCH / 01-ASSESSMENT 进 ④ 时按本版范围单独补。
> 版本号 `v5.18.0` 为**拟用号**，本文件不修改 `VERSION`。
> **每条需求必须可判定**：写不出判据的不算需求。

## 1. 版本定位

| 项 | 内容 |
|---|---|
| 一句话 | 把九版欠账里**要从零建**的 6 项做出来，并在收口时**把开发期留下的临时账号与临时项目清干净** |
| 性质 | **建设 + 清场版**：前半段建组件/抽页面/接拓扑，后半段清场，缺一不可 |
| 上游 | 5.17 已完成 7 项取证与接线；本版接剩下 6 项 + 新增清场 1 项 |
| 不追求 | 不新增菜单、不改主题、不重写用例页与报告页 |

### 1.1 为什么清场必须和建设同版

清场要清的是「5.8~5.18 全程」的残留，包括 **5.17 自己造的演示项目与 500 台压测样本**、以及本版造数。
若把清场单独放一版，这一版又会产生新的残留，永远追不上。**清场放在本版最后一波，作为收口的前置条件。**

## 2. 约束与术语

| 术语 | 含义 |
|---|---|
| 临时对象 | 开发期创建、无真实业务用途的账号与项目（含其用例/用例集/报告/设备/凭证） |
| 三信号判定 | `is_demo=1` / 引用面为零 / 非内容资产规模；**禁止按名字猜** |
| 内容资产 | 有真实用例规模且被文档当作资产引用的项目（`ED202-COMMON` 813、`PLATFORM-LIB` 730、`EHT-PYTEST-LIB` 469） |
| 引用面 | `scripts/` `tools/` `frontend/src/` 中对某账号/项目的引用；被探针与门禁引用的不可删 |
| 仅实测 | 拓扑过滤态：只保留 `source=MEASURED` 的边 |

**硬约束**：

1. **不新增菜单**：导入向导留在操作列，拓扑不新增页面。
2. **删除类动作双闸**：`--apply` + 确认变量；库名只认 `_it`（运维恢复）。
3. **清场前必须备份**并校验 hash；真对象零变化是硬判据。
4. **迁移只能追加**：从 `V11_79` 起（本版预期零迁移）。
5. **门禁只增不减**：新增机检带 `--self-test`。

冲突预览返回 `toCreate / toUpdate / conflicts`。

**验收判据**

| # | 判据 | 证据形态 |
