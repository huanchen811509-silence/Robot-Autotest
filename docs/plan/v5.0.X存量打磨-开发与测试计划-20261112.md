## 0. 结论先行

1. **五批次顺序不可跳**：B0「先证明」→ B1「看得清点得着」→ B2「跑得快」→ B3「靠得住」→ B4「守得住」。B0 未冻结四项口径冲突（C-01~C-04）与效果基线，B1/B2 的任何「提升」都不可判定。
2. **本版工程策略是「零新增表、零破坏性 API、零执行链改动」**。所有收益来自度量补证、局部治理、机检加固与证据归档；需要新表或改双内核的需求一律退出本版。
3. **30 条 FR ↔ 30 个 WBS 包 ↔ 42 条 TC**，编号一一可追；新增 4 个机检脚本全部带 `--selfcheck` 负向注入，门禁从 32 步扩到 36 步，**只增不删、不降判据**。
4. **测试纪律沿用项目硬规矩**：只认真实链路；单测绿 / 构建绿不是放行理由；未测或未过不填 PASS；`NOT-RUN` / `BLOCKED` 必须写阻塞原因与所需条件；不接受实现方自证。
5. **实验室与现场分离**：本机 CDP、离线契约、fake CLI、小数据冒烟的结果不得折算成真实用户、真实端点或真机达标。
6. **本轮仍止于文档**：首轮评审已完成、D1~D9 按建议裁定；本合订本自此留档，执行依据为拆出的两份独立计划。**开工授权尚未下达**：未编码、未测试、未跑门禁、未改 `VERSION` / `CHANGELOG`、未提交、未推送、未同步 WSL、未判 G 门、未发版、未产生对外口径。

## 2. 工程策略与架构设计

### 2.1 设计原则

| 原则 | 落地方式 |
|---|---|
| 度量先行 | B0 建基线与口径裁决，之后每项目标都有前后两份证据；无基线判 `PARTIAL` |
| 局部治理 | 只改被证据定位的模块；不引入新框架、不换组件库、不拆服务 |
| 零数据改动 | 目标零新增表与零新增列；确需时从 `V11_46` 起追加并配 down |
| 机检守门 | 每个新判据配一个可 `--selfcheck` 的脚本，删步骤或注入反例必须判红 |
| 证据可复核 | 所有证据落 `docs/evidence/v5.0.0/` 入库路径，不引用被忽略的 `gates/logs/` |
| 可回退 | 新能力默认关闭；危险操作先 dry-run；回滚脚本先备份再动 |
| 不伪造 | 现场、真机、人工、真实端点类未执行一律 `NOT-RUN` / `BLOCKED` 并写阻塞原因 |

### 2.3 后端设计要点

1. **契约层**：`openapi.json` 与 `gen_api_contract.py` 为端点单一真源；新增 `tools/check_doc_endpoints.py` 扫描两份规划文档，端点命中率 100%、零孤儿。禁止在文档里写计划端点当作已实现。
2. **性能层**：`perf_baseline.py` 的 5 个只读 GET 保持原判据；长列表与运行链压测走独立脚本 `tools/perf_longlist.py` / `tools/perf_runchain.py`，输出样本规模、机器规格、轮次、p50/p95，接门禁第 22 步同批取证。
3. **安全层**：凭据、令牌、现场口令不进证据、日志、metadata、文档；`secret-scan.sh` 与 `check_report_sensitive.py` 为零容差；真注入用备份拷贝还原，禁止 `git checkout`。
4. **AI 层**：评测协议与真实端点调用分离。协议与脱敏边界在 B3 完成；真实端点调用为 P2 且需大师单独授权，未授权时 `NOT-RUN`，不得用 fake CLI 20/20 折算。
5. **状态层**：六态字典（成功 / 部分 / 未执行 / 失败 / 阻塞 / 降级）由单一文件导出，采集、报告、台账三处引用；不新增「不适用」状态（沿用 v4.12 测试报告 §6 裁决）。

### 2.4 前端设计要点

1. **令牌**：颜色一律 `var(...)`，`check_colors.py` 连 fallback hex 也拦；断点复用既有档位，不扩 `tools/px-allow.txt`；`DataTable` 壳覆盖率维持 56 处不下降。
2. **无障碍**：18 处交互目标按 WCAG 2.2 最小 24×24 CSS px 整改；焦点环 ≥3:1、200% 缩放、键盘 Tab 顺序逐页走查；自动化扫描覆盖约 57%，其余标注「需人工」。
3. **表单**：暗色下拉走同一令牌，不写死背景；`dark-select-probe.mjs` 保持「备份主题偏好 → 跑完还原」。
4. **密度**：全量列表页重新盘点（v4.x 已改造，不沿用 11-09 的旧读数作基线）；分页组件统一，禁止 `size=10` 散落硬编码；密度探针判据「分页下方空白 ≤120px 或 ≤10%」。
5. **浮层**：危险确认保留模态但遮罩避让顶栏（沿用 v4.x 工作区浮层定位层决策）；不新增全局遮罩层。
6. **国际化**：新增文案双语同步、零硬编码中文；C-01 裁决后按统一口径跑 `check_i18n.py`。

## 附录 B · 已踩过的坑（本版禁止重复）

1. `check_md_tables.py` 把表格单元格内代码中的裸竖线当列分隔符，须转义为 `\|`；代码块与引用块内的竖线不受影响，不要全局替换。
2. `check_release_docs.py` 只认全编号 `FR-v<version>-NN`；区间 `FR-v4.10-01 ~ 04` 会被展开成短编号判孤儿。
3. `check_colors.py` 连 `var(--accent, #2563eb)` 的 fallback hex 也拦；`check_tokens.py` 的 px 白名单不轻易扩。
4. `gen_build_info.py` 必须在**合并后**重跑，且 `mvn package` 阶段会重生成，顺序反了运行期 commit 就滞后。
5. `check_delivery_bundle.py` 取 `sorted(releases/*.tar.gz)[-1]`，同版本两个包时旧包必须先归档。
6. `curl` 的 `--noproxy '*'` 不加引号会被 shell 展开成当前目录文件名。
7. `db_exec` 查不带库名限定的 SQL 必须加 `-D "$DB_NAME"`；已应用 Flyway 迁移不可改只能追加。
8. 负向验证必须「备份 → 注入 → 定向判据红 → 备份还原 → 复跑绿」，禁止用 `git checkout` 还原。
9. 就绪探针打 `:8081`；`:8001/_ping` 是 node 入口自回 200，不算数。
10. `docs/evidence/gates/logs/` 被 `.gitignore` 忽略，报告引用它会导致 clone 后不可复核。
11. 源码对齐 ≠ 部署对齐：systemd 跑 `backend/target/*.jar`，改码须重建 jar 并重启服务。
12. WSL 非登录 shell 没有 node 进 PATH；`npx` 会落到 Windows shim 报 UNC 路径不支持，需显式 `/opt/node22/bin/node`。
