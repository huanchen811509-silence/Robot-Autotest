# CLI 多 agent 接入与内置兜底 · 评估增补（2026-11-08）

> 承接：`AI助手可用性评估增补-20261108.md`（FR-AI-01..08）、`v2.3-PRD-增补草案`（界面与主题）。
> 触发：大师 2026-11-08 指示「CLI 要增加 Hermes agent、deepseek harness TUI，保底在软件包里集成一个 pi agent」。

## 1. 结论先行

三件事可以一次做完，且已具备可判定条件：

| # | 事项 | 结论 | 关键事实 |
|---|---|---|---|
| 1 | 接入 Hermes agent | **可做，已实测可用** | `hermes -z '<text>'` rc=0，本机输出「已连通」，9270 ms |
| 2 | 接入 DeepSeek Harness（`dsh`） | **集成可做，真实推理待凭据** | `dsh headless '<text>'` 能起进程并给出结构化错误：`MISSING_CREDENTIAL ... DEEPSEEK_API_KEY`；用 ARK key 会被判 401 |
| 3 | 软件包内置 pi agent 兜底 | **可做，已端到端成立** | pi 1.5.0（MIT）装到独立目录，后端在 PATH 收窄到只剩它时仍返回「已连通」，1697 ms |

同时暴露并修掉一个**只有真实链路才会暴露的缺陷**：内置 pi 的 npm bin 是 `#!/usr/bin/env node`，
只认调用方 PATH 上的 node；后端 systemd 的 PATH 不含 node 时被判 `exitCode=127`，「兜底」等于没有。
现在由 `bin/pi` wrapper 自己解析 node，同一 PATH 下 rc=0。

**场景 B 的意义**：把后端 PATH 收窄为 `/usr/local/bin:/usr/bin:/bin`，让 hermes / dsh / claude / codex / gemini / aider

这就是「保底」两个字的可判定形态。

## 3. 方案对比

| 方案 | 做法 | 优点 | 缺点 | 采用 |
|---|---|---|---|---|
| A. 不自己做，只写文档教用户装 | 文档说明如何自行安装三条 CLI | 零成本、零体积 | AI 面板在「什么都没有」的机器上永远停在 L1，等于没解决 | 否 |
| B. 只加候选，不做内置 | `CANDIDATES` 扩到 7 条，全靠 PATH | 改动极小 | 本机实测仍有 4 条不可用；用户装不上就等于全废 | 否（只采纳一半） |
| C. 加候选 + 内置 pi 兜底 | B 的基础上随包安装 pi，并加 wrapper 解决 node 依赖 | 最坏情况仍能作答；pi 为 MIT、单入口 | 安装目录 158 MB；pi 版本迭代快 | **是** |
| D. 自研 agent | 自己写一个最小 CLI | 完全可控 | 与「不做重复轮子」冲突，且维护成本高于收益 | 否 |

## 6. 风险登记册

| 编号 | 风险 | 影响 | 处置 |
|---|---|---|---|
| R-1 | 内置副本 158 MB，显著增大安装体积 | 分发成本上升 | 安装按需触发（`ensure-pi-agent.sh`），不随 jar 打包；文档写明体积 |

| R-5 | 探测只看「可执行文件在不在」，不代表能推理 | 选中坏 CLI 后失败 | 既有降级路径已覆盖；`distinguishes_runnable: false` 写进配置档 |

## 7. 明确「不做」清单

- 不代管、不代填、不落库任何 CLI 凭据（`never_log_credentials: true` 保持）。
- 不把 pi 的 158 MB 依赖塞进 git 仓库或 Maven 产物。
- 不为 dsh 造 DeepSeek key，也不把 ARK key 冒充 deepseek key（已实测会被 401）。
- 不改这三条 CLI 的交互式形态（Hermes 的 TUI、dsh 的 `dsh tui`、pi 的交互模式）；后端只走非交互。
- 不在本批扩 WBS 分母（仍 124 完成 / 6 待现场）。

## 8. 关于「deepseek harness TUI」的口径澄清

大师原话里的「tui」是产品形态名：`dsh` 的 `tui` profile 供**人**在终端里交互使用，
而后端集成必须走 `dsh headless '<text>'`（单次任务、打印结果即退出）。
两者共用同一套 profile 与凭据，只是入口不同。本批集成的是 `headless` 入口；
`dsh tui` 保留给人工排障，后端不启动任何 TUI（无法在无 TTY 的子进程里工作）。

本机 `~/.dsh/profiles` 目前只有 `headless` 与 `web`，**没有 `tui` profile**；
若大师要用 TUI，需先 `dsh tui --from-default-profile tui` 生成，属人工操作，不在本批范围。
