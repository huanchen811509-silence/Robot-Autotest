### W2 · v2.2 分布式分片执行

**目标**：一个 run 可按策略拆分到多个执行节点，结果与单节点等价。

- **模型**：`execution_shard`（run_id, shard_no, case_scope, node_id, state, attempt, lease_until, fencing_token）；
  状态机 `PENDING → LEASED → RUNNING → PASSED/FAILED/LOST`。
- **分片策略**：默认**按套件**（保住 Suite Setup/Teardown 语义）；可选按用例（仅限无套件级状态的用例集）；
  按计划分片只在"套件间无共享 fixture"时开放。
- **调度**：节点资格（内核版本、标签、在线、并发余量）+ 负载最小 + 亲和；租约 TTL + fencing token 防双写。
- **聚合**：shard 结果按原顺序回写 `test_result`；根 run 的 metadata 只写一次；套件树跨分片合并。
- **API/UI**：run 创建增加 `shardPolicy`；run 详情显示分片看板（每片状态/节点/耗时）；保留单节点路径为默认。
- **等价判据**：同一 fixtures 用例集，分片 vs 单节点：`verdict` 计数一致、`case_key` 集合一致、keyword 树结构一致（时长允许不同）。

**依赖**：NODX 节点心跳/注册已可用；`execution_node` 表已存在（V9_4）；W0.1 已修（否则聚合后仍无法跨 run 对比）。

**风险**：套件级 setup 被拆散 → 默认按套件；RF 的全局变量/库状态不可跨进程 → 分片执行必须独立进程，禁止共享 `.venv` 状态。

### W3 · v2.2 故障转移与恢复

- **心跳失联**：连续 3 个周期无心跳 → 节点 `OFFLINE`；其租约到期自动回收。
- **重派**：`LOST` shard 重新入队，`attempt+1`；结果唯一键 `(run_id, shard_no, attempt)`，重复投递幂等。
- **主控重启**：启动时从 DB 恢复 shard 状态；`LEASED/RUNNING` 且租约已过期的 shard 重新派发。
- **降级**：全部节点离线 → 按配置"退回本机执行"或"拒绝并保留 PENDING"（默认后者，避免静默改变执行环境）。
- **故障注入 4 场景**：节点进程 kill、节点网络断、主控重启、重复投递；每场景断言"无重复 test_result、无丢失 shard"。
