# v2.4 · CLI 多 agent 接入与内置兜底 · ③ PRD 增补草案

> 承接：`v2.4-CLI多agent-评估增补-20261108.md`（②）。本文件把评估结论落成可判定需求。
> 版本号 v2.4 为建议号段，正式落号见 `版本落号决议-20261108.md` 的后续修订。

## 1. 版本定位与范围

| 项 | 内容 |
|---|---|
| 定位 | 让 AI 面板「至少有一条能用」的 CLI 路径，而不是「装了才可能用」 |
| 范围 | 后端候选清单与探测、argv 模板、内置 pi agent 的安装与解析、参数注入 |
| 不在范围 | 前端界面改造（沿用既有 AI 抽屉）、CLI 交互式 TUI、凭据托管 |
| 依赖 | 既有 FR-AI-01..08 的降级/审计/二次确认机制，全部复用，不重做 |

## 2. 用户场景

| 场景 | 前置 | 期望 |
|---|---|---|
| S1 装了 Hermes | 用户机器有 `hermes` 在 PATH | 面板 L2/L3 可用，`/api/ai/state` 的 `hermes=true`，提问能出答案 |
| S2 装了 DeepSeek Harness | `dsh` 在 PATH 且配好 DeepSeek key | 走 `dsh headless` 单次任务出答案 |
| S3 什么都没有 | 无任何外部 CLI，仅有软件包内置副本 | 仍能出答案；`bundledAgent=true`，`primaryCli()=pi` |
| S4 用户自己装了 pi | PATH 上有 `pi` | 用用户的 pi 与凭据，**不**用内置副本 |
| S5 有人显式指定 | `AI_CLI_PATH` 注入 | 注入优先于内置，也优先于 PATH |

## 3. 功能需求

### 3.1 FR-AI-09 候选清单扩展

**需求**：候选从 `claude, codex, gemini, aider` 扩为
`hermes, dsh, claude, codex, gemini, aider, pi`（有序、最后一个为兜底）。

**验收判据**

| 编号 | 判据 | 形态 |
|---|---|---|
| V-CLI-01 | `AiCliAdapter.CANDIDATES` 严格等于上述 7 元有序数组 | 单测 `containsExactly` |
| V-CLI-02 | 老四条（claude→codex→gemini→aider）相对顺序不变 | 单测过滤后 `containsExactly` |
| V-CLI-03 | `pi` 位于最后一位 | 单测取末位断言 |
| V-CLI-04 | 每条候选有独立 argv 模板，且均不含 `--prompt-file` | 单测遍历 |
| V-CLI-05 | `hermes` = `[hermes,-z,text]`；`dsh` = `[dsh,headless,text]`；`pi` = `[pi,-p,text]` | 单测三条精确断言 |
| V-CLI-06 | `/api/ai/state` 逐条回报 7 个布尔 + `bundledAgent` + `bundledAgentPath` | 真实 HTTP |

### 3.2 FR-AI-10 内置 pi agent 兜底

**需求**：软件包提供幂等安装入口，把 `@earendil-works/pi-coding-agent@1.5.0`（MIT）
装到 `~/.local/share/robot-autotest/agents/pi`；后端在「PATH 上没有 pi」时使用它。

**验收判据**

| 编号 | 判据 | 形态 |
|---|---|---|
| V-CLI-07 | `tools/ai/ensure-pi-agent.sh --check` 已装 → rc=0；未装 → rc=2，且不联网 | 脚本 + 证据 |
| V-CLI-08 | `AiBundledAgent.piExecutable()` 优先 `bin/pi`，缺失时回退 `node_modules/.bin/pi` | 单测两条 |
| V-CLI-09 | 收窄 PATH 后 `primaryCli()=pi`，`execute()` 返回 `degraded=false` | 真实 HTTP（场景 B） |
| V-CLI-10 | `AI_CLI_PATH` 注入时，`pi` 的 argv[0] 用注入值而非内置路径 | 单测 |
| V-CLI-11 | 内置目录不存在时，`pi` 的 argv[0] 仍是裸名 `pi`，不拼坏路径 | 单测 |

### 3.3 FR-AI-10a node 依赖自解析

**需求**：内置副本的启动器不得依赖调用方 PATH 上的 node。

| 编号 | 判据 | 形态 |
|---|---|---|
| V-CLI-12 | 同一收窄 PATH 下，`bin/pi --version` rc=0，`node_modules/.bin/pi --version` rc=127 | 证据日志对照 |
| V-CLI-13 | 安装脚本在复制后自动生成 wrapper 并 `chmod 755` | 脚本幂等 + 目录检查 |

### 3.4 FR-AI-10b 运行期参数注入

**需求**：支持 `AI_CLI_ARGS`（空白分隔）追加到 argv 末尾，用于给 pi 补 `--provider` / `--model`。

| 编号 | 判据 | 形态 |
|---|---|---|
| V-CLI-14 | 配置后 argv 末尾严格等于注入序列 | 单测 `endsWith` |
| V-CLI-15 | 未配置时 `command()` 与 `argvFor()` 严格相等 | 单测 |
| V-CLI-16 | 非法/空白值不产生任何多余参数 | 单测 |

## 4. 非功能需求

| 编号 | 要求 | 判据 |
|---|---|---|
| NFR-CLI-01 | 凭据零落库、零打印 | `config/ai-cli.yml` 的 `never_log_credentials` 保持 true；证据日志中 key 一律 `<redacted>` |

## 6. 依赖、假设与风险

- 假设：用户机器有 node（用于首次安装 pi）。若没有，`ensure-pi-agent.sh` 返回 rc=2 并提示，不静默失败。
- 假设：pi 的 `-p` 语义短期不变；若变，改常量 + 单测即可。
- 风险：dsh 真实推理依赖 DeepSeek 官方 key，本机没有，故 `dsh` 只到「链路通」。
- 风险：内置副本 158 MB，分发成本实存；已在评估 R-1 登记。

## 7. 明确的非目标

- 不做 CLI 的凭据托管 / 代填 / 轮换。
- 不做前端候选选择器 UI（本轮沿用后端自动选第一条可用）。
- 不启动任何 TUI 子进程。
- 不因为新增候选而提高 L3 的确认要求（二次确认与审计不变）。
