## 4. 「带条件通过」的口径（必须先立规矩）

| 情形 | 允许吗 | 写法要求 |
|---|---|---|
| 某门大部分判据达标、个别项因环境缺失未验 | 允许，但必须**点名** | 写清「哪一条未验 / 缺什么环境 / 补齐后如何复核」，不得写成「基本通过」 |
| 用下一个版本的证据补上一个门的缺口 | **不允许** | 双线不抵扣；v2.2 / v2.3 的证据不得抵扣 G8 |
| 用单测绿代替真链路 | **不允许** | 规划 §7.4；B4 要求 S 类检查项必须有脚本与 CI job |
| 先对外称发版、后补判定 | **不允许** | `docs/release/README.md` §1.2「不存在『版本发了但门禁没过』这种状态」 |
