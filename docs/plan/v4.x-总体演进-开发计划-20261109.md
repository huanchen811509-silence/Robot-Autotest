## 2. 迁移与部署

| 项 | 计划 |
|---|---|
| 数据库迁移 | 现有最新 `V11_27`；4.1 若新增表从 **`V11_28`** 起追加，`db/down/V11_28*.down.sql` 手写回滚；**已应用迁移不可改**（checksum mismatch） |
| 租户守卫 | 新表登记 `TenantGuard.TENANT_TABLES`；所有 SQL 带 `project_id`；`db-audit` 的 88 表基线与 append-only 分类同步 |
| 迁移演练 | 加列走 `MODE=alter`、建表走 `MODE=table`（`scripts/migration-down-up-drill.sh`）、索引变更走 `scripts/index-migration-drill.sh`；复合索引存在性用 `IF(COUNT(*)>0,1,0)` |
| IT 库 | 库名以 `_it` 结尾；`robot_it` 漂移时按「mysqldump 备份 → 重建空库 → `DB_NAME=robot_it mvn -o -B flyway:migrate`」恢复 |
| 后端部署 | 改码必须重建 jar + `systemctl --user restart robot-autotest-backend`（**源码对齐 ≠ 部署对齐**） |
| 前端部署 | `npx vite build` 重建 `frontend/dist`；根 `CHANGELOG.md` 同步到 `frontend/public/CHANGELOG.md` |
| 契约与版本 | 新增端点后 `python3 tools/gen_api_contract.py`；落号时 `scripts/gen_build_info.py` + `tools/check_version_consistency.py`（四副本） |
| 交付包 | 每批收口重跑 `bash scripts/package-release.sh`；MANIFEST / sha256 归档到 `docs/evidence/v4.x.0/` |
| 工作区目录 | `workspace/` 属**运行数据**：写入 `uninstall.sh` 保留清单与 `backup.sh` 范围，绝不随程序删除；不入库（加 `.gitignore` 规则） |

## 3. 门禁与取证

| 门禁 | 判据 |
|---|---|
| 新增机检器 | `check_workspace_bundle.py`（目录契约 / 凭据零落盘 / 无自动同步 / manifest 校验 / 路径穿越）带 `--self-check` 正负样本；`check_case_command.py` 扩三类脱敏 |
| 门禁步骤 | 4.0 计划新增第 **31** 步（更新机制静态契约）、4.1 计划新增第 **32** 步（工作区机检）；每步同步 `check_structure`、`--selfcheck` 的「删该步必变红」，并在 CHANGELOG 记口径变更 |
| 结构自检 | 每批收口 `bash scripts/gates.sh --selfcheck` 必须 `FAILS=0`，含新增步骤的负向实证 |
| 真链路 | 导出/导入/向导/升级一律真 HTTP + 真库 + 真浏览器；夹具不塞 SQL 假行 |
| 只读 | 只读页源码级无写函数，运行时由 CDP `Network.requestWillBeSent` 证明加载期 0 写请求 |
| 负向验证 | 备份 → 注入 → 定向判据必须红 → **用备份拷贝还原**（别 `git checkout`）→ 复跑绿 |
| 凭据 | 导出件、日志、MANIFEST、交付包全量过 `scripts/secret-scan.sh` 与 `tools/security_scan.py` |
| 就绪探针 | 打 `:8081/actuator/health`；`:8001/_ping` 是 node 入口自回 200，不算后端就绪 |
