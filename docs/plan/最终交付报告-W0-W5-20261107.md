## 4. 验证中发现并修掉的真实缺陷

这几处都是「定向单测全绿但真跑/真启动才暴露」的问题，已作为门禁价值样例记录：

1. **全局租约回收 SQL 触发租户守卫 → 应用启动失败**（W3）。跨项目 sweep 的 `UPDATE` 未含 `project_id`，
   `TenantGuard.requireProjectScope` 抛异常。修复：`WHERE` 补 `AND project_id > 0`（与既有跨项目查询口径一致）。
2. **启动恢复异常拖垮 Spring 上下文**（W3）。`ApplicationReadyEvent` 监听器抛异常会让整个应用起不来；
   改为捕获并记 `ERROR`，租约到期仍会被自然回收。
3. **时间线 `state` 小写导致前端轮询不停**（W4）。库里的 `run_status` 是小写（`canceled`/`finished`），
   接口统一 `toUpperCase(Locale.ROOT)`，前端终态判定恢复。
4. **性能门禁首版误红**（W4）。判据「劣化 >10% 且绝对增量 >15ms」在宿主 load 3+ 时把调度噪声判成回归；
   改为绝对下限 **30ms** + 「3 轮 × 9 采样取最好轮 P95」，代价是 30ms 以内的劣化不再拦截（已在 README 写明）。
5. **`SAME_SLOT` 逐触发点重复报**（W5）。同一组计划在 3 个未来触发点全撞上会产出 3 条同名冲突，
   改为按计划集合聚合、只报最早时刻。
6. **批量启用 `nextFireAt` 测试期望算错时区**（W5）。cron 是 `Asia/Shanghai` 的 02:00，`NOW=00:00Z` 时应为
   `18:00Z`，原期望写成 `02:00Z`；属测试期望错误，已修正并写明换算过程。
