## 1. 范围

**做什么**：把大师补充的 7 项需求（顶栏浮层范式、账户下拉、项目目录化解耦、创建项目向导、折叠留白、
更新部署机制、系统评估与 4.X 规划）与已有可运维能力合并成一条可评审、可排期、可判定的大版本线。

**不做什么**：不 bump 版本、不实装、不测试、不落号、不判 G 门、不创建公开 Release；
不把 MySQL 换成文件系统、不做 DB/磁盘双真源、不做 impersonation、不导出凭据明文；
不做 deb/rpm/Docker/Windows 安装包，不在 GitHub-hosted CI 跑真库/CDP/全量门禁。

**基线（已核实）**：`VERSION=3.11.0`；门禁 30 步；88 业务表（56 张含 `project_id`）；
OpenAPI 284 endpoints / 225 paths；i18n 1687/1687；`robot_file` 26 行；交付包 282 文件 / 48 MB。

### 3.4 重点判据细化

**`FR-v4.1-01/02` 的唯一真源约束**：DB 是运行时唯一真源，`workspace/` 是**交换格式**，
目录内 `README` 与 `project.json` 必须明示「手工改动需显式导入才生效」；
实现里不得出现「DB 写完后自动同步目录」或反向的后台任务（机检负向样本判红）。

**`FR-v4.0-05` 的安全默认态**：同版本升级须 `--force` + 二次确认；降级默认拒绝，仅 `--force --restore-db` 允许；
迁移清单在 dry-run 阶段只读列出，`--apply` 才执行；IT 库名守卫 `_it`；
`--apply` 前必须完成 DB 全量备份；仅 expand-contract 迁移允许 `--schema=keep`，否则回滚必须恢复 DB 备份；
回滚失败按 `docs/ROLLBACK.md` 人工恢复，RTO ≤ 10 分钟、RPO = 0。

| 位置 | 控件 | 4.X 处置 | 计数 |
|---|---|---|---|
| 上下文 | 当前项目 select | 保留顶栏 | 1 |
| 工具 | 命令面板（检索） | 保留顶栏 | 1 |

**跨实例导入的引用解析（`FR-v4.1-02`）**：

| 引用 | 稳定业务键 | 目标缺失时 |
|---|---|---|
| 成员 | 用户名 / 登录名（不用本地 user id） | 默认 skip 并逐条报告；禁止自动授予 admin |
| 用例 | `robot_file.path` 或用例编号 | skip 并报告；不得自动改挂到同名用例 |
| 用例集 items | 用例稳定键 + 顺序 | 引用缺失则整条 item skip 并报告 |
| 设备 / 链路 | 资产名称 + 类型 + 项目 code | 按业务键匹配；缺失则 skip，不新建凭据 |
| 凭据 | 凭据名称 + 掩码指纹 | 只写引用与掩码，绝不导出密文；缺失则 skip |
| 报告 / 运行 | 运行编号 + 报告编号 | 仅作归档，不写入可执行运行表 |

**冷启动规则**：目标实例没有该 `project-code` 时，导入默认**拒绝并提示先创建项目**；
若用户显式选择「创建为草稿」，导入者需二次确认后才成为该项目 admin，禁止根据 `members.json` 自动授权；
创建失败不得留下半成品项目。

**`manifest` 完整性与真实性**：sha256 只能防误改，不能防伪造。导出包必须带服务端密钥的 HMAC/签名（ADR-4X-12）；
导入先验签，未验签包按不可信拒绝或进入隔离区，不得直接写入可执行表；
导入的 `.robot/.py` 需扫描并标记来源，执行前仍需人工确认。

**`workspace/` 生命周期**：属运行数据，不随程序删除；`uninstall.sh` 的 `KEEP_DIRS` 增加 `workspace`，
`backup.sh` 纳入备份范围，`.gitignore` 忽略 `workspace/`；部署位置、只读文件系统、磁盘配额在 `W40-00` 定并写入 A-03 结论。

## 5. 架构决策（ADR 摘要）

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-4X-01 | DB 为运行时唯一真源，`workspace/` 为显式导入导出的交换格式 | 56 张表的事务/权限/审计不能丢；双真源不可证一致 |
| ADR-4X-02 | 凭据零落盘：`assets/` 只写引用与掩码 | 目录会被拷贝传递，密文出界等同泄露面扩大 |
| ADR-4X-03 | 导入复用 `FileWorkspaceService.normalize()` + manifest sha256 | 防路径穿越与篡改，避免再造一套路径规则 |
| ADR-4X-04 | 统一浮层锚定 `.app-main`，顶栏层级最高 | 与 AI 抽屉「不占顶栏」语义一致；一套焦点/ESC/窄屏策略 |
| ADR-4X-05 | 页面内危险确认保留模态，遮罩避让顶栏 | 统一范式不能弱化二次确认的强提示 |
| ADR-4X-06 | 「切换用户」= 登出重登，不引入 impersonation | 后端零基础，且避免管理员隐式越权 |
| ADR-4X-07 | 向导是编排层，不新增业务实体表；模板是版本化 JSON 文件 | 防止再造平行数据模型，模板可随工作区传递 |
| ADR-4X-08 | `update.sh` 默认 dry-run；仅 expand-contract 迁移允许 `--schema=keep`，否则用 DB 备份回滚 | 与 `docs/ROLLBACK.md` 一致，避免旧二进制在新 schema 上无法启动 |
| ADR-4X-09 | 交付流水线继续 GitHub-hosted，质量门只加「无 DB」测试 | 真库 / CDP 无法在 hosted runner 复刻 |
| ADR-4X-10 | `pr.yml` 保持 self-hosted 不动；Release job 不写入 workflow | 现场条件与对外口径均不属代码问题 |
| ADR-4X-11 | 4.X 收编 `v3.12+`，原三份文档保留并标注 | 避免双计划口径分叉，保留审计轨迹 |
| ADR-4X-12 | 导出包 manifest 带服务端密钥 HMAC/签名，导入先验签 | sha256 只能防误改，不能防伪造 |
| ADR-4X-13 | 跨实例引用按稳定业务键映射；成员默认 skip，禁止自动授权 | 目标实例 user/asset/case id 均不同，直接搬 id 必悬空 |
| ADR-4X-14 | 升级前 DB 全量备份；回滚失败按 `ROLLBACK.md` 人工恢复 | 保证 RPO = 0，回滚本身失败也有出路 |
| ADR-4X-15 | `workspace/` 属运行数据，纳入 uninstall / backup / `.gitignore` | 避免卸载或备份时误删 / 漏备交换格式 |

7. **G 门判定、正式发版与对外口径仍由大师出书面结论**；本版任何文档不得自称「已发版」。
