## 0. 前置依赖与基线

| 依赖项 | 当前状态 | 对本次规划的影响 |
|---|---|---|
| v5.22.0 落号 | **未落号**：已跑到 ⑦ 回写，HEAD `32953bd`，VERSION 仍 `5.21.0` | v5.23.0 的起点必须是 v5.22.0 落号之后，否则 CHANGELOG/VERSION 会乱 |

| 体验评审 | 已完成，40 条短板（P0×3、P1×5、P2×15、P3×10）+ 5 条横向问题 | 本 PRD 逐条吸收，来源列可追溯 |
| 门禁 67/68 步 | `FAILS=0` | 新增检查项（本 PRD 第七章）须作为第 69+ 步接入，且必须先自证再进门禁 |

**总目标（一句话）**：把"能力齐备但用户走不通"的平台，改造成"第一次上手、一个人能独立走完 建集 → 执行 → 出对外报告"的平台；同时不牺牲已经建立的可信度红线（缺项不导出、命令白名单公开、预检先判）。

**非目标（本规划明确不做）**：

| 不做 | 原因 |
|---|---|
| 重写信息架构（合并全局/项目两套菜单） | 与 D-01 已定口径冲突，改动面过大且无用户痛点支撑；本规划只做"同名页可区分 + 模式状态可见" |
| 取消缺项导出红线 | 这是可信度基石，只做"堵住之后给出路"，不放松 |
| 引入新的前端框架/组件库 | 与体验优化无关，风险收益不成立 |
| 多租户/权限模型调整 | 不在本次评审证据范围内 |

## 11. 全局约束（任何版本都不得破坏）
