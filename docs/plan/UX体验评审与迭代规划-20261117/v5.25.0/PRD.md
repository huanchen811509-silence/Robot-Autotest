## 1. 背景与用户故事

### 故事 F：一个懂测试但不懂这个系统的人，读不懂自己的报告

> 报告上写「未判定 · 该报告入库时未记录判据，结论无法判定；不按失败数推断」。我懂测试，但"判据"在这里指什么？下面又写「缺证据 70」，我明明跑了。
> 运行记录写「内核返回失败（exit 1）：有用例未通过」。exit 1 是什么？我要的是"有 4 条没过"。
> 覆盖率卡写「含待评审 13% ／ 排除待评审 10.3%（D12 双口径并列）其中待评审 178 条……所以这个数更低，不是更高」——这句像开发在跟我解释。

**根因**：界面文案沿用了实现语言（判据/内核/双口径/互斥/源表无值），没有面向"测试负责人"这一读者做翻译；指标没有口径说明，同一个百分比换个算法就变。

## 2. 目标与非目标

| 项 | 内容 |
|---|---|
| 目标 | 不懂本系统的测试负责人能独立读完报告并复述结论；每个数字都能点开看"怎么算的" |
| 度量 | 术语黑名单命中 ≥15 处 → ≤3（v5.25 收口）→ 0（v5.27 机检守住）；口径浮层覆盖全部比率指标 |
| 非目标 | 不改后端判据算法（只改展示措辞）；不做多语言新增（仅 zh-CN 与 en-US 同步） |

## 4. 术语替换表（首批 40 条，节选）

| 旧词 | 新词 | 出现处 |
|---|---|---|
| 判据 | 判定依据 | 报告结论区 |
| 未判定 | 无法判定（未记录判定依据） | 报告首屏 |
| 缺证据 | 无执行证据 | 证据层 |
| 源表无值 | 未填写 | 用例详情 |
| 需补判 | 待判定安全级 | 预检 |
| 不互斥 | 可同时使用 | 设备范围 |
| 内核返回失败（exit 1） | 执行未通过（有 N 条用例失败） | 运行记录 |
| D12 双口径并列 | 两种统计口径 | 覆盖率卡 |
| 含待评审 / 排除待评审 | 全部用例 / 已评审用例 | 覆盖率卡 |
| 台架 | 测试环境 | pytest 工程 |
| 预检 | 执行前检查 | 发起执行 |
| 冻结 | 定稿 | 测试报告 |
| 软删 | 移入回收站 | 列表操作 |
| 就绪度 | 准备情况 | 台架卡 |
| 闸 / 硬约束 | 校验规则 | 多处 |
| 回写 | 结果同步 | CI 相关 |
| 存量同步 | 历史数据同步 | 运维 |
| 演练 | 故障演练（保留，但加一句说明） | 运维 |
| 脱敏 | 隐藏敏感信息 | 导出 |
| 内核 | 执行引擎 | 执行相关 |

> 完整 40 条见 `docs/plan/术语替换表-v5.25.md`（W75-01 交付物）。
