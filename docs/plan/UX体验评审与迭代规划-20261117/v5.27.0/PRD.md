## 1. 背景与用户故事

### 故事 I：同一个时间，四种写法

> 执行报告里是 `2026-11-17T05:00:19.814Z`，运行记录是 `2026/11/17 11:26:30`，环境采集是 `2026/11/16 12:04:42`。我不知道哪个是本地时间。

### 故事 J：学到的规则，下一页就失效

> 用例集的「立即执行」有确认框，pytest 页的「发起执行」没有。
> 执行报告的导出按钮是灰的并告诉我缺哪 9 项；测试报告页的导出点了毫无反应。
> 同一类动作，三种处理。

**根因**：格式化与交互规范散落在各处，没有统一的"同场景同做法"约束，也没有机检守着。

---

## 2. 目标与非目标

| 项 | 内容 |
|---|---|
| 目标 | 全站只有一种日期格式、一种语言口径；同类动作只有一种处理方式，且由机检守住 |
| 度量 | 日期格式 3 种 → 1 种；同场景不一致处 ≥3 → 0；裸枚举与英文残留 → 0 |
| 非目标 | 不做时区切换 UI（固定本地时区 + 显示时区说明）；不重做 i18n 框架 |

## 4. 依赖与风险

| 项 | 说明 |
|---|---|
| 依赖 v5.24 的 `RunConfirmPanel` | FR-05 复用它，不新写 |
| 依赖 v5.23 的"导出失败可见" | FR-04 的机检对象 |
| 风险：格式函数替换不彻底 | 遗漏点靠机检兜底，故 FR-04 的机检必须覆盖日期 |
| 风险：后端 message 含英文枚举 | 需同步改后端文案常量，不能只改前端映射 |
| 风险：real 模式强制确认影响自动化 | 需保留服务账号的 `confirmReal=true` 显式传参通道（不破坏 CI） |
