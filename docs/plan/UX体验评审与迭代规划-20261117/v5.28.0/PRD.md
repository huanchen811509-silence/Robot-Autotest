## 1. 背景与用户故事

### 故事 K：拿到 10 页报告，看不到结论

> 我导出的报告首页是"内部版 · 含缺失项"，往下是十项 metadata 全"缺失"，然后套件树 [FAIL]，接着一条条 `IM-CER-008 SKIP 29ms 本用例未下发外部命令`，连续铺了 8 页。
> 4 条失败到底因为什么，我在 PDF 里翻了半天才找到。

**根因**：报告结构按"数据产生顺序"排（metadata → 套件树 → 逐条明细），没有按"读者关心顺序"排（结论 → 失败 → 跳过汇总 → 明细）；SKIP 与 FAIL 同等展示，导致关键信息被稀释。

### 故事 L1：谁批准了这份报告发给客户？

> 我把草稿点「冻结」，它就变成对外可导出的状态了。但没人知道我改过什么、谁看过、谁同意发出去。
> 客户问到"这份数据谁确认的"，我答不上来。

**根因**：状态机只有 `DRAFT → FROZEN`，冻结既当"定稿"又当"审核通过"，缺审批人与审批记录。

### 故事 L2：客户问这批用例跑了几次、什么时候过的

> 报告是"按最近一次执行"生成的。可那一次只跑了 9 条（其余 61 条跳过），客户看到的就是这份。
> 我真正想说的是："这批用例在 EHT 环境、v5.30 版本、这 7 天里跑了 5 次，每个用例至少通过过一次。"

**根因**：客户报告的对象被绑成"一次 run"，而交付结论需要的是"一个批次"（用例范围 + 环境 + 版本 + 时间窗）。

### 故事 L3：内部信息进了对外文档

> 我要把报告发给客户，但里面写着 `/home/evergreen/venvs/nic-fake/bin/python` 和 `内核返回失败（exit 1）`。

**根因**：对外/内部只区分了页眉标识，没有对内容做分层脱敏。

## 2. 目标与非目标

| 项 | 内容 |
|---|---|
| 目标 | 拿到 PDF 的人，前 2 页就知道"过没过、为什么没过、下一步做什么"；对外版不含内部实现细节 |
| 度量 | 70 项规模报告：SKIP 相关页数 ≤1；前 2 页含结论 + 失败数 + 失败原因；对外版内部路径出现 0 次 |
| 非目标 | 不做报告富文本编辑器；不做报告在线协作批注；不改字段白名单（C5） |

## 3. 需求明细

| FR | 需求 | 验收判据 | 优先级 |
|---|---|---|---|
| FR-v5.28-01 | PDF 结构重排：① 结论与判定依据 ② 失败明细（含复现建议）③ 跳过汇总（1 段）④ 用例明细 ⑤ 附录（metadata/证据层） | ① 前 2 页含结论、失败数、至少 1 条失败原因；② 章节顺序与上述一致；③ 附录可省略但不可前置 | P0 |
| FR-v5.28-02 | SKIP 明细默认折叠为汇总行（"61 条跳过，其中 61 条因未下发命令"），明细附在附录 | ① 70 项规模下 SKIP 相关页数 ≤1；② 汇总行数字与接口一致；③ 附录可查到逐条 | P0 |
| FR-v5.28-03 | 报告章节可配置（项目级模板：套件树/证据层/AI 叙述/趋势/附录） | ① 关闭某章节后重新导出，PDF 中无该章节；② 配置项持久化；③ 不影响已冻结的历史报告 | P1 |
| FR-v5.28-04 | 报告版本对比：同一 run 的 v1..vN 差异高亮（数字变化、结论变化） | ① 对比视图列出变动字段 ≥1；② 无差异时明确提示"无变化"；③ 可跳转到两版原文 | P2 |
| FR-v5.28-05 | 对外版脱敏：隐去执行机路径、内核命令、内部 ID、`exit N` 等技术细节 | ① 对外 PDF 不含 `/home/`、`/mnt/`、`exit `；② 内部版保留（可追溯）；③ 脱敏规则可配置但默认开启 | P1 |
| FR-v5.28-06 | AI 叙述落地为可用结论段落（受证据约束），失败时降级为模板段落而非空白 | ① 30 秒内产出 ≥150 字结论；② 数字与报告证据一致（逐项核对）；③ 接口失败显示模板段落 | P2 |
| FR-v5.28-07 | **审核态**：状态机增 `PENDING_REVIEW`，流转 `DRAFT → PENDING_REVIEW → FROZEN`（通过）/ `→ DRAFT`（驳回）；记录审核人、审核时间、审核意见；**对外导出前置条件 = FROZEN 且有审核记录** | ① 未经审核的草稿对外导出被拒且提示"需审核通过"；② 审核通过后 FROZEN 且可导出；③ 驳回后回到 DRAFT 且审核意见可见；④ 审计表留下 approver/时间/意见 | P1 |
| FR-v5.28-08 | **交付批次**：以「项目 + 用例集 + 环境快照 + SW_BUILD + 时间窗」定义批次；报告按批次取数（用例级取最近一次通过，并展示"运行 N 次/通过 M 次"）；报告附支撑结论的 run 清单 | ① 批次报告覆盖该窗内全部相关 run；② 用例级结论取最近一次通过；③ 附 run 清单（runId + 时间 + 结论）；④ 存在从未通过的用例时结论为不通过并列出 | P2 |
