## 5. 证据形态规范

| 形态 | 要求 | 存放 |
|---|---|---|
| 截图 | PNG，1440×900，文件名含 TC 编号，关键区域不得裁切 | `docs/evidence/v5.23.0/<WBS>/shots/` |
| 接口 | 请求体 + 响应体（脱敏 token），或一条可重跑命令 + 其 stdout | 同上 `.json` / `.txt` |
| PDF | 保留原文件，正文用文本提取（不是截图） | 同上 `.pdf` |
| DOM 断言 | 断言脚本 + 输出日志（含 PASS/FAIL 行） | `run.py` / `run.mjs` + `out.log` |
| 机检 | `check_*.py` 输出行（须含统计与 PASS/FAIL） | `out.log` |

**证据纪律**

1. 每条 TC 必须有**可打开的产物**，不接受"我验证过了"的口述；
2. 断言脚本必须自带**负向自证**（至少 1 条用例在改动前应判红），否则视同未测；
3. 报告类证据（PDF）必须用文本提取校验中文可读，不靠肉眼看截图。

## 6. 降级与放行规则

| 情形 | 规则 |
|---|---|
| 某 TC 未达预期但已验证「不影响主链路」 | 标 **降级达成**，须写明理由 + 授权人（大师），并在版本 05-TEST-REPORT 中列明 |
| P0 任一条 FAIL | **不得发版**，无例外 |
| P1 累计 ≥3 条 FAIL | 不得发版，除非大师书面同意带缺陷发布 |
| P2/P3 FAIL | 可发版，须登记遗留项与修复版本 |
| 机检项（第 69/70 步）FAIL | 视同 P0 |
