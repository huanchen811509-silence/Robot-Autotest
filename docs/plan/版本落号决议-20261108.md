## 3. 目录形态：指针式，不复制正文

每个版本目录放 **3 份**（`PRD.md` / `DEV-PLAN.md` / `TEST-PLAN.md`），每份只写：
文档编号、定位、范围、**真源指针**（指向 `docs/plan/` 下的增补草案）、当前状态、判据入口、遗留。

**理由**：同一份 PRD 如果在 `docs/plan/` 与 `docs/release/` 各存一份正文，改一处忘一处就会口径分叉——
v2.1 已经用「指针式」跑通过一次（`v2.1-platform/` 三份均指向 `docs/plan/` 的评估与草案），本决议沿用。

**不建 `00-RESEARCH.md` / `01-ASSESSMENT.md` / `05-TEST-REPORT.md`**：这两个版本走的是「增补草案」路线，
调研与评估并入了各自的评估文档（v2.2 见 `ED202与demo对齐评估-20261107.md` + `AI助手可用性评估增补-20261108.md`；
v2.3 见 `界面与主题优化评估-20261108.md`）。缺这两份会被 `check_release_docs.py` 判为「未启动」并只报 INFO，
**不判 FAIL**，与 v2.1 的现状一致。

## 5. 边界与待复核

1. **号段是本次新立的**。若大师另有编排（例如希望 v2.2/v2.3 共用一个批次号，或把 v2.1 也补号），
   一次性改号即可——号只出现在本决议与六个版本目录文件的头部，**不影响任何已跑的测试结论与证据**。
2. 本决议**不判 G9 / G10**，只给它们落号。判定动作仍归大师，学徒只备料。
3. 本决议不 bump 版本号、不建 tag、不触发发布。
