## 1. 需求背景与判据原则

四条诉求来自大师 2026-11-08。第 ② 道评估已把现状与缺口定清，本节只重复与需求判定直接相关的事实：

| 事实 | 读数 | 来源 |
|---|---|---|
| 一级菜单已是 8 组两级结构 | 8 组 / 2 叶子 / 6 分组 / **22 个分组内二级项** / 首屏 30 行 | `frontend/src/config/navigation.ts` |
| 同一页面两个名字 | 侧栏「工作台」vs 页头「总览」 | `navigation.ts:56` 与 `OverviewView.vue:239` |
| 「报告」叶子实际承载 4 个页面 | 列表 / 模板 / 详情 / 打印，靠 `alsoMatch` 强拉点亮 | `navigation.ts` vs `router/index.ts:73-98` |
| `/test-reports` 是孤儿页 | 路由与视图都在，导航树无任何项指向它 | `router/index.ts:99-103` vs `NAVIGATION` 全表 |
| 工作台强依赖当前项目，无跨项目视图 | `/overview` 首行即判 `projectId` | `OverviewView.vue:74`、`:252` |
| 项目 DTO 无统计字段 | 6 个字段，无任何计数 | `api/iam.ts:33-41` |
| 顶栏 9 个交互控件，但**排版是主要问题** | 按钮高 27px vs 下拉高 23px（差 4px）；`.app-project` 样式零定义；统一 `gap: 10px` | `main.css:209-215`、`.btn` / `.app-lang` 定义 |
| 主题已三模式六强调色两密度 | 12 个强调色变体块 | `theme.css:268-380` |
| 滚动条零样式 | `-webkit-scrollbar` 全仓 0 命中 | 全仓 grep |

**判据原则（本 PRD 的硬要求）**：每条 FR 必须能被一条命令或一条单测判定。写不出判据的需求不入本表——宁可降成 NFR 或列入「不做」。

## 4. 功能需求：顶栏排版 / 排序 / 美工（FR-UI-15..19）

> 大师 2026-11-08 澄清：本节要的是**同一批按钮的排版、排序、美工优化**，不是收敛控件数量、也不把功能搬进二级菜单。因此本节**不减少任何功能入口**（唯一的移除项是「关于」，理由是与侧栏已有入口重复），也**不新增组件**。

| 编号 | 需求 | 优先级 | 验收判据 |
|---|---|---|---|
| FR-UI-15 | 顶栏排版统一到 28px 栅格：所有按钮与下拉的高度一致（`28px`）；图标按钮为 28×28 方形、图标 16px 居中、圆角 6px；组内间距 6px、组间 14px | P0 | 组件测试读 `getBoundingClientRect()`：4 类控件（图标按钮 / 文字按钮 / 项目下拉 / 语言下拉）高度两两差 ≤ 1px 且 = 28；每个图标按钮 `offsetWidth === offsetHeight === 28` |
| FR-UI-16 | 主题快捷按钮改为二态（light ↔ dark）；`system` 只在外观弹层里选择 | P1 | 单测断言点击一次后 `data-theme` 在 light/dark 间翻转，不出现 system；外观弹层仍有三选项 |
| FR-UI-17 | 登出保留在顶栏最右，但加 `danger` 视觉与二次确认 | P0 | 组件测试断言：登出按钮含 `danger` 类；点击后出现确认层；取消不调用 `auth.logout` |
| FR-UI-18 | 顶栏右侧按「上下文 → 工具 → 偏好 → 账户」**四段**排序，段间 1 条分隔线（共 3 条）；Tab 顺序与视觉顺序一致；侧栏折叠按钮移出顶栏（移到侧栏头部）；「关于」按钮移除（侧栏「系统设置 > 关于」已有同一入口） | P0 | 组件测试断言：4 个段落容器按序存在、分隔线数量 = 3；顶栏内不存在「关于」按钮；侧栏头部存在折叠按钮；键盘 Tab 序列与 DOM 顺序一致 |
| FR-UI-19 | 项目选择器有独立造型（不借用语言下拉样式）：面板底 + 强边框 + 前置图标 + 当前项目名 + 启用状态点；最大宽 180px，超长省略；未选项目时显示引导文案 | P1 | 组件测试断言：`.app-project` 在样式文件中有独立定义块（`grep` 命中 ≥ 1）且不与 `.app-lang` 共用选择器；有项目时显示名称与状态点；无项目时显示引导；宽度 ≤ 180px |

**为什么项目选择器要独立造型而不是换成自定义面板**：它现在是原生 `<select>`，与语言下拉共用 `.app-lang` 的皮——这是「高频主操作」和「极低频偏好」同形的问题。但换成自绘面板要新增组件、新增键盘导航、新增焦点管理，成本远大于收益。按本次澄清（做美工不做重构），保留原生 `<select>` 的可用性优势，只给它独立视觉与尺寸约束。需求 ② 的「在卡牌页选项目」才是带搜索的完整切换入口，两者分工明确：顶栏管「快速切」，卡牌页管「看清再切」。

## 9. 附录 B：顶栏结构（目标态）

**设计原则：保留全部功能入口，只改排版、排序与美工。** 唯一被移除的是「关于」按钮（侧栏「系统设置 > 关于」已有同一入口，属去重复）。侧栏折叠按钮移出顶栏，改挂侧栏头部。

```text
┌────────────────────────────────────────────────────────────────────────────────────┐
│ 测试平台定位语          [▣ 项目名 ●] │ [检索] [AI] │ [外观] [中/EN] │ [用户名 角色] [登出] │
│                         └─ 上下文 ─┘   └─ 工具 ─┘   └─ 偏好 ──┘   └──── 账户 ────┘ │
│                          组内 6px / 组间 14px + 1px 分隔线 ×3 / 全部控件高 28px      │
└────────────────────────────────────────────────────────────────────────────────────┘
```

| 段 | 元素 | 造型规格 | 行为 |
|---|---|---|---|
| 左 | 页头定位语 | 13px / `--text-muted` / `min-width: 0` + 省略 | 只读；拥挤时先省略它，控件区不收缩 |
| 段 1 上下文 | 项目选择器 | **独立样式**（面板底 + 强边框 + `dashboard` 图标 + 项目名 + 状态点），28px 高、最大宽 180px | 原生 `<select>` 保留；切换即 `setProject` 并写 localStorage |
| 段 2 工具 | 检索 | 28×28 图标按钮，`search` 图标 | 打开命令面板，`title` 带 `⌘K` |
| 段 2 工具 | AI 助手 | 28×28 图标按钮，`sparkles` 图标 | 开抽屉；`ai.enabled=false` 时整项不渲染 |
| 段 3 偏好 | 外观 | 28×28 图标按钮，`palette` 图标 | 打开外观弹层（主题三选 + 强调色六选 + 密度二选） |
| 段 3 偏好 | 语言 | `language` 图标 + 统一壳，显示 `中 / EN` | 二选切换，不做循环 |
| 段 4 账户 | 用户名 + 角色 | 文本容器，`line-height: 28px`，角色为 `--text-muted` 小字 | 只读展示 |
| 段 4 账户 | 登出 | `logout` 图标 + `.btn-ghost.danger` | 二次确认后 `auth.logout()` |

**主题快捷按钮的去留**：原三态循环按钮（V1 缺陷）改为**二态**（light ↔ dark）后并入段 3 偏好，与外观弹层并列——外观弹层管「全部外观选项含 system」，快捷按钮管「一键亮/暗」。二者不重复：一个给全量选项，一个给最高频的那一次切换。

**已移除项**（各有明确去处，不是砍功能）：

| 原控件 | 处理 | 去处 |
|---|---|---|
| 关于 | 移除顶栏按钮 | 侧栏「系统设置 > 关于」（`settings-about` → `/about`），入口本已存在 |
| 侧栏折叠 | 移出顶栏 | 侧栏头部，与产品名同行；图标 `chevronRight` + 折叠时 `rotate(180deg)`，加 `aria-expanded` |
