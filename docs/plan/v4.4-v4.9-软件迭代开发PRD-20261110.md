## 0. 结论先行

1. **一句话目标**：让「Excel 公共用例库」成为平台的一等公民——可幂等导入、可反向导出、可按一级/二级分类筛选、可被项目引用、可随版本同步、可沉淀为模板。
2. **顺序由依赖决定，不由偏好决定**：`权限与成员（4.4）→ 双模式（4.5）→ 公共库与导入（4.6）→ 导出（4.6.1）→ 资产与引用（4.7）→ 模板与向导（4.8）→ 存量同步（4.9）→ 优化与 GA（4.9.1/4.9.2）`。
3. **三个「先做否则返工」的判断**：
   - 不先把成员改成多角色，双模式的「全局角色 ∪ 项目角色」就无处求值，权限矩阵会建在沙地上；
   - 不先做反向导出 round-trip，导入「对不对」只能靠人眼抽样，730 条用例的质量无法证明；
   - 不先做双模式的新 IA，模板的二级菜单就得先建在旧导航里，4.8 再搬一次。
4. **本轮 5 + 5 项拍板全部收敛为约束**（详见 §2.3 与两报告「已拍板决策」节）：平台项目数据域、默认引用、编码只读、模板团队共享、同步默认 `track-latest`。
5. **收尾不是「写文档」**：4.9.1 / 4.9.2 把性能、可访问性、双语、迁移回滚演练、门禁收红、OpenAPI 与证据索引列为**有 FR 编号的可验收需求**，不做完不算 GA。
6. **顶栏与品牌一次收口**：白泽 Logo 双主题接入、账户菜单瘦身、强调色色板改圆形统一放 4.5.1——4.5.0 刚改过顶栏，分两次做等于白改一遍布局。

## 1. 背景、问题与目标

### 1.1 现状基线（4.3.0 事实）

| 事实 | 证据 | 对本期的影响 |

| 项目/模板编码已改为 `前缀-引擎-年月-序号`，引擎缩写 **RF / PYT** | `frontend/src/config/projectCode.ts`、`projectTemplates.ts` | 本期所有新对象（模板、导入批次）沿用同一编号语汇 |

| 参考实现可用其方法论、不可直接复用代码 | `测试自动化demo程序/04 8001平台/backend/niclab/` | 三层幂等、预览/提交两段式、反向导出三套算法照搬设计 |

### 1.2 五个结构性问题

| # | 问题 | 现状表现 | 不解决的后果 |
|---|---|---|---|
| P1 | 数据进不来 | 730 条用例只能躺在 Excel；平台内没有批量入口 | 公共库永远是空壳，后续引用/同步/模板全部无对象 |
| P2 | 全局与项目无边界 | 所有页面都是「当前项目」；没有公共管理面 | 每个项目重复录同一批用例，改一次要改 N 个项目 |
| P3 | 权限粒度不足 | 单账号单角色；PM 与工程师在导航上无差别 | 无法安全开放「全局模式」，只能靠口头约束 |
| P4 | 模板不可运营 | 模板写死在代码里，新增要发版 | 「把这套项目沉淀为模板」无法产品化 |
| P5 | 存量项目无法跟随 | 公共库更新后，老项目仍停在旧内容 | 公共库越更新，项目间差异越大，形成第二套事实源 |

### 1.3 产品目标（可验收）

| 编号 | 目标 | 量化判据 |
|---|---|---|
| G1 | 公共库可建立 | 样本 Excel 一次导入成功 **730/730**，错误行 0 或全部可下载定位 |
| G2 | 导入幂等 | 同一文件重复提交：新增用例 **0**、新增版本 **0**、返回同一批次结果 |
| G3 | 双向可证 | 导入 → 导出 → 再导入，业务键与内容字段差异 **0**（看板页除外） |
| G4 | 项目可用公共库 | 空白项目创建时可选公共用例/资产；引用关系可在项目页看到来源 |
| G5 | 存量可跟随 | 公共库更新后，项目同步预览可解释每一条变更；`local_override` 内容 **0 覆盖** |
| G6 | 权限不倒退 | 四角色 × 新资源 × 新动作的越权用例 **0 漏格**（后端强制，前端只做显隐） |

### 1.4 非目标（本期明确不做）

- 不做用例在线协同编辑、不做富文本/附件正文（现有编辑器与导入正文已够用）；
- 不做执行链改造、不新增执行内核（RF / Pytest 双内核沿用 v2.7 现状）；
- 不做 AI 生成用例、不做需求-用例自动追溯；
- 不做移动端原生 App（仅保证窄屏可用）；
- 不做多租户计费、不做对外 SaaS 化；
- 不做 Excel 公式计算引擎（公式单元格按缓存值读取，`#REF!` 等错误值按原文保留并标记）。

## 2. 用户、角色与权限

### 2.1 角色画像与核心诉求

| 角色 | 典型任务 | 本期最在意 |
|---|---|---|
| ADMIN 管理员 | 建公共库、管模板、改编码、处置冲突 | 「全局可控、出事能回滚」 |
| PM 项目经理 | 跨项目看用例与资产、从模板建项目、分配成员 | 「看得见全局，但不越权改别人的项目」 |
| ENGINEER 测试工程师 | 在项目里引用公共用例、执行、同步 | 「引用来的用例能直接用，不被上游悄悄改坏」 |
| VIEWER 只读 | 看报告、看用例 | 「不会误操作，页面不给我不能点的按钮」 |

### 2.2 权限矩阵增量（后端为准）

| 资源 / 动作 | ADMIN | PM | ENGINEER | VIEWER |
|---|---|---|---|---|
| `global:enter`（进入全局模式） | ✅ | ✅ | ❌ | ❌ |
| `global:project:read` | ✅ 全部 | ✅ 全部（只读） | ❌ | ❌ |
| `global:project:write` | ✅ | ✅ 仅自己创建/被加入 | ❌ | ❌ |
| `global:case:import` | ✅ | ✅ | ❌ | ❌ |
| `global:case:export` | ✅ | ✅ | ❌ | ❌ |
| `global:case:edit` | ✅ | ✅（公共库仅 ADMIN） | ❌ | ❌ |
| `global:asset:import` | ✅ | ✅ | ❌ | ❌ |
| `global:template:manage` | ✅ | ✅ 团队内 | ❌ | ❌ |
| `template:promote`（提升为全局） | ✅ | ❌ | ❌ | ❌ |
| `project:code:change` | ✅（一次 + reason） | ❌ | ❌ | ❌ |
| `project:member:write` | ✅ | ✅ 自己项目 | ❌ | ❌ |
| `project:sync:run` | ✅ | ✅ 自己项目 | ✅ 自己项目（仅预览） | ❌ |

> 实现纪律：前端只根据能力码显隐，**所有判定在后端**；`authz-matrix.yaml` 必须与 `PermissionMatrix` 同轮更新，单测覆盖「角色 × 资源 × 动作」全格。

### 2.3 已拍板决策的落地口径

| 决策 | 落地口径 |
|---|---|
| Q1 PM 全局可见范围 | 全部项目**只读可见**；自己创建或被加入的项目可写。列表用 `own / joined / readonly` 三态标签，写操作按项目逐个判定 |
| Q2 公共库数据域 | 单例「平台项目」`project.kind='platform'`，复用 57 张 `project_id` 表；平台项目不可删、不可停用、不出现在普通项目列表 |
| Q3 引用 vs 复制 | 默认引用；复制为显式二次确认，文案写明「复制后不再随公共库更新」 |
| Q4 编码只读 | 编辑态不可改；`PUT /api/projects/{id}/code` 仅 ADMIN、仅一次、必须 `reason`、写审计 |
| Q5 模板共享 | `private`（本人）/ `team`（团队，默认）/ `public`（全局，仅 ADMIN 可提升） |

### 2.4 多角色求值规则

1. 有效项目权限 = **全局角色权限 ∪ 项目角色权限**（并集，取最大允许）；
2. 同一用户在同一项目可有 1–3 个项目角色，`project_member.member_role` 保存「主角色」用于展示与排序；
3. 移除角色时若导致项目无 PM，服务端拒绝并返回 `LAST_PM_REQUIRED`；
4. 旧数据回填：`member_role` 逐行写入 `project_member_role`，回填脚本幂等，失败可回滚。

### 3.3 排序原则与三条反例

**原则**：数据先于界面、模型先于交互、能被引用先于能存模板、能证明正确先于能批量同步。

| 反例（不采用） | 为什么错 |
|---|---|
| 先做模板再导入 | 模板要存「用例/资产」，公共库还没有对象，只能存空壳 |
| 先做双模式再做成员多角色 | 双模式的授权分配依赖角色求值，单角色下必须返工 |
| 先做存量同步再做导出 | 同步没有 round-trip 基线，「同步后是否一致」无法判定 |

### 3.4 版本落号与回写规则

1. 每版收口时 `VERSION` 落号到该主线（如 `4.6.0`），CHANGELOG 增小节并标 `<!-- current -->`；
2. 「关于」页、版本迭代页、`/api/_ping`、CHANGELOG 四处版本号一致；
3. 本 PRD 的 FR 编号只增不改；实现偏离时在该版 PRD 摘要里写偏差，不回改本文；
4. 任何一版不必等前一版的「门禁判定」才开工，但**必须等前一版退出条件全部满足**（判定与开发解耦）。

## 4. 4.4.0 权限与成员治理

**目标**：把「一人一角色」升级为「一人多角色 + 批量成员」，并把「能否进入全局模式」变成服务端能力而非页面约定。

**用户故事**

- US-44-01：作为 PM，我在创建项目时一次勾选 5 个成员并给每人分配 1–2 个角色，不必逐个添加。
- US-44-02：作为测试负责人，我既是项目的 ENGINEER 又是 VIEWER 角色组的成员，权限按并集生效，不需要为我要两个账号。
- US-44-03：作为 ADMIN，我把最后一名 PM 降权时被拒绝，并看到「项目必须保留至少一名项目经理」。

**功能需求**

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-v4.4-01 | 新增 `project_member_role(project_id,user_id,role_code)`，主键三列；`project_member.member_role` 保留为主角色 | DDL 与 down 脚本可正/回滚；旧数据 100% 回填；重复写入幂等 |
| FR-v4.4-02 | 有效权限按「全局角色 ∪ 项目角色」求值 | 单元测试覆盖 4 角色 × 资源 × 动作全格；结果与 `authz-matrix.yaml` 一致 |
| FR-v4.4-03 | 成员批量多选：向导成员步与项目成员页支持一次选 N 人 | 一次加 5 人成功；部分失败返回逐人原因；重复用户去重 |
| FR-v4.4-04 | 成员行内多角色编辑，保存即时生效 | 同一人 2 角色保存后权限并集生效；刷新后不丢 |
| FR-v4.4-05 | 最后一名 PM 保护 | 移除/降权最后 PM 返回 409 `LAST_PM_REQUIRED`；前端按钮禁用并给文案 |

### 5.4 品牌与顶栏优化评估（2026-11-10 补充需求）

#### 5.4.1 资产盘点（`Robot-Autotest/logo/`）

| 文件 | 格式 | 画面构成 | 结论 |
|---|---|---|---|
| `白泽Logo_白底黑线矢量版.svg` | SVG 矢量，1254×1254 | 满幅白底 `#FFFFFF` + 黑线 `#111111`（8 条独立 path） | 作为**亮色主题品牌展示件**；直接放顶栏会带一块白方块 |
| `白泽Logo_黑金矢量版.svg` | SVG 矢量，1254×1254 | 径向黑底 `#17151A→#040713` + 香槟金渐变（`#FFEBC0→#C78F47`） | 作为**暗色主题品牌展示件**；金色是渐变，不能用 `currentColor` 一键换色 |
| `白色版本.png` | PNG，800×800，RGB **无 Alpha** | 白底不透明 | 缩到 24px 边缘发糊且带白底，**只用于文档/演示**，不进 UI |
| `金色版本.png` | PNG，800×800，RGB **无 Alpha** | 黑底不透明 | 放亮色界面会出现黑框；**只用于文档/演示**，不进 UI |

> 结论：UI 一律用 SVG，不用 PNG；两份 SVG 都带满幅背景，必须先拆出「透明底标记」，否则无法融入顶栏/侧栏。

#### 5.4.2 集成方案（三层）

| 层 | 用途 | 做法 | 尺寸 |
|---|---|---|---|
| 标记层 `logo-mark.svg` | 顶栏、折叠侧栏、面包屑首页、加载态 | 从两份 SVG 移除满幅 `rect`，路径改 `fill="currentColor"`（亮色黑、暗色金）；另存一份保留金色渐变的 `logo-mark-gold.svg` 供暗色 | 24 / 28 |
| 展示层 `logo-lockup-*.svg` | 登录页、关于页、空态/启动页 | 整图作「品牌砖」：`border-radius: var(--radius-xl)` + 1px 主题边框 + `--surface-2` 底；亮/暗各一份 | 48 / 72 |
| 图标层 | favicon、PWA、快捷方式 | 由标记层导出 32 / 180 / 512 PNG；`manifest` 按 `prefers-color-scheme` 提供亮/暗两套 | 32 / 180 / 512 |

**主题与强调色规则**

1. 亮色主题标记用 `--logo-fg`（近黑），暗色用 `--logo-gold`（`#E5B464` 系）；两者都是新增 token，不写死颜色；
2. **标记默认不跟随强调色**。理由有二：6 强调色 × 2 主题 = 12 组，跟随会让品牌色被稀释；`gold` 强调色与金色标记同色时，选中态与品牌标记无法区分；
3. 强调色只作用于按钮、选中态、图表主色；Logo 所在容器统一 `--surface-2`，保证 12 组下不撞色；
4. 对比度：标记与相邻背景 ≥ 3:1（非文本图形 AA）；登录页正文与底图 ≥ 4.5:1；
5. 主题切换时 150 ms 交叉淡入；`prefers-reduced-motion` 下直接切换，不做缩放/旋转；
6. 预留尺寸：顶栏 `24×24`、折叠侧栏 `28×28`、登录 `72×72`、关于 `48×48`，用固定盒模型防布局位移。

#### 5.4.4 强调色色板（方框 → 圆形）

## 10. 横向设计

### 10.1 幂等规范（三层）

| 层 | 键 | 作用 | 失败表现（必须避免） |
|---|---|---|---|
| 文件级 | `file_sha256` + `idempotency_key` | 同一次上传重复提交不产生新批次 | 重复点击生成 2 个批次 |
| 行级 | `(project_id, external_id)`；无编号用 `content_key` | 重复导入同一行不翻倍 | 730 条变 1460 条 |
| 版本级 | `content_sha` | 内容未变不产生新版本 | 版本表线性膨胀 |

**统一响应**：重复提交返回首次批次 id + `idempotent=true`，前端提示「与批次 #N 一致，无新增变更」。

### 10.2 分类体系

1. 字典表 `case_category(id, code, l1, l2, sort_no, enabled)`，`code` 全局唯一；
2. 用例表冗余 `category_l1/category_l2` 并建联合索引，列表按冗余列过滤（避免三表联查）；
3. 归一化在解析层完成：`trim` → 全角转半角 → 多空格合并 → 空值归「未分类」；
4. 分类用途三处：列表筛选、批量建用例集、看板聚合；三处口径一致（同一 SQL 视图）。

### 10.3 导入导出格式契约

| 项 | 规则 |
|---|---|
| Sheet 识别 | 按名称别名匹配（`Import/导入` 等）+ 内容嗅探；未知 Sheet 忽略并记录 |
| 表头行 | 前 10 行内探测；两套命名同时支持 |
| 列序（导出） | 冻结 14 列；新增列只追加；列名走别名表 |
| 分节表 | 以「服务器 / 交换机 / 端口」等节标题切段；空段跳过 |
| 数值/日期 | 按单元格类型读取；公式取缓存值；错误值保留原文并标记 |
| 版本 | 工作簿版本号入库；不认识的版本给警告，不阻断 |
| 文件 | ≤ 20 MB；行数 ≤ 20000；zip 膨胀比 ≤ 100；仅 `.xlsx` |

## 14. 风险与缓解

## 附录 A 术语

| 术语 | 含义 |
|---|---|
| 公共库 | 平台项目内的用例/资产，供各项目引用 |
| 平台项目 | `project.kind='platform'` 的单例项目，承载公共库 |
| 引用 | 项目记录「来源 id」，内容随公共库更新（`track-latest`） |
| 复制 | 项目内独立副本，不再跟随公共库 |
| `local_override` | 引用后被项目本地修改，同步时受保护 |
| round-trip | 导入 → 导出 → 再导入的差异比对 |
| 软失效 | 标记 `deprecated` 而非物理删除 |
