## 2. 背景：为什么会突然「要重新发 jar」

用例库 `7ee6877` 把待评审脚本放进 `tests/nic/pending_review/`（54 个文件）与
`tests/nic/awaiting_review/`（92 个文件），目录内 `conftest.py` 明确写「审核通过后再迁入特性目录」。

但平台侧 `PytestScriptScanner.SKIP_DIRS` 原本只有 7 个产物类目录
（`.git/.venv/venv/__pycache__/artifacts/node_modules/.pytest_cache`），**不认评审目录**，于是：

- 扫描 217 个脚本，其中 146 个未过评审；
- 138 条库中已有编号被绑到**待评审版本**（执行会跑到没过审的代码）；
- `IM-NET-007` / `IM-NET-057` 在正式目录与 `pending_review` 各有一份 → 重复绑定 2 条；
- 覆盖率虚高到 44.3%。

### 2.1 与「用例和平台解耦」的关系（大师问过，这里定口径）

既有解耦口径是 PRD **N3：git 是用例真源，平台只引用不改写**。这条守住了——本次只 `fetch` + `ff merge`，
未改 `pytest-cases` 任何字节。

但 N3 管的是**所有权**，没管**读取边界**。而「哪些文件算正式用例」原先由编译期常量
`SKIP_DIRS` 决定，不是数据也不是配置——所以仓库侧一调整目录就要改码发版。

**结论**：解耦只做了写侧，读侧仍是硬编码耦合。本次把边界挪到运行期配置，属于补齐，
不是推翻 N3。以后仓库再增删语义目录，改配置即可，**不需要再发 jar**。

## 3. 改了什么

后端 4 个源文件 + 2 个测试 + 前端 3 个文件：

| 文件 | 改动 | 判据 |
|---|---|---|
| `application/kernel/pytest/PytestScriptScanner.java` | `SKIP_DIRS` 内置 `pending_review`、`awaiting_review`；新增 `scan(repoRoot, extraSkipDirs)` 重载；`skipped()` 按路径段取并集 | 新单测「默认跳过两级评审目录」 |
| `application/kernel/pytest/PytestProjectSettings.java` | 新增 `SCAN_EXCLUDE = pytest.scan_exclude` 常量与 `scanExclude()` 解析（`[,;\s]+` 切分、去空、`Set.copyOf`） | 配置读写实测 |
| `application/kernel/pytest/PytestSettingsService.java` | 键进 `KNOWN` 白名单；`validate()` 新增 `scan_exclude` 分支，含 `/`、`\`、`..` 一律拒 | 新单测「只接受目录名不接受路径」 |
| `application/kernel/pytest/PytestBindingSyncService.java` | `sync()` 传 `PytestProjectSettings.scanExclude(config)` | 同步实测 71 条 |
| `frontend/src/views/PytestWorkbenchView.vue` | `SETTING_FIELDS` / `settingLabelKeys` 增 `scan_exclude` | `npm run build` 后 dist 含该键 |
| `frontend/src/locales/{zh-CN,en-US}.ts` | 各补一条 `settingLabels.scan_exclude` | 同上 |

**设计取舍（接手人注意）**：`scan_exclude` 是**追加**语义，只能多跳过、不能减少。
内置排除清单（含评审目录）永不放宽——缩窄扫描范围是安全方向，放宽不是。
未配置 ≠ 不排除：空值仍走内置清单。
