## 3. 负向与反向验证

| 编号 | 注入方式 | 期望 | 实测 |
|---|---|---|---|
| N-CLI-01 | 用裸 npm bin 替代 wrapper（同一收窄 PATH） | 必须失败 | **rc=127 判红**；换回 wrapper rc=0 回绿 |
| N-CLI-02 | 内置目录指向空临时目录 | `available()=false`，argv[0] 仍为裸名 | 单测 PASS |
| N-CLI-03 | 同时设 `AI_CLI_PATH` 与内置副本 | 注入值胜出 | 单测 PASS |
| N-CLI-04 | `AI_CLI_ARGS` 传非法参数（如裸 `--provider`） | 子进程 rc≠0，接口仍 200 且 `degraded=true` | **实测：`Unknown option: --provider`，degraded=true，接口未 5xx** |
| N-CLI-05 | 缺凭据的 dsh | 返回结构化错误，不崩 | `MISSING_CREDENTIAL` / 401，`degraded=true` |

N-CLI-01 与 N-CLI-04 是**自然发生的反向证据**（不是为测试而造）：前者出现在 wrapper 上线前的那次场景 B，
后者出现在 `AI_CLI_ARGS` 被 systemd 拆断的那次场景 B。两次都如实留在 `backend-chain.log` 里，未删除。
