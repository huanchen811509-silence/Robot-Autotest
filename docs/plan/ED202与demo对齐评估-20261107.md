## 1. 结论先行

1. **上一轮评估的「先收口、再判定、后试点」结论仍然成立**，本轮新增的 demo 对齐与 ED202 导入**不能插到层 S 之前**。理由：demo 对齐要动 `test_scenario`、菜单、导入解析三处，而 v2.0 台账仍有 44 PARTIAL / 7 NOT-RUN、G4/G5/G7/G8 未判；在证据债未清时开新功能面，会让第七道回写再欠一笔。故推荐顺序 **P0 收口 → P1 本机证据 → P2 判门 → P3 demo 对齐与 ED202 导入 → P4 现场与试点**。
2. **demo 副本是残缺副本，不能当完整可移植源**：实测只有 `backend/niclab/`（259 个 `.py`）+ 运行数据 1.5 GiB，**无 `frontend/`、无 `docs/`**；`app.py:127` 明确指向 `frontend/static/index.html`，该文件不存在 → 副本无法启动界面。菜单只能从 `data/tmp/perf-baseline-7bn_pa4i/regression.html:40-53` 的 14 组 `<details>` 快照、17 张 PNG 截图与 `CHANGELOG.md`（847 行）反推。**这是必须写进 PRD 的前置条件，不是可以忽略的细节。**
3. **「全面移植菜单」不能做成 1:1 复制**：demo 是**设备 / CX7 网卡实测平台**（14 组里 6 组是业务能力域，依赖 GPU01/02、400G 口、交换机 SSH），本平台是 **RF / pytest 通用自动化测试平台**。1:1 复制会把通用平台改造成 CX7 专用平台。推荐「**平台管理域对齐、业务能力域降为筛选标签**」——这是本评估最重要的有意取舍，需大师拍板。
4. **ED202 的分母有两套，必须先定口径再导入**：实测唯一用例编号 **813** 条，其中「测试用例看板」**730** 条 = 六张明细表并集（差集双向均为 0），`UECGSE适配` **83** 条与看板**零交集**、未计入 730。看板自报「总用例数 730 / 通过率 0.4658」，状态分布 通过 330 / 通过-人工 10 / 部分完成 54 / 跳过 52 / 待执行 261 / 不通过 23。**若直接以 730 建库，83 条 UEC 适配会被静默丢掉。**
5. **ED202 现在导不进本平台**：`CaseImportService.java:36-44` 明确把「测试步骤 / A 端命令 / B 端命令 / 交换机配置」等列**静默忽略不入库**；`:82-103` 的 `HEADER_ALIASES` 没有「二级分类」映射；`:128-132` 只取**第 0 个 sheet**，而 ED202 的用例分散在 6 个 sheet 且表头行不一致（Import 在第 3 行，其余在第 1 行）。这不是配置问题，是**三处真功能缺口**。
6. **「场景 + 项目」两层在本平台是半截的**：`test_scenario`（V8_3:33-41）只存 `case_set_ids` 逗号串、无外键、只允许一层，`POST /api/scenarios/4/execute` 实测 **404**（`docs/evidence/v2.0/a4-http-e2e/raw/http-trace.jsonl:69`）；用例直接挂 `project_id`，不存在「项目 → 场景 → 用例」组织。demo 的 `test_sets.kind` 三态（`case_set` / `scenario` / `execution_selection`）是更完整且可直接借鉴的模型。
7. **demo 最值得借鉴的不是菜单，是证据链纪律**：冻结计划 SHA + 幂等提交、未知提交只读找回不重发、每例三遍独立证据、`[hostname]` + `#步骤N说明 → 真实短命令 → 完整 stdout/stderr + 退出码` 的 LOG 格式、历史通过不计本轮、缺失原始流明确拒绝伪造。这些与本平台「不接受单测绿当放行理由」「output.xml metadata 六必填」同向，且**不依赖真实设备**，是纯平台能力。
8. **demo 的「判定与报告」自身是待开发**（`regression.html:44` 标 `data-phase="4"`，`CHANGELOG.md:399`「尚未创建报告实现/文档」），而本平台的报告/导出/快照反而更完备。**这一项应反向输出，不是移植输入。**

### 4.1 分母与唯一性（本次实跑）

| 项 | 实测 | 说明 |
|---|---|---|
| 文件 | 381736 B，7 个 sheet | `测试用例看板` / `Import详细测试流程` / `XCCL详细测试流程` / `AI参数网_详细测试流程` / `存储_详细测试流程` / `HCI详细测试流程` / `UECGSE适配` |

### 4.3 场景 / 项目映射的输入

ED202 的「一级分类」可直接作为**场景**候选，「业务域（sheet）」可作为**项目或场景组**候选。实测一级分类样例：基础管理测试、系统与网卡管理、CCL通信测试、基础组网与链路、存储协议与基础网络、RDMA与用户态存储、云平台接入测试、Kubernetes RDMA资源与网络接入等；二级分类如 BMC/BIOS识别、集合通信功能、iSCSI协议接入、PF直通与虚拟机接入。**分类名不统一、有跨 sheet 同名**，映射前需一张人工确认的对照表，不能自动按字符串生成后即宣称完成。
