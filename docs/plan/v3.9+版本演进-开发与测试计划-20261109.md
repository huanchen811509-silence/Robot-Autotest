## 1. 结论与执行摘要

**一句话**：本计划把 11 条问题（Q1–Q9 + 追加的 Q10/Q11）拆成 **17 个可独立验收的工作包**，分三批（v3.9.0 / v3.10.0 / v3.11.0）推进，每包都有“改动点 → 验收命令 → 证据路径”三件套；新增 **2 个门禁步骤**（28 用例命令契约、29 资产采集契约）并**扩展 2 个**（27 对比度纳入表单控件、23 版本一致性纳入 CHANGELOG 小节比对）。

三个必须提前说清的约束：

1. **Q1 无法闭环验证到底**：原生 `<select>` 弹层不能被 CDP 截图。计划里安排“计算样式断言 100% 自动化 + 双主题各 1 帧人工确认”，人工那一帧必须真做，否则不算过。
2. **Q2 的 pytest 侧命令不会自动出现**：pytest 用例默认不打印命令，只能靠标记或约定。计划里规定 `NONE` 必须显式展示并写原因，**不允许平台编造命令**。
3. **Q7 的真实采集需要设备与凭据**：命令集与解析可用离线夹具验证，真实设备采集一律标 `BLOCKED` 并写原因，不用模拟数据充当实测。

## 3. 架构与设计决策（ADR-39-01 ~ 08）

| ADR | 主题 | 决策 | 理由 | 代价 |
|---|---|---|---|---|
| ADR-39-01 | 下拉控件主题适配 | **全局兜底**：用元素选择器给所有 `select`/`option` 设不透明底色与显式 `color-scheme`，各页不再各自写 | 一处修复覆盖 10 个现存 + 未来新增；避免“改了这个忘了那个” | 个别页面若有特殊视觉需求需用显式覆盖类 |
| ADR-39-02 | 用例命令数据模型 | **扩展 `test_result` 加 3 列**（`command_text` / `command_source` / `command_exit_code`），不新建表 | 与用例结果同生命周期，天然按 run/case 索引；新表要额外 JOIN | 表变宽；迁移需可空先行 |
| ADR-39-03 | pytest 日志保留 | 归一化**保留** `stdout/stderr/log/longrepr`，落 `log_span` 可切片 | 能力本就存在于 json-report，丢弃是净损失 | 解析代码变复杂；大日志需截断上限 |
| ADR-39-04 | RF 命令提取 | **识别式提取**（关键字名白名单 + 参数首值），不做全文正则盲扫 | 盲扫会把断言消息误判成命令 | 新入口需登记白名单，未识别要告警 |
| ADR-39-05 | 列表密度 | 页大小选项化 + 表格自适应容器，**移除固定 `45vh`** | 固定高度与固定条数双重限制导致半屏空白 | 需处理空态与极窄屏 |
| ADR-39-06 | 计划页信息架构 | **三区 + 行内操作收菜单**，新建改抽屉 | 单页四件事是认知过载根源 | 改动面大，需功能对照表防漏 |
| ADR-39-07 | 报告来源 | `TestReport` 增 `source_type`（RUN/CASE_SET）与 `case_set_id`，**快照仍内联数据** | 保持“冻结后自包含”这一既有硬约束 | 快照体积增大；需体积观测 |
| ADR-39-08 | 资产采集 | **显式触发 + 命令白名单 + 复用 SSH 通道**，不在后台自动跑 | 采集是设备侧动作，需可控可审计 | 用户要主动点一次 |

## 4. 数据模型变更

> 硬规矩：已应用迁移不可改，只能追加；NOT NULL 改造走“加可空 → 回填 → 收紧”三步。

| 迁移文件 | 变更 | 兼容性 | 回滚 |
|---|---|---|---|
| `V11_24__v3_9_case_command.sql` | `test_result` 增 `command_text TEXT NULL`、`command_source VARCHAR(24) NULL`、`command_exit_code INT NULL` | 纯新增可空列，旧数据不影响 | `DROP COLUMN` 三列 |
| `V11_25__v3_9_report_tpl_preset.sql` | 新增 `report_template_preset`（预置模板定义，代码内置 + 表存项目级覆盖） | 新表，无外键改动 | `DROP TABLE` |
| `V12_1__v3_10_report_source.sql` | `test_report` 增 `source_type VARCHAR(16) NOT NULL DEFAULT 'RUN'`、`case_set_id BIGINT NULL` | 有默认值，旧行自动为 RUN | 删列（默认值不丢语义） |
| `V11_26__v3_11_host_inventory.sql` | 新增 `device_host_spec`（device_id、类别、键、值、命令、采集时间、状态）；`device_port` 增 `rdma_device`、`gid_index`、`link_layer` | 新表 + 可空列 | `DROP TABLE` / `DROP COLUMN` |

**索引**：`device_host_spec(device_id, category, collected_at)`；`test_result(run_id, case_id)` 已有，不重复建。

**回填策略**：历史 `test_result` 的 `command_text` 保持 `NULL`，报告页显示“历史数据未采集（v3.9.0 之前）”，**不批量猜测**。
