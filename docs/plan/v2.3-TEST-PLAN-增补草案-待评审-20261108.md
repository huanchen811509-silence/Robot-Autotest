### 3.1.1 执行与报告合并专项（TC-UI-29..33）

这 5 条是为「执行 + 报告合并」这一个决策单独设的判据。合并动的是导航结构，坏起来是**静默**的（入口在但点不到、或权限被悄悄收回），所以必须逐条实测。

| 编号 | FR | 用例 | 怎么做 | 通过判据 | 证据形态 |
|---|---|---|---|---|---|
| TC-UI-29 | FR-UI-26 | 合并组结构与顺序 | 读 `NAVIGATION`，定位 `key === 'execution'`，取 children 的 path 序列；同时断言不存在 `key === 'reports'` 的一级项 | path 序列严格等于 `/runs`, `/plans`, `/nodes`, `/reports`, `/reports/templates`, `/test-reports`；`reports` 一级项数 = 0 | vitest 输出行（打印实际序列） |
| TC-UI-30 | FR-UI-27 | 角色矩阵无回归 | 用 `navKeysForRole` 取 viewer / engineer / admin 的可见 key 集合，与**合并前的基线**逐项比对 | viewer 含 3 个报告项、不含 3 个运行项；engineer 6 项全含；admin 含全部。三项集合与基线逐 key 相等 | vitest 输出行 + 三个角色集合快照 |
| TC-UI-31 | FR-UI-28 | 孤儿页消失且可点达 | ① 单测统计 `path === '/test-reports'` 的叶子数；② 浏览器回归里从侧栏真实点击该入口 | 叶子数 = 1；点击后 URL 变为 `/test-reports` 且页面渲染出列表（非 404、非空白） | vitest 输出行 + 浏览器截图 + 当前 URL 读数 |
| TC-UI-32 | FR-UI-29 | section 分隔与判定隔离 | ① 断言前 3 项 `section === 'run'`、后 3 项 `section === 'report'`；② 渲染后数该组内分隔线数量；③ 对同一路由分别在「带 section」与「不带 section」的节点上跑 `isLeafActive` | section 取值正确；分隔线数量 = 1；两次 `isLeafActive` 结果相同（证明 section 不参与判定） | vitest 输出行 |
| TC-UI-33 | FR-UI-30 | 业务域约束不倒退 | 跑 `hasBusinessDomainAsTopLevel(NAVIGATION)`；再跑 v2.2 MENU-01 的既有断言 | 返回 `false`；MENU-01 用例全过、无一条被删或跳过 | vitest 输出行 + 用例清单比对 |

**TC-UI-30 的基线怎么拿**：合并前先在当前 `main` 上跑一次 `navKeysForRole('viewer' \| 'engineer' \| 'admin')`，把三个集合存进 `docs/evidence/v3.0.1/v23/UI-01/role-baseline.json`。合并后与这份基线比对，**不是**与改动后自己算的期望值比对——否则等于自证。

**TC-UI-31 为什么必须上浏览器**：单测只能证明「导航树里有这一项」，证明不了「点下去真能到」。v2.2 已经踩过同类坑（`executeScenario` 源码有、jar 里没有，真实 HTTP 一直 404），所以这条必须有真实点击后的 URL 与截图。

## 6. metadata 约定（本批适用性说明）

本批测试**不产出 Robot Framework `output.xml`**（全是 vitest / JUnit / curl / 浏览器），因此 metadata 六必填（`CASE_ID` / `RUN_ID` / `QA_PROJECT` / `DUT` / `LINK` / `SW_BUILD`）在本批无落盘对象。

但规则不因此失效，替代约束如下：

| 项 | 本批落法 |
|---|---|
| 可追溯 | 每份证据 README 顶部写明：执行时间、执行人（学徒）、基线提交号、命令原文、结果行 |
| 唯一键 | 证据目录用 `v23/<包号>/`，原始件用 `raw-20261108/<包号>-<项>.log` |
| 凭据 | 证据里不得出现密码/token 原文；curl 命令中的 token 用 `$TOKEN` 占位，不落真值 |
| 未来若引入 RF 套件 | 必须按六必填补齐，且 `check_output_metadata.py` 会扫 `docs/evidence/v3.0.1/**` |
