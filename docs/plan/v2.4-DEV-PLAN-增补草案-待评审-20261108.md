## 2. 关键实现点

### 2.1 候选顺序

```text
hermes → dsh → claude → codex → gemini → aider → pi
```

- 前两条是大师点名新增的外部 CLI，优先尝试。
- 中间四条是原有候选，相对顺序一字未改（避免既有部署选型漂移）。
- `pi` 末位兜底：外部全不可用时才轮到软件包自带的副本。

### 2.2 可执行文件解析优先级

```text
AI_CLI_PATH 注入  >  PATH 上的同名命令（仅 pi）  >  内置副本 bin/pi  >  内置副本 node_modules/.bin/pi
```

`AI_CLI_PATH` 对**任何** CLI 生效（既有能力）；内置解析只对 `pi` 生效。

### 2.3 内置启动器 wrapper

```sh
#!/bin/sh
SELF_DIR=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd) || exit 1
ROOT=$(CDPATH= cd -- "$SELF_DIR/.." && pwd) || exit 1
for d in /opt/node24/bin /usr/local/bin /usr/bin /bin "$HOME/.local/bin"; do
    if [ -x "$d/node" ]; then PATH="$d:$PATH"; export PATH; break; fi
done
exec "$ROOT/node_modules/.bin/pi" "$@"
```

用纯 sh 写、不依赖 node 自身，避免「找 node 的启动器又需要 node」的循环。

## 4. 偏差登记

| 编号 | 偏差 | 原因 | 处置 |
|---|---|---|---|
| D-1 | 初版把 `pi` 放在第三位 | 写代码时先入为主按「已验证可用优先」，与「保底」语义冲突 | 单测 `piIsTheLastCandidateAsBundledFallback` 判红后改为末位 |
| D-2 | 内置 pi 在收窄 PATH 下 `exitCode=127` | npm bin 的 shebang 是 `#!/usr/bin/env node`；后端 PATH 不含 node | 新增 `bin/pi` wrapper 自解析 node；后端优先用 wrapper；补两条单测 |
| D-3 | `AI_CLI_ARGS` 被 systemd 拆断 | `Environment=A=1 B=2` 会按空格拆成多个赋值 | systemd 侧加引号：`Environment="AI_CLI_ARGS=..."`；写入证据日志 |
| D-4 | dsh 未能真实推理 | 需 DeepSeek 官方 key，本机 ARK key 被判 401 | 如实记「链路通、缺凭据」，未绕过；待大师提供 key |
| D-5 | 内置副本 158 MB | pi 及其依赖体积 | 不随 jar 打包，按需安装；评估 R-1 登记 |
| D-6 | 实际执行顺序是「先验证、后编码、再补文档」 | 不先试跑就无法写出可判定验收项（例如 dsh 缺的是凭据不是集成），也无法发现 127 缺陷 | 本文档如实记录顺序，不假装「文档先行」；结论与读数均来自实测 |
