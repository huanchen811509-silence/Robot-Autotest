**排版断言的写法（不能只断「有几个按钮」）**：

| 断言 | 判据 |
|---|---|
| 控件高度一致 | 取 4 类控件的 `getBoundingClientRect().height`，两两差 ≤ 1 且等于 28 |
| 图标按钮方正 | 每个图标按钮 `offsetWidth === offsetHeight === 28` |
| 段落与分隔 | `[data-testid^="header-section-"]` 数量 = 4 且顺序固定；分隔线元素数量 = 3 |
| 组内 vs 组间间距 | 组内相邻间距 < 组间间距（读 computed style，不断具体像素值以免受缩放影响） |
| 「关于」已移除 | 顶栏内不存在 `aria-label` 等于关于词条的按钮 |
| 侧栏折叠位置 | 侧栏头部容器内存在折叠按钮，顶栏内不存在 |
| 登出安全 | 登出按钮含 `danger` 类；点击后 `ConfirmModal` 可见；取消时 `auth.logout` 未被调用 |

**为什么这次不新增组件**：v1.0 曾计划 `ProjectSwitcher.vue` + `UserMenu.vue`。按大师「做排版美工、不搬功能」的澄清，二者都不再需要——项目切换保留原生 `<select>` 只换造型，语言/登出保留平铺只补图标与危险色。少两个组件意味着少两份状态管理、少两份键盘可达性测试，风险显著下降。

## 5. 偏差与回退

| 情形 | 处理 |
|---|---|
| `scrollbar-gutter` 引发布局回归 | 先只给 `.app-main` 加，不行则退到「仅 `scrollbar-width: thin`」，并在证据里写明取舍 |
| 卡牌聚合 SQL 超预算（P95 > 800ms） | 先加索引（`run.project_id` + `run_status` 复合），仍超则改为「首屏只算概要、细节按需」，并记偏差 |
| 某强调色主色不达 AA | 按 PRD 降级：保留主色、只调派生、书面写「不可用于正文低于 X px」，不偷偷降阈值 |
| 菜单重排后某测试大面积失败 | 先修断言再看是否真回归；**不许**为了让测试过而回退顺序（顺序是本节拍板项） |
| 后端端点无法在真链路验证 | 不允许用单测替代；先查服务是否旧 jar（v2.2 已踩过：源码对齐 ≠ 部署对齐），重建并重启后再验 |
| **合并后 `viewer` 角色丢失报告入口** | 立即回退到「组级不带 capability + 子项分别带」的方案，**不许**改成「给 viewer 加 `execution:read`」——那是放大权限，不是修回归 |
| **28px 栅格与 naive-ui 内建尺寸打架** | 顶栏内一律原生 `<button>` + 自定义 class；若某控件必须用 naive-ui 组件，则该控件独占一行二次对齐，并在证据里记例外 |
| **合并组 6 项导致侧栏过长** | 不改回 8 组（那是拍板项）；先启用「默认只展开当前组」，实测仍不可接受再评估「报告模板」并入报告列表工具栏（PRD L-UI-05） |
