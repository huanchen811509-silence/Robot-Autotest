## 1. 结论先行

本轮不是“再加功能”，而是**把已经交付的功能变得可看清、可追溯、可选对、摸得着**。

一句话概括十一条需求的共同根因：**平台在 v3.0–v3.4 把“能力”堆齐了，但“看到的界面”和“留下的证据”没跟上**——下拉框在暗色下白底看不见（Q1）、用例日志记了却不落到报告页（Q2）、列表页一半工作区空着（Q3）、计划页一屏 244 个可点控件（Q4）、模板页要滚 1.8 屏才能勾完字段（Q5）、对外报告要手打 runId（Q6）、资产页看不到机器的 CPU/GPU/RoCE（Q7）、环境与维护 8 个页面只有壳（Q8）；追加的两条同样是“收不住”与“对不上”——侧栏收起后空间没收住、按钮被顶栏压住、刷新也救不回（Q10），版本收口后关于页与版本迭代页缺少强制同步点（Q11）。

因此版本线按“**看得清 → 选得对 → 摸得着**”三段推进：

| 版本 | 主题 | 解决 | 交付后用户能感知的变化 |
|---|---|---|---|
| **v3.9.0** | 看得清、查得到 | Q1 Q2 Q3 Q5 | 暗色下拉能看清；每个用例在报告页直接看到“下发命令 + 结果”；列表页不再半屏空白；模板字段分卡片、有预置模板 |
| **v3.10.0** | 选得对、走得顺 | Q4 Q6 | 计划页按钮从“一屏 244 个”收敛到分区 ≤8 个主操作；对外报告草稿用下拉选执行记录与用例集，不再手打 runId |
| **v3.11.0** | 摸得着 | Q7 Q8 | 资产页能看到每台机器的 OS / 内核 / CPU / 内存 / 磁盘 / GPU / 网卡 / RoCE / IP / 路由；环境与拓扑、维护与恢复 8 个页面接上真实数据 |
| **v3.12.0（候选）** | 有节奏、防退化 | Q9 | 周期质量周报、资产漂移 diff、命令一键复跑、全量对比度巡检 |

三条线各有独立验收判据，不互相“顶账”：v3.9.0 的验收**不**依赖 v3.10.0 的成果，反之亦然。

## 3. 问题定义与根因

| 问题 | 表面现象 | 根因（都已定位到代码） | 不修的后果 |
|---|---|---|---|
| P1 暗色下拉不可读 | 下拉弹层白底、字看不清 | `select` 底色透明 + 无 `option` 规则；原生弹层回落 UA 默认色 | 暗色用户无法选项目/语言/枚举，功能等于不可用 |
| P2 日志有却不进报告 | 报告页看不到“这条用例发了什么命令” | 平台只打 run 级 argv；pytest 归一化丢 `stdout`；报告页无命令字段 | 对外报告无法自证“测了什么”，只能靠人工翻 log.html |
| P3 密度策略不统一 | 有的页半屏空白，有的页 55 行挤满 | 页大小硬编码 10 + 表格 `45vh`；计划页无分页 | 大屏浪费，小屏滚动；同一产品两种手感 |

## 7. 详细需求说明

### 7.1 FR-v3.9-01 暗色下拉可读

**现状**：10 个 select 全透明（Q1-1），`option` 无样式（Q1-2）。

**要求**：
1. 所有 `select` 必须有**不透明**底色（亮色用面板色、暗色用面板色），不得依赖父级背景透出。
2. `option` 显式设置前景与背景，取主题令牌，不写死色值。
3. `select` 上显式声明 `color-scheme`，与当前主题一致，保证原生弹层跟随。
4. 亮色主题不得因修复而变暗；两套主题都要过对比度。
5. 未来新增 select 自动受约束——用**统一类或元素选择器**兜底，不靠逐个改。

**边界与异常**：
- 禁用态：保持可辨识的低对比，但对比不低于 3:1（非文本元素口径）。
- 浏览器差异：Chrome/Edge（Chromium）为基准；Firefox 允许弹层样式不同，但不得白底浅字。
- 移动窄屏：下拉展开为全屏选择器时同样适用。

**判据**：探针 `flagged=0`；双主题各截图 1 张人工确认；亮色对比度不回退。

### 7.2 FR-v3.9-02 双内核用例级日志契约

**目标**：让“这条用例下发了什么命令、过程如何、结果如何”成为**平台一等数据**，而不是散落在框架日志里。

**契约字段**（每条用例一行）：

| 字段 | 含义 | 必填 | 无命令时 |
|---|---|---|---|
| `case_key` | 用例唯一键 | 是 | — |
| `command_text` | 下发命令原文（不含凭据） | 是 | 写 `NONE` |
| `command_source` | 来源：`RF_KEYWORD` / `PYTEST_MARK` / `STDOUT_EXTRACT` / `NONE` | 是 | 写 `NONE` |
| `exit_code` | 真实退出码 | 否 | 写 `null`，不写 0 |
| `log_span` | 过程日志区间 | 否 | 写空区间并说明 |
| `result` | PASS/FAIL/SKIP | 是 | — |

**两个内核的取材方式**：
- **RF**：解析 `output.xml` 关键字参数，识别 `Execute Command` / `Run Process` / `远端执行` / `SSH 执行命令` 等入口；同一用例多条命令时取首条为主、其余入明细。
- **pytest**：① 归一化保留 stage 的 `stdout/stderr/log/longrepr`；② 支持 `@pytest.mark.commandline("...")` 显式声明；③ 用例按约定打印 `$ <命令>` 时从 stdout 提取；三条都不满足则 `NONE`。

**硬约束**：
- 命令原文必须**脱敏**（沿用 `EvidenceLogWriter.scrub` 规则），凭据永不入库。
- 不得由平台“推测”命令：来源必须是框架事实。
- 采集失败不得静默：写 `NONE` 并记原因，报告页可见。

**判据**：两个内核各跑一次真实 run，用例覆盖率 100%（含 `NONE` 行）；抽样 10 条命令与源日志逐字一致；门禁 28 步机检 PASS。

### 7.3 FR-v3.9-03 报告页“命令 + 结果”

**现状**：报告详情页有日志抽屉，但无命令列（Q2-6）；pytest 抽屉为空（Q2-7）。

**要求**：
1. 用例列表新增“下发命令”列（超长折叠，可展开全文，可一键复制）。
2. pytest 与 RF 的 run 都必须有值（或显式“本用例未下发外部命令”）。
3. 命令旁附“结果”与耗时，导出 PDF/HTML 时同样包含。
4. 命令与日志抽屉联动：点命令定位到该条日志行。

**判据**：两种内核各 1 个真实 run 截图；抽样比对表 10 条；导出件含命令列。

### 7.4 FR-v3.9-04 列表密度

**要求**：
1. 页大小可选 10/20/50/100，选择记忆到用户偏好。
2. 默认按视口自适应：以“表格可用高度 / 行高”估算，向上取到最近的档位。
3. 表格高度改为自适应容器（去掉固定 `45vh`），底部不再留大面积空白。
4. 计划列表补分页（单页 ≤ 50 行），与其它列表统一。
5. 空态高度不塌陷，避免“空表格只有 44px”。

**判据**：复测三页，空白 ≤ 120px 或 ≤ 10% 视口；页大小切换后不刷新页面即可生效。

### 7.5 FR-v3.9-05 模板字段卡片

**分类**（按现有白名单 21 字段，不改字段集）：

| 分类 | 字段 | 数量 |
|---|---|---|
| 标识与版本 | reportId、title、version、frozenAt | 4（全必填） |
| 结论与统计 | conclusion、passCount、failCount、skipCount、passRate、caseTotal、caseCovered、coverageRate、failureDistribution、trend | 10 |
| 环境与构建 | projectName、swBuild、caseKind、startedAt、finishedAt | 5 |
| 合规声明 | disclaimer、watermark | 2（全必填） |

**预置模板**（≥4 个）：简版（标识 + 结论 + 合规）、标准（简版 + 统计）、完整（全部 21 项）、审计（标识 + 统计 + metadata 五项）。

**要求**：卡片内勾选，勾中即入已选区；已选区改为紧凑列表（一行一项，标题展开编辑）；必填项以锁定样式呈现并说明原因；整页高度 ≤ 1 屏。

**判据**：DOM 高度 ≤ 900px；4 个预置可一键应用；必填项无法取消。

### 7.6 FR-v3.9-06 侧栏收起可用且可逆

**根因链**（四步，缺一不可复现）：`.app-side` 顶部残留 `width: 200px` → grid 列收到 56px 但侧栏被自身宽度撑出列外 → 溢出部分被从 56px 起画的顶栏压住 → 按钮点不到；而折叠态已落 `localStorage`，于是刷新也回不去。

**方案（最小改动，不砍功能）**：

1. 删掉 `.app-side` 的遗留 `width: 200px`，宽度交给 `grid-template-columns`；
2. 补 `min-width: 0`（grid item 默认 `auto`，会被内容撑开）与 `overflow-x: hidden`；
3. **保留**折叠按钮与 56px 图标轨 —— 图标轨本身是有效形态，问题在实现不在形态，所以不选「直接移除」。

**判据**：见 §6.1 的 5 项。`node scripts/side-toggle-probe.mjs --selfcheck` 必红，不带参数必绿。

**为什么不用 `el.click()` 验证**：脚本调用会绕过遮挡，正好把「点不到」这个真实缺陷掩盖掉。探针走 CDP 真实鼠标事件（`Input.dispatchMouseEvent`），命中失败即判红。

### 7.7 FR-v3.9-07 关于与版本迭代同步

**现状定性**：两处都是动态读源，机制没错；缺的是「收口动作」没有强制点，且关于页没有变更入口。

**方案**：

1. 关于页新增「最近更新」区块：复用版本迭代页的**同一份数据源**（`/CHANGELOG.md` + `parseChangelog`），展示当前版本标题与前 4 条变更，并提供「查看完整版本迭代」跳转；
2. 门禁 23 步扩展：两份 CHANGELOG 的**当前版本小节逐字比对**（只比该版本小节，尾部未发版工作记录不计），并要求四类小节齐全、「新增/变更/修复」各有条目；
3. 收口清单固化为一条可判定动作：`VERSION` / 根 `CHANGELOG` / `public` 副本 / 关于页版本 / 版本迭代首条 —— 五处同版本，由门禁 23 步一次判完。

**判据**：见 §6.1 的 5 项。`node scripts/about-changelog-probe.mjs --selfcheck` 必红，不带参数必绿。

### 7.8 FR-v3.10-01 计划页信息架构

**目标**：把“一屏 244 个控件”变成“三区 + 收敛操作”。

**分区方案**：
- **上区 计划列表**：工具栏只留 新建 / 刷新 / 更多（计划组、依赖图、返回运行列表收进“更多”）；行内只留“详情”，编辑/暂停/触发/删除进行尾“更多”菜单。
- **中区 冲突处理**（折叠，默认收起，有冲突时显示计数徽标）。
- **下区 跳过事件**（折叠，默认收起）。
- 新建/编辑改为侧边抽屉或独立页，不再与列表同屏。

**要求**：首屏主操作 ≤ 8；每个原功能有明确新位置（给功能对照表）；键盘可达；批量操作仍需二次确认。

**判据**：DOM 控件计数 ≤ 8（首屏）+ 行内 1；原 12 个功能逐项可达且有用例覆盖。

### 7.11 FR-v3.11-01 资产主机清单

**采集项与命令**（全部只读，白名单）：

| 类别 | 采集命令（已核实可用） | 展示 |
|---|---|---|
| 操作系统 | `grep -m1 PRETTY_NAME /etc/os-release` | 名称 + 版本 |
| 内核 | `uname -r` | 版本串 |
| CPU | `nproc` + `lscpu`（型号/核数/主频） | 核数 + 型号 |
| 内存 | `free -m` | 总量 + 可用 |
| 磁盘 | `df -P /` + `lsblk -d -o NAME,SIZE,ROTA` | 容量 + 类型（SSD/HDD） |
| GPU | `nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader` | 型号 × 数量 + 驱动 |
| 网卡 | `ip -br addr` + `ethtool -i <if>` + `/sys/class/net/<if>/speed` | 接口/IP/驱动/固件/速率 |
| RoCE | `ibv_devinfo -v` 或 `/sys/class/infiniband/*/ports/*/rate` + GID 表 | 设备/端口状态/速率/GID |
| 路由 | `ip route` | 默认路由与关键网段 |

**要求**：每项带命令与采集时间；失败项写“未采集到”+ 原因；不写假值；采集为**显式触发**（不在后台自动跑）；凭据只从凭据库取。

**判据**：门禁 29 步机检 10 类齐全；离线夹具验证解析；失败项语义正确。
