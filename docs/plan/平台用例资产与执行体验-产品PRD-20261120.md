## 0. 一页纸摘要

**要解决的三件事**：

1. **用例跑不起来**——三条硬拦截同时成立（默认 `LX` 阻断、未绑定整单 400、绑定验证态不可达），且前端无任何按钮能解开。
2. **同一批数据三种看法**——公共用例 730 条、EHT pytest 库 469 条、项目库，三套组件、三套列、两处没有详情。
3. **同一功能两套行为**——全局/项目在用例、用例集、用户三处真双轨；「我参与的项目」还少一批项目。

**四个版本，一条主线**：先把拦截解开（v5.31）→ 再把结构统一（v5.32）→ 再把资源和计划管住（v5.33）→ 最后做报告与环境（v5.34）。

| 版本 | 主题 | FR | 一句话交付 |
|---|---|---|---|
| v5.31.0 | 跑得起来 | 8 | 绑定可确认、安全级可定级可确认、优先级归一、筛选不骗人、项目不漏、评审态不误导 |
| v5.32.0 | 一处看全 | 5 | 一个用例库视图覆盖公共/EHT/项目；筛选后能建集；用例集两侧同构 |
| v5.33.0 | 管得住 | 6 | 计划合并、节点可删可改可观察、列表有 CRUD 基线、备份能删 |
| v5.34.0 | 看得懂 | 4 | 报告模板开箱 3 个、环境有统一骨架、拓扑移植白泽真出图、链路带置信度 |

**不做什么**：不合并公共库与 EHT 库的数据（只统一呈现）；不放开平台内置报告模板的编辑（只做复制路径）；不引入图库（拓扑继续自绘）；**白泽只作只读参考**（不改其仓库、不复制代码、不引入其构建产物）；**不搬运白泽的后端拓扑推断算法**（它耦合白泽自己的快照索引与规划表）；不改 ADR-0013 的拦截强度，只把「硬阻断」改为「知情确认」（已裁定，见 §12）。

## 1. 背景与问题定义

### 1.1 用户视角的三个故事

**故事 A（跑不起来）**：我新建一条用例，默认安全级是「LX 未判定」；我建了一个用例集，点「立即执行」，返回 400「存在未绑定脚本的用例」；我把脚本补上、绑定也同步了，界面显示「已绑定 · 未校验」，但**没有任何地方能点「确认」**；我再试，还是被拦。三个红灯，一个开关都没有。

**故事 B（看不一致）**：我在「全局-公共用例」看到 730 条，有分类树、有分页、点开有 27 个字段的详情；我切到「EHT pytest 用例库工程」，看到总数写着 469，但列表只显示 50 条，翻不了页，也点不开详情。这两个页面在我的认知里都是「用例库」。

**故事 C（不敢删）**：我备份了 4 次，磁盘上 4 个包。我想删掉旧的，发现备份列表没有操作列，接口里也没有 DELETE。同样的情况出现在执行节点（9 个，8 个是历史残留）、项目内分组（能建不能删）、凭据（能建不能改）。

### 1.2 根因（引自评估报告，不重复论证）

| 编号 | 根因 | 性质 |
|---|---|---|
| C1 | 用例资产没有「一等对象」，三个页面各自查询、各自渲染 | 结构 |
| C2 | 执行没有单一裁决点，状态展示与拦截逻辑各写各的 | 结构 |
| C3 | 全局与项目各写一套，能力不对等 | 结构 |
| C4 | 若干字段只写不读或只读不写（死字段、不可达状态） | 技术债 |
| C5 | 列表页缺少统一的 CRUD 基线，靠逐页随手实现 | 规范缺失 |

### 1.3 目标（可度量）

| 目标 | 现状 | 目标值 | 度量方式 |
|---|---|---|---|
| 用例可执行率 | 96.1% 用例为 LX 且阻断；未绑定整单失败 | 被拦截时 100% 有可操作出口 | 执行预检返回的每条拦截都带「去哪解开」的链接或按钮 |
| 用例库视图一致性 | 3 套组件、列数 8/8/4 | 3 处同一组件、字段清单 diff = 0 | 组件快照 + 字段清单对比 |
| 列表 CRUD 覆盖 | 21 个列表中 9 个无删除 | 每个列表显式属于 L0/L1/L2 三级 | 门禁机检 |
| 双轨 | 3 组真双轨 | 0 组 | 双轨台账逐项核销 |

## 5. 统一口径与术语（开发前必须钉死）

| 术语 | 定义 | 禁止用法 |
|---|---|---|
| **用例库** | 一个可查询的用例集合，由某个项目承载（`project.kind` 区分 `platform` / `pytest-suite` / `standard`） | 不要用「公共用例页面」「EHT 页面」指代数据本身 |
| **公共用例库** | `project.kind='platform'` 的单例项目（当前 project 88） | 不要与「平台用例集」混为一谈 |
| **平台用例集** | `test_set.project_id IS NULL AND owner_scope='PLATFORM'` | 不是「公共用例库的用例集」 |
| **执行计划 / 计划** | `execution_plan` 实体，含 `cron`（可空）。**「测试计划」是同一实体的旧菜单名，本线起废弃** | 不要再出现两个菜单名 |
| **立即执行** | 对已有计划或临时选择立刻产生一次 run，`trigger_type=manual` | 不要与「定时触发」混称 |
| **未定级** | `safety_level='LX'`。列表显示为「—」，详情显示「未定级（LX）」 | 不要再显示「LX 未判定」 |
| **绑定已确认** | `case_script_binding.verified=1`（`BOUND_VERIFIED`） | 不要用「已校验」指代自动同步态 |
| **能力级别** | 列表页 CRUD 基线：L0 只读、L1 可增删、L2 全 CRUD | 不要出现无标注的只读列表 |

### 5.1 状态字段的唯一定义（本线收敛）

| 字段 | 归属 | 取值 | 谁写 | 谁读 |
|---|---|---|---|---|
| `safety_level` | 用例 | L0/L1/L2/LX | 新建表单、批量定级、导入 | 执行预检、列表筛选 |
| `priority` | 用例 | P0/P1/P2/P3 或 NULL | 新建、批量改、导入归一 | 列表排序/筛选、执行范围 |
| `review_status` | 用例 | draft/pending/approved/rejected | 提交/评审 | 列表筛选；**本线决定是否进执行门禁（O-04）** |
| `enabled` | 用例 | true/false | 启停 | 执行、列表默认过滤 |
| `verified` | 脚本绑定 | 0/1 | 同步（写 0）、人工确认（写 1） | 列表脚本态、执行预检 |
| `status`（计划） | 计划 | ENABLED/PAUSED | 暂停/恢复 | 调度器、列表 |

> `test_case.status`（tinyint，恒 1）在本线删除；若要保留「用例启停」，用新列 `enabled`，不复用死字段。

### FR-v5.31-01 脚本绑定人工确认

**问题**：绑定四态里 `BOUND_VERIFIED` 运行期不可达——同步写 `verified=false`，仓储 `update` 零调用，无确认端点。用户看到「已绑定 · 未校验」却无法确认。

**需求**：
1. 新增端点 `POST /api/projects/{projectId}/cases/{caseId}/binding/confirm`，把指定内核的绑定置 `verified=1`，写审计。
2. 用例详情面板的脚本区、用例集成员详情的脚本区，各提供一个「确认绑定」按钮（有 `case:write` 才显示）。
3. 确认前展示将确认的 `scriptPath` 与 `nodeId`，避免确认错对象。
4. 支持批量确认：用例列表勾选后「确认脚本绑定」，逐条写审计。

**验收判据**：
1. 对 1 条 `BOUND_UNVERIFIED` 用例点确认后，`case_script_binding.verified=1`，列表脚本态变为「已绑定 · 已确认」。
2. 执行预检对已确认用例不再输出 `CASE_UNVERIFIED` 类违规。
3. 无 `case:write` 的用户调用该端点返回 403。
4. 每次确认产生一条审计，含操作人、用例编号、内核、脚本路径。
5. 批量确认 10 条，全部成功时审计 10 条；部分失败时返回成功/失败清单，不整体回滚。

**不做**：不做「自动确认」（自动同步的绑定必须人工过目）；不改绑定表结构。

### FR-v5.31-02 安全级定级向导与列表降噪

**问题**：1953/2032 条用例是 `LX`，而 `LX` 与 `L2` 同等阻断执行。用户看到满屏看不懂的红标，且无法批量处理。

**需求**：
1. **列表降噪**：用例列表「安全级」列对 `LX` 显示「—」；仅在「筛选」与「详情」中显示「未定级（LX）」。筛选器保留 LX 选项并显示计数。
2. **批量定级向导**：入口在用例列表勾选后与「未定级 N 条」提示条上。向导三步：① 按一级分类分组展示未定级用例数；② 为每个分类选择推荐级别（L0 只读 / L1 可逆写 / L2 高危）；③ 预览影响条数并确认。
3. **推荐规则可解释**：分类的推荐级别来自一张可维护的映射表（分类 → 建议级别），首次落库为内置默认（只读查询类 L0、配置写入类 L1、故障注入/重启类 L2），允许管理员调整。
4. 定级写 `safety_level` 并写审计（批量一条审计，含条数与分类）。
5. **执行侧不再直接 403**：未定级用例改由执行确认面板知情确认（详见 `FR-v5.31-07`），`SAFETY_LEVEL_BLOCKED` 仅保留给「确认后仍未勾选」的情况。

**验收判据**：
1. 列表页不再出现「LX 未判定」字样；`zh-CN` 与 `en-US` 同步。
2. 选中 20 条未定级用例，走完向导后 20 条 `safety_level` 更新为所选级别，审计 1 条。
3. 定级后立即执行，不再因 `SAFETY_LEVEL_BLOCKED` 失败。

## 13. 验收与门禁

| 门禁项 | 内容 | 自证要求 |
|---|---|---|
| 用例库一致性 | 三处列/筛选/详情字段 diff = 0 | 断言组件快照；改一处列名应判红 |
| 分类树缩进 | 子项文字 x > 母项文字 x | 注入 `padding-left:0` 应判红 |
| 项目可见性 | `scope=mine` 与总览集合差 = ∅ | 去掉组授权应判红 |
| 优先级合法 | 非法 `priority` 计数 = 0 | 插入 T0 应判红 |
| 列表能力基线 | 无操作列必须 L0 标注 | 新增无标注页面应判红 |
| 备份删除三同步 | `.gz`/`.sha256`/manifest 同时消失 | 只删 `.gz` 应判红 |
| 拓扑真实渲染 | DOM 有 `svg` 且节点数 = 接口设备数 | 退回表格应判红 |

> 纪律：机检必须进门禁；`--self-test` 要真注入→判红→还原；不接受「单测绿/构建绿」当放行理由。
