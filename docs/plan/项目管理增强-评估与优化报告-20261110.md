## 0. 结论先行

1. **R1（编码自动生成）与 R2（删除弹层打不出字）已修完并有回归断言**，不进入 v4.4 排期。
2. **R3（向导内选用例/资产）与 R7（全局/项目双模式）是同一件事的两面**：先有「全局公共库」才谈得上「向导里挑公共用例」。因此 **必须先做 R7 的权限与数据域，再做 R3**；反过来做会在项目域里堆一套临时的「伪全局」接口，后续必拆。
3. **R4（存为模板）与 R5（模板二级菜单）应合并为一个工作包**：模板不落库、只存在仓库 `config/project-templates/*.json` 里，且被硬编码要求恰好 4 个（`TEMPLATE_PROBLEMS` 里 `count !== 4` 直接判红）。不先做持久化，任何「存为模板」都只能写文件、要求重新构建，产品上不可接受。
4. **R6（成员多选 + 多角色）是纯数据模型改造**，与 R7 的权限模型强耦合：先改 `project_member` 的基数，再谈「全局角色 ∪ 项目角色」的求值规则，否则双模式的权限矩阵会建在沙地上。
5. **推荐顺序**：`W44-01 权限与角色求值` → `W44-02 成员多角色` → `W44-03 模板持久化 + 二级菜单` → `W44-04 全局/项目双模式` → `W44-05 公共库与引用` → `W44-06 向导内选用例/资产` → `W44-07 回归与证据`。

**需要拍板的 5 件事**（详见 §8）：PM 是否全项目可见、全局库用「平台项目」还是独立表、公共用例「引用 vs 复制」的默认值、编码是否创建后不可改、模板是否允许跨团队共享。

## 2. 逐项需求评估

### 2.1 R1 项目编码自动生成（已交付）

**现状问题**：创建向导的「项目编码」是纯手填。编码既是唯一键（后端重复即拒），又是日常沟通、命令行、日志检索的主键——让用户自己起名，必然出现 `test`、`test1`、`ceshi` 这类不可检索的编码。

**已落地的机制**（`frontend/src/config/projectCode.ts`）：

```
建议值 = 前缀 + "-" + 引擎 + "-" + 年月 + "-" + 三位序号（同组最大值 + 1，超过 999 自然进四位）
示例：API-RF-202611-001 / PY-PYT-202611-002 / PRJ-RF-202611-007
```

> 说明：v1.1 起按你的补充要求加入「引擎 + 年月」两段（Robot Framework→`RF`，Pytest→`PYT`），
> 序号在「同前缀 + 同引擎 + 同月份」内递增，跨月从 001 重新起算。

规则取舍：

| 设计点 | 选择 | 理由 |
|---|---|---|
| 前缀来源 | 所选模板的 `codePrefix` | 编码自带类型语义；模板已强制前缀格式 `^[A-Z][A-Z0-9]{1,7}$` |
| 序号口径 | 同前缀独立递增 | 不同业务线互不挤占；删项目后号码不复用（保留可追溯性） |
| 是否加日期 | 不加 | 编码要能被口头念出来、能贴进命令行；日期会拉长到 20+ 字符 |
| 是否强制 | 不强制，可改 | 存在外部系统已有编码规范的团队；唯一性由后端 409 兜底 |
| 中文项目名转拼音 | 不做 | 需要额外词库与多音字处理，收益低；前缀+序号已能保证可读 |
| 并发安全 | 前端建议值 + 后端唯一键 | 私有项目对当前账号不可见时会漏号，因此后端 409 是**唯一权威**；错误提示沿用现有冲突文案 |

**已实现细节**：进入「基本信息」步时拉一次项目卡列表取已有编码；用户改过编码后不再覆盖；「重新生成」按钮把当前值也计入已用，避免连点两次得到同一个值。单测 5 例覆盖空库、跨前缀、补零、999 进位、非法前缀。

**后续增强（W44-01 可选）**：新增 `GET /api/projects/next-code?prefix=API`，在服务端按 `MAX` 计算，彻底消除「私有项目不可见导致漏号」。成本低（一个只读接口 + 一条 SQL），建议随 v4.4 一并做。

**另一个待决策点**：编码创建后是否允许修改。建议**创建后只读**（管理员在项目设置里可改一次并写审计），否则编码作为外部引用键会失效。

### 2.2 R2 删除弹层输入框无法输入（已修复）

**现象**：工作台项目卡的「彻底删除」弹层能打开，但编码输入框点进去打不出任何字符。

**根因判断**：弹层原先用 naive-ui `NModal`，它自带焦点管理与遮罩层，和页面既有的全局快捷键、`useFocusTrap` 叠在一起时，键盘焦点没有真正落到输入框上——表现就是「光标像是进去了，字进不来」。这类问题在单测里不会暴露（jsdom 不跑真实焦点管理），只在真实浏览器里出现，所以 v4.3.0 的门禁与单测全绿也没拦住。

**修复方式**（`frontend/src/views/WorkbenchView.vue`）：

- 去掉 `NModal`，改为 `<Teleport to="body">` + 项目自绘遮罩（`.delete-mask`）+ `useFocusTrap` 的组合；
- 打开即把焦点送进弹层容器，**第一个可聚焦元素就是编码输入框**；Esc 关闭、Tab 在弹层内循环；
- 遮罩从顶栏下沿开始（`top: var(--header-h)`），不压顶栏，与全局浮层口径一致；
- 点击遮罩空白处关闭，`deleteBusy` 期间禁止关闭。

**回归断言**（`frontend/src/views/WorkbenchView.spec.ts`，3 例）：

1. 打开后 `document.activeElement` 必须是输入框（这一条直接锁死「焦点被抢」）；
2. 逐字输入后 model 真的变化、编码匹配时确认按钮由禁用转可用；
3. 编码不匹配时按钮保持禁用、不调删除接口；匹配后按项目 id 调 `DELETE`。

**遗留验证项**：CDP 真浏览器回归仍受环境限制（门禁 13 基线红）。建议在 W44-07 用真实浏览器补一次「打开→输入→确认→卡片消失」的截图证据。

### 2.3 R3 空白项目在向导中也要能选测试用例 / 测试资产

**需求解读**：现在向导只填元信息，用例与资产要么建完项目再进「用例」「资产」页逐个加，要么从模板继承——而模板里根本没有内容项。用户希望 **建项目这一步就能把「用什么跑」配好**，即使项目是「空白」的（没选模板）。

**为什么现在做不到**（两层原因，必须都解）：

1. **数据层**：模板只描述默认值，没有「用例集/场景/资产」的结构化条目；
2. **权限与数据域层**：项目之间彼此隔离（每张业务表都带 `project_id`，`TenantGuard` 强制项目作用域），所以「从别的项目挑用例」本质上不是「选」而是「引用或复制」，需要显式的跨项目语义。

**建议方案**：新增向导第 3 步「内容（可选）」：

| 区块 | 内容 | 语义 |
|---|---|---|
| 用例 | 从「公共用例库」勾选用例集 / 测试场景 / 单条用例 | 默认**引用**（运行时按引用解析），可选择「复制为副本」 |
| 资产 | 从「平台资产池」勾选设备 / 链路 / 环境 / 凭据 | 复用既有 `project_asset` 引用，不复制实体 |
| 成员 | 默认角色预填（已有能力，可保持不变） | — |

关键约束：

- **允许全空**：三项都可跳过，跳过即得到「空白项目」，与现状等价；
- **引用不是复制**：资产必须引用（设备是共享物理资源，复制会产生两份互相矛盾的台账）；用例默认引用，复制只作为显式选项；
- **公共用例被引用后不可硬删**：沿用 `busyCounts` 的思路，新增 `case_reference` 计数参与 409 判定；
- **事务**：项目行 + 成员 + 引用关系一次提交，任一失败整体回滚，避免「项目建好了但引用丢了一半」；
- **审计**：一条 `project:create` 记录里带上 `caseSetRefs/assetRefs` 数量，不刷 N 条明细。

**依赖**：必须先有 R7 的「公共库」数据域。若不先做 R7，只能做成「从当前项目复制」，价值有限。

**验收**：空白项目创建后，向导里勾选的用例集在「用例」页可见且来源标记为「引用」；资产在「资产」页可见且 `project_asset` 有引用行；取消全部勾选仍能建成空项目。

### 2.4 R4 把项目存为项目模板

**现状**：模板是仓库里的 4 个 JSON 文件（`blank / api-regression / ui-web / pytest-service`），构建期校验、运行期只读。想「把 A 项目的配置存成模板给 B 用」没有入口。

**建议方案**：模板落库。

```sql
-- 模板主体
CREATE TABLE project_template (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  template_key  VARCHAR(64)  NOT NULL,       -- 稳定 key，创建项目时回填来源
  name          VARCHAR(128) NOT NULL,
  description   VARCHAR(512) NULL,
  test_kernel   VARCHAR(16)  NOT NULL,       -- robot | pytest
  visibility    VARCHAR(16)  NOT NULL,       -- private | project | public
  code_prefix   VARCHAR(8)   NOT NULL,
  default_role  VARCHAR(32)  NOT NULL,
  tags          JSON         NULL,
  builtin       TINYINT      NOT NULL DEFAULT 0,   -- 内置 4 个 = 1，禁止删除，只可停用
  enabled       TINYINT      NOT NULL DEFAULT 1,
  owner_id      BIGINT       NULL,
  scope         VARCHAR(16)  NOT NULL DEFAULT 'team', -- team | global
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_template_key (template_key)
);

-- 模板内容项（用例集 / 场景 / 单用例 / 资产）
CREATE TABLE project_template_item (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  template_id  BIGINT NOT NULL,
  item_kind    VARCHAR(16) NOT NULL,  -- case_set | scenario | case | asset
  source_project_id BIGINT NULL,      -- 引用来源项目；源删除后置 NULL
  source_id    BIGINT NOT NULL,       -- 源对象 id（asset 时为 project_asset/资产池 id）
  ref_mode     VARCHAR(16) NOT NULL DEFAULT 'reference', -- reference | copy
  UNIQUE KEY uk_template_item (template_id, item_kind, source_project_id, source_id)
);

-- 模板的默认设置快照（可选，等价于 project_setting）
CREATE TABLE project_template_setting (
  template_id BIGINT NOT NULL,
  setting_key VARCHAR(64) NOT NULL,
  setting_value TEXT NULL,
  PRIMARY KEY (template_id, setting_key)
);
```

**「另存为模板」入口**：项目卡更多菜单、项目设置页各放一个；弹窗选择保存范围：

| 范围 | 包含 | 默认 |
|---|---|---|
| 仅配置 | 内核/可见性/前缀/标签/默认角色 | ✔ |
| + 成员角色 | 成员的用户与角色（不保存具体人，只保存「角色配比」） | ○ |
| + 用例引用 | 用例集/场景/用例（reference 方式） | ○ |
| + 资产引用 | 设备/链路/环境（reference 方式） | ○ |

**不保存**：运行历史、报告、凭据密文、审计、SLO 数据。凭据只能存「需要哪类凭据」的占位，不能导出密文。

**边界**：源用例/资产被删除后模板项降级——创建时不阻断，跳过失效项并在确认页提示「N 项已失效，已跳过」。

### 2.5 R5 项目模板单独二级菜单

**建议**：放在「全局模式」下的二级菜单 `全局管理 → 项目模板`（与 R7 联动），项目模式下不出现（避免用户误以为模板属于某个项目）。

页面结构：

```
项目模板
├─ 列表：key / 名称 / 内核 / 可见性 / 内容项数量 / 引用次数 / 内置标记 / 状态
├─ 详情：基本信息｜默认运行配置｜成员默认角色｜用例与用例集｜测试场景｜测试资产｜可见范围
├─ 动作：新建（空白/克隆）、编辑、停用、删除（仅非内置且无项目引用）
└─ 追溯：引用该模板创建的项目列表（点击进入项目）
```

权限：

| 角色 | 列表 | 编辑 | 新建 | 删除 | 全局共享 |
|---|---|---|---|---|---|
| ADMIN | ✔ | ✔ | ✔ | ✔（非内置） | ✔ |
| PM | ✔ | 仅自己/本团队 | ✔ | 仅自己创建 | ✘ |
| ENGINEER / VIEWER | 只读 | ✘ | ✘ | ✘ | ✘ |

**与向导打通**：模板步骤改为从接口拉取（内置 + 团队 + 全局），显示「包含 N 个用例集 / M 项资产」，并在右侧预览；选择后进入 §2.3 的「内容」步时默认勾选模板项，可增删。

**兼容**：迁移脚本把 4 个 JSON 落成 `builtin=1` 的行；前端 `projectTemplates.ts` 的静态数组保留一个版本作为「离线兜底」，同时把 `count !== 4` 的硬校验改为「内置模板完整性校验（4 个 key 必须存在）」。

### 2.6 R6 项目成员多选 + 单账号多角色

**现状**：`project_member` 唯一键 `(project_id, user_id)`，只有一列 `member_role`；向导里一次只能加一个人、一个角色。

**需求拆成两件事**：

1. **多选**：一次勾选多个用户，批量加同一角色；
2. **多角色**：一个账号在同一项目里可以同时是 `pm` + `engineer`（小团队常态）。

**数据模型建议**：

```sql
-- 成员主体保留（承载状态、加入时间）
ALTER TABLE project_member
  ADD COLUMN status TINYINT NOT NULL DEFAULT 1,      -- 1 启用 / 0 停用（软移除）
  ADD COLUMN joined_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP;

-- 角色拆表：一个成员 N 个角色
CREATE TABLE project_member_role (
  project_id BIGINT NOT NULL,
  user_id    BIGINT NOT NULL,
  role_code  VARCHAR(32) NOT NULL,
  granted_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (project_id, user_id, role_code)
);
```

**兼容迁移**：先把 `project_member.member_role` 全量回填到 `project_member_role`，旧列保留一个版本（只读、写时同步），下个版本再删。回填脚本必须幂等。

**权限求值规则（关键）**：建议明确写成一条可测的公式：

```
项目内有效动作 =
   ADMIN 全局角色                      → 全部
   否则：项目内角色集合 ∪ 全局角色中"项目可映射"的部分
```

具体地：

- `admin`：任意项目的全部动作（现状即如此）；
- `pm`（全局）：可建项目；对自己创建/被加入的项目，等价于项目内 `pm`；对未加入的项目仅只读元信息（**待拍板**）；
- `engineer/viewer`（全局）：只能进入自己加入的项目，动作取项目内角色与全局角色的**交集上限**（项目内 `viewer` + 全局 `engineer` = 项目内 `viewer`，不越权）；
- 至少保留 1 名项目 `pm`：删除/降权最后一名 pm 时拒绝（400 + 明确文案），避免项目变成「无人可管」。

**接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/projects/{id}/members` | 返回 `{userId, username, roleCodes[], status}` |
| PUT | `/api/projects/{id}/members` | 全量覆盖：批量增删 + 角色集合（幂等） |
| POST | `/api/projects/{id}/members/batch` | 批量添加（`userIds[] + roleCodes[]`），向导用 |
| DELETE | `/api/projects/{id}/members/{userId}` | 移除（仍拦截最后一名 pm） |

**前端**：向导第 4 步改为「多选用户 + 角色多选标签」；成员管理页表格改为可勾选行 + 行内角色标签 + 批量操作条。角色标签要能区分「全局角色（只读展示）」与「项目角色（可编辑）」——现在 `ProjectService` 已经刻意只展示 `member_role`，这个约定要保留。

### 2.7 R7 全局模式 / 项目模式双模式

**现状**：单一侧边栏，所有数据都是项目域；顶栏有项目下拉但界面结构不随项目变化。用户要「在全局层面管理公共用例/资产，再切回某个项目干活」，现在只能靠反复切项目。

**建议的目标形态**：

```
右上角：[ 全局 ] [ 项目：ED202-COMMON ▾ ]     ← 分段控件，切换即换导航与数据域
全局模式导航：项目 / 公共用例库 / 公共资产 / 项目模板 / 平台设置（用户·角色·审计·SLO）
项目模式导航：工作台 / 用例 / 用例集 / 场景 / 执行 / 报告 / 资产 / 连接与拓扑 / 环境 / 成员 / 设置
```

**权限**（与 R6 的求值规则合并成一张表）：

| 能力 | ADMIN | PM | ENGINEER | VIEWER |
|---|---|---|---|---|
| 进入全局模式 `global:enter` | ✔ | ✔ | ✘ | ✘ |
| 全局·项目管理（建/停用/删除） | ✔ | 建 ✔ / 删 ✘ | ✘ | ✘ |
| 全局·公共用例库读写 | ✔ | ✔ | ✘ | ✘ |
| 全局·公共资产读写 | ✔ | ✔ | ✘ | ✘ |
| 全局·模板管理 | ✔ | 自有 ✔ | 只读 | 只读 |
| 全局·用户与角色 | ✔ | ✘ | ✘ | ✘ |
| 全局·审计与 SLO | ✔ | 只读 | ✘ | ✘ |
| 项目模式 | 全部项目 | 加入的项目 | 加入的项目 | 加入的项目 |

**切换语义**（容易做错的地方，先定死）：

| 场景 | 行为 |
|---|---|
| 全局 → 项目 | 若已有当前项目则直接进；否则进项目选择页（不默认随机挑一个） |
| 项目 → 全局 | 记住当前项目，全局模式顶部仍显示「将进入：XXX」 |
| 无权限的用户 | 切换器只显示「项目」段，全局段置灰并给出原因 tooltip；**后端也要 403**，不能只靠前端隐藏 |
| 直接访问全局 URL | 无 `global:enter` → 403 页（不是空白页） |
| 全局模式下点「项目」行 | 等价于「进入该项目」，自动切到项目模式 |

**后端数据域方案（两个选项，需拍板）**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 平台项目（推荐） | 新增一条 `project.kind='platform'` 的系统项目（不可删、不出现在普通项目列表），公共用例/资产都挂它；全局接口读的就是它的数据 | 复用全部既有 SQL/仓储/权限/审计/引用逻辑；改动集中在「列表过滤 + 权限」 | 需要给 `project` 加 kind 与过滤条件；要防止平台项目被误删/误改 |
| B. 独立公共库表 | 新建 `library_case / library_asset` 等 | 语义干净、不污染项目表 | 用例/资产/引用/执行/报告全链路要写第二套；与「项目内选公共用例」的引用解析要写桥接；长期双写风险高 |

推荐 **A**：本项目已有 57 张表带 `project_id`、`TenantGuard` 全局强制项目作用域，独立表方案等于把整套领域再实现一遍。

**API 命名空间**：新增 `/api/global/**`（服务端内部仍落到平台项目 id），例如：

```
GET    /api/global/projects                 # 项目总览（含成员数、用例数、最近运行）
GET    /api/global/library/case-sets
GET    /api/global/library/scenarios
GET    /api/global/assets?type=device
POST   /api/global/assets/{type}/{id}/publish   # 把项目资产提升为公共资产
GET    /api/global/templates
POST   /api/global/templates
```

**前端架构**：

- `stores/uiMode.ts`：`mode: 'global' | 'project'`，持久化到 `localStorage`，随用户偏好同步；
- `config/navigation.ts`：导航从「一维列表」改为 `mode → groups → items` 两层结构，能力码继续用 `capability` 字段过滤（现有 `ROLE_CAPABILITIES` 扩展 `global:*`）；
- 路由：全局模式用 `/g/**` 前缀（可深链、可审计），项目模式保持现有路径 + store 中的当前项目（避免把 projectId 塞满 URL 造成历史包袱）；
- 请求层：`request()` 增加 `scope` 概念（`global` / `project`），项目模式缺当前项目时统一抛「请先选择项目」，不要发 `projectId=undefined` 的请求。

**缓存与失效**：全局库数据不按项目缓存；项目模式缓存键必须含 `projectId`（v4.3.0 的资产派生缓存已按项目指纹做，沿用即可）。全局资产变更 → 广播失效所有引用项目（复用现有 `AFTER_COMMIT` 事件失效机制）。

## 7. 验收判据（DoD）

1. 编码：新项目默认值符合 `前缀-NNN`；手改后不被覆盖；重复提交返回 409 且提示可操作。
