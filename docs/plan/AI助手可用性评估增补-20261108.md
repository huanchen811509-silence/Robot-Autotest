## 1. 结论先行

1. **「还不能用」不是打不开，是点了不真干活**。面板能打开、5 个端点能返回 200、动作会写 `audit_log`，但 `application/ai/` 全包**没有任何真实模型调用链**：无 `ProcessBuilder` / `Runtime.exec`、无 HTTP 客户端、无模型端点 / API key / 鉴权 / 重试。`AiPanelService.execute():80-82` 二次确认后只写审计并返回拼好的文案；`suggest():54-63` 只回固定模板摘要。已核实（一手代码 grep + `a9-ai-call/README.md:17,81-82`）。
2. **三条在册缺口全部属实**，且上一轮评估 A5 已要求「修复 + 真实复跑」或「书面降级 + 授权人」，不留悬空：G-A9-1（L3 不调模型）、G-A9-2（`--prompt-file` 被真实 CLI 拒，`claude -p` 才可用）、G-A9-3（`AtomicLong(1000)` 内存会话 id 重启复用，审计里 9 条不同项目的 `AI_SESSION_OPEN` 全是 `1001`）。
3. **v2.0 测试台账 TC-51..57 全 PARTIAL、TC-58 PASS**；WBS 里 AIX-01..05 却全标「已完成」。这是**台账口径与实测不符**，本版不许沿用「已完成」当作可用结论。
4. **数据库三张 AI 表建了但没用**：`ai_session` / `ai_action` / `ai_cli_probe`（`V8_4__ai_panel.sql`），Java 侧只在 `audit.record()` 里把它们当 resource_type 字符串，无任何 INSERT/SELECT。会话真实状态是 `ConcurrentHashMap` 内存态。
5. **前端无输入能力**：抽屉里唯一输入控件是二次确认 checkbox，没有文本/提示词输入框，用户无法提问；展示区只有 4 个只读字段与一行结果。即使后端接通模型，用户仍「用不了」。
6. **两个开关没接线**：`ai.enabled`（`SystemSettingService.java:30`，默认 `false`）与 `feature.ai.panel`（`v2.0 DEV-PLAN:287`，默认 off）全仓无消费方，所以面板实际能打开。补真实调用链时必须一并定开关语义，否则会出现「开关关着但照样调模型」。
7. **可用方案**：沿用 v2.0 评估 D6 已定裁决 **A（本机 CLI 子进程）**，按 CLI 分别适配 argv，做会话/动作落库、前端输入与结果呈现、超时与进程树终止，用**可注入的假 CLI** 走完整自动化验证；**真实模型调用留 `G-授权`**。
8. **AI 助手与层 M 并列不抵扣**：层 N 不改 ED202 导入、不改菜单 8 组、不触碰 G4/G5/G7/G8；两条线各自的证据与回归基线分开。
