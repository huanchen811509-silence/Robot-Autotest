## 0. 结论先行

1. **先收基线，再动产品代码。** v3.1–v3.4 的实现在 WSL 与 E 盘两仓都还没入库（HEAD 同为 `4dea84a`，2026-11-08 15:46）[已核实]；WSL 工作树 2940 项变更里 2765 项是文件模式位噪声[已核实]。**B0 不通过，任何编码 / 迁移 / 测试执行都不启动。**
2. **门禁现状必须按时间戳读。** `scripts/gates.sh` 已声明 27 步[已核实]；11-09 00:02–00:05 分步日志显示 12 / 13 / 20–27 各步 PASS（13 步 `checks=48 fails=0`，CDP 已恢复；12 步 87 表 PASS）[已核实]；但 `00-full-run.log` 仍是 **11-08 12:06 的 19 步 `FAILS=2`** 旧汇总[已核实]。**既不能拿旧汇总当现状，也不能据分步日志宣称 27 步全绿。**
3. **测试体系从「机器门」补成「机器门 + 人的效果证据」。** 上一轮交付了性能预算、AI 黄金集、安全 / 容量 / 对比度机检，但 Top 8 任务、SUS、搜索查询集、CWV、跨浏览器、axe 全量、diff 覆盖均无证据[已核实]。本轮新增 L7 体验 / L8 无障碍与视觉 / L9 韧性与演练 / L10 现场人工四层。
4. **保持模块化单体，不做分布式重写。** 68 个 Controller、345 个路由注解、87 张表、57 个迁移[已核实]足以承载打磨；优先做基线固化、回归扩容、契约守护、局部精修与新能力运营化。
5. **门禁分层，不继续堆步数。** 27 步分快速门（每次提交）/ 重门（版本候选）/ 发版门（大师）；新增步骤必须先 `--selfcheck` 证明「删步骤会变红」，再纳入。**汇总日志同批次**是 v3.5.0 的硬判据。
6. **证据优先于结论**：每个包、每条 TC 必须有可复现命令、原始输出、结论与失败 / 阻塞说明；现场项只记真实结果或 `BLOCKED`。
7. **评审授权是硬闸门**：本次只交两份规划文档，**交付即暂停**；未授权前任何实现动作视为越权。

### 1.5 主要根因（为什么这一轮是「证明与收口」而不是「继续加功能」）

1. **交付速度 > 验证速度**：一天四版，机器门补得快，人的效果证据没跟上 [推断]。
2. **门禁增长缺少汇总治理**：19→27 步，汇总仍停在 19 步时点 [已核实]。
3. **新增能力未进回归基线**：搜索 / 缓存 / 流式 / 归档 / 准入 / 告警等尚无对应 `REG-*` 组 [推断]。
4. **基线未入库**：代码与 `VERSION` 都在工作树，任何「优化前后对比」缺乏可复现起点 [已核实]。
5. **单机机检不等于用户体感**：API p95 / 包体达标，但 INP / LCP / CLS、跨浏览器、键盘路径无数据 [已核实 + 推断]。

## 2. 总体工程策略与架构设计

### 2.1 设计原则

| # | 原则 | 落地约束 |
|---|---|---|
| P1 | 基线先行 | B0 未过不动产品代码；`VERSION` / `build-info` / 入口 CHANGELOG 三处一致 |
| P2 | 先度量后优化 | 每个优化包交「基线 → 改动 → 对比 → 结论」四段证据；无基线不许优化 |
| P3 | 语义不变 | 性能 / 体验改造不得改变执行结果、状态映射、报告口径、权限与审计 |
| P4 | 最小改动 | 能用回归、索引、开关、文案、局部组件解决的，不引入新中间件 / 新框架 |
| P5 | 默认安全 | 新能力默认关闭或灰度；危险动作确认 + 可撤销；AI 不自动执行高影响动作 |
| P6 | 可回滚 | 迁移带 down；开关可关；缓存可旁路；发布可回退 |
| P7 | 单一事实源 | 错误码、分页、时间、状态、指标、性能预算、契约口径集中定义 |
| P8 | 证据可复现 | 命令、原始输出、结论、失败 / 阻塞四件套；不伪造、不推演现场 |

### 2.2 架构决策（授权后落 ADR，本文只列结论与护栏）

| 编号 | 决策 | 理由 | 护栏 |
|---|---|---|---|
| ADR-35-01 | 保持模块化单体与双内核执行链 | 68 Controller / 87 表 / 单机部署与运维能力匹配 | ArchUnit 守分层；不引入 Redis / MQ / 独立搜索集群 |
| ADR-35-02 | 基线固化采用「WSL 权威副本收口 → 双远程一致 → E 盘快进」 | 与 `AGENTS.md` 反向通道一致，避免 9P 上 push 卡死 | 提交前清模式位噪声；三处 sha 一致才算完成 |
| ADR-35-03 | 门禁分层：快速门 / 重门 / 发版门，不新增无自检步骤 | 27 步已偏重，继续堆会拖慢反馈 | 新步骤先 `--selfcheck` 负向实证；汇总与分步同批次 |
| ADR-35-04 | 效果度量走「服务端聚合 + 内部可选客户端事件」 | 隐私与性能兼顾 | 默认关闭、可关闭、事件字典评审、无凭据 / 用例正文 / 实网配置 |
| ADR-35-05 | 浏览器回归以 Playwright 为主、CDP 可选 | 消除 `:9222` 单点，支持跨浏览器 | **不重启大师已取消的后台任务**；先用现有可用通道；截图入证据 |

| ADR-35-07 | AI 评测扩黄金集并引入用户采纳口径 | 20 条机器分不足以证明生产力 | 事实 / 推测 / 建议三段；无证据拒答；采纳定义冻结；人工确认闸门 |
| ADR-35-08 | 新能力运营化以「默认策略 + 降级 + 演练 + 成本」四件套收口 | 归档 / 准入 / 配额 / 告警上线但未练过故障 | 8 个运行手册场景；注入演练；默认停用项不擅自开启 |
| ADR-35-09 | 变更管理引入特性开关与发布记录，DORA 只建读数不设考核 | 避免指标驱动造假 | 小批次、可回退、记录版本戳与回滚点 |
| ADR-35-10 | 安全按 OWASP ASVS + LLM Top 10（2025）逐条自评 | AI 风险在应用层不在模型层 | 最小权限、人工审批、提示注入 / 过度代理 / 无界消耗专项用例 |

### 2.3 后端设计要点

1. **契约与回归**：`gen_api_contract.py --check` 进快速门；新增端点同步更新契约测试；`REG-*` 按能力域组织，每组可单跑。
2. **查询与性能**：沿用 `PageQuery` / 键集分页 / 排序白名单 / 列表投影；新增索引必须附 `EXPLAIN` 前后对比与 down 迁移；慢查询阈值与 `SlowQuery.measure` 不变。
3. **缓存与异步**：`TtlCache` 键含项目与权限范围、写后即失效、异常降级直查；`BoundedExecutor` 队列有界、拒绝回落到调用线程、优雅停机排空；不扩大缓存范围到写路径。
4. **执行链**：幂等键、`RunAdmissionService` 三层上限、终态统一 `transition` 释放名额、孤儿进程对账——**本轮只补回归与演练，不改语义**。
5. **错误与诊断**：统一「业务码 + HTTP + 可读消息 + 诊断 ID」；诊断 ID 与 `X-Request-Id` / traceId 对齐，供错误文案「下一步」使用。
6. **AI**：SSE 事件序列不变；事实校验失败显式标红；`reviewed=true` 才落库；新增故障注入点（CLI 不可用 / 超时 / 配额耗尽）只走配置，不改主链。

### 2.4 前端设计要点

1. **页面原语增量**：不在本轮重做主题；把六态矩阵补进既有原语，逐页迁移时同步补视觉快照与键盘用例。
2. **交互性能**：路由级动态导入、编辑器独立分包、`DataTable.virtualScroll`、`api/http.ts` 去重 / 短缓存 / 写后清缓存沿用；新增 CWV 采样点不改请求语义。
3. **可访问性**：焦点陷阱统一 `useFocusTrap`；WCAG 2.2 新增准则逐条落（焦点外观、24×24 目标尺寸、拖曳替代、一致帮助、冗余输入、可访问认证）。
4. **状态与文案**：错误统一映射为「原因 + 下一步 + 诊断 ID」；「未测量」不得显示为 0；`skipped>0` 不得显示为全部通过。
5. **AI 面板**：流式 / 停止 / 引用 chip / 模板 / 历史 / 导出沿用；新增降级提示与成本 / 配额可见，不新增自主执行能力。

### 2.5 数据与迁移

- 只追加；已应用迁移 checksum 不可变；NOT NULL 改造走「加可空 → 回填 → 收紧」三步。
- 每支高风险迁移附 down、回填 SQL、校验 SQL 与回滚判据；`DB_NAME=robot_it` 独立库实跑后再进主库。
- 归档策略默认 `enabled=false`，**授权前不移动任何数据**；归档候选查询必须走 `idx_run_project_created`。
- 新表 / 字段先兼容读再加约束；跨版本删列需 ADR 且至少隔一版。
- 体验事件若落库，字段最小化、不包含用例正文 / 凭据 / 实网配置，且随开关可完全关闭。

| 约束 | 做法 |
|---|---|
| WSL 跨层展开 | `wsl.exe -d Ubuntu-24.04 bash -lc '...$VAR...'` 会被外层 Git Bash 提前展开；复杂脚本写临时文件 cp 到 `/tmp` 再 `bash /tmp/x.sh`；外部 CLI 一律 `< /dev/null` |
| 9P 性能 | `/mnt/*` 禁止构建与测试（实测慢 35 倍）；构建 / 门禁一律回 WSL ext4 |
| 源码 ≠ 部署 | systemd 跑 `backend/target/*.jar`；改码必须重建 jar + `systemctl --user restart robot-autotest-backend` |
| 迁移 | 已应用迁移不可改只能追加（checksum mismatch）；`DB_NAME=robot_it` 守卫 `_it` 结尾 |
| 门禁前 | `set -a; . ~/.config/robot-autotest/env; set +a`；缺 `CRED_MASTER_KEY` 会让 WS E2E 起不来 |
| 就绪探针 | 打 `:8081`；`:8001/_ping` 是 node 入口自回 200，不算数 |
| 负向验证 | 备份 → 注入 → 定向判据必须红 → 用**备份拷贝**还原（别 `git checkout`）→ 复跑绿 |
| 取样判据 | 全量扫 + 打印命中位置，防「新数据挤掉老样本」造成假绿 |
| 机检判定 | `check_release_docs.py` 只认全编号 `FR-<版本>-xx`；TC 结果必须写在 `05-TEST-REPORT.md`；`check_md_tables.py` 改哪些文档就显式传哪些路径 |
| 文档补丁 | 按内容匹配 + 命中次数断言，不用行号；写盘后 `assert '\ufffd' not in text` 防字符损坏；Markdown 表格一次性输出 |
| RF / pabot | `--dryrun` 语法错退出码仍 0 → 双判输出有无 `[ ERROR ]`；pabot 子进程需显式 PATH |
| pytest 运行时 | `~/venvs/deepseek-harness`（pytest 9.2.0 + xdist + json-report）；json-report 1.5.0 metadata 落 `environment` 键；rf-stack venv 无 pytest |
| 密钥断言 | 别对整段响应查 `sk-`（会命中描述文本），逐条校验 `keyMasked` 前缀 |
| 体积预算 | 排除 `*View-*`；`packages/editor` 独立 vitest 要单独跑 |
| 元数据 | `output.xml` 十项 metadata 为对外可见面，不放凭据；`RUN_ID` 键名不可改 |

### 4.3 用例与缺陷规则

- **编号**：`TC-v3.5-001` 起按版本递增；回归组用 `REG-<能力域>`；证据文件 `docs/evidence/v3.5.0/<包>/`。

- **结果落点**：TC 实测结果必须写进对应版本的 `05-TEST-REPORT.md`（写在 TEST-PLAN 里不算）。
- **缺陷分级**：S1 阻断（数据错 / 越权 / 执行结果语义变化 / 高危漏洞）→ 立即停版；S2 严重（P0 判据不达标 / 回归失败）→ 修完复测；S3 一般 → 排期；S4 文案 / 视觉 → 批量收口。
- **不稳定用例**：进 `flaky-ledger.md`，隔离 → 定位 → 修复 → 回归并入；比率 < 2%；**不许直接删用例或改断言迁就实现**。
- **负向验证**：备份 → 注入 → 定向判据必须红 → 用备份拷贝还原 → 复跑绿；四步缺一不算验证。

### 6.3 告警与 SLO

- SLO：工作时段可用性 ≥99.5%/月；API p95 ≤150ms（规模数据）；运行成功率 ≥95%；RPO ≤24h / RTO ≤2h；MTTR ≤30min；MTTD ≤5min。
- 演练：告警注入验证 MTTD 与恢复闭环，防误报风暴；结论进 SLO 日报与错误预算。

### 6.4 备份、恢复、容量与成本

- 每日全量 + 增量；保留 7 / 30 / 90 分层；备份后自动校验可读与关键表行数。
- 季度恢复演练：恢复到隔离库 `robot_it`，跑关键查询、比对计数与抽样、记录 RTO（门禁 26 步已有 `RTO=20s RPO=0s tables=76` 的隔离库读数，正式 RPO 由备份计划决定）。

- 成本：AI 会话配额、归档存储、日志保留三处可见；默认策略不擅自开启（归档 `enabled=false`）。

| 术语 | 含义 |
|---|---|
| 快速门 / 重门 / 发版门 | 按执行时机划分的门禁层次，不改变 `gates.sh` 步骤编号 |

| `BLOCKED` / `PARTIAL` | 现场项未验 / 部分达成；均不得读作通过 |
