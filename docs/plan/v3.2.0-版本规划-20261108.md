## 1. 版本目标与定位

v3.1.0 解决「顺手」，v3.2.0 解决「**快而稳**」：先把性能与可靠性变成**可测量的预算**，再做查询、缓存、异步、执行链、前端分包与可观测性治理。本版不做分布式改造、不引搜索引擎、不换 ORM。

**一句话判据**：在固定规模数据集上，四类预算有基线、有门禁、有证据；重复提交不重复运行、重启状态一致、停机不丢审计。

| 目标 | 量化口径 |
|---|---|
| 接口快 | 核心列表 p95 ≤ 150ms（1 万用例 / 10 万运行数据集） |
| 首屏快 | 主入口 ≤ 300 KiB gzip；单路由块 ≤ 150 KiB；路由切换 ≤ 300ms |
| 列表稳 | 1 万行滚动 ≥ 50fps；无整页白屏 |
| 运行稳 | 重复提交 0 重复运行；重启后运行状态一致；孤儿进程 0 |
| 可追溯 | 任一 UI 错误可追到后端日志与 SQL/执行记录（traceId 贯通） |

## 3. 四类预算（先立预算，再谈优化）

| 类别 | 指标 | 阈值 | 测量方式 | 数据源 |
|---|---|---|---|---|
| API | 核心列表 p95 / p99 | ≤150ms / ≤300ms | JUnit 压测采样（≥3 轮 × 200 次），落 JSON | 1 万用例、10 万运行、百万日志 |
| API | 慢查询 | >200ms 记 WARN，>500ms 记 ERROR | 仓储层埋点 + 结构化日志 | 同上 |
| 前端 | 主入口 / 单路由块 gzip | ≤300 KiB / ≤150 KiB | `check_bundle_budget.py` 扩展为双阈值 | `frontend/dist` |
| 前端 | 路由切换 | ≤300ms | Playwright 计时（navigation → 首屏可交互） | 生产构建 |
| 长列表 | 1 万行滚动帧率 | ≥50fps | Playwright + rAF 采样 | 用例列表虚拟滚动 |
| 运行链 | 运行创建接口 p95 | ≤200ms | 压测采样 | 队列空闲基线 |
| 运行链 | 日志写入吞吐 | ≥5000 行/s，不丢行 | 日志订阅补发一致性校验 | 本地执行节点 |
| 相对回退 | 相较基线退化 | >10% 或 >30ms 即红，须解释并授权 | 预算报告 diff | 本版基线 |

口径固定：数据集由 EW32-01 生成器产出的**同一份随机种子**数据；测量机与并发度写进报告；每轮预热 30s、采样 60s、取 p95/p99。

## 7. 技术方案要点（贴合现有代码）

| 主题 | 方案 | 约束 |
|---|---|---|
| 分页 | 新增 `common/query/PageQuery`（page/size/sort 白名单，size 上限 100）；深分页改键集（`WHERE id < ?` 或 `(updated_at,id)`） | 不改既有 URL 参数语义，避免前端大面积返工 |
| 投影 | 列表 SQL 显式列，`SELECT *` 清零 | 只清 6 处；其余不动 |
| 索引 | 新增 `V11_19` 复合索引（用例 `project_id,updated_at`、运行 `project_id,id`、审计 `project_id,created_at`） | 必须配 `db/down/` 与 `SchemaIT` 表数不变（仅索引） |
| 缓存 | 进程内 `ConcurrentHashMap` + TTL（不引外部中间件）；键含 `projectId`；写路径按资源类型精确失效 | 缓存不得绕过 `TenantGuard` |
| 异步 | Spring `ApplicationEventPublisher` + 自建有界 `ThreadPoolExecutor`（队列满拒绝并降级为同步） | 审计优先保留；通知可丢可补偿 |
| 幂等 | 提交侧 `Idempotency-Key`（缺省按 run 请求指纹），`run` 表加唯一列 | 新增列需默认值，历史 run 不受影响 |
| 前端虚拟化 | `DataTable` 增加可选的窗口化渲染（固定行高 + 缓冲行） | 不改现有列配置与选择语义 |
| 可观测 | `spring-boot-starter-actuator` 只暴露 health/metrics；Micrometer `Timer` 记仓储与接口耗时；traceId 走 MDC + 响应头 | 新增依赖需批准；不引 Prometheus registry |
| 合同 | 生成 OpenAPI（构建期导出 JSON），关键 8 个接口做契约测试 | 先覆盖核心域，不求全覆盖 |

**新增依赖清单（需批准）**：`spring-boot-starter-actuator`（含 micrometer-core）。缓存与虚拟化均不引第三方库。

## 8. 门禁与证据

- 沿用 G0–G10；本版新增：`perf-budget`（四类预算）、`arch-guard`（ArchUnit 失败即红）、`contract`（OpenAPI diff + 契约测试）。
- 证据目录：`docs/evidence/v3.2.0/EW32-01 … EW32-10/`，每个目录 `README.md` + `logs/` + `perf/`（采样原始数据与统计方法）。
- 预算报告必须写：机器、并发、数据规模、种子、轮次、p95/p99、与基线 diff。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 数据集生成慢、占空间 | 生成器支持按规模裁剪；百万日志用流式写入，生成后只读挂载 |
| 缓存一致性出错 | 写路径按资源精确失效 + 关闭缓存的等价用例作为回归护栏 |
| 异步丢审计 | 审计事件走「同步兜底」路径：入队失败立即同步落库 |
| 执行链改动影响既有执行 | 幂等与恢复用开关控制，默认开启但可一键回退；RF/pytest 执行主链不改语义 |
| 前端虚拟化破坏表格语义 | 虚拟化仅对大列表启用（>200 行），保留 `<table>` 结构，键盘与勾选行为回归 |
| Windows 环境限制（`sh` 缺失等） | 性能与契约门禁在 CI（Linux）跑；本地只跑可执行子集，证据区分「本机/CI」来源 |
| 预算门禁抖动 | 采样 3 轮取中位；机器负载记录；抖动超限先复测再判红 |
