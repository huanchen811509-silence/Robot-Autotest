## 0. 测试治理与准入准出（v1.1 新增）

**准入**：

1. PRD / DEV-PLAN / TEST-PLAN 三份文档状态为「已评审通过」，且 `check_release_docs.py` / `check_md_tables.py` 通过。
2. `W40-00` 基线快照已留档：`VERSION`、门禁步数、三端测试读数、CDP 探活、`workspace/` 部署位置。
3. 4.0 P0 前 `G-06`（演练环境）与 `G-07`（原始样本）必须有补齐方案；4.2 前 `G-04` 必须有可用主机；交互类 TC 前 `G-01` 探活通过。
4. 测试数据使用真项目；临时 prefix / `_it` 库 / 备份可还原；原始含密样本放不可提交的安全目录。

**准出**：

1. P0/P1 TC 全部 PASS；`PARTIAL` / `BLOCKED` / `NOT-RUN` 需有书面说明与授权，P0 不得以 `NOT-RUN` 收口。
2. 无 S1/S2 未关闭缺陷；S3 有明确遗留说明。
3. 全量门禁 `FAILS=0`；`--selfcheck FAILS=0`；i18n 键集相等；axe 无 serious/critical。
4. 证据目录、`05-TEST-REPORT`、⑦ 回写全部完成。

**暂停条件**：环境不可用、真库损坏、未验签 bundle 被误放行、P0 回归失败、原始样本泄漏。

**缺陷分级**：S1 数据丢失 / 安全 / P0 不可用；S2 主流程不可用或证据不可复现；S3 体验 / 文案 / 非关键边界。S1/S2 阻断发版。

**轮次**：包级 smoke（每包）→ 批次 regression（每批）→ 版本 full（收口）→ 负向注入（导入 / 回滚 / CI）。

**环境矩阵**：

| 维度 | 必测 | 抽查 / 条件 |
|---|---|---|
| 浏览器 | Chromium（CDP） | Firefox（环境具备时） |
| 视口 | 1024 / 1280 / 1440 / 1920 | 125% / 150% 缩放 |
| 操作系统 | Linux 运维环境 | Windows 中文路径导出导入 |
| 数据库 | `robot_it`（MariaDB / MySQL 8） | 真库备份恢复 |
| 服务 | `:8081` 后端 + `:8001` node + `:9222` CDP | 断网 / 后端不健康降级 |

**自动化映射**：机检 / 单测 / 真 HTTP / CDP 自动化优先；必须手工的截图走查、axe、键盘逐页走查单列，不能用源码断言替代。

**基线读数**：`W40-00` 记录当期后端 / 前端 / 编辑器测试用例数、门禁步数与构建时长，作为 `TC-v4.0-19` / `TC-v4.2-04` 的对照基线。

## 2. 取证策略

| 层级 | 做法 | 反例（禁止） |
|---|---|---|
| 静态 | 机检器 + `--self-check` 正负样本，判据要能变红 | 只跑正样本、恒定返回 0 |
| 单测 | 纯逻辑抽到 `utils/` 或 Java 测试类，避开 naive-ui 虚拟列表 | 用夹具自证真链路 |
| 真 HTTP | 先登录拿 token，再采真实接口与真库读数 | 直接 INSERT 假行当证据 |
| 真浏览器 | CDP `:9222` 录 `Network.requestWillBeSent` 证明只读、量 DOM 矩形证浮层不遮顶栏 | 只靠源码断言「没写方法」 |
| 真升级 | 临时 prefix + 非生产库，升级前后健康与凭据哈希对照 | 在生产库上直接试 |
| 负向 | 备份 → 注入 → 定向判据必须红 → **用备份拷贝还原** → 复跑绿 | 用 `git checkout` 还原 |
| CI | `gh run view` 取真实结论，失败修到绿再归档 | 把 `pending` 当成功 |
| 跨实例 | A 实例真导出 → B 实例（空库 / 已有项目）真导入，双库按稳定业务键对照 | 只在一套库上自导自入 |
| bundle 真实性 | 篡改文件 / 篡改 manifest / 两者同改 / 未验签四种样本必须红 | 只验「文件哈希对得上」 |
| 全表面 | 报告 / 打印 / docx / API / 审计 / 运行日志 / 控制台 / 导出包逐面扫 | 只扫报告页一页 |
