## 2. 取证策略

| 层级 | 做法 | 反例（禁止） |
|---|---|---|
| 静态 | 机检器 + `--self-check` 正负样本，判据要能变红 | 只跑正样本、恒定返回 0 |
| 单测 | 纯逻辑抽到 `utils/` 或 Java 测试类，避开 naive-ui 虚拟列表 | 用夹具自证真链路 |
| 真 HTTP | 先登录拿 token，再采真实接口与真库读数 | 直接 INSERT 假行当证据 |
| 真浏览器 | CDP `:9222` 录 `Network.requestWillBeSent` 证明只读、量 DOM 矩形证浮层不遮顶栏 | 只靠源码断言「没写方法」 |
| 真升级 | 临时 prefix + 非生产库，升级前后健康与凭据哈希对照 | 在生产库上直接试 |
| 负向 | 备份 → 注入 → 定向判据必须红 → **用备份拷贝还原** → 复跑绿 | 用 `git checkout` 还原 |
| CI | `gh run view` 取真实结论，失败修到绿再归档 | 把 `pending` 当成功 |

## 4. 横向回归放行命令

```bash
bash scripts/gates.sh                       # 全量门禁（当期步数）
bash scripts/gates.sh --selfcheck            # 负向自检
(cd backend && mvn -o -B test)               # 后端单测
(cd frontend && npx vitest run)              # 前端单测
(cd packages/editor && npx vitest run)       # 编辑器单测
(cd frontend && npx vue-tsc --noEmit)        # 类型检查
(cd frontend && npx vite build)              # 前端构建
python3 tools/check_i18n.py                  # 中英键集
python3 tools/check_version_consistency.py   # 版本四副本
python3 tools/check_delivery_bundle.py --self-check

bash scripts/package-release.sh              # 交付包
python3 tools/check_release_docs.py          # 六份产物
```
