## 1. 版本定位与范围

- **做**：平台管理域菜单对齐、ED202 全量可追溯导入、场景 / 项目 / 用例集 / 执行选择四层组织、不可变判据版本、冻结计划与证据链、历史/当前双计数看板。
- **不做**：demo 6 组业务能力域菜单与设备执行器、真实 CX7/GPU/交换机采集、判定与报告的反向移植、ED202 原表改写、用例脚本全量重写（详见 §8）。
- **定位边界**：本平台仍是 Robot Framework / pytest 通用自动化测试平台；demo 的业务能力域只作为用例的 `domain_tag` / `capability` 筛选标签存在。

## 2. 用户与角色

沿用 v2.1 PRD §2，不新增角色。本版新增的操作主体仍是「测试工程师（编辑用例与场景）」「项目管理员（建项目与导入）」「只读审计者（看看板与证据）」三类，权限矩阵沿用 `navigation.ts:269-323` 的能力过滤。

## 3. 典型场景

1. **导入**：管理员在「测试用例 / 用例导入与评估」选 `ED202测试用例_V0.4.xlsx`，系统一次读 7 个 sheet，预检报告给出 813 条唯一编号、双向差集 0、缺判据条目数，确认后单事务落库；原文件只读并记 SHA。
2. **建组织**：在一个 `ED202 公共用例库` 项目下，按 sheet 生成 7 个用例集，按人工确认的一级分类对照表生成场景；用例步骤与二级分类完整可见。
3. **组执行**：工程师在「用例集与测试场景」勾选跨总表用例保存设计；执行页生成 `execution_selection` 冻结快照（含设备与链路绑定 SHA），**不改来源设计**。
4. **跑与取证**：冻结计划提交一次；未知状态只读找回不重发；每例 3 个独立 `RUN_ID`；每轮证据含命令原文、stdout/stderr、真实退出码与 `[hostname]` 标识。
5. **看与判**：看板同屏显示「历史标签」与「本轮当前」双计数；原始流 LOG 可弹窗、JSON 可下载；缺失原始流明确标 missing，不补造、不判 PASS。
