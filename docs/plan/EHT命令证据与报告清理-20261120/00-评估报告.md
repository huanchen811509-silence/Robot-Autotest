## 2. 问题②结论：软删除现状与"删不掉"根因

### 2.1 已核实：数据量

| 表 | 总数 | 软删数 | 说明 |
|---|---|---|---|
| `run` | 79 | **57** | 执行报告展示层；大量"陈列"来自这里 |
| `test_report` | 13 | 1 | 用户报告；未软删的 9 DRAFT / 2 REVOKED / 1 ARCHIVED |
| `test_case` | 2101 | 0 | 用例库；当前无软删数据 |

未软删的 `test_report` 里**空快照报告 = 0 条**——"内容为空"的真实含义是**报告里有结论但缺证据列**（如命令列 NONE），不是快照本身为空。

### 2.2 已核实：删除实现全是软删

| 对象 | SQL | 位置 |
|---|---|---|
| run | `UPDATE run SET deleted_at=NOW(3)...` | `ReportLifecycleService.java:58-61` |
| test_report | `UPDATE test_report SET deleted_at=NOW(3)...` | `ReportLifecycleService.java:76-79` |
| test_case | `UPDATE test_case SET deleted_at=CURRENT_TIMESTAMP(3)...` | `TestCaseRepositoryJdbc.java:239-244` |

### 2.3 已核实："删不掉"的两个直接根因

**根因 A（主）**：执行记录列表走了漏过滤的查询。
- `RunRepositoryJdbc.page()`（`353-390 行`）的 WHERE 只有 `project_id` 与可选 `run_status`，**没有 `deleted_at IS NULL`**。
- 同项目另一入口 `ReportRepositoryJdbc.page()`（`217-232 行`）**有**过滤。
- 前端 `RunsView.vue:359` 用本地 `Set` 记录已删行来隐藏，F5 刷新后本地状态清空，后端又把软删行返回 → **"删了又出现"**。

**根因 B**：冻结件明确禁止删除。
- 后端 `ReportLifecycleService.java:240-242`：`if (isFrozen(row)) throw ... "已冻结，请先解冻"`。
- 前端 `TestReportsView.vue:290-294` 冻结件不渲染删除按钮。

### 2.4 已核实：物理删除的硬约束

- `run` 有 5 张子表外键**无 CASCADE**：`test_result`、`keyword_result`、`run_artifact`（`V1__baseline.sql:488/506/523`）、`pytest_case_step`（`V11_48:35`）、`manual_execution`（`V11_55:58`）。物理删必须**先按序清子表**。
- `test_report_export` / `test_report_audit` 在 `db/schema-contract.json:6-8` 标为 **append-only 审计表**。物理删报告会留下孤儿审计行。
- 现成可复用：`ArchiveRepositoryJdbc.moveTestResults()`（`113-130 行`）已有"先归档再删子表"的 SQL；`ReportRepositoryJdbc.java:156-158` 有幂等清理子表。
