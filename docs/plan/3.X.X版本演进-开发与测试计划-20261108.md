## 0. 结论先行

1. **保持模块化单体，不做分布式重写。** 现有 57 个 Controller、222 个路由、71 张表足以承载 3.X.X；优先治理查询、缓存、异步、前端加载与可观测性。
2. **先立预算，再谈优化。** v3.2.0 用固定规模数据集建立 API、前端、长列表、运行链四类预算；所有优化以预算和证据说话。
3. **测试体系从“单测 + 手工浏览器回归”升级为十层。** 增加契约、性能、韧性、视觉、无障碍、安全、AI 评测、迁移、现场人工层。
4. **门禁分层。** 快速门禁每次提交；重门禁（性能、视觉、韧性、恢复演练）在版本候选与发版前执行，避免 30 步门禁拖垮日常。
5. **证据优先于结论。** 所有版本、包、测试必须有可复现日志/截图/报告；现场项只记录真实结果或 `BLOCKED`，禁止推演与伪造。
6. **评审授权是硬闸门。** 本文与 PRD 通过评审并获正式授权后，才启动编码、迁移、测试与证据生产。

### 1.3 主要根因

1. **查询无统一规范**：分页、排序、上限、索引各自实现，规模上升后深分页与全字段查询放大 I/O。
2. **读多写少但无缓存**：总览、项目卡片、参考数据重复计算；无失效策略与降级。
3. **请求线程承担非关键动作**：审计、通知、指标汇总与主请求耦合，峰值时放大尾延迟。
4. **前端整包与直出长列表**：首屏与长列表随数据量线性变差。
5. **缺链路与指标**：错误只能靠文本日志定位，无法量化 SLO。
6. **体验实现分散**：页面框架、状态、表单、批量各自实现，导致一致性与维护成本。
7. **AI 上下文窄且不可评**：回答泛化、无引用、无配额与降级，难以稳定用于生产。
8. **运维闭环不足**：告警拉取、备份演练手工、无 SLO 与容量结论。

## 2. 工程策略与架构设计

### 2.1 设计原则

- **最小改动优先**：能通过索引、批量化、缓存、分包解决，不引入新中间件。
- **语义不变**：性能与体验改造不得改变执行结果、报告口径、权限与审计。
- **先度量后优化**：每个优化包必须提交基线、改动、对比、结论四段证据。
- **默认安全**：新开关默认关闭或灰度；危险动作需确认/撤销；AI 不自动提交。
- **可回滚**：迁移有 down；开关可关；发布可回退；缓存可旁路。
- **单一事实源**：错误码、分页、时间、状态、指标口径集中定义。

### 2.2 架构决策

| 编号 | 决策 | 理由 | 护栏 |
|---|---|---|---|
| ADR-3X-01 | 保持模块化单体与双内核执行链 | 现有规模与团队运维能力匹配；避免分布式复杂度 | 用 ArchUnit 守分层；跨层调用即失败 |
| ADR-3X-02 | 读路径引入进程内缓存（Caffeine） | 读多写少、单实例部署；无需新中间件 | TTL/容量/失效/旁路可配；不做跨项目共享键 |
| ADR-3X-03 | 非关键动作走应用事件 + 有界线程池 | 降低请求尾延迟；审计/通知/指标可异步 | 队列有界、拒绝策略、停机排空、失败补偿 |
| ADR-3X-04 | 统一分页：默认页大小 + 上限 + 排序白名单；深分页键集 | 避免 OFFSET 深翻与任意排序 | 兼容旧参数一个版本；契约测试覆盖 |
| ADR-3X-05 | 以代码生成 OpenAPI，契约测试入 CI | 222 路由靠人守不现实 | 合同变更需评审；破坏性变更显式标注 |
| ADR-3X-06 | 可观测性采用链路 ID + 结构化日志 + 指标端点 | 排障与 SLO 前置 | 日志脱敏；指标低基数；不引入外部 APM |
| ADR-3X-07 | AI 流式采用 SSE，上下文由服务端组装并脱敏 | 首字快、可控、可引用 | 超时/取消/重试；禁止凭据入提示词；真实 CLI 仅授权环境 |
| ADR-3X-08 | 浏览器回归以 Playwright 为主、CDP 可选 | 消除 9222 单点；可跨浏览器 | 先做冒烟与 Top 8；截图入证据；CI 可选运行 |
| ADR-3X-09 | 数据保留分层：热库 + 归档表/文件 | 控制主库体积与查询成本 | 归档可查、可恢复；策略可配；审计不丢 |
| ADR-3X-10 | 设计系统在现有令牌上增量扩展 | 不重做主题；先统一原语 | 令牌扫描；禁止页面硬编码；白名单可审计 |

### 2.3 后端设计要点

1. **查询层**
   - 统一 `PageQuery`（页码/页大小/游标/排序/过滤）与上限；排序字段白名单；拒绝无上限导出。
   - 列表查询走投影，禁止 `SELECT *`；批量查询替代循环单查；聚合查询按项目/时间分桶。
   - 深分页改键集（`created_at, id`）；保留 OFFSET 的查询必须写理由与规模上限。
   - 为高频过滤/排序补复合索引；每个索引附 `EXPLAIN` 前后对比与 down 迁移。
   - 慢查询阈值可配，输出 SQL 指纹、耗时、行数、请求链路 ID；不含参数敏感值。

2. **缓存层**
   - 仅缓存低变更、可容忍短时陈旧的数据：项目卡片、总览计数、参考字典、权限只读快照。
   - 键必须含项目与权限范围；TTL 短（秒级）；写操作按项目/实体失效；提供全局旁路开关。
   - 指标记录命中/未命中/加载耗时/内存；缓存异常自动降级到直查。

3. **异步与事件**
   - 审计、通知、指标汇总、报告后处理走应用事件；执行主链仍同步可控。
   - 有界队列 + 拒绝策略 + 重试上限；队列积压入指标与告警。
   - 优雅停机：停止接收、排空队列、标记未完成事件；关键审计同步落库。

4. **执行链**
   - 运行请求幂等键（项目 + 计划 + 参数摘要 + 请求 ID）；重复提交返回既有运行。
   - 节点租约 + 心跳限频；离线判定阈值可配；孤儿进程/临时目录定时清理。
   - 服务重启后按运行状态机恢复：运行中→未知/失败需人工确认；不伪造完成。
   - 并发上限、排队与公平调度可配；队列可见、可取消。

5. **API 与架构**
   - 错误码统一：业务码 + HTTP 状态 + 可读消息 + 诊断 ID。
   - OpenAPI 合同由代码生成；关键接口契约测试；破坏性变更显式版本化或兼容期。
   - ArchUnit 增加：API 不直连基础设施、领域不依赖 Web、应用不依赖具体 JDBC、包内聚规则。

### 2.4 前端设计要点

1. **页面原语**：先建原语再迁移页面，避免“顺手重写”；每迁移一页补对应视觉快照与键盘用例。
2. **搜索**：前端聚合入口 + 后端统一搜索 API；结果按实体类型分组；权限过滤在服务端完成；最近记录本地存储。
3. **长列表**：统一 DataGrid 包装，虚拟滚动、列设置、保存视图、分页条；1 万行作为验收规模。
4. **加载策略**：路由级动态导入；主入口只保留壳与公共依赖；编辑器继续独立；图标按需；预取下一跳。
5. **状态管理**：请求去重与短缓存；错误统一映射；提交防重；草稿本地存储与恢复提示。
6. **无障碍**：抽屉/弹窗焦点陷阱与返回；键盘路径；`aria` 名称；对比度与缩放走查。
7. **AI 面板**：流式消息、停止、重试、上下文 Chip、证据链接、建议卡；错误与降级可读。

### 2.5 数据与迁移

- 迁移只追加；每个高风险迁移附 down、回填、校验 SQL 与回滚判据。
- 新表/字段先双写或兼容读，再切开关，最后清理；禁止一步替换。
- 搜索/通知/视图/会话等新模型先建最小字段，避免过度设计。
- 归档策略按表分级：运行日志、审计、报告产物、AI 会话；保留期可配并写审计。

- 不稳定用例进入隔离台账：首次记录、复现次数、根因、修复/移除、责任人。

- 逃逸缺陷必须补回归 TC，并在发布复盘中说明入口为何未覆盖。
- AI 相关缺陷单独标记：事实错误、引用缺失、越权上下文、凭据泄漏、时延退化。

## 6. 运维保障计划

### 6.1 部署拓扑

- 单主机：前端静态服务（8081）+ 后端 Jar（8001）+ MariaDB + 执行节点；systemd 托管。
- 构建只在 WSL ext4 进行；产物带版本戳与构建号；Windows 副本不参与发布。
- STAGING 与生产同构；FIELD 节点独立，不共享生产数据。
- 发布流程：构建 → 迁移预检 → 健康检查 → 切流 → 观察 → 记录版本戳；失败回滚。

### 6.2 可观测性

| 能力 | 要求 |
|---|---|
| 链路 ID | 前端请求生成/透传；后端日志、SQL、执行记录、AI 调用共用 |
| 结构化日志 | JSON；级别、模块、项目、用户、链路 ID、错误码；脱敏 |
| 指标 | 请求量/时延/错误率、队列、缓存、运行状态、节点心跳、备份时效、AI 时延/配额 |
| 慢查询 | 阈值可配；SQL 指纹、耗时、行数、链路 ID |
| 健康检查 | 存活/就绪分离；依赖（DB、磁盘、AI CLI）状态 |
| 看板 | 体验、性能、运行、AI、运维五类；SLO 达标率与错误预算 |

### 6.3 告警与 SLO

- 规则：可用性、5xx、p95、运行失败率、队列积压、节点离线、磁盘、备份失败、AI 降级、证书/依赖异常。
- 通道：站内 + Webhook/邮件；去重、抑制、恢复通知；通道故障降级站内并记录。
- SLO：工作时段可用性 99.5%/月；API p95 ≤150ms（规模数据）；运行成功率 ≥95%；备份 RPO ≤24h、RTO ≤2h；MTTR ≤30min。
- 告警演练：注入故障，验证 MTTD ≤5min、恢复闭环、无误报风暴。

### 6.4 备份、恢复与容量

- 每日全量 + 增量策略；保留 7/30/90 分层；备份后自动校验可读与关键表行数。
- 每季度恢复演练：恢复到隔离库、跑关键查询、比对计数与抽样、记录 RTO。
- 容量基线：5 万用例、百万日志、50 并发运行、2 节点；输出 CPU/内存/磁盘/连接数曲线与建议。
- 归档：运行日志/审计/报告产物/AI 会话按策略归档；归档可查、可恢复、审计不丢。

### 6.5 运行手册清单

1. 运行卡住/队列积压。
2. 节点离线/心跳异常。
3. 数据库不可用/连接耗尽。
4. 磁盘满/日志暴涨。
5. AI CLI 超时/降级/配额耗尽。
6. 备份失败/恢复失败。
7. 发布失败/回滚。
8. 权限/凭据异常与应急吊销。

### 9.3 版本退出判据

- P0 全达成；P1 达成或降级有授权；P2 有去向。
- 十层测试按版本重点执行；门禁 G0–G10 通过（G9/G10 发版前）。
- 性能/无障碍/契约/安全/韧性证据齐全；无越线。
- 迁移可回滚；备份可恢复；告警可触达；手册可执行。
- 证据完整、可复现；文档/WBS/CHANGELOG 回写。
- **既有发版门禁单独记录**，3.X.X 验收不替代 G4/G5/G7/G8 与 G6 观察钟。

## 10. 变更控制与暂停点

### 10.1 变更控制

- FR 变更：更新 PRD、影响分析、TC 调整、重新基线化；P0 变更需产品负责人书面确认。
- 技术方案变更：更新 ADR；涉及数据/权限/合同/性能语义的，需 C1 复审。
- 范围裁剪：标“延后”，写原因、影响、替代、授权人、去向；不得删除包。
- 测试期间冻结功能范围；只接受阻断缺陷修复与安全修复。
- 迁移变更：必须含 down、回填、校验与回滚演练记录。

### 10.2 暂停点

- 本次交付**只产出两份规划文档**，不启动编码、迁移、测试执行或发布。
- 等待产品负责人完成评审、内容调整与正式授权后，从 B0/C1 开始执行。
- 评审未通过前，任何实现动作均视为越权。

### 11.4 术语
