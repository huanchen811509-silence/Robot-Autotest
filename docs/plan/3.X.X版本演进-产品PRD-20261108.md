## 0. 结论先行

1. **3.X.X 不是继续堆功能，而是把 v3.0.1 已经具备的能力变成“顺手、快、可信、可运维”。** 产品功能面已基本完整，当前短板集中在操作路径、反馈质量、规模性能、AI 可用深度与运维闭环。
2. **演进分四条版本线：v3.1.0「顺手」、v3.2.0「快而稳」、v3.3.0「聪明」、v3.4.0「规模化」。** 前三版为必做主线，v3.4.0 为规模化与稳态收口，可按评审结论裁剪。
3. **先度量、再优化。** v3.1.0 建立任务成功率、耗时、点击数、搜索命中、错误恢复等体验基线；v3.2.0 建立 API、前端包体、长列表、并发执行等性能预算，并纳入门禁。
4. **智能化坚持“有据可依、可控可退”。** AI 只基于可见上下文回答，结论必须能追溯到运行、用例或报告证据；不自动改代码、不自动提交、不虚构实网/真机结果。
5. **不以重构换速度。** 保持模块化单体与现有双内核执行链，优先做查询治理、局部缓存、异步非关键路径、前端按需加载与可观测性，避免分布式化带来的运维复杂度。

一句话验收：**核心任务更少步、页面更快出结果、失败更快定位、报告更容易读懂、系统更早发现问题。**

## 1. 背景与现状基线

### 1.1 已具备的能力

| 能力域 | v3.0.1 现状 |

| 项目与权限 | 多项目、项目级资源隔离、成员与角色、资产引用与 403 保护 |
| 用例与资产 | 用例库、目录树、编辑器包、设备/链路/凭据/共享资产 |
| 执行内核 | Robot Framework 与 pytest 双内核、计划/套件/运行/日志/产物 |
| 报告与洞察 | HTML/PDF/DOCX/XLSX 报告、趋势、对比、失败聚类、报告敏感信息扫描 |
| 计划与批量 | 计划冲突检测、批量启停、最近 N 次聚类、跨运行聚类禁用重跑 |
| 界面体系 | 主题/强调色/密度、设计令牌、i18n、编辑器独立分包、品牌扫描 |
| AI | CLI 适配、配置页、对话面板、凭据加密、契约机检 |
| 工程质量 | 19 步门禁、ArchUnit、Jacoco、1099 后端测试、397 前端测试、219 编辑器测试 |

### 1.2 规模与技术画像

| 指标 | 当前值 | 对 3.X.X 的含义 |
|---|---|---|
| 后端路由 | 57 个 Controller、222 个路由注解 | 功能面广，需统一契约与查询规范 |
| 数据库 | 71 张表、51 个迁移、46 个索引 | 迁移只能追加，性能治理需可回滚 |
| 后端测试 | 1099 个 `@Test` | 回归底盘足够，缺契约/性能/韧性层 |
| 前端测试 | 55 个 spec、397 个用例；编辑器 24 个 spec、219 个用例 | 组件层扎实，缺端到端与视觉/无障碍回归 |
| 性能基线 | 5 个读接口、9 次采样，p95 约 20ms（小数据量） | 只能证明“小数据不慢”，不能证明“规模下不慢” |
| 门禁 | `scripts/gates.sh` 19 步，18 PASS / 1 FAIL（CDP 不可用） | 浏览器回归存在单点依赖，需替代方案 |
| 查询实现 | 20 处 `OFFSET`、6 处 `SELECT *`、分页分散在 9 个仓库类 | 长列表与大数据量下存在抖动风险 |
| 架构能力 | 未发现 `@Cacheable`/Caffeine、`@Async`/应用事件、MDC/链路 ID、Actuator/Micrometer、OpenAPI | 读多写少场景无缓存，排障缺链路，契约靠人守 |
| 前端能力 | 未发现虚拟列表、保存视图、统一的焦点闭环验收；无站内通知入口 | 长列表、重复筛选、键盘操作与运行完成提醒是体验缺口 |
| AI 能力 | 对话为非流式；上下文以对话文本为主；无提示词库与评测集 | “能用”但不够快、不够准、不可量化 |

### 1.3 七个维度的主要差距

| 维度 | 主要差距 | 用户可感知后果 |
|---|---|---|
| 系统架构 | 同步调用为主，读接口无缓存，非关键动作占用请求线程；无统一 API 契约 | 数据量上来后页面变慢，排障靠日志猜 |
| 软件设计 | 分页/查询/错误码/状态模型分散；缺少页面级组合原语 | 同类页面行为不一致，修改成本高 |
| 程序实现 | 20 处 OFFSET、6 处 SELECT *、部分循环内查询；前端整包加载、长列表直出 | 大数据量卡顿、内存上涨、首屏变慢 |
| 测试体系 | 缺契约、性能回归、视觉、无障碍、韧性、AI 评测；CDP 单点 | 回归靠人看，性能退化发现晚 |
| UI/UX 设计 | 页面框架、空/错/加载状态、工具栏、表单反馈未完全统一；深色/浅色细节仍靠逐页修 | 视觉层级不稳定，学习成本偏高 |
| 用户体验 | 无实体级全局搜索、无保存视图、无撤销、无站内通知、无新手引导；键盘与读屏支持零散 | 重复操作多、找不到入口、误操作不可恢复 |
| 运维保障 | 告警以拉取为主，无推送通道；备份恢复演练未自动化；无 SLO 看板与容量报告 | 故障发现依赖人盯，恢复时间不可承诺 |
| 智能化 | AI 非流式、上下文窄、无证据引用、无提示词库/评测集、无配额与降级策略 | 回答慢、泛、不可复核，难以形成稳定生产力 |

### 1.4 基线约束

- 现行发布门禁 G4/G5/G7/G8 与 G6 七日观察钟**不因 3.X.X 规划而自动通过**；3.X.X 的版本验收不替代既有发版判定。
- 6 个现场相关包（WS-05、EXE-05、EXE-06、EXEC-02、EXEC-03、EXEC-05）仍需真实节点/真机/实网验证，任何文档与测试均不得伪造现场结果。
- 构建与测试以 WSL ext4 权威副本为准；Windows 中文路径副本不作为构建基线。
- 数据迁移只追加、不修改历史；高风险变更必须有 down 脚本与回滚判据。

## 2. 用户与核心场景

### 2.1 角色

| 角色 | 主要诉求 | 高频动作 | 当前主要痛点 |
|---|---|---|---|
| 测试工程师 | 快速写用例、发起运行、定位失败 | 搜用例、改用例、跑单计划、看日志 | 搜索弱、表单反馈慢、失败定位靠翻日志 |
| 测试负责人 | 掌握项目质量与风险 | 看总览、排计划、看趋势、审报告 | 信息分散、报告叙述性弱、批量操作不完整 |
| 平台管理员/运维 | 稳定运行、快速恢复 | 部署、看健康、处理告警、备份 | 告警不主动、恢复靠手工、缺容量视图 |
| 项目访客/审阅者 | 快速理解结果 | 看报告、看趋势、分享链接 | 报告门槛高、关键结论不突出 |

### 2.2 核心任务（Top 8）

1. 切换项目并在一屏内判断“今天哪里不对”。
2. 从用例库快速找到目标用例并完成修改/评审。
3. 发起一次运行前确认环境、节点、凭据、计划冲突。
4. 运行中判断进度、剩余时间与是否卡住。
5. 运行失败后从聚类进入单条失败并定位原因。
6. 读懂一份报告并向他人解释结论。
7. 批量调整计划/用例状态且可回退。
8. 让 AI 基于当前运行/用例/报告给出可复核的分析。

### 2.3 典型场景与期望

| 场景 | 现状 | 3.X.X 期望 |
|---|---|---|
| 早上巡检 | 逐个项目点开、逐页看 | 工作台聚合“需关注”，通知中心给出变化 |
| 找一条用例 | 目录逐层点、命令面板只能跳页面 | 全局搜索直接命中用例/运行/报告，支持最近与收藏 |
| 发起运行 | 表单填完才知道节点/凭据不可用 | 发起前预检，问题就地修复，冲突前置提示 |
| 等运行 | 只看到状态，不知道还要多久 | 进度、阶段、ETA、卡住提示，可订阅完成通知 |
| 定位失败 | 聚类后仍需人工翻多份日志 | 聚类解释 + 证据引用 + 建议检查项，一键跳证据 |
| 写报告 | 导出后人工补结论 | 事实型摘要、对比洞察、可编辑叙述、引用可追溯 |
| 误操作 | 确认弹窗后直接生效 | 高风险操作二次确认，可撤销/可恢复 |
| 排障 | 看日志、猜链路 | 请求链路 ID、慢查询、指标看板、告警推送 |

### 3.3 护栏指标（不可交换）

- 不因体验优化降低既有安全、权限、审计能力。
- 不因性能优化改变执行结果语义或报告口径。
- 不因 AI 引入自动改代码、自动提交、自动执行高风险动作。
- 不伪造真机、实网、负载结果；现场项只记录真实证据或 BLOCKED。
- 不引入需要额外基础设施且无 ADR 的组件（如 Redis、消息队列、独立搜索集群）。

### 3.4 非目标

- 不做微服务化/分布式重写，不引入多租户公有云形态。
- 不做原生移动端；仅保证 760px 以上桌面/平板可用。
- 不替换 Robot Framework/pytest 内核，不重造执行引擎。
- 不新增与“打磨存量”无关的大功能域（如新的资产管理体系）。
- 不在本阶段承诺真实 CI Runner 自动注册、真实 DUT 全量自动化。

## 4. 版本路线图

| 版本 | 主题 | 用户可见结果 | 关键能力 | 退出判据 |
|---|---|---|---|---|
| v3.1.0 | 顺手 | 路径短、反馈清楚、误操作可退、运行可等 | 页面原语、实体搜索、保存视图、批量+撤销、表单恢复、运行预检/ETA、报告可读、通知中心、新手引导、无障碍收口 | Top 8 成功率 ≥ 90%；一致性 100%；无严重无障碍项；体验基线落库 |
| v3.2.0 | 快而稳 | 大数据不卡、页面更快、问题可定位 | 查询治理、索引、局部缓存、批量聚合、异步非关键路径、执行链可靠性、前端分包/虚拟列表、链路 ID/指标/慢查询、OpenAPI/契约 | 规模数据集 p95 ≤ 150ms；前端预算达标；性能回退 0；契约测试全绿 |
| v3.3.0 | 聪明 | AI 更快更准有依据；问题主动通知；运维有 SLO | 流式/取消、上下文与引用、提示词库、失败分诊、报告叙述、用例草稿、会话与配额、AI 评测；告警推送、SLO 看板、运行手册、备份恢复自动化、优雅发布 | AI 事实一致性 ≥ 95%、采纳率 ≥ 70%；告警 MTTD ≤ 5min；恢复演练通过；MTTR ≤ 30min |
| v3.4.0 | 规模化 | 大数据、并发、安全、无障碍与灾备可承诺 | 归档/保留、并发与多节点、安全加固、AA/i18n、DR 演练、容量报告、GA 检查单 | 5 万用例/百万级日志可用；50 并发运行稳定；安全与 DR 演练通过 |
| 补丁线 | 稳定 | 快速修复不夹带功能 | 3.1.x / 3.2.x / 3.3.x / 3.4.x 仅缺陷、文案、性能微调与安全修复 | 回归通过、无新增范围 |

### 4.1 依赖顺序

- v3.1.0 必须先建立体验基线与页面原语，后续版本才有统一承载。
- v3.2.0 的缓存、异步、可观测性是 v3.3.0 告警、SLO、AI 配额的前置。
- v3.3.0 的通知中心依赖 v3.1.0 的站内通知模型；AI 证据引用依赖 v3.2.0 的链路 ID 与查询聚合。
- v3.4.0 依赖前三版的性能、测试与运维能力，不单独先行。

| 软件设计 | 设计原语与状态模型 | 查询/分页/错误码规范 | AI 能力分层与配额 | 保留策略与降级 |
| 程序实现 | 搜索/视图/批量/通知 | 索引、批聚合、分包、虚拟列表 | 流式、引用、评测 | 安全、无障碍、i18n |

| UI/UX | 统一框架、层级、状态、动效 | 性能态（骨架/预取） | AI 面板与证据呈现 | AA、密度、响应式收口 |
| 用户体验 | 少步、可撤销、可搜索 | 快、稳、可感知进度 | 主动提醒、可复核智能 | 大团队/大规模可用 |
| 运维保障 | 站内通知 | 链路、指标、慢查询 | 告警、SLO、备份恢复 | 容量、DR、安全运营 |

## 5. 需求详述

### 5.1 v3.1.0「顺手」

#### FR-3.1-01 统一页面框架与视觉层级（P0）

**问题**：列表、详情、运行、报告、设置页头部/工具栏/状态区各自实现，层级与间距不稳定。

**要求**：
- 提供页面原语：PageHeader、Toolbar、FilterBar、EmptyState、ErrorState、Skeleton、StatusBadge、FormField、ConfirmDialog、SidePanel、Toast、DataGrid 包装。
- 所有一级页面统一“标题—摘要—主操作—筛选—内容”的阅读顺序；主操作唯一且可见。
- 状态一律使用语义令牌，禁止页面硬编码颜色、圆角、阴影。

**验收**：
- 100% 一级页面使用统一原语，扫描脚本 0 例外（白名单需说明）。
- 硬编码颜色 0；深浅色与 6 种强调色下对比度 AA。
- 1440/1280/1024/760 四档无横向溢出、无遮挡主操作。

#### FR-3.1-02 全局实体搜索与命令面板 2.0（P0）

**问题**：命令面板只能跳页面，不能搜用例/运行/报告/项目；用户仍靠目录逐层找。

**要求**：
- 顶部全局搜索支持项目、用例、运行、报告、计划、资产六类实体；结果按相关度与最近使用排序。
- 支持 `Ctrl/Cmd+K` 唤起；支持键盘上下选择、回车打开、Esc 关闭；保留最近 10 条。
- 无结果时给出“放宽关键词/切换项目/新建”的下一步；搜索范围可切换当前项目/全部项目。
- 结果只展示必要摘要，不泄露凭据与敏感字段。

**验收**：
- 固定 50 条查询集 Top3 命中 ≥ 80%，零结果 < 10%。
- 键盘全流程可达，焦点不丢失；打开结果 ≤ 300ms（本地缓存命中）。
- 搜索结果与权限一致，无越权数据。

#### FR-3.1-03 保存视图、筛选与列设置（P1）

**问题**：高频筛选每次重填；列宽/密度/排序不能保存；切换页面即丢失。

**要求**：
- 列表页支持保存当前筛选/排序/列显示为“视图”，可命名、设默认、删除、复制。
- 支持按项目保存；同一用户跨会话保持；提供 3 个内置视图（全部/我的/需关注）。
- 列设置支持显示/隐藏、顺序、宽度；密度沿用全局令牌。

**验收**：
- 保存后刷新/重登仍生效；默认视图只影响本人。
- 视图应用后结果与筛选条件一致；删除有确认且可撤销。
- 视图数量上限与命名冲突有明确提示。

#### FR-3.1-04 批量操作与撤销（P0）

**问题**：计划已支持批量启停，但用例、报告、资产等仍逐条操作；高风险动作确认后不可恢复。

**要求**：
- 列表统一多选：全选当前页/全选筛选结果需明确区分；批量操作显示影响数量。
- 覆盖用例状态、计划启停、报告归档、资产引用移除等高频动作。
- 对可逆动作提供 5 分钟内撤销；不可逆动作必须二次确认并写明后果。
- 批量失败逐条返回原因，不因单条失败中断全部。

**验收**：
- 批量操作结果与逐条操作一致；失败项可重试/导出。
- 撤销在时限内 100% 生效；超时给出明确提示。
- 批量操作审计记录完整，包含操作者、范围、结果。

#### FR-3.1-05 表单校验、草稿与错误恢复（P0）

**问题**：错误提示偏系统化，用户不知道下一步；长表单切换/刷新丢失内容。

**要求**：
- 字段级即时校验 + 提交级汇总；错误文案统一“哪里错、为什么、怎么改”。
- 长表单（用例、计划、项目、凭据、AI 配置）支持本地草稿与离开提醒；恢复时标明“草稿时间”。
- 服务端错误映射为可读信息，保留原始错误码供排障；网络失败可重试且不重复提交。
- 提交按钮具备进行中/成功/失败状态，防双击。

**验收**：
- 一次提交成功率 ≥ 98%；错误字段自动聚焦。
- 刷新/误关后草稿可恢复；放弃草稿需确认。
- 弱网/超时场景不产生重复记录。

#### FR-3.1-06 运行发起预检、进度与 ETA（P0）

**问题**：发起后才发现节点离线/凭据失效/计划冲突；运行中只有状态，无阶段与剩余时间。

**要求**：
- 发起前预检：项目、计划、节点在线、凭据可用、冲突、目标文件可写、并发上限；结果分级（阻断/提醒/通过）。
- 阻断项就地提供修复入口或返回路径；提醒项允许确认后继续。
- 运行中展示阶段（准备/执行/收集/报告）、用例进度、已用时、ETA、最近心跳；超时/卡住给出提示。
- 运行完成/失败可订阅站内通知。

**验收**：
- 预检阻断项 100% 在发起前暴露；无“发起后才发现”的 P0 场景。
- 进度与最终结果一致；ETA 在稳定阶段误差 ≤ 20%。
- 卡住判定有阈值与证据，不误报正常长用例。

#### FR-3.1-07 报告可读性与对比洞察（P1）

**问题**：报告信息全但结论不突出；对比/趋势需要人工解读。

**要求**：
- 报告首屏给出“结论摘要、关键指标、主要风险、建议动作”，均可跳转证据。
- 对比视图突出新增失败、修复、耗时变化、波动项；变化标注口径与样本量。
- 失败项按聚类分组，展示共同特征与证据入口；不把相关性表述为因果。
- 支持分享链接与只读视图；敏感信息继续走既有扫描。

**验收**：
- 5 名目标用户可在 3 分钟内说出“本次是否可发布/主要风险”。
- 摘要中的每个数字可追溯到明细；口径不一致时明确标注。
- 分享视图不泄露敏感字段，权限与主视图一致。

#### FR-3.1-08 站内通知中心 v1（P1）

**问题**：运行完成/失败、计划冲突、节点离线只能靠用户自己回来看；通知表存在但无站内消费入口。

**要求**：
- 顶栏通知入口：未读数、分组（运行/计划/系统）、已读/全部已读、跳转来源。
- 事件去重与聚合：同一运行只保留最终状态；同一计划冲突合并。
- 通知可在个人偏好中按类型关闭；保留期与清理策略明确。
- 通知内容不含凭据与敏感日志。

**验收**：
- 运行完成/失败、计划冲突、节点离线 3 类事件 100% 产生通知。
- 未读数准确；已读状态跨会话保持；跳转落到正确详情。
- 关闭类型后不再产生该类站内通知，但审计仍保留。

#### FR-3.1-09 新手引导、帮助与快捷键（P2）

**问题**：新用户不知道先做什么；帮助入口分散；键盘用户缺少速查。

**要求**：
- 首次进入提供 5 步清单：建项目/接节点/建用例/跑一次/看报告；可跳过、可恢复。
- 提供示例项目/示例数据一键体验，可安全删除。
- 页面内提供上下文帮助（字段说明、口径解释）；快捷键帮助面板。
- 引导不阻断老用户，可在设置中永久关闭。

**验收**：
- 新用户按清单完成 Top 5 首次任务，无需外部培训。
- 示例数据与真实数据隔离，删除不影响真实项目。
- 快捷键面板列出的组合全部可用。

#### FR-3.1-10 无障碍与响应式收口（P1）

**问题**：抽屉/弹窗的焦点回位、键盘路径与读屏名称缺少统一验收；760–1024 宽度局部拥挤。

**要求**：
- 抽屉/弹窗焦点陷阱、Esc 关闭、返回焦点；所有交互控件有可读名称与焦点态。
- 支持 200% 缩放；表格/表单在 1024 与 760 宽度可用；关键页面无横向滚动。
- 尊重“减少动效”系统设置；动效只用于状态变化，不用于装饰。
- 关键流程提供键盘操作路径。

**验收**：
- axe 扫描关键页面 0 严重项；键盘完成 Top 8 任务。
- 200% 缩放无内容截断；760 宽度主操作可见。
- 减少动效下功能不受影响。

### 5.2 v3.2.0「快而稳」

#### FR-3.2-01 性能预算与规模基线（P0）

**要求**：建立 API、前端、长列表、运行链四类预算；固定 1 万用例/10 万运行/百万日志数据集；预算纳入门禁；任何回退超 10% 或 30ms 必须解释并授权。

**验收**：四类预算有基线报告；门禁可判定；规模数据集可重复生成；回退 0 次越线。

#### FR-3.2-02 查询与分页治理（P0）

**要求**：清理 `SELECT *` 与循环内查询；统一分页参数、上限与排序白名单；深分页改游标/键集；为高频过滤/排序补索引并附 `EXPLAIN` 证据；慢查询有日志与阈值。

**验收**：20 处 OFFSET 全部评估（改造或保留理由）；6 处 `SELECT *` 清零；核心列表在规模数据集 p95 ≤ 150ms；索引变更含 down 脚本。

#### FR-3.2-03 只读缓存与批量聚合（P1）

**要求**：对低变更、读多写少的参考数据与总览指标引入进程内缓存，明确 TTL、容量、失效与降级；批量查询替代逐项查询；缓存不改变权限与审计语义。

**验收**：缓存命中率与内存有指标；数据变更后 1 次请求内失效；禁用缓存时功能一致；无跨项目越权缓存。

#### FR-3.2-04 异步事件与非关键路径（P1）

**要求**：审计、通知、指标汇总等非关键动作通过有界线程池/应用事件异步执行；执行主链仍同步可控；队列满/异常有降级与告警；优雅停机不丢关键事件。

**验收**：非关键动作不阻塞请求；异步失败可重试/补偿；停机时任务有明确落盘或丢弃策略；审计不丢。

#### FR-3.2-05 执行链可靠性（P0）

**要求**：运行请求幂等；节点租约与心跳限频；孤儿进程/临时目录自动清理；服务重启后可恢复运行状态；并发上限与公平调度可配置。

**验收**：重复提交不产生重复运行；节点掉线可判定；重启后运行状态一致；无孤儿进程累积。

#### FR-3.2-06 前端性能与长列表（P0）

**要求**：路由级按需加载；主入口与路由块预算；长列表虚拟滚动；请求去重与短缓存；骨架屏与预取；图片/图标按需。

**验收**：主入口 ≤ 300 KiB gzip；路由块 ≤ 150 KiB；1 万行滚动 ≥ 50fps；路由切换 ≤ 300ms；无整页白屏。

#### FR-3.2-07 可观测性（P0）

**要求**：请求链路 ID 贯穿前端、后端、执行器与日志；结构化日志；关键指标（请求量/时延/错误率/队列/运行状态/缓存）；慢查询；健康与就绪探针；指标看板。

**验收**：任一请求可从 UI 错误提示追到后端日志与 SQL/执行记录；指标看板可用；健康检查区分存活/就绪；日志不含凭据。

#### FR-3.2-08 API 合同与架构守护（P1）

**要求**：产出 OpenAPI 合同；关键接口契约测试；错误码/分页/时间/枚举统一；ArchUnit 增加分层与依赖规则；高风险变更走 ADR。

**验收**：合同可生成、可校验、与实现一致；契约测试全绿；架构规则失败即门禁红；ADR 索引完整。

### 5.3 v3.3.0「聪明」

#### FR-3.3-01 流式对话与取消（P0）

**要求**：SSE/分块流式输出；首字 ≤ 3s；可停止生成；超时/断线可恢复；失败给出可重试原因；不阻塞其他请求。

**验收**：流式与非流式结果一致；取消后无残留任务；断线重连不重复计费；首字与完成时延达标。

#### FR-3.3-02 上下文感知与证据引用（P0）

**要求**：AI 可读取当前项目/运行/用例/报告的结构化上下文；回答中的事实必须带证据链接（运行 ID、用例 ID、报告段落、日志行）；上下文不足时明确说“不足以判断”；敏感字段脱敏。

**验收**：黄金集事实一致性 ≥ 95%；无证据断言为 0；引用可跳转且权限一致；提示词与日志无凭据。

#### FR-3.3-03 提示词库与快捷动作（P1）

**要求**：内置失败分诊、报告摘要、用例草稿、计划体检、日志解释等模板；支持项目级自定义；可从当前页面一键带入上下文；模板版本化。

**验收**：模板可发现、可复用、可编辑；带入上下文正确；删除/更新不影响历史会话。

#### FR-3.3-04 失败分诊助手（P0）

**要求**：基于聚类与单条失败给出“现象、可能原因、证据、建议检查项、下一步”；区分事实与推测；不承诺根因；建议动作需人工确认后执行。

**验收**：分诊结论与证据一致；推测有标注；用户采纳率 ≥ 70%；错误建议可反馈并进入评测集。

#### FR-3.3-05 报告叙述助手（P1）

**要求**：生成事实型摘要、风险、对比变化与建议；每个数字可追溯；支持人工编辑与重新生成；导出保留来源说明。

**验收**：摘要无虚构数字；编辑后不影响原始报告；导出内容与页面一致。

#### FR-3.3-06 用例草稿助手（P1）

**要求**：从自然语言/需求片段生成用例草稿（步骤、预期、标签），明确“草稿”状态；必须人工审阅后才能保存/提交；不自动改存量用例。

**验收**：草稿可编辑、可丢弃；保存前强制审阅确认；生成内容有来源标注；无自动提交。

#### FR-3.3-07 会话持久化、检索与配额（P1）

**要求**：会话与消息持久化，可按项目/时间/关键词检索；支持重命名、删除、导出；按项目配置模型/温度/超时/令牌预算；超限降级或阻断并提示。

**验收**：重登后会话可恢复；检索命中；配额与降级可验证；配置变更审计。

#### FR-3.3-08 AI 评测与守门（P0）

**要求**：建立黄金问题集（分诊/摘要/草稿/日志解释）；离线跑分含事实性、引用完整、时延、拒答；真实 CLI 仅在授权环境调用；默认 fake CLI 契约测试；评测结果入证据。

**验收**：每次变更可对比评分；事实一致性 ≥ 95%；严重幻觉 0；评测可重复。

#### FR-3.3-09 主动通知与告警（P0）

**要求**：站内通知 + Webhook/邮件通道；告警规则覆盖可用性、错误率、运行失败、队列积压、磁盘/备份；去重、抑制、恢复通知；通道失败降级到站内。

**验收**：注入故障 5 分钟内触达；恢复后自动闭环；重复告警被抑制；通道故障不影响主流程。

#### FR-3.3-10 SLO 看板、运行手册与恢复演练（P1）

**要求**：定义可用性/时延/运行成功率/备份时效 SLO；看板展示达标率与错误预算；提供运行卡住、节点离线、数据库异常、磁盘满、AI 降级、备份恢复手册；备份恢复自动化校验。

**验收**：SLO 看板可查；手册步骤可执行；季度恢复演练通过；MTTR ≤ 30 分钟。

#### FR-3.3-11 优雅发布与回滚（P1）

**要求**：版本戳、健康校验、优雅停机/排空、失败自动回滚；迁移与代码回滚顺序明确；发布记录可追溯。

**验收**：发布过程请求不中断或可接受；回滚在 10 分钟内完成；数据不丢；版本戳一致。

| FR-3.4-02 并发与多节点 | 50 并发运行、节点公平调度、限流与背压 | 并发稳定、无饥饿、无孤儿；资源曲线可解释 |

## 6. UI/UX 设计规范

### 6.1 设计原则

1. **先结论后细节**：首屏先回答“现在怎么样、要不要处理”，再给明细。
2. **一个主操作**：同一区域只保留一个视觉最强的主动作，其余降级为次级/更多菜单。
3. **状态可预期**：加载、空、错、无权限、降级五种状态都有明确视觉与下一步。
4. **可逆优先**：能撤销就不弹确认；不能撤销才二次确认，并写明后果。
5. **密度可调**：默认信息密度适中，提供紧凑模式；不靠缩小字号塞内容。
6. **动效克制**：只表达状态变化与空间关系；尊重减少动效。
7. **可访问**：键盘、读屏、对比度、缩放是默认能力，不是补丁。

### 6.2 设计系统增量

| 类别 | 新增/收口 | 说明 |
|---|---|---|
| 布局原语 | PageHeader、Section、Toolbar、FilterBar、SplitPane | 统一层级、间距、吸附与滚动 |
| 状态原语 | EmptyState、ErrorState、Skeleton、DegradedBanner | 每页必须声明状态 |
| 操作原语 | PrimaryAction、MoreMenu、ConfirmDialog、UndoBar | 主操作唯一、危险动作可逆 |
| 数据原语 | DataGrid、ColumnSettings、SavedView、PaginationBar | 虚拟滚动、列设置、视图、统一分页 |
| 表单原语 | FormField、HelpText、ValidationSummary、DraftBanner | 字段级校验与草稿恢复 |
| 反馈原语 | Toast、InlineAlert、NotificationItem、ProgressSteps | 成功/失败/进行中一致 |
| AI 原语 | ContextChip、EvidenceLink、SuggestionCard、StreamingMessage | 上下文、引用、建议、流式 |

### 6.3 页面模板

| 模板 | 适用页面 | 结构 |
|---|---|---|
| 总览型 | 工作台、项目总览 | 标题 + 关键指标 + 需关注 + 最近活动 |
| 列表型 | 用例、运行、报告、计划、资产 | 标题 + 主操作 + 筛选 + 批量栏 + 表格/卡片 |
| 详情型 | 用例详情、运行详情、报告详情 | 摘要 + 状态 + 主操作 + 标签页 + 证据 |
| 编辑型 | 用例编辑、计划编辑、设置 | 分组表单 + 校验摘要 + 草稿状态 + 保存栏 |
| 运行型 | 运行监控 | 阶段 + 进度 + ETA + 日志 + 操作 |
| 配置型 | 项目设置、AI 配置、通知偏好 | 分组 + 说明 + 测试连接 + 保存 |

### 6.4 状态矩阵

| 状态 | 视觉 | 文案 | 必须提供 |
|---|---|---|---|
| 加载 | 骨架/局部 spinner | 正在加载… | 不闪白、不跳动 |
| 空 | 插图/图标 + 说明 | 为什么为空 | 新建/导入/切换范围 |
| 错误 | 错误块 + 错误码 | 原因 + 下一步 | 重试/返回/复制诊断 |
| 无权限 | 锁图标 | 缺什么权限 | 申请/切换项目/返回 |
| 降级 | 顶部条 | 哪个能力降级 | 影响范围 + 替代路径 |
| 部分成功 | 结果条 | 成功 N/失败 M | 失败明细/重试/导出 |

### 6.5 视觉与无障碍

- 颜色只走语义令牌；深浅色、6 强调色、2 密度组合全部走查。
- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1；焦点态可见且不被裁切。
- 字号阶梯固定；表格数字右对齐、等宽数字；时间统一格式与时区。
- 图标统一线性风格与尺寸；不以颜色作为唯一状态信息。
- 动效 150–250ms，缓动一致；减少动效下仅保留必要反馈。
- 760/1024/1280/1440 四档走查；不承诺手机原生布局。

### 6.6 内容设计

- 术语统一：项目、用例、计划、套件、运行、报告、资产、节点、凭据。
- 按钮用动词：保存、发起运行、重跑失败项、导出报告；不用“确定”承载多种语义。
- 错误文案三段式：发生了什么、为什么、下一步。
- 危险动作写明影响对象与范围；批量操作显示数量。
- 时间、数量、百分比统一口径，报告与页面一致。

## 8. 数据与产品度量

### 8.1 原则

- 当前无前端产品埋点；3.X.X 采用**服务端聚合优先、客户端最小化可选**的方式。
- 不采集用例正文、日志正文、凭据、个人信息；只采集页面/动作/耗时/结果/错误码。
- 客户端采集默认关闭或仅内部项目开启，需在评审中拍板；提供一键关闭与数据导出/清理说明。
- 指标用于改进体验，不用于个人绩效。

### 8.2 事件清单（建议）

| 事件 | 关键字段 | 用途 |
|---|---|---|
| page_view | 页面、项目、角色、耗时 | 入口与停留 |
| task_start/end | 任务类型、结果、耗时、步骤数 | Top 8 成功率与效率 |
| search_query/result_click | 范围、词数、Top3 是否命中、零结果 | 搜索质量 |
| filter_save/apply | 视图、字段数 | 视图使用 |
| bulk_action/undo | 动作、数量、结果 | 批量与可逆 |
| run_launch/preflight | 预检结果、阻断类型 | 发起质量 |
| run_progress | 阶段、ETA 偏差、卡住 | 运行可感知 |
| report_open/summary_view | 报告类型、摘要点击 | 报告可读 |
| ai_chat/stream/cancel/feedback | 模板、首字、完成、采纳、错误 | AI 质量 |
| error_recovery | 错误码、是否恢复、下一步点击 | 错误可用 |

### 8.3 看板

- 体验：Top 8 成功率/耗时/步数、搜索命中、错误恢复、SUS。
- 性能：API p95/p99、LCP、路由、包体、长列表帧率、慢查询。
- 运行：发起成功率、预检阻断分布、卡住率、完成时延、失败聚类 Top N。
- AI：首字/完成、事实一致性、采纳率、拒答率、配额命中、降级率。
- 运维：可用性、错误率、告警 MTTD、MTTR、备份时效、恢复演练。

## 9. 发布、灰度与回滚

### 9.1 特性开关

建议开关：`ui.v3.primitives`、`search.v3.entities`、`views.v3.saved`、`bulk.v3.undo`、`notifications.v3.inapp`、`perf.v3.cache`、`perf.v3.virtual`、`ai.v3.stream`、`ai.v3.context`、`ops.v3.alerts`。开关必须可服务端配置、可审计、默认安全。

### 9.2 灰度顺序

1. 内部示例项目/测试项目。
2. 单一真实项目（低风险、有人值守）。
3. 全部项目。
4. 每步观察错误率、性能、用户反馈与回滚条件；不达标即回退开关。

### 9.3 回滚判据

- P0/P1 功能不可用或数据错误。
- API p95 超预算 30% 且持续。
- 错误率翻倍且 30 分钟内不可定位。
- 权限/审计/凭据出现任何异常。
- 迁移不可逆或数据校验失败。

### 9.4 迁移与兼容

- 迁移只追加；高风险变更提供 down 脚本、回填脚本与校验 SQL。
- 新字段/表先兼容旧读写，再切开关，最后清理。
- 版本号使用构建号，不使用 alpha/beta 标签。

## 11. 验收与评审

### 11.1 版本退出检查单

- 所有 P0 FR 达成；P1 未达成有降级说明与授权人；P2 可延后并写去向。

- 契约、集成、E2E、性能、安全、韧性、AI 评测按计划执行并留证。

## 12. 附录

### 12.1 术语

- **页面原语**：跨页面复用的布局/状态/操作/表单/数据组件。
