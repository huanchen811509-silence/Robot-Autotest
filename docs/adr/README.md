# 架构决策记录（ADR）

**归属** DOC-04 ｜ **对应** FR-v0.1-22

ADR 用来记「为什么这么定」，不记「代码怎么写」。代码怎么写由 `CONVENTIONS-*` 与源码负责；
**凡是会约束三个以上版本的决定，都必须有一条 ADR**，否则半年后没人知道当初为什么这么选。

## 何时写、何时改

| 情形 | 动作 |
|---|---|
| 新架构决策（分层、存储、迁移、CI 落点、外部契约） | 新建 `NNNN-<短标题>.md`，编号顺延，不复用 |
| 已生效的决策被推翻 | **不改原文**，在原文件顶部标 `状态：已废弃（被 ADR-NNNN 取代）`，再新建一条 |
| 只是补充说明 | 改原文件的「后果」段，并在修订记录加一行 |

状态取值：`提议` / `已采纳` / `已废弃` / `已取代`。
