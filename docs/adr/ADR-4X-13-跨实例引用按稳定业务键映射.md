# ADR-4X-13 · 跨实例引用按稳定业务键映射，成员默认 skip 且禁止自动授权

- **状态**：已采纳
- **日期**：2026-11-09
- **决策人**：大师（书面批准 2026-11-09）
- **约束范围**：v4.1.0 起工作区导入的成员 / 用例 / 用例集 / 设备链路 / 凭据 / 报告引用解析

## 背景

`FR-v4.1-02` ⑨ 要求「成员 / 设备 / 凭据 / 用例集引用按稳定业务键映射，成员默认 skip 且禁止自动授予 admin，
资产无法解析逐条 skip 报告，runs / reports 仅作归档不入执行表」。

已知事实：`project_member.user_id`、`device.id`、`robot_file.id`、`test_case.id` 都是**实例内自增**，
A 实例的 `user_id=7` 在 B 实例可能是另一个人。直接搬 id 的结果是静默错挂，比导入失败危险得多。
另一事实：`roleCode` 与 `member_role` 已是两套口径（`admin/pm/engineer/viewer` vs `owner/member/viewer`），
导入端若按 `members.json` 里的角色字符串自动写成员表，等于绕过目标实例的授权流程。

## 选项

| 选项 | 优点 | 代价 | 为何不选 / 为何选 |
|---|---|---|---|
| ① 原样搬 id | 实现最省事 | 跨实例必悬空或错挂；不可检测 | 不选 |
| ② 全部重建（缺什么建什么） | 导入后「看起来完整」 | 会在目标实例凭空造用户、凭据与设备，越权面失控 | 不选 |
| ③ 稳定业务键匹配 + 缺失即 skip + 逐条报告 | 结果可解释、可复现；绝不扩权 | 导入后可能缺成员/资产，需要人工补 | **选** |

## 决定

| 引用 | 稳定业务键 | 目标缺失时 |
|---|---|---|
| 成员 | 登录名（`app_user.username`），不用 `user_id` | skip 并逐条报告；**禁止**自动授予 admin，**禁止**自动建用户 |
| 用例 | `test_case.case_code`，脚本文件用 `robot_file.path` | skip 并报告；不改挂到同名用例 |
| 用例集条目 | 用例 `case_code` + `seq_no` | 整条 item skip 并报告 |
| 设备 / 链路 | 资产名称 + 类型 + 项目 code | 按业务键匹配；缺失 skip，不新建 |
| 凭据 | 凭据名称 + 掩码指纹（sha256 前 12 位） | 只写引用与掩码；缺失 skip；**绝不导出密文** |
| 报告 / 运行 | `run_id` + 报告编号 | 仅归档到 `workspace/<code>/archive/`，不写 `run` / `test_report` |

边界：

- 冷启动（目标实例没有该 `project-code`）：默认**拒绝并提示先创建项目**；
  用户显式选择「创建为草稿」时，导入者二次确认后才成为该项目 admin，**不读 `members.json` 自动授权**。
- 创建草稿失败不得留下半成品项目（与导入的「单事务」是同一条纪律）。
- 映射失败只影响该条目，不使整批回滚；但**验签 / 路径安全 / 格式版本**失败是整批拒绝。

## 后果

- 正面：导入结果每条都能给出「命中 / 跳过 / 原因」；不会在目标实例制造隐式授权。
- 负面：跨实例导入后通常要人工补成员与资产，用户会感到「没导全」；因此 UI 必须把 skip 清单放在冲突报告首屏。
- 触发复核的条件：出现「导入后必须自动可用」的明确需求时，先补目标实例的用户目录同步能力，再谈自动授权。
