# ADR-39-02 · 用例命令三列直接放 test_result，不建独立表

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-09 |
| 约束范围 | v3.9.0 起报告与执行域（表结构、读取链、导出） |
| 依据 | RA-PRD-39-001 §3 ADR-39-02；迁移 `V11_24` |

## 背景

报告页要显示「这条用例到底下发了什么命令」。本版口径是**一条用例一条命令**（首条，见 ADR-39-04 的边界）。若另立 `case_command` 表，报告页一行要多一次 JOIN，且必然出现「有结果无命令行」与「有命令行无结果」两种半状态。

## 决策

在 `test_result` 上直接加 `command_text TEXT NULL` / `command_source VARCHAR(24) NULL` / `command_exit_code INT NULL` 三列，全部可空、历史数据不回填。
`command_source` 用 `VARCHAR(24)` 而非 `ENUM`：新增来源不该再动表结构，合法性由 `CaseCommandExtractor` 与门禁第 28 步双重把关。

## 后果与护栏

- 正面：命令与结论同生命周期、同 `run/case` 索引，一次查询拿全；回滚只需删三列（`V11_24....down.sql`）。
- 负面：未来「一条用例多条命令」必须建子表并做一次数据搬迁，届时 `test_result` 三列只能保留「首条」语义。
- 护栏：三列不设默认值、不写 `0` 冒充「退出码为 0」；未知一律 `NULL`。
- 复核条件：出现同一用例需保留多条命令（循环下发、重试）的需求时，改按 ADR 新建子表并标注本 ADR 为已取代。

## 验证方式

`TC-v3.9-06`（三列贯通到读取链）、`TC-v3.9-22`（down→up 真实演练，`docs/evidence/v3.9.0/EW39-02/down-up-rehearsal.log`）。
