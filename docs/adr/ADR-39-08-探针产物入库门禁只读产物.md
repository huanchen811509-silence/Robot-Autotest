# ADR-39-08 · 探针产物入库，门禁只读产物

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-09 |
| 约束范围 | v3.9.0 起全部浏览器探针与门禁判据的分工 |
| 依据 | RA-PRD-39-001 §3 ADR-39-08；`docs/evidence/v3.9.0/` |

## 背景

探针脚本既能采集又能判定时，很容易演变成「脚本自己说自己绿」：把判据写在采集里，一旦采集失败就跳过判定，门禁照样绿。反过来，若门禁自己重新采集，又会出现「取证与判据用两份数据」的口径分裂。

## 决策

- **采集**：脚本跑真实浏览器/真实库，把原始读数写进 `docs/evidence/v<版本>/<工作包>/`，JSON 入库。
- **判定**：门禁只读产物并套判据，不重新采集；产物缺失即判红，不允许「没数据算通过」。
- **自证**：每个探针必须带 `--selfcheck`，注入劣化后判据必须变红，否则探针本身不算可信。

## 后果与护栏

- 正面：「数据怎么来」与「算不算达标」互不掩盖；证据可被人手工复核。
- 负面：证据文件进版本库会变大；探针与门禁要维护两处（采集格式 + 读格式）。
- 护栏：门禁第 28 步对「证据缺失/抽样为空」判红；探针改字段名必须同步门禁读取侧。
- 复核条件：证据体积成为仓库负担时，改为「产物摘要入库 + 大文件放 artifacts」，但判据读取方式不变。

## 验证方式

`TC-v3.9-08`（六类脏数据自证全红）、`TC-v3.9-03` / `TC-v3.9-19`（探针 `--selfcheck` 判红）。
