# ADR-39-03 · NONE 与 NULL 语义分离：本来没有 vs 还没采集

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-09 |
| 约束范围 | v3.9.0 起报告读取、导出、覆盖率判据 |
| 依据 | RA-PRD-39-001 §3 ADR-39-03；门禁第 28 步 |

## 背景

`command_text` 为空有两种完全不同的原因：**用例本来就没下发外部命令**（例如纯断言用例），以及 **v3.9.0 之前入库、当时没有采集这个字段**。若两者都显示空白、都算「无命令」，覆盖率会得出错误结论——用历史数据凑出的 100% 是假证据。

## 决策

- 入库侧：确实没有命令 → 写字符串 `NONE`；历史未采集 → 保持 `NULL`。
- 展示侧：`NONE` 显示「本用例未下发外部命令」，`NULL` 显示「未采集（v3.9.0 之前的报告）」。
- 判据侧：覆盖率只认「有真实命令」与「显式 `NONE`」两种，遇到 `NULL` 直接判红并要求重跑，不许计入分母。

## 后果与护栏

- 正面：覆盖率可判定、可解释；历史报告不被迫重算，也不污染新结论。
- 负面：任何读取方都必须识别三态（`null` / `NONE` / 原文），少一个分支就显示错文案。
- 护栏：`RunCaseRow` / `CaseNode` / 前端类型三处注释写明三态；`SuiteTree.spec` 断言 `NONE` 与 `null` 文案**不同**；`check_case_command.py --self-check` 的「历史 NULL 行」用例必须判红。
- 复核条件：历史数据被统一回填（会消灭 `NULL` 态）时，本 ADR 需同步修订。

## 验证方式

`TC-v3.9-09`、`TC-v3.9-08`（自证含「历史 NULL 行」脏数据）。
